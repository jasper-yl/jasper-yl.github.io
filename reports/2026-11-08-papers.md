## 热度榜：Agent Context 精选

### [Why Pay for Long Reasoning When Rewrite Do Trick?](https://arxiv.org/abs/2611.03852)
- 热度：HF 👍13（入榜 3 天，新增 +13）；无代码，无 X 数据
- 问题：长推理 trace 成本高，能否不重训，只靠改写自己的历史推理来省 token。
- 方法：在工具结果返回之前，把先前的推理改写成「紧凑状态记录」（compact state records），再对比原始历史和紧凑历史下的后续生成。测试用开源权重模型，另有 software-agent 部署实验。
- 结论/意义：被接受的紧凑历史通常会缩短后续推理，coding 案例中重复验证减少；agent 部署中可降低总花费，但任务质量和含改写的耗时取决于目标模型和压缩器，作者呼吁做按模型区分的压缩策略。

### [Tools Need Not Speak in Text: Latent Context Compression for Agents (Coca-Cola)](https://arxiv.org/abs/2611.06500)
- 热度：HF 👍5（入榜 3 天，新增 +5）；代码 [THU-Agent/Coca-cola](https://github.com/THU-Agent/Coca-cola) ⭐7
- 问题：agent 把原始工具输出直接追加进上下文，开销大且稀释注意力；文本层面的剪枝和摘要压缩率有限。
- 方法：把工具观测压成 latent token，嵌入 agent 的输入 embedding 空间。提出 Action-Preserving Training，让完整观测和压缩观测下的下一步动作分布对齐，使 latent token 保留对决策关键的信息。
- 结论/意义：在 web 搜索 agent、4 个 QA 基准、2 个模型家族上，token 消耗降 70.01%–89.24%，端到端耗时降 24.45%–55.97%，任务表现持续提升。

### [Switch-SWE: Do Coding Agents Hold Focus When Switching Between Unfinished Tasks?](https://arxiv.org/abs/2611.02017)
- 热度：HF 👍10（入榜 5 天，新增 +10）；代码 [Miraclecsc/Switch-SWE](https://github.com/Miraclecsc/Switch-SWE) ⭐26
- 问题：同一仓库里穿插多个未完成任务时，agent 能否恢复先前任务的需求和进度。
- 方法：基准含 200 个 focus task、19 个 Python 仓库，配成 400 个匹配会话（中断与不中断）。轨迹分析发现常见失败是跨任务需求混淆和任务状态丢失。作者提出插件式上下文管理模块，挑选与任务相关的历史，并维护简短的任务状态摘要。
- 结论/意义：7 个 coding agent 平均 focus 任务解决率下降 11.5 个百分点（范围 6.0–15.0）；在 OpenCode 上，该模块使完成率提升 5.5–15.5 个百分点。

### [Can Large Language Model Agents Learn by Watching Tutorial Videos? (TAL)](https://arxiv.org/abs/2611.01460)
- 热度：HF 👍5（入榜 5 天，新增 +3）；无代码
- 问题：agent 能否不更新参数，从教程视频里持续学习。
- 方法：把教程视频整理成持久的结构化「tutorialbook」记忆，用对抗式两阶段过程提出难的、基于视频的问题来精炼记忆。推理时通过目录（TOC）树检索，由模型推理驱动检索，不依赖 embedding 相似度。
- 结论/意义：在 VidLearn（72 个国际象棋教程视频、12 种开局）上，相对原始 MLLM，训练集和测试集分别最多提升 113% 和 91%；实战中 69% 的对局开局阶段局面优于原始模型。

### [GEPA-Curator: Curated Learning for Self Improving Agents](https://arxiv.org/abs/2610.37651)
- 热度：HF 👍8（入榜 5 天，新增 +3）；无代码
- 问题：反射式 prompt 优化器（如 GEPA）从失败 rollout 学习，但有些失败来自 harness 限制、随机性或噪声评审，并不是有用信号。
- 方法：包含两个组件。任务筛选负责过滤会给出噪声信号的任务；成功轨迹检索为某个任务选择性检索过往成功轨迹，作为额外上下文交给 prompt 优化器。
- 结论/意义：在 GoBrowse、ALFWorld、AppWorld、τ-bench 上，相对 GEPA 最多提升 20.7%，相对 ACE 最多提升 21.2%。

### [Dory1.0-4B: A Looped Normalized-GPT](https://arxiv.org/abs/2611.03998)
- 热度：HF 👍12（入榜 4 天，新增 +9）；无代码链接
- 问题：如何让一个 checkpoint 按推理预算弹性调节深度，同时不增加 KV cache。
- 方法：循环（latent-recurrent）的 4B 模型，共享的递归块可重复应用。循环时只缓存最后一圈的 KV，因此无论循环几次，KV-cache 占用都与不循环的模型相同。上下文长度扩展到 256K。
- 结论/意义：2 圈及以上时，12 个基准平均优于 Qwen3.5-9B、Gemma 4 12B、Gemma 4 26B-A4B；4 圈时 agentic 基准生成的 token 比 1 圈少 1.3–2.5 倍。

### [The SIMPLE Law for Energy Cost of LLM Inference](https://arxiv.org/abs/2611.03330)
- 热度：HF 👍9（入榜 5 天，新增 +9）；无代码
- 问题：每个 token 的能耗并不相同，缺少解析模型。
- 方法：推导 MHA/GQA 的计算和访存复杂度闭式表达，得到四参数的 SIMPLE 模型，把 prefill 和 decode 分开，decode 再拆成 KV-cache 项和下一 token 计算项。
- 结论/意义：13 个稠密 LLM、H100 上 R²=0.969、MAPE 11.97%，比 SOTA 低 3.1–3.5 倍。agentic 请求单次能耗是非 agentic 的 13.0 倍；prefix caching 去掉约 93% 的 prefill 成本，但 KV-cache 项不变，缓存后的 agentic 请求仍高 4.8 倍。

## 研究趋势观察
- 上下文压缩分成两条路线：文本层（把推理历史改写成状态记录，[2611.03852](https://arxiv.org/abs/2611.03852)）和 latent 层（把工具输出压成 latent token，[Coca-Cola](https://arxiv.org/abs/2611.06500)）。两者都强调压缩后要保住决策能力，并报告了效率收益：token 降 70.01%–89.24%；花费降低，但质量取决于模型。
- 长程任务里的「状态丢失」开始有量化基准：[Switch-SWE](https://arxiv.org/abs/2611.02017) 测得任务切换造成平均 11.5 个百分点的损失，harness 持续演化时的遗忘（94.0%→32.0%）是另一个例子。两者都指向记忆和上下文如何被选择与保留。
- KV cache 既是通信介质，也是成本项：[SwarmEvolve](https://arxiv.org/abs/2611.08483) 用它在 agent 间传递想法，[Dory1.0-4B](https://arxiv.org/abs/2611.03998) 只缓存最后一圈的 KV 来控制内存，[SIMPLE 定律](https://arxiv.org/abs/2611.03330)测得缓存后的 agentic 请求能耗仍是普通请求的 4.8 倍。
- 热度偏低且分散：Agent Context 的 status=hot 论文最高 👍13，其余 Agent 方向最高 👍15；今天没有 hot 论文带来 X 提及或明显的 GitHub 星数增长（最高 ⭐40 为 DR Pixel，不在 Agent Context 精选内）。本次数据没有 GitHub 项目侧数据，无法写工程侧呼应。
