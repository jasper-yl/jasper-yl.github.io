## 热度榜：Agent Context 精选

### [Folio: Recoverable Multi-Resolution Context Folding for Long-Horizon Language Agents](https://arxiv.org/abs/2611.16627)
- 热度：非 HF 来源（arXiv），HF 暂无点赞；入榜 5 天；无代码仓库，无 X 数据。
- 问题：长程 Agent 靠模型总结历史来压缩上下文，每次压缩都要重读重写历史，成本高。
- 方法：运行时同步记录三级视图：L1 是模型回复里顺带写的 turn note，L2 是运行时写的每次调用事件清单，L3 是原始来源记录。压缩时按内容的旧程度选更粗的视图，并在上下文里留下指向 L2/L3 的句柄。恢复工具按页读取，在文件里对全文做计算，发现记入持久 dossier。折叠触发时，保留预算计入落点价格。
- 结论/意义：LOCA-bench 75 题、统一用 DeepSeek-V4-Pro，Folio 解 66 题；同一运行时用模型写压缩解 54 题；Claude Code、Codex、SoL-Pi 为 49–59 题。耗时约为对手的一半，成本比模型写压缩低 2.4 倍，每次折叠中位数 0.6 秒。

### [Coding Agent Memory Post-Training II (CAMP-II)](https://arxiv.org/abs/2611.14009)
- 热度：arXiv 来源，HF 暂无点赞；入榜 7 天；无代码仓库。
- 问题：长程任务的历史超出上下文，Agent 要自己决定写什么、读什么。已有的 on-policy distillation（OPD）依赖教师没见过的记忆工具，指导无效。
- 方法：提出 CAMG-II 环境套件（Shop、Coding、AutoResearch、General、Visual），给 Agent 普通 Bash 和跨上下文替换持续存在的工作区，让它把文件当记忆。CAMP-II 用全异步 OPD 在五个环境上联合训练一个策略，从熟悉文件操作的冻结教师那里学这种文件式记忆行为。
- 结论/意义：在 CAMG-II 上的增益是最强 OPD 基线的 2.97 倍；行为可迁移到 Terminal-Bench 2.1 和 SWE-Bench Pro V2。

### [When Should Agents Remember? Falsification-Gated Self-Evolution (FGSE)](https://arxiv.org/abs/2611.14326)
- 热度：arXiv 来源，HF 暂无点赞；入榜 7 天。
- 问题：把单次经验直接写入记忆，局部成功并不可靠。
- 方法：每条候选 lesson 表示为一个假设，带前置条件、行为改变、预期效果和验证器。先在临时状态上应用，用目标迁移、证伪、归档回归三类探针测试，再按收益和风险决定提交、改写或拒绝。
- 结论/意义：WebArena 39.8，AppWorld 78.8，τ-Retail/τ-Airline Pass^1 为 0.724/0.487；证伪失败 5.0%，回归损害 1.3%，有害提交更新 3.6%。

### [Discovering Effective Agent Memory Designs through Program Evolution (MAPE)](https://arxiv.org/abs/2611.17068)
- 热度：arXiv 来源，HF 暂无点赞；入榜 5 天；代码：[ash-ding/MAPE](https://github.com/ash-ding/MAPE)（数据未给星数）。
- 问题：记忆系统靠人工设计，不清楚哪些设计选择真正有效。
- 方法：从最小种子出发，用标准化生命周期接口和「诊断—提议」循环演化整套记忆程序。归纳出两个模式：保留原始对话作为可检索证据；按查询意图组织检索到的证据。
- 结论/意义：LoCoMo 与 LongMemEval 上绝对准确率最多 +12%，服务成本为人工基线的 35%；把组合模块移植到五个现有记忆系统，全部提升。

### [SHADOWPREFILL: Keeping Your Next Model Warm for Per-Step Model Routing](https://arxiv.org/abs/2611.13176)
- 热度：arXiv 来源，HF 暂无点赞；入榜 7 天。
- 问题：每步路由换模型会丢失 prefix cache（KV cache 按模型分），前缀命中率从同模型的 80–89% 降到 44–65%，切换调用耗时是原来的 1.5–3.2 倍。生产编码 Agent 轨迹的平均上下文为 63K token。
- 方法：在空闲容量上提前为未被选中的模型预填会话上下文，利用在途请求的 SLO 余量，shadow KV 溢出到主机内存；shadow 不完整时回退到冷切换。
- 结论/意义：在 24 个模型对、五个 agentic 基准套件上，切换调用延迟 −8.5–21.4%，LLM 调用延迟 −3.7–17.7%，路由 token 成本 −22.5–46.1%，每请求能耗仅 +0.4%。

### [Continual-ARC: Measuring Skill Acquisition over a Working Lifetime](https://arxiv.org/abs/2611.14505)
- 热度：HF 👍2（入榜 2 天，首次 9，之后 −7）；代码：[unifyai/continual-arc](https://github.com/unifyai/continual-arc) ⭐38。
- 问题：现有基准只测单一领域、每个实例只出现一次，记忆型与权重型持续学习无法在同一尺度上比较。
- 方法：用三个 ARC-AGI 版本构成终身任务流，任务隔一段时间带新实例回归，按消耗的反馈预算计分；学完后冻结，在见过的任务（记忆）和未见任务（泛化）上测试。对比对象有冻结权重的 Agent harness（有/无持久化）、两个提示底线、程序归纳法和蒸馏权重。
- 结论/意义：harness 的持久化除非有专家指导，通常不提升记忆；多数 harness 方法学到的比「缓存每个任务示例」的底线还少；harness 方法在未见任务上无增益，权重学习有明显增益。

### [MemCredit: From Relevance to Utility for Decision-Time Memory in Long-Horizon Web Agents](https://arxiv.org/abs/2611.15600)
- 热度：arXiv 来源，HF 暂无点赞；入榜 5 天。
- 问题：与当前状态语义最相关的记忆，未必最能改善动作。
- 方法：通过受控反事实干预估计单条记忆的边际贡献，蒸馏成轻量的效用估计器。语义相关性只用来召回候选，在固定 token 预算下由预测效用决定保留哪些记忆。
- 结论/意义：ALFWorld 在 500-token 历史记忆预算下 SR@50 为 86.57，BM25 检索为 65.67%；反事实分析显示记忆效用稀疏、强依赖状态，语义相关性难以刻画。

### [DISCERN: Preserve at Write, Resolve at Read for Persistent LLM-Agent Memory](https://arxiv.org/abs/2611.15729)
- 热度：arXiv 来源，HF 暂无点赞；入榜 5 天。
- 问题：企业 Agent 跨多会话的记忆中，事实相互矛盾、被替代，相似实体在嵌入空间里混淆。
- 方法：写入时构建严格只增、双时间轴的溯源图，不合并易混实体，也不丢弃被取代的值；读取时用零 LLM 的工具面驱动 agentic 循环导航，最终只能提交四种受控终止动作之一。
- 结论/意义：在作者自建的 ENT-310 上，弃答 F1 为 0.924，八个基线最高 0.802；宏平均答案正确率 0.861，最强基线 0.806。零调参用于 LoCoMo 全集为 0.663，基线为 0.638。

## 🆕 New：昨晚新公布

- [Context Has a Price: Adding and Removing Context for LLM Coding Agents under Prefix Caching](https://arxiv.org/abs/2611.22238)：在 20,000+ 次运行里分别计未缓存输入、缓存输入和输出。检索代码让读/搜命令减少 18–34%，但缓存价为十分之一时成本增加 33–42%；删旧观察在无缓存折扣时省 19–36%，十分之一缓存价时反而增加 38–116%。
- [Stopping Is Not the Limit（SCoRe）](https://arxiv.org/abs/2611.22888)：漏洞利用任务里，Agent 常在预算未用完时停止；SCoRe 在连续停止回复处压缩上下文，并把「不可能」的判断标为未证实。MiMo 在 2,000 轮达到能力覆盖 67.0%，原停止策略下为 32.4%。
- [When Agent Skills Go Stale](https://arxiv.org/abs/2611.22525)：环境变化后，原本有益的 skill 可能使任务表现下降超过 10 个百分点，或使执行成本增加近 40%；选择性维护（回放检查、修复、验证）使准确率最高 +67pp，执行步数最多 −37%。
- [RAG in a Trenchcoat](https://arxiv.org/abs/2611.22179)：极简记忆 BRIDGE 在 LongMemEval-S 和 BEAM 上与 SOTA 持平，在 EverMemBench 上领先 5.7–6.3 分，reader prompt 约 5–7K token；作者主张记忆应评估「能让 Agent 做什么」，而非「检索到什么」。
- [SkillBuffBench](https://arxiv.org/abs/2611.22017)：把 Skill 访问分为无 Skill、指定 Skill、从已装库自动调用三档，再与记忆开关、四种 harness、多个模型交叉；任务来自材料科学、生物等领域的专家。结果尚未发布，评测仍在进行。
- [Multi-Agent Memory Inconsistency](https://arxiv.org/abs/2611.22245)：强制委派使两个冲突声明都被检索到的比例从 50.2% 升到 68.7%，但冲突检出率从 16.2% 降到 13.2%；worker 只报告了 35.2% 被检索到的冲突对。
- [Self-Improvement Memory Enables Continual Recursive Self-Improvement](https://arxiv.org/abs/2611.18856)：给 harness 优化器（而非任务策略）配记忆，按反复出现的问题分组，记录编辑理由、预测与观察到的结果；十个编码源运行中比仅 harness 续跑平均 +2.36 分（p=0.003）（初步热度 👍25）。
- [TeleChat to Xing4](https://arxiv.org/abs/2611.22115)：Xing 4 系列大模型，在 8,192 张昇腾 910C 上预训练 285B 参数模型，并推出统一的 Agent 执行平台 TeleGym（初步热度 👍147）。
- [AscendGYM](https://arxiv.org/abs/2611.17621)：昇腾 NPU 内核优化基准，48 个内核、三档难度，提出按 token 成本衡量加速的 Speedup-Token Score；仓库 [SLAI-AITP/AscendGYM](https://github.com/SLAI-AITP/AscendGYM) ⭐25（初步热度 👍91）。
- [ForceHarness](https://arxiv.org/abs/2611.21099)：让冻结的前沿模型借助力控原语和「物理翻译层」使用力信息；真实机械臂上 GPT-6 Astra 零样本成功率从 3.3% 升到 90.0%；仓库 [showlab/ForceHarness](https://github.com/showlab/ForceHarness) ⭐24（初步热度 👍38）。
- [VideoNexus](https://arxiv.org/abs/2611.21392)：长视频 Agent 把感知交给上下文独立的子 Agent，只回传紧凑的时序证据；LVBench 88.6%，成本为内置 agentic 处理的 44%（初步热度 👍18）。
- [RepoFactory](https://arxiv.org/abs/2611.21152)：把真实仓库转成可验证的训练环境，产出 10,159 个环境、覆盖 17 个软件领域；训练 Qwen3.5-35B-A3B 后 NL2Repo-Bench +22.6 个百分点；仓库 [IQuestLab/RepoFactory](https://github.com/IQuestLab/RepoFactory)（初步热度 👍10）。

## 研究趋势观察

- 热度榜的点赞集中在模型技术报告（Sage、K2-Horizon）和 Agent 评测基准（SWE-CoWork、Accelerate Bench、OutfitterBench）。这些基准测的都是长程、含协作或组织背景的任务，完整交付率远低于部分通过率：SWE-CoWork 的 F2P 约 63%，完整完成不到 8%。
- Agent Context 论文的点赞几乎为零，社区热度还没追上这批 arXiv 新论文，但议题集中：压缩（Folio）、记忆写入与取舍（FGSE、MemCredit、DISCERN）、KV/prefix cache 与路由（SHADOWPREFILL）、持续学习（Continual-ARC）。
- 「复杂机制不一定划算」的结论反复出现：Continual-ARC 中 harness 持久化不如缓存示例；RAG in a Trenchcoat 中极简 RAG 追平 SOTA；Context Has a Price 中删上下文在 cache 折扣下可能更贵。上下文管理方法需要按真实价格和后续行为来评估。
- 工程侧：本批数据里 Agent Context 论文基本没有星数可观的仓库（Continual-ARC ⭐38 是例外），不对 GitHub 项目做呼应判断。
