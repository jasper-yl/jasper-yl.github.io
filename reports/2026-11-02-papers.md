## 热度榜：Agent Context 精选

### [ReGE: Stronger Agents through Experience Synthesis](https://arxiv.org/abs/2610.33861)
- 热度：HF 👍14（入榜 5 天，新增 +1）；代码 [TIGER-AI-Lab/ReGE](https://github.com/TIGER-AI-Lab/ReGE) 1 星
- 问题：Agent 多次尝试同一任务留下的执行记录，如何变成下一次尝试能直接用的指导。
- 方法：ReGE-Syn 用一次 coach 调用，把有界的执行记录和可用产物联合合成为自包含的指导，串起任务发现、建议动作和已知陷阱。student 从初始环境状态出发，按当前观察调整这份指导。全程使用同一个基础模型，不更新参数，也不依赖更强的教师模型。
- 结论/意义：四个基准平均提升 GPT +9.9、Claude +8.8 个百分点。在 BrowseComp-Plus 子集上，指导构造 token 比 AggAgent 少 98.2%（GPT）和 95.5%（Claude），联合合成的指导明显短于直接拼接历史或分别摘要。这是最直接的「经验压缩成上下文」工作，点赞涨幅只有 +1，但数字清楚。

### [Rare, Relevant, and Still Wrong: How Memory Fails LLM Group Decisions](https://arxiv.org/abs/2610.37624)
- 热度：HF 👍9（入榜 5 天，新增 +5）；无代码
- 问题：LLM 小组讨论被压成短记忆交给最终决策者时，记忆该保留什么。
- 方法：提出诊断基准 CrossProfile（60 个模板、480 个任务），在文本不变的前提下，交叉控制支持、诱饵、无关事实的归属。对比「保留最稀有」和「保留与决策标准相关」两种启发式，在 Qwen2.5-7B、Llama-3.1-8B 和两个 DeepSeek 模型上测试。
- 结论/意义：两种启发式都在可预测的地方失败。相关性筛选会放进诱饵，即使是完美的相关性过滤器，在经典 hidden-profile 配置下也比 rarest-first 低 23–31 分；rarest-first 平均不比随机好。准确率取决于记忆保留下来的证据平衡，与选择策略无关。去掉归属标签（多 Agent 提及的事实被额外加权）可提升 13–24 分。自然讨论中，完整记录的准确率反而低于完全不做笔记。

### [MemSteer: Turning User Histories into Supervision for Agent Memory Optimization](https://arxiv.org/abs/2610.39276)
- 热度：HF 👍5（入榜 3 天，新增 +5）；无代码
- 问题：新用户的历史没有标注，无法评估和改进记忆设计。
- 方法：MemSteer 把无标注的用户历史变成带证据的问答监督：先构造「证据落地的答案计划」，再生成问题，并做来源核对和盲答恢复。MemSteer-Opt 用这些问答评估记忆设计，结合证据引导的失败诊断，修改记忆存储、检索和上下文构造，不更新模型参数。
- 结论/意义：相对 Base-BM25，ATM-Bench Question Score +13.4 分；RHELM 准确率在无/有外部数据下分别 +4.1、+6.6，效果与官方问答引导的优化相当。

### [Skill^{infty}: Recursive Self-Improvement for Agent Skill Optimization](https://arxiv.org/abs/2610.35434)
- 热度：HF 👍8（入榜 6 天，新增 +5）；代码 [taowangcheng/Skill-Infinity](https://github.com/taowangcheng/Skill-Infinity) 6 星
- 问题：现有技能优化器的流程靠手工设计，元技能被固定在流水线里，每个任务都要重学。
- 方法：meta agent 按元技能（meta-skill）优化任务技能，再用同样的流程优化元技能本身。优化由 Agent 主导：诊断执行轨迹、提出候选、请求独立评审、分配搜索预算。元技能与任务技能解耦，两层都是标准技能包，通过原生技能发现加载。
- 结论/意义：83 个 SkillsBench 任务上通过率 60.7%，高于人工技能的 56.4% 和 SkillEvolver 的 54.5%。

### [Matched Capabilities, Different Behaviors: A Controlled Study of MCP and CLI Interfaces for Language Agents](https://arxiv.org/abs/2610.34298)
- 热度：HF 👍5（入榜 6 天，新增 +5）；代码 [ModalityDance/MICA](https://github.com/ModalityDance/MICA) 0 星
- 问题：能力相同时，MCP 和 CLI 这两种面向模型的接口表示是否会改变 Agent 行为。
- 方法：MICA 从同一份语义动作契约渲染出 MCP 和 CLI，走同一个运行时，覆盖六个模型、三个交互环境。论文还提出 DART，保留已验证的语义决策，只修复与接口相关的实现。
- 结论/意义：接口匹配时，性能和交互成本差异依然显著，2,004 个回合中 94.3% 出现结构性分歧。DART 在六个设置中全部提升，最多 +9.0 分，并在三个环境里把 MCP token 成本最多降低 27.1k/任务。

### [Rethinking Verification in Agent Harnesses](https://arxiv.org/abs/2610.34577)
- 热度：HF 👍10（入榜 5 天，新增 +1）；无代码
- 问题：harness 该如何组织验证，包括何时介入、谁来检查、如何修订。
- 方法：框架分四层：初始指令、中途提醒、完成关卡、独立评审。在七个前沿编码模型上比较 17 种设计，使用 Terminal-Bench 和 SWE-bench Verified，并引入 VisualBench。
- 结论/意义：独立评审的准确率/成本权衡最好：TB 平均准确率 +5.9–9.5 个百分点（成本为基线的 1.13–1.25 倍），SWE +3.9–6.6（1.00–1.04 倍）。完成关卡增益更大，但成本更高。

### [Your Policy Is Secretly a Harness: The Decision Geometry of Agent Interfaces](https://arxiv.org/abs/2610.37255)
- 热度：HF 👍8（入榜 5 天，新增 +2）；代码 [2020-qqtcg/HRP](https://github.com/2020-qqtcg/HRP) 1 星
- 问题：策略在某个 harness 下训练后，换一个 harness 还剩多少能力。
- 方法：在 KL 正则控制下证明，最优策略的 log odds 恢复其 harness 对各动作的偏好；部署回报等于 harness 上限减去策略失配。训练只改变失配，换 harness 则两项都变，所以固定模型去比较 harness 会把两者混在一起。
- 结论/意义：MiniWoB++ 中仅把观察字段顺序反过来，训练后模型成功率就从 85.0% 降到 19.2%。在 Terminal-Bench Lite 上，「上限减失配」能复现准确率排序，单独任一项都不能。

### [Beyond Benchmarks: Can Small Open-Weight Models Get Real Coding Work Done?](https://arxiv.org/abs/2610.34241)
- 热度：HF 👍9（入榜 6 天，新增 +8）；无代码
- 问题：小型开源权重模型能否真正完成编码工作。
- 方法：一份单人工程经验报告（2026 年 7–10 月），覆盖 vLLM、SGLang、llama.cpp、MLX，证据包括 4,165 个编码 Agent 网关回合和三项委托研究，关注工具调用格式、上下文行为、cache 复用与会话连续性。
- 结论/意义：保存的冷前缀请求，首 token 延迟中位数约 69.4 s；高复用请求为 2.8 s（观察性数据）。委托给量化 Qwen3-Coder 30B-A3B 的 worker 通过 12/15 和 14/15，直接编码为 15/15。作者声明各项研究不合并，也不对模型排名。

## 研究趋势观察
- harness 成为一等研究对象。热度榜里至少三篇（验证策略、MCP 对 CLI、策略即 harness）都在量化同一个模型换 harness 差多少，例如字段顺序反转使成功率从 85.0% 降到 19.2%。New 里的 RoboArchitect 把 harness 的自动化设计推向机器人。
- 上下文压缩有两条路并行。一条在文本层，把经验或历史合成为短指导（ReGE、KITE、知识编译）；另一条在模型层，用 soft token 和稀疏注意力（ASTC、LSA、ZHA）。证据层面有警示：CrossProfile 显示压缩策略不决定结果，保留下来的证据平衡才决定，完整记录甚至不如无笔记。
- cache 与调度从工程侧进入论文。TAO 的 cache 信用，以及 Beyond Benchmarks 中 69.4 s 对 2.8 s 的首 token 延迟，都说明 cache 复用是 Agent 服务里的首要变量。工程侧的呼应是 [infiniflow/ragflow](https://github.com/infiniflow/ragflow)，它的论文把 harness 与「最小充分上下文」放在了一起。
- 工具选择的完整性被重新测量。多工具检索研究表明单工具评测会高估能力，top-10 完整性在多目标查询上只有 .08–.17，与 MCP 接口表示会影响行为的结果相呼应。
