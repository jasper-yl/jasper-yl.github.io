## 一、🔥 热度榜：Agent Context 精选

### [CoworkOS](https://arxiv.org/abs/2611.03178)
- 热度：HF 👍96（入榜 1 天，新增 +11）；代码 [RUC-NLPIR/CoworkOS](https://github.com/RUC-NLPIR/CoworkOS) ★104；X 无数据。
- 问题：长程办公任务既要高质量交付，又要长期监控与决策。
- 方法：通用 harness，把任务策略（模型决定动作、委派、验收）和执行管理（运行时维护状态与反馈）分开。三层架构可直接执行，也可同步或异步委派给 Subagent。引入分层 workspace 和持久语义记忆，工作文件、关键决策、长时 Job 日志可跨 Agent 和会话共享复用，中断后可恢复。
- 结论/意义：在 12 个基准、6 类真实应用上与 Codex、DeepSeek Harness 等前沿 Agent 应用相比有竞争力。案例中以 GLM-5.3 为骨干，对 Qwen3.6-35B-A3B 做 RSI 驱动的自动后训练，5 轮内 8 个基准平均分从 33.19 升到 42.95（+9.76）。

### [Switch-SWE](https://arxiv.org/abs/2611.02017)
- 热度：HF 👍6（入榜 1 天，新增 +6）；代码 [Miraclecsc/Switch-SWE](https://github.com/Miraclecsc/Switch-SWE) ★26。
- 问题：编码 Agent 在同一仓库里被打断、切换到别的未完成任务后，能否恢复原任务的需求与进度。
- 方法：从 19 个 Python 仓库取 200 个 focus 任务，重构成 400 个匹配会话（不间断对比穿插其他任务）。轨迹分析发现两类典型行为：跨任务需求混淆、任务状态丢失。为此提出即插即用的上下文管理模块，选取与任务相关的历史，并维护简洁的任务状态摘要。
- 结论/意义：7 个编码 Agent 平均因任务穿插损失 11.5 个百分点（范围 6.0–15.0）；在 OpenCode 上该模块使完成率提升 5.5–15.5 个百分点。

### [SWE-Trail](https://arxiv.org/abs/2611.02074)
- 热度：HF 👍38（入榜 1 天，新增 +7）；无代码仓库。
- 问题：独立采样多条轨迹会越来越冗余；把历史当建议放进 Agent 上下文，又会造成训练与测试不一致。
- 方法：用早期轨迹决定在哪个状态多花采集力气，历史始终留在 Agent 上下文之外。走到该状态时，Agent 用普通上下文提出候选下一步动作，SWE-Trail 从同一检查点短暂执行这些动作，再决定走哪条路线。
- 结论/意义：124B 学生模型（Ling-3.0-flash-base）在 SWE-bench Multilingual 和 Pro 上比独立采样分别提升 2.33 和 1.60 个百分点；去掉历史后在 Multilingual 上只涨 0.11。

### [MemSteer](https://arxiv.org/abs/2610.39276)
- 热度：HF 👍8（入榜 5 天，新增 +8）；无代码仓库。
- 问题：新用户的历史没有标注，难以优化 Agent 记忆设计。
- 方法：把未标注的用户历史变成带证据的 QA 监督：先生成证据落地的答案计划，再生成问题，并做来源审计和盲答恢复。MemSteer-Opt 用这些监督做设计评估和失败诊断，在不更新模型参数的前提下修改记忆存储、检索和上下文构造。
- 结论/意义：相对 Base-BM25，ATM-Bench Question Score +13.4 分，RHELM 准确率在无/有外部数据时分别 +4.1、+6.6；监督效果与官方 QA 引导的优化相当。

### [Rare, Relevant, and Still Wrong: How Memory Fails LLM Group Decisions](https://arxiv.org/abs/2610.37624)
- 热度：HF 👍8（入榜 7 天，新增 +4）；无代码仓库。
- 问题：LLM 群体讨论被压缩成短记忆交给最终决策者时，该保留什么。
- 方法：提出诊断基准 CrossProfile（60 个模板、480 个任务），把支持、诱饵、无关事实的归属交叉设置而文本不变，测试「保留最稀有的」和「保留与决策标准相关的」两种启发式。
- 结论/意义：两者都有可预测的失败。按相关性选会放进诱饵，完美相关性过滤器在经典配置下也输给稀有优先 23–31 分；稀有优先平均不比随机好。准确率取决于记忆保留的证据平衡，与选择策略无关。决策模型还偏信「多个 Agent 都提到」的事实，去掉归属标签可提升 13–24 分；自然讨论中完整转录的准确率低于完全不做笔记。

### [GEPA-Curator](https://arxiv.org/abs/2610.37651)
- 热度：HF 👍6（入榜 1 天，新增 +1）；无代码仓库。
- 问题：反思式 prompt 优化器从失败 rollout 学习，但失败可能源于噪声或 harness 限制，学习信号不可靠。
- 方法：任务筛选，过滤噪声大的任务；成功轨迹检索，为某任务有选择地检索过往成功轨迹，作为额外上下文交给优化器。
- 结论/意义：在 GoBrowse、ALFWorld、AppWorld、τ-bench 上持平或超过两个基线，最高比 GEPA 高 20.7%，比 ACE 高 21.2%。

### [Can LLM Agents Learn by Watching Tutorial Videos?（TAL）](https://arxiv.org/abs/2611.01460)
- 热度：HF 👍5（入榜 1 天，新增 +3）；无代码仓库。
- 问题：能否不更新参数，让 Agent 从教程视频学习。
- 方法：把教程视频整合成持久的结构化「tutorialbook」记忆，通过两阶段对抗过程提出与视频相关的难题，并用它们精炼记忆。推理时沿目录（TOC）树检索，让检索与模型推理挂钩，不依赖嵌入相似度。
- 结论/意义：在 72 个国际象棋教程视频的 VidLearn 上，相对原始 MLLM 在训练/测试划分上最高提升 113%/91%，且随视频增多单调提升；实际对局中 69% 的对局开局局面强于原始模型。

### [Rethinking Verification in Agent Harnesses](https://arxiv.org/abs/2610.34577)
- 热度：HF 👍7（入榜 7 天，首次出现后 -2）；无代码仓库。
- 问题：harness 中如何组织验证，缺少指导。
- 方法：把验证作为测试时扩展的一个维度，覆盖初始指令、执行中提醒、完成门控、独立评审四层，比较 17 种设计、7 个前沿编码模型，并提出 VisualBench。
- 结论/意义：独立评审的精度/成本最划算：Terminal-Bench 提升 5.9–9.5 个百分点（成本 1.13–1.25 倍），SWE-bench Verified 提升 3.9–6.6 个百分点（成本 1.00–1.04 倍）；完成门控收益更大，成本明显上升。

## 四、🆕 New：昨晚新公布
- [Route Anything](https://arxiv.org/abs/2611.05275)：研究跨 25 个基准、452 个候选配置的模型/策略路由；逐输入的 oracle 路由比最佳固定候选高 5.4 分，路由使效率平均提升 8.82 倍（初步热度 👍93，代码 [InfRec-Cardinal/route-anything](https://github.com/InfRec-Cardinal/route-anything) ★2）。
- [Axion 1.0](https://arxiv.org/abs/2611.03233)：完全开源的 Agent 基础模型，只用两阶段 SFT + RL 三步训练，并开放完整数据与训练配方（👍38，代码 [bytedance/axion1_0](https://github.com/bytedance/axion1_0) ★19）。
- [ToolSpace](https://arxiv.org/abs/2611.05036)：以工具为中心合成 MCP 长程环境，从真实执行轨迹挖掘相邻调用的依赖；Qwen3.6-35B-A3B 七个基准平均分从 23.0 升到 41.0（加 RL 为 43.2）（👍32，代码 [dongguanting/ToolSpace](https://github.com/dongguanting/ToolSpace) ★7）。
- [ParetoSaddler](https://arxiv.org/abs/2611.02079)：同时优化质量与成本的 harness 自动优化；GAIA2 上质量 56.22%→62.89%，每任务成本 $0.78→$0.45（👍16）。
- [WebHarbor](https://arxiv.org/abs/2611.03634)：153 个可 docker 部署的真实网站复刻环境，3,518 个任务，用于 GUI web agent 的评测和 RL 训练（👍19，代码 [aiming-lab/WebHarbor](https://github.com/aiming-lab/WebHarbor) ★44）。
- [Caper（"Shall We Approve?"）](https://arxiv.org/abs/2610.40753)：在快照沙箱中预执行命令，让独立审批者根据实际效果决定放行或回滚；在 SABER 上有害结果率 6.7%（对比至少 14.8%）（👍11）。
- [EvoGroup](https://arxiv.org/abs/2611.03868)：面向群组 Agent 共享上下文的自演化 harness，从 6 个工具冷启动；EverMemBench 留出集 pass@1 从 71.07% 升到 89.58%，高于 Claude Code 的 85.83%。
- [What Is This Memory Useful For?](https://arxiv.org/abs/2611.03930)：测量长期 Agent 记忆的任务条件效用；任务无关的摘要和结构化记录收益都小于原始记忆，且在软件工程和科学编码基准上记忆无可测效果。
- [EvoMemState](https://arxiv.org/abs/2611.03743)：为个人 Agent 记忆在事实之外增加关系状态和推理状态，用 RL 学习针对请求生成推理状态，改进检索完整性与回答准确率。
- [How Agent Skills Evolve](https://arxiv.org/abs/2611.04456)：对 GitHub 上 84,200 个 skills、750,898 次提交的实证研究；演化集中在与项目耦合的 skills，冗余是维护问题，安全类改动降低风险有限。
- [GeoFaham](https://arxiv.org/abs/2611.04977)：微软的灾害地理空间多 Agent 系统；Response Store 把完整输出放在 LLM 上下文之外，Agent 间只传标识符和摘要；得分 0.940 对 0.879，token 少 7.5 倍（代码 [microsoft/GeoFaham](https://github.com/microsoft/GeoFaham)）。
- [SKILL2STEER](https://arxiv.org/abs/2611.04497)：超网络把自然语言 skill 编译成低秩激活偏移，每个 skill 2.36M 参数（比权重空间适配器少 9.25 倍）；编译后的偏移带的是通用行为先验，不是 skill 内容（错误的 skill 文档与正确的效果相当）。

## 五、研究趋势观察
- 记忆与上下文的研究重心从「怎么存、怎么取」转向「存什么、如何度量」：[MemSteer](https://arxiv.org/abs/2610.39276) 用用户历史自动生成监督；[Rare, Relevant, and Still Wrong](https://arxiv.org/abs/2610.37624) 与 New 区的 [What Is This Memory Useful For?](https://arxiv.org/abs/2611.03930) 都发现简单的压缩或选择启发式不可靠，后者还发现记忆在编码类任务上收益不明显。
- Harness 成为独立研究对象：[CoworkOS](https://arxiv.org/abs/2611.03178)（持久记忆加分层 workspace）、[Rethinking Verification in Agent Harnesses](https://arxiv.org/abs/2610.34577)（验证策略）、[ParetoSaddler](https://arxiv.org/abs/2611.02079) 与 [EvoGroup](https://arxiv.org/abs/2611.03868)（harness 自动演化）。热度榜里 harness 一词出现频繁，但只有 CoworkOS 热度较高。
- 工程侧信号有限：[CoworkOS](https://github.com/RUC-NLPIR/CoworkOS) ★104、[uni-robot-agent](https://github.com/Open-RUA/uni-robot-agent) ★162、[CUA-Master](https://github.com/xlyu0106/CUA-Master) ★88，说明带代码的 harness 和 CUA 工作更受关注；本日数据没有 GitHub 项目榜，未做对应的工程侧比较。
- 本日 hot 里的上下文类论文点赞普遍很低（多数 ≤8），热度主要由少数综述和大型 harness 工作拉高，结论宜保守。
