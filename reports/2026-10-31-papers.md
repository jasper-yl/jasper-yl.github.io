## 今日要点

- Harness 与 Skill 的自进化是今天最集中的主题。[2610.33024](https://arxiv.org/abs/2610.33024) 发现同一份 skill 对强模型有益，对弱模型反而有害；[2610.35434](https://arxiv.org/abs/2610.35434) 做 skill 的递归自优化；[2610.34724](https://arxiv.org/abs/2610.34724) 和 [2610.33861](https://arxiv.org/abs/2610.33861) 把轨迹蒸馏成可检索的经验。
- 工程侧开始关注 prompt cache 对 Agent 的影响。[2610.34241](https://arxiv.org/abs/2610.34241) 的实测显示，冷前缀请求首 token 约 69.4 s，高复用请求约 2.8 s；[2610.37230](https://arxiv.org/abs/2610.37230) 把 cache 复用和工具返回时机纳入调度。
- 本期热度最高的是 [Youtu-Parsing-Omni](https://arxiv.org/abs/2610.39301)，HF 👍152，一天内新增 +132，定位是给 Agent 用的多模态解析（感知）层。
- 多篇评测指向同一件事：推理预算加大不等于更准。[2610.34491](https://arxiv.org/abs/2610.34491) 发现最高 effort 最多比最低档贵 42 倍，却未必更准。
- 「简单 harness 胜过复杂方案」的结果多次出现：[RoboHarness](https://arxiv.org/abs/2610.14018)、[h1](https://arxiv.org/abs/2610.35962)。

## 一、🔥 热度榜：Agent Context 精选

### [Evolving to Match Capabilities: Improving Harness Self-Evolution via Skill Adaptation](https://arxiv.org/abs/2610.33024)
- 热度：HF 👍32（入榜 4 天，新增 +21）；代码 [zhihaoyang30/skill-adaptation-code](https://github.com/zhihaoyang30/skill-adaptation-code) ⭐6
- 问题：harness 里的 skill 对强模型有效，对弱模型可能无益甚至有害。
- 方法：作者跨 7 个模型、3 个基准找到 103 组 task-skill 对，同一份 skill 让 GPT-5.6-luna 提高 31.1 分，让 Gemma-4-E4B 降低 8.8 分；弱模型失败的运行中，86% 违反的要求在 skill 里已经写明。作者从工具执行、上下文管理、指令遵循、验证四类失败里提炼出一个固定的 meta-skill，由 Kimi-K3 据此改写 skill，使其更易被执行，再放进五轮自进化循环，每个模型根据轨迹和 verifier 反馈改写自己的 skill。
- 结论/意义：改写使 3 个弱执行者提升 5.1–14.1 分；放进自进化循环后，7 个执行者的最终分数比没有 meta-skill 的循环高 2.0–5.1 分。

### [Skill^∞: Recursive Self-Improvement for Agent Skill Optimization](https://arxiv.org/abs/2610.35434)
- 热度：HF 👍11（入榜 4 天，新增 +8）；代码 [taowangcheng/Skill-Infinity](https://github.com/taowangcheng/Skill-Infinity) ⭐6
- 问题：现有 skill 优化器的流程由人手设计；即使演化 meta-skill，也被固定在一条流水线里，且每个任务要重新学一遍。
- 方法：meta agent 按 meta-skill 诊断执行轨迹、提出候选、请求独立评审、分配搜索预算，用同一套流程优化任务 skill 和 meta-skill 自身。meta-skill 与任务 skill 解耦，在多个 skill 优化任务上精炼后可复用到不同领域；两层 skill 都是标准包，通过原生 skill discovery 加载。
- 结论/意义：在 83 个 SkillsBench 任务上通过率 60.7%，人工 skill 为 56.4%，SkillEvolver 为 54.5%。

### [Harness-Model Collaboration for Long-Horizon Continual Learning (HaMo)](https://arxiv.org/abs/2610.34724)
- 热度：HF 👍21（入榜 3 天，新增 +16）
- 问题：长程 Agent 要么靠模型适配，要么靠外部记忆，持续学习和快速复用只能二选一。
- 方法：先把轨迹蒸馏成策略级「经验卡」，供即时检索（非参数、快）；再用「经验条件化」的持续学习目标训练模型，让它会解读、落地并执行检索到的策略（参数化、慢）。参数更新用的轨迹，按检索覆盖率挑选，求紧凑且互补。
- 结论/意义：在域内和跨域迁移下，都优于只用 harness 和只用模型的适配，留存和适应都有改善。

### [ReGE: Stronger Agents through Experience Synthesis](https://arxiv.org/abs/2610.33861)
- 热度：HF 👍18（入榜 3 天，新增 +5）；代码 [TIGER-AI-Lab/ReGE](https://github.com/TIGER-AI-Lab/ReGE) ⭐1
- 问题：多次尝试留下的执行记录里有事实、有用操作和失败，如何变成下一次尝试的指导。
- 方法：ReGE-Syn 用一次 coach 调用，把有界的执行记录和产物合成为自包含的指导，把任务发现与建议动作、常见坑连起来。student 从初始环境出发，按当前观察调整这份指导。生成、合成、执行用同一个基础模型，无参数更新，也不需要更强的教师。
- 结论/意义：四个基准上平均准确率 GPT 提高 9.9 个百分点，Claude 提高 8.8 个百分点；在 BrowseComp-Plus 子集上，指导构建 token 比 AggAgent 少 98.2%（GPT）和 95.5%（Claude）；联合合成得到的指导，比直接塞历史或各自独立摘要短得多。

### [Δτ-Bench: Pushing Agents Toward a Moving Capability](https://arxiv.org/abs/2610.34238)
- 热度：HF 👍28（入榜 4 天，新增 +8）；代码 [zjunlp/delta-tau-bench](https://github.com/zjunlp/delta-tau-bench) ⭐5
- 问题：大型工具生态会演化（工具消失、被替换、出现更高效的替代），现有基准不测 Agent 能否更新已积累的程序性知识。
- 方法：基准含 1,588 个已验证的多轮任务、42 个领域、6 个先后相继的生态状态。作者同时提出 Steward，一个生态管理器，通过增量 skill 维护和任务执行中的动态供给，联合管理工具与程序性知识。
- 结论/意义：最强的被测模型或 harness 也只有 42.3% 任务成功率；现有 skill 学习方法的初期收益在生态演化后不能稳定保持；Steward 在生态变化中成功率更高，skill 维护开销更低。

### [Beyond Benchmarks: Can Small Open-Weight Models Get Real Coding Work Done?](https://arxiv.org/abs/2610.34241)
- 热度：HF 👍13（入榜 4 天，新增 +12）
- 问题：开源小模型在本地服务后，离真正完成编码工作还有多远。
- 方法：这是一份系统经验报告，覆盖 vLLM、SGLang、llama.cpp、MLX 和多种编码客户端，数据来自 4,165 个编码 Agent 网关轮次、623 个调试任务和三个委派研究。与上下文相关的证据：兼容端点背后的模型在工具调用格式、轮次控制、上下文行为、cache 复用上各不相同；保存的冷前缀请求 TTFT 中位数约 69.4 s，高复用请求约 2.8 s（观察性数据）。
- 结论/意义：在两个有直接编码对照的研究中，直接编码的「每次验证成功的前沿模型成本」更低；作者明确说这些研究不合并，也不给模型或运行时排名。

### [TAO: Tool-Aware Joint Scheduling for LLM-Based Agentic Serving](https://arxiv.org/abs/2610.37230)
- 热度：HF 👍58（入榜 2 天，新增 +43）
- 问题：Agent 服务在 GPU 推理和 CPU 工具之间交替，现有系统忽略工具返回是否就绪，并用启发式决定准入和放置，浪费资源。
- 方法：价值接口综合三项：近期工具就绪度、带时间衰减的节点级 cache 信用、token 占用；再用动态规划在容量约束下，联合选择并放置等待中的会话。
- 结论/意义：12 种模型-负载-并发设置中，相对每个指标上最好的 SOTA 基线，延迟最多降 26.8%，TTFT 最多降 36.3%，解码吞吐最多升 29.5%。这是 KV cache 与 Agent 调度结合的方向，也是本期 HF 点赞最高的上下文相关论文。

### [DraMaze: A Multi-Agent Pipeline with Future-Aware Memory for Diverse Microdrama Script Generation](https://arxiv.org/abs/2610.32002)
- 热度：HF 👍20（入榜 5 天，新增 +12）
- 问题：长篇剧本生成中，情节机制随生成逐渐趋同；常规检索会强化套路重复，并忽略对未来情节重要的历史信息。
- 方法：用套路记忆引导的进化树搜索与变异，探索多样的因果路径；构建「反向叙事依赖树」，按未来叙事目标来组织、保留和检索历史记忆。
- 结论/意义：60 集、最多 6 万字的剧本上，因果模式重复降低 32.1%，Logic 得分 82.5，比最佳基线高 8.5 分。

## 五、研究趋势观察

- Skill 与经验成为自进化的主要载体。[2610.33024](https://arxiv.org/abs/2610.33024)、[2610.35434](https://arxiv.org/abs/2610.35434)、[2610.34724](https://arxiv.org/abs/2610.34724)、[2610.33861](https://arxiv.org/abs/2610.33861) 都在回答怎样把执行轨迹变成可复用的指导。它们大多不更新参数（或只轻度更新），把经验压缩成短而自包含的文本；ReGE 的指导构建 token 减少 95% 以上，是压缩收益最直接的数字。skill 的效果还取决于执行者的能力，写得多不等于有用，见 [2610.33024](https://arxiv.org/abs/2610.33024)。
- 成本与 cache 进入 Agent 研究的主线。[2610.37230](https://arxiv.org/abs/2610.37230) 在调度里加入 cache 信用；[2610.34241](https://arxiv.org/abs/2610.34241) 实测冷前缀与高复用的 TTFT 相差约 25 倍（69.4 s 对 2.8 s，观察性数据）；[2610.34491](https://arxiv.org/abs/2610.34491) 质疑固定最高 effort 的性价比。这几篇都把效果和成本放在一起评估。
- 评测显示 Agent 能执行但不够可靠。[Δτ-Bench](https://arxiv.org/abs/2610.34238) 最强成绩只有 42.3%；[Agent Mosaic](https://arxiv.org/abs/2610.30418) 在加了安全措施后仍有 32.37% 泄露；[EPSBench](https://arxiv.org/abs/2610.38293) 的区间覆盖不足。
- 简单 harness 加好工具接口的路线。[RoboHarness](https://github.com/BinceQu/RoboHarness)（⭐280）和 [h1](https://arxiv.org/abs/2610.35962) 都说明接口设计比复杂工作流更重要。带仓库的论文里，星数较高的还有 [AutoTavern](https://github.com/MCG-NJU/AutoTavern)（⭐179）和 [VibeGame](https://github.com/tettethu/VibeGame)（⭐297，HF 👍22，游戏开发 Agent 团队，属 Agent 其他方向，本期未列入）。
