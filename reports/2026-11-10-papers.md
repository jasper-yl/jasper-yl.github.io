## 热度榜：Agent Context 精选

### [Tools Need Not Speak in Text: Latent Context Compression for Agents](https://arxiv.org/abs/2611.06500)
- 热度：HF 👍7（入榜 5 天，新增 +7）；无 X 提及数据；代码 [THU-Agent/Coca-cola](https://github.com/THU-Agent/Coca-cola)，8 星
- 问题：Agent 把原始工具输出直接追加进上下文，长而嘈杂的观测占用开销并稀释注意力，文本层面的剪枝和摘要压缩比有限。
- 方法：Coca-Cola 把工具观测压缩成潜在 token，直接嵌入 Agent 的输入 embedding 空间。Action-Preserving Training 让 Agent 在完整观测与压缩观测下的下一步动作分布对齐，迫使压缩模型保留对决策足够的信息。
- 结论/意义：在 4 个 QA 基准、2 个模型家族的 web 搜索 Agent 上，token 消耗降低 70.01%–89.24%，端到端耗时降低 24.45%–55.97%，任务表现还持续提升。这是今天最直接的上下文压缩论文，有代码，热度低但主题最贴合。

### [Do Agents Still Follow the Rules? Benchmarking Rule Compliance under Agent Context Compaction](https://arxiv.org/abs/2611.03223)
- 热度：HF 👍0（入榜 7 天）；无代码链接
- 问题：Agent 压缩历史后，规则是否还能约束后续动作；以往工作在完整 harness 之外测试，也不清楚违规从哪来。
- 方法：ARCBench 建在开源 pi agent harness 上，从执行中的真实动作测量规则遵守并拆分违规来源，同时考察不同压缩配置和对抗设置。
- 结论/意义：压缩很少删掉规则，多数违规发生在规则仍在压缩历史中时（Agent 把后来的请求当作许可）；最强的针对压缩器的攻击让违规翻倍以上，保留规则的压缩运行，违规率比完整历史高出两倍以上。规则留在摘要里不等于规则起作用，对 Harness 设计有直接启示。

### [Can Large Language Model Agents Learn by Watching Tutorial Videos?](https://arxiv.org/abs/2611.01460)
- 热度：HF 👍6（入榜 7 天，新增 +4）；无代码
- 问题：Agent 能力在训练后冻结，如何不更新参数就从大量教程视频里学习。
- 方法：Tutorial Agentic Learning（TAL）经两阶段对抗过程，先挖掘有难度的、基于视频的问题，再用它们修正记忆，把教程视频整理成持久的结构化「教程书」记忆。推理时通过目录（TOC）树检索，让检索与模型推理绑定，不靠 embedding 相似度。
- 结论/意义：在 72 个国际象棋教程视频构建的 VidLearn 上，相对原始 MLLM，训练/测试划分最多提升 113% / 91%，实战对局中 69% 的对局开局阶段局面更强。非参数持续学习加目录树检索的记忆设计有特色，但只在象棋（外加第二个领域）上验证。

### [A State Change Is Local, Its Consequences Are Not: Dependency-Aware State Revision for Long-Term Agent Memory](https://arxiv.org/abs/2611.02912)
- 热度：HF 👍0（入榜 7 天）；无代码
- 问题：上游事实变化时，记忆系统只改被直接矛盾的那条记忆，依赖它的信念、计划和动作仍被当作有效。
- 方法：StateGraph 维护从交互历史中恢复的状态依赖图，用反事实验证检验每条候选边（去掉前提后依赖状态是否还成立），只有强依赖失效且无独立支撑路径时才使下游状态失效。
- 结论/意义：在作者自建的 50 例 StateChangeBench 上，Impact-F1 领先 CUPMem 重实现，深度 1 为 +6.9 个百分点，深度 3+ 为 +26.0；公开长期记忆基准上点估计与基线相当或更高。摘要自称 initial evidence，基准是作者自建的小样本，结论要保守看。

### [Parallelism-Aligned Pruning and Round-Aware Context Reuse for On-Device Multimodal Agents](https://arxiv.org/abs/2611.02601)
- 热度：HF 👍0（入榜 7 天）；无代码
- 问题：端侧多模态 Agent 用前缀缓存时，历史视觉 token 一直留在持久 KV cache 里，轮数一多容量就爆；注意力结构也与边缘加速器核数不整除。
- 方法：PARC 按生命周期把系统提示、持久文本历史、临时视觉观测分开，工具执行期间更新文本历史，让历史图像移出持久缓存，同一预算下能容纳更多轮。另有对齐核数的结构化剪枝。
- 结论/意义：2,062 个 GUI 动作上增量接口无精度回退；七核部署下视觉编码延迟 −11.4%，解码吞吐 +23.8%，单堆内存高水位 −12.7%。

### [When Cache Pressure Becomes a Trap: Metastability in Agent Serving](https://arxiv.org/abs/2611.02543)
- 热度：HF 👍0（入榜 7 天）；无代码
- 问题：Agent 反复发送不断增长的对话，前缀复用是服务效率的关键；短暂突发会破坏复用，使负载恢复后服务仍长期退化。
- 方法：在 SGLang 上，一次十分钟的突发让随后一小时的 goodput 降低约 88%。机制是种群-缓存反馈：会话变慢，总上下文变大，缓存未命中，重算更慢。论文提出 Basin，固定会话优先级，按预测峰值上下文预留准入预算，用空闲 decode 内存扩展缓存，并削减多余需求。
- 结论/意义：真实 H200 1P3D 部署下，goodput 为 Continuum 的 1.20–1.70 倍，为仅用 HiCache 的 2.35–3.59 倍。

### [FlyHash for LLM Agent Memory: An Empirical Validation and a New Application](https://arxiv.org/abs/2611.05791)
- 热度：HF 👍3（入榜 5 天，新增 +3）；代码 [mohanji/flyhash-agent-memory](https://github.com/mohanji/flyhash-agent-memory)，1 星
- 问题：果蝇嗅觉回路启发的 FlyHash 局部敏感哈希，用在 Agent 记忆检索上是否真有收益。
- 方法：在匹配比特数的协议下检验。质量优势成立（10 个种子、4 个数据集）；但同比特下码更大、比较更慢，常规规模下 HNSW 仍优于两种哈希方法；在真实记忆相关性标签上优势仍成立。
- 结论/意义：作者如实写出两条削弱头条结果的发现，哈希方案的实际适用面比质量结果暗示的更窄。这是一篇诚实报告负面结果的论文。

## 研究趋势观察

- 压缩或记忆之后决策是否仍可靠，成了独立的问题。[THU-Agent/Coca-cola](https://github.com/THU-Agent/Coca-cola)（潜在 token 压缩）、[ARCBench](https://arxiv.org/abs/2611.03223)（压缩后的规则遵守）、[StateGraph](https://arxiv.org/abs/2611.02912)（记忆修订的下游依赖）关心的都是这一点，省了多少 token 只是其中一项。
- KV cache 与 Agent 上下文管理开始协同设计。热度榜上的 [Metastability](https://arxiv.org/abs/2611.02543)、[PARC](https://arxiv.org/abs/2611.02601)，以及昨晚的 [Evolving Infra](https://arxiv.org/abs/2611.12304)、[sharar-project/hibana](https://github.com/sharar-project/hibana)、[VerKV](https://arxiv.org/abs/2611.11319)、[OmniJev/Flide](https://github.com/OmniJev/Flide)，都在讨论 Agent 多轮增长的上下文如何影响缓存与服务；Evolving Infra 还直接用 Agent 上下文管理的信号来指导缓存淘汰。
- Harness 自进化的可靠性受到质疑。[Beneath the Surface](https://arxiv.org/abs/2611.07624) 与 [THU-Agent/continual-harness-evolution](https://github.com/THU-Agent/continual-harness-evolution) 同一天入榜，都指出分数上升掩盖了遗忘和成本上升；与此同时 [HEELO](https://arxiv.org/abs/2611.07461)、Auriga 等 harness 工作仍在报告大幅提升，两边形成对照。
- 记忆系统在 LoCoMo、LongMemEval 上继续竞争。[MIRIX-2.0](https://arxiv.org/abs/2611.12068) 与 [Qi202/SoMem](https://github.com/Qi202/SoMem) 同日出现，前者用类型化多 Agent 加超图，后者用普通链接文档，路线差别明显。本次输入中没有对应的 GitHub 工程侧数据，不做呼应判断。
