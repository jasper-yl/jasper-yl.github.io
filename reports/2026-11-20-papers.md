## 一、🔥 热度榜：Agent Context 精选

### [The Resolution Hypothesis: Agent Evolution's Key Is Identifying Improvements](https://arxiv.org/abs/2611.23068)
- 热度：HF 👍36（入榜 1 天，新增 +4，首次出现时 32）；无代码仓库。
- 问题：Agent 自进化（演化 prompt、skills、memories）为什么常常停滞，各论文的方法互有胜负？
- 方法：对 7 种进化方法、6 个模型做了超过 10M 次 LLM 调用的实验，分两层检验：候选层看选择能否区分好坏 artifact，方法层看方法排名是否稳定。
- 结论/意义：有益的候选 artifact 确实存在，但选择并不比随机更能区分好坏，误差逐轮累积。几个百分点的方法间差距小于同一方法两次独立运行的差异，已发表的排名常常靠运气。瓶颈在识别改进，不在提出改进。

### [Thinking Fast, Anywhere: One System-1 for the Decision Points of Any Agent Workflow (AnyS1)](https://arxiv.org/abs/2611.23751)
- 热度：HF 👍14（入榜 1 天，新增 +11，首次出现时 3）；代码 [middle-chunjie/AnyS1](https://github.com/middle-chunjie/AnyS1) ⭐3。
- 问题：Agent 每一步都调用大模型（System-2），成本和延迟高；现有双系统方案需要为每个环境手写钩子。
- 方法：从 1000 多个公开 Skills 中挖出可枚举的决策点，在隔离容器里收集执行轨迹，构建 Any-DP 数据集，训练一个 4B 的指针式 System-1 模型。运行时由编译后的工作流用一次前向解决常规决策，置信度低于校准阈值时回退到 System-2。
- 结论/意义：在 3 个未见过的基准上保持任务可靠性，单 episode 成本降低 75-91%，模型调用时间降低 63-92%。它把 Skills 用作决策结构的来源，这种做法少见，但与上下文本身的关系偏间接。

### [Folio: Recoverable Multi-Resolution Context Folding for Long-Horizon Language Agents](https://arxiv.org/abs/2611.16627)
- 热度：arXiv 来源，无 HF 点赞（入榜 7 天），无代码仓库。热度为 0，但它是今日最直接的上下文折叠论文，所以入选。
- 问题：长程 Agent 靠模型自己做摘要来压缩历史，每次压缩都要重读重写历史，代价高。
- 方法：运行时同步记录三层视图：模型随回复写的简短轮次笔记（L1）、运行时写的每次调用事件清单（L2）、捕获的原始记录（L3）。折叠时程序化地为旧轮次选更粗的视图，并打印索引 L2/L3 的句柄。恢复工具按页读取，在文件中对全文做计算，发现记在持久 dossier 里。折叠触发条件把保留预算算进「落点」。
- 结论/意义：在 75 个 LOCA-bench 任务上用 DeepSeek-V4-Pro，Folio 解决 66 个；模型自写压缩的同一运行时解决 54 个，Claude Code、Codex、SoL-Pi 解决 49-59 个。耗时约为它们的一半，成本比同一运行时低 2.4 倍，每次折叠中位耗时 0.6 秒。

### [Discovering Effective Agent Memory Designs through Program Evolution (MAPE)](https://arxiv.org/abs/2611.17068)
- 热度：arXiv 来源，无 HF 点赞（入榜 7 天）；代码 [ash-ding/MAPE](https://github.com/ash-ding/MAPE)，星数数据中未给出。
- 问题：Agent 记忆设计靠手工，不清楚哪些设计选择真正有效。
- 方法：MAPE 从最小种子出发，通过标准化的生命周期接口和「诊断-提案」迭代循环，演化整套记忆程序。
- 结论/意义：在 LoCoMo 和 LongMemEval 上，绝对准确率比手工设计的基线最多高 12%，服务成本为其 35%。归纳出两条设计规律：保留原始对话作为可检索证据，因为抽取式记忆会丢细节；按查询意图组织检索到的证据。把组织模块移植到 5 个现有记忆系统后，5 个都有提升。

### [Continual-ARC: Measuring Skill Acquisition over a Working Lifetime](https://arxiv.org/abs/2611.14505)
- 热度：HF 👍2（入榜 4 天，新增 -7，首次出现时 9）；代码 [unifyai/continual-arc](https://github.com/unifyai/continual-arc) ⭐38。点赞净下降，选它是因为结论与记忆方向直接相关。
- 问题：持续学习基准多为单领域、每个实例只出现一次，记忆型与权重型系统无法在同一尺度上比较。
- 方法：用三个 ARC-AGI 版本构建终身任务流：同一任务隔一段时间带新实例回来，新任务不断加入，学习者按反馈预算付费换取演示、提交或重试。流结束后冻结学习者，在见过的任务（测记忆）和未见任务（测泛化）上测试。
- 结论/意义：harness 里的持久化通常不能提升记忆，除非有明确的专家指导。大多数 harness 方法学到的比「只缓存每个任务演示」的下限还少，在未见任务上没有任何 harness 方法获益，而权重学习有明显增益。

### [Reducing Batch Makespan for LLM Agent Workloads through Inference-Environment Coordination](https://arxiv.org/abs/2611.16661)
- 热度：HF 👍3（入榜 7 天，新增 +3）；无代码仓库。
- 问题：评测、合成数据、RL rollout 等批量 Agent 任务在 LLM 推理和环境交互之间交替，批完成时间长。
- 方法：针对混合架构 LLM，用负载资源模型在 KV cache 与循环状态之间分配 GPU 显存。轨迹感知的路由和调度促进缓存复用并均衡负载。环境容量受限时，把样本准入与环境执行解耦，并提出 CAAS，优先调度长链以缩短批尾。
- 结论/意义：在 BFCL、SWE-bench Multilingual、WideSearch、MCP-Atlas 上 makespan 降低 10.4%–65.0%，评测分数保持一致。

### [AstroMemBench: A Benchmark for Memory Systems in Embodied Spacecraft Agents](https://arxiv.org/abs/2611.16590)
- 热度：arXiv 来源，无 HF 点赞（入榜 7 天）；代码 [flyingView/AstroMemBench-v1](https://github.com/flyingView/AstroMemBench-v1)。
- 问题：航天器长期自主需要利用操作历史，缺少对应的记忆测试。
- 方法：用「场景-挑战-能力」方法把需求映射为可执行的记忆测试，覆盖 16 个记忆子挑战、140 个模板、2240 个实例、9 个任务。确定性环境按任务完成、状态变化、安全和资源使用打分。
- 结论/意义：Mem0、Chain-of-Memory、LightMem 和 RAG 在同会话内都优于原生 Pi Agent，三种记忆系统相对 RAG 没有明确优势；会话重启后 Mem0 比 RAG 高 12.25 分。收益主要在指令保留和结果复用，持续状态跟踪和能量预留上收益有限。

### [BLIP-Live: Balancing Timeliness & Firing Precision in Proactive Streaming Video Agents](https://arxiv.org/abs/2611.21553)
- 热度：HF 👍9（入榜 1 天，新增 +4，首次出现时 5）；无代码仓库（摘要说将发布）。
- 问题：流式视频 Agent 要在证据足够时尽早响应，又不能过早、重复或错误地响应。
- 方法：构建 BLIP-Live-780K 人工标注数据集和 PAUC-F 指标，研究与模型无关的推理 harness 和训练流程。
- 结论/意义：滑动视觉窗口、在线交互记忆和结构化响应输出的组合表现最强；BLIP-Live-Qwen 在 4 个主动流式基准上达到 SOTA，最多比基线高 44%，并超过多个闭源 API 模型。与上下文的关联在「在线交互记忆」这一组件，属辅助成分。

## 五、研究趋势观察
- 上下文管理的取舍：[Folio](https://arxiv.org/abs/2611.16627) 保留可恢复的多级视图，GrepMem（[2611.25123](https://arxiv.org/abs/2611.25123)）保留无损日志加 grep，两者都想避开模型自写摘要的有损压缩，做法相反。[Embeddings vs. Grep](https://arxiv.org/abs/2611.20455) 的结论也指向 grep 式检索，在代码搜索里与稠密检索相当。
- Skills 与自进化的可靠性：热度榜里的 [Resolution Hypothesis](https://arxiv.org/abs/2611.23068) 和 New 里的两篇 Skills 自进化论文，都在讨论如何可靠地判断改进，而不是如何提出更多候选。[Continual-ARC](https://arxiv.org/abs/2611.14505) 显示 harness 持久化的学习收益有限，权重学习在未见任务上更有效。
- KV cache 服务 Agent 工作负载：热度榜里的 [Batch Makespan](https://arxiv.org/abs/2611.16661)，New 里的 [Aggron](https://arxiv.org/abs/2611.26435)、[TripleKV](https://arxiv.org/abs/2611.25112)、[FrontierReplay](https://arxiv.org/abs/2611.26020)，都针对 Agent 多轮、工具等待的特点做缓存和调度优化，系统侧的论文集中在这里。
- 工程侧呼应：数据中没有 GitHub 项目榜单，无法与工程项目对照；论文代码仓库的星数普遍很小，最高是 [agentscope-ai/Piccolo](https://github.com/agentscope-ai/Piccolo) 的 60，其次是 [unifyai/continual-arc](https://github.com/unifyai/continual-arc) 的 38 和 [game2player/Game2Player](https://github.com/game2player/Game2Player) 的 25。
- 补充：热度最高的 Tideway（[2611.14848](https://arxiv.org/abs/2611.14848)，👍58）是消费级设备上 MoE 权重的分层内存管理，属推理系统，未归入 Agent Context，不放进报告。
