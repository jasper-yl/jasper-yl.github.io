### [Read Less, Solve More: Token-Efficient Sparse Reading of External Content for AI Agents（SparseRead）](https://arxiv.org/abs/2608.22237)
- 热度：HF 👍21（入榜 1 天，新增 +8，首次出现时 13）；代码 [Liuzedooong/SparseReading](https://github.com/Liuzedooong/SparseReading) ⭐15。11-12 日报曾作为 new 报道，当时初步 👍13。
- 问题：Web Agent 反复读网页、文档、仓库和工具返回，常把整个对象读进来，实际只需要少量证据，token 和延迟都高，相关证据也被稀释。
- 方法：不改模型的「读取控制层」，分三部分。Read Intent Protocol 跟踪不断变化的需求和来源覆盖情况；Adaptive Reader Backends 选择怎样定位并展示证据；Budgeted Read Gate 限制每个 episode 累计的原始内容暴露量，并带忠实的完整视图回退。统一的 Reader 接口适配不同类型的资源。
- 结论：6 个模型（含 Claude Opus 5）、5 个场景下，总 token 最多降 92.9%，耗时最多降 89.0%，97% 的设置下质量持平或更好。Web deep-search 任务 token 降 31.0–43.0%，完成时间降 23.0–37.0%。接入 3 个 Agent 框架，验证了可移植性。

### [CORE: Coarse-to-Fine Search with Context Management for Deep Research](https://arxiv.org/abs/2611.07859)
- 热度：arXiv 源，HF 👍0，入榜 7 天；无代码链接。入选原因是主题贴近 Agent Context，不是热度。
- 问题：深度研究 Agent 的检索适合用长段落匹配，但每条返回的观察都会留在上下文里直到结束，所以返回的证据应该短。
- 方法：免训练的 harness。先用稠密检索器找段落，再复用 late-interaction 重排器的 token 级相似度，只返回每段里最相关的片段。上下文管理允许 Agent 扩展已检索来源周围的上下文，并抑制重复片段。
- 结论：与 Tongyi DeepResearch、OpenResearcher 两种 harness 对比（受控的封闭搜索设置），在 3 个模型、3 个基准（BrowseComp-Plus、BrowseComp-Wikipedia、BrowseComp-Plus-CM）上，答案准确率和证据召回达到 SOTA，语料最多 5.53 亿文档。

### [QRAE: Query-Relevant Attention Entropy for Context Compression in DeepSearch Agents](https://arxiv.org/abs/2611.07976)
- 热度：arXiv 源，HF 👍0，入榜 7 天；无代码链接。
- 问题：DeepSearch Agent 不断累积检索来源，token 和延迟随之增加，而很多结果对后续推理没有贡献。
- 方法：在线上下文压缩。用稀疏的证据评估注意力头，决定哪些完整的检索 chunk 留在上下文里。打分用成对 prefill：一次不带 query 作对照，抵消共享的注意力响应；再用归一化熵衡量 chunk 内正向响应的广度。高分 chunk 进入持久证据白名单，不确定的 chunk 留在候选缓存，之后可重新评估。不需要额外的生成式压缩，也不改注意力算子。
- 结论：多个 DeepSearch 基准和推理模型上，任务成功率平均 +2.35 个百分点，端到端延迟平均降 30%，报告的 token 用量平均降 45%；在接近 100B 参数的模型上也成立。

### [Octopus: One Brain, Many Branches for Latent-KV Multi-Agent Reinforcement Learning](https://arxiv.org/abs/2611.06956)
- 热度：arXiv 源，HF 👍0，入榜 7 天；无代码链接。
- 问题：现有多智能体框架在各分支重复保存前缀 KV cache，靠重新 prefill 文本摘要来交换发现，RL 时还会压平或丢掉分支之间的依赖。
- 方法：单模型多智能体 RL。所有线程共享同一个主干，通过 GPU 上的 KV 状态有向无环图协作，提供 fork、read_thread、wait_threads、rewind、commit 五个原语。Zero-Copy Radix Forking 让分支成为共享物理 KV 页上的 O(1) 游标视图；Attention-Only KV Mounting 把兄弟线程的 KV 块直接挂进全注意力层，绕过线性循环状态；Packed DAG-GRPO 把所有分支打包进一次块稀疏注意力，用留一分支的边际奖励分配反事实信用。
- 结论：Qwen3.5-4B 训练后，BrowseComp-Plus 准确率 49.6%（比单智能体 GRPO 高 17.5 个点，比文本摘要式多智能体 RL 高 12.5 个点），OpenResearcher 51.2%。跑赢最大 250× 参数的稠密检索 Agent，训练吞吐 3.3×，峰值 KV 内存降 2.8×。挂载设计把跑偏率从 57.9% 降到 2.7%（21×），同时保留 92.2% 的全文互信息。

### [Compaction, decay and reinforcement in a two-tier conversational memory: a paired evaluation against retrieval-augmented generation](https://arxiv.org/abs/2611.09807)
- 热度：arXiv 源，HF 👍0，入榜 4 天；无代码链接。
- 问题：对话 Agent 要决定保留什么：保留原文再检索（RAG），还是把每轮压缩成原子事实再检索。
- 方法：在 LoCoMo 的 1,985 个问题上做配对对比。两种方案用同一份存储、生成器和评审，用 McNemar 精确检验分析两者结论不一致的 512 个问题。
- 结论：在同类工作报告的四个类别上，压缩 71.4%，RAG 64.6%，领先 6.8 个点（p = 5.5e-08），prompt token 少 34%。包含对抗类的全部五类时，领先缩到 2.0 且不再显著，因为 RAG 在对抗类领先 14.6。论文的解释是：压缩保留事实断言而丢掉措辞，答案是「数值」时占优，答案要求「原话」时吃亏。

### [Micius-Flash: Lightweight Agentic Intelligence for Engineering](https://arxiv.org/abs/2611.10015)
- 热度：HF 👍9（入榜 2 天，新增 +5）；无代码链接。
- 问题：工程（半导体、硬件编码、PCB）领域缺少能用工具的轻量 Agent 模型。
- 方法：27B 多模态模型，256K 上下文。用知识树驱动的数据飞轮合成数据，训练多个专家模型，再通过多教师在线策略蒸馏（MOPD）合并。配套 Micius Harness，连接 EDA 工具、KiCad 和执行环境。
- 结论：硬件代码基准平均 64.2%，比同尺寸基线高 15.0 个点；半导体 Agent 基准 62.4%，高 17.2 个点。

## 🆕 New：昨晚新公布
- [Folio](https://arxiv.org/abs/2611.16627)：长程 Agent 的可恢复多分辨率上下文折叠。运行时记录三层视图（模型写的轮次笔记 L1、运行时写的事件清单 L2、原始记录 L3），由运行时程序化折叠，通过句柄按需恢复。LOCA-bench 75 个任务上解决 66 个，同一运行时用模型写摘要为 54 个，Claude Code、Codex、SoL-Pi 为 49–59 个；耗时约一半，成本低 2.4 倍，每次折叠中位数 0.6 秒。
- [Discovering Effective Agent Memory Designs through Program Evolution（MAPE）](https://arxiv.org/abs/2611.17068)：用程序演化搜索记忆设计。LoCoMo 和 LongMemEval 上准确率最多比人工设计基线高 12%，服务成本只有 35%；发现保留原始对话作可检索证据、按查询意图组合证据这两个模式有效。
- [HiVe-Mem](https://arxiv.org/abs/2611.12872)（👍3）：多模态记忆，横向沿关系图扩展记忆，纵向用可训练选择器为每条记忆组合证据形式；3 个多模态记忆基准上 token 用量比最省的多模态基线少约 90%。代码 [ViktorAxelsen/HiVe-Mem](https://github.com/ViktorAxelsen/HiVe-Mem)。
- [MemCredit](https://arxiv.org/abs/2611.15600)：记忆选择从「语义相关」改为「决策效用」，用反事实干预估计每条记忆的边际贡献，再蒸馏成轻量估计器。ALFWorld 在 500 token 记忆预算下 SR@50 为 86.57，BM25 检索为 65.67%。
- [DISCERN](https://arxiv.org/abs/2611.15729)：「写入时保留、读取时消歧」的持久记忆。写入时建立只增不改的双时态溯源图，读取时用零 LLM 的工具面导航。ENT-310 上弃答 F1 为 0.924，8 个基线最高 0.802；LoCoMo 上宏平均答案正确率 0.663 对 0.638。
- [Experience-Handoff RL（ACE-RL）](https://arxiv.org/abs/2611.16409)（👍1）：固定 Agentic Context Engineering（ACE）harness，训练一个模型同时负责行动、反思和整理任务 playbook，按这些经验交接物对后续 rollout 的实际影响来优化。多个 Agent 基准上优于基线。代码 [doyoungkim-ml/ehrl](https://github.com/doyoungkim-ml/ehrl)。
- [HeMeR](https://arxiv.org/abs/2611.16487)：具身 Agent 的异构记忆（陈述、程序、工作记忆）结构化 KV 复用，只重算受记忆更新影响的 KV。真实机器人任务成功率 83.20%，单步推理时间相对 MemRL 从 2.94 秒降到 1.87 秒。
- [Recompute or Restore?](https://arxiv.org/abs/2611.15126)：多模型 Agent 工作流在静态图 NPU（Rebellions ATOM+）上，从主机内存恢复 KV 还是重算。两种过载条件下工作流 SLO 达标率从 22.8% 升到 100%、从 9.4% 升到 99.8%；默认服务崩溃时 89.5% 的 planner prompt token 之前算过。
- [Wayfinder](https://arxiv.org/abs/2611.16053)：用下游 Agent 引用的文档作反馈，自适应地给聊天、工单、邮件、知识库等资源做路由；资源内容语义重叠时路由最好，资源来自不同语料时基于描述的工具检索就够。
- [AstroMemBench](https://arxiv.org/abs/2611.16590)：航天器具身 Agent 的记忆评测，140 个模板、2240 个实例、16 个子挑战；同会话内 Mem0、Chain-of-Memory、LightMem、RAG 都优于原生 Pi Agent，三个记忆系统相对 RAG 没有明显优势；会话重启后 Mem0 比 RAG 高 12.25 个点。
- [Actor, Judge, or Teacher?](https://arxiv.org/abs/2611.17167)（👍29）：决策模型作为教师，把 Qwen2.5-1.5B 策略在 ALFWorld 上相对 GRPO 从 72.8% 提到 82.9%，WebShop 上从 56.8% 提到 71.4%；结论是「差的执行者也能当好教师」。代码 [ZJU-REAL/decision-agents](https://github.com/ZJU-REAL/decision-agents) ⭐3。
- [Agent-R^2](https://arxiv.org/abs/2611.08219)（👍3）：用真实来源合成生产力任务数据，4k 个实例训练 4B 模型，GDPval 上 51.0%，Qwen3-235B-A22B-Thinking 为 48.0%。代码 [ZJU-REAL/Agent-R2](https://github.com/ZJU-REAL/Agent-R2) ⭐6。

## 研究趋势观察
- 上下文成本的处理从压缩扩展到准入。[SparseRead](https://arxiv.org/abs/2608.22237) 控制读什么，[CORE](https://arxiv.org/abs/2611.07859) 和 [QRAE](https://arxiv.org/abs/2611.07976) 控制留什么，New 里的 [Folio](https://arxiv.org/abs/2611.16627) 控制怎么折叠并能恢复。这些论文的主要指标是 token 和延迟，成功率基本持平：QRAE 平均 +2.35 个点，SparseRead 在 97% 的设置下质量不降。
- 记忆研究的重心从存取转向选哪条和如何评。[MemCredit](https://arxiv.org/abs/2611.15600) 用决策效用代替语义相关，[DISCERN](https://arxiv.org/abs/2611.15729) 指出消歧和弃答才是难点（召回已接近饱和，约 0.93–0.98），[MAPE](https://arxiv.org/abs/2611.17068) 用搜索来找设计。两篇对话记忆论文都在 LoCoMo 上做对比，结论都指向压缩保留值、丢失措辞。
- KV cache 与 Agent 工作流结合：[Octopus](https://arxiv.org/abs/2611.06956) 把 KV 当作多分支共享状态，[HeMeR](https://arxiv.org/abs/2611.16487) 复用具身记忆的 KV，[Nebula](https://arxiv.org/abs/2611.09474)（位置无关缓存，TTFT 中位数平均降 61.4%）和 [Recompute or Restore?](https://arxiv.org/abs/2611.15126) 的 NPU 主机分层 KV 都在解决工作流中重复 prefill 的成本。这些论文的数据里没有对应的 GitHub 项目，不作工程侧呼应的判断。
- 安全与可靠性是热度榜的另一条线：[Authorization Drift in LLM Agents](https://arxiv.org/abs/2611.09113)、[Coding or Cheating?](https://arxiv.org/abs/2611.10404)、[MemoryDojo](https://arxiv.org/abs/2611.09721)（所有被测记忆系统都易受投毒）。数据里同样没有对应的 GitHub 项目，不写工程侧呼应。
