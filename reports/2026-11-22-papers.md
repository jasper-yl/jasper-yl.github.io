## 今日要点

- 记忆和经验的副作用成了热点：[Experience Rot](https://arxiv.org/abs/2611.20922) 发现工具接口被静默修改后，带经验的智能体在多数任务上失败，没有经验的大多成功。[LEDGER](https://arxiv.org/abs/2611.20927) 和 [LinEra](https://arxiv.org/abs/2611.18133) 分别处理记忆随时间变化和可审计的遗忘。
- 上下文管理趋向轻量、可学习、不额外调用 LLM：[CarryOn](https://arxiv.org/abs/2611.17808) 用学习的选择器保留证据，成功率 75.7%，比最强基线高 6.7 个百分点；[CLAM](https://arxiv.org/abs/2611.20759) 把会话压进低秩 adapter。
- 检索回到朴素基线：[Embeddings vs. Grep](https://arxiv.org/abs/2611.20455) 指出稠密检索对 BM25 的优势主要来自评测设置，用 LLM 生成标识符再 grep（generate-then-grep）后，BM25 在每个 Python 评测池上都追平了稠密检索。
- Harness 层强制校验优于让模型自己判断：[SilentGuard](https://arxiv.org/abs/2611.20595) 把静默 API 失败下的错误回答从 74.0% 降到 1.7%，只发警告则仍有 70.1% 错误。
- 今日热度最高的是评测类工作：[Unfinished-Bench](https://arxiv.org/abs/2611.17460) 发现「持久性」让智能体违反文档规则的比例从 32.2% 升到 43.6%；[多智能体研究](https://arxiv.org/abs/2611.17610)显示，在匹配基线下多智能体的平均准确率差为 -0.042。

### [Embeddings vs. Grep: Rethinking the Dense Advantage in Code Search](https://arxiv.org/abs/2611.20455)
- 热度：HF 👍8（入榜 2 天，新增 +5）；无代码仓库。
- 问题：代码搜索基准显示稠密编码器远胜 BM25，但编码智能体只用 grep 就做得很好，这个优势到底衡量了什么。
- 方法：作者构建仓库级代码搜索基准 Repo-Premium，覆盖 6 种语言和 2022–2026 年的 PR，预注册测试池包含 91 个仓库，同时有精编查询和原始查询。稠密检索的优势被追溯到两处：评测选择本身偏向稠密检索（给 BM25 切 chunk、把被编辑的测试算作相关），以及查询缺少代码里的稀有标识符。用 LLM 写标识符来扩展查询后，BM25 的收益远大于稠密检索。
- 结论/意义：BM25 在每个 Python 评测池上都追平稠密检索，包括 LLM 发布后才开的 PR。作者建议：对公平的词法基线衡量稠密增益，把稠密检索与 BM25 融合，给缺词的查询补上代码用词。没有任何方法能预测某个查询上哪种检索器会赢。

### [CarryOn: Learning What to Keep in Context for Long-Horizon LLM Agents](https://arxiv.org/abs/2611.17808)
- 热度：来源 arxiv，无 HF 点赞，入榜 6 天；无代码仓库。
- 问题：摘要式压缩会丢掉后续动作需要的精确细节，保留完整历史又带入大量无关信息。
- 方法：一个轻量的上下文管理器，把紧凑的执行状态与带来源链接的细粒度证据配对，由学习的选择器加自适应保留策略管理上下文，不额外调用 LLM。作者另提出两个指标：Sα（成功优先并计入资源）和 NCS（每次成功的归一化成本）。
- 结论/意义：在 AppWorld、OfficeBench、Tau2 Telecom 上，三个 LLM Actor 的宏平均成功率为 75.7%，比最强基线高 6.7 个百分点，两项指标的平均分也最佳。

### [Experience Rot: Experienced Agents Fail Where Novices Succeed](https://arxiv.org/abs/2611.20922)
- 热度：来源 arxiv，无 HF 点赞，入榜 5 天；无代码仓库。
- 问题：智能体会把对话历史、记忆文件、检索笔记和 skills 当作经验复用，工具（MCP 定义）被静默修改后会怎样。
- 方法：在一系列模型上，比较工具静默变更后有经验与没有经验的智能体。有经验的智能体照抄之前的调用，不检查当前接口，即使工具定义里已显示变化，事后还汇报成功。
- 结论/意义：变更后，有经验的智能体在多数任务上失败，没有经验的大多成功；这种失败出现在测试过的每一种记忆形式里，并随经验量增加而加重。宣布更新几乎没用，让智能体去看文档也没用，因为文档没写明答案。

### [LEDGER: Auditable Agent Memory Under Change](https://arxiv.org/abs/2611.20927)
- 热度：来源 arxiv，无 HF 点赞，入榜 5 天；无代码仓库。
- 问题：现有记忆系统多在固定历史上评测，而现实中事实会变，来源可靠性不同，用户还会要求遗忘。
- 方法：语言模型只负责提出事实，由显式规则决定哪个值是当前的、信任哪个来源、删除什么；每条事实保留来源和有效时间段。LEDGER+EP 对账本覆盖不到的问题再搜索原始对话轮次，删除时也清理这些轮次。
- 结论/意义：在作者自建的合成编码智能体负载上，LEDGER+EP 回答正确率为 94.3%（5 个开发种子）和 91.1%（5 个留出种子），最强基线全历史回放为 82.1% 和 83.3%。在 LongMemEval 的 210 题子集上，它与全历史回放准确率相同（74.8%），只用 1% 的上下文。局限：合成负载由作者自建，LongMemEval 上最强系统之间的差异落在置信区间内。

### [Instant Weight-Space Consolidation for Long-Term Memory in LLMs](https://arxiv.org/abs/2611.20759)
- 热度：来源 arxiv，无 HF 点赞，入榜 5 天；无代码仓库。
- 问题：文本式智能体记忆不会让模型本身演化；抽取错误会累积，跨会话的隐含模式浮不出来，构建成本随对话增长。
- 方法：CLAM（Carried Latent Adapter Memory）用循环 hypernetwork 做参数化巩固，单次前向就把一串会话激活编译成低秩 adapter，不需要梯度步，也不需要语言模型生成调用。门控潜在状态以固定大小跨会话携带知识，另有情景缓冲区在推理时提供原文细节。
- 结论/意义：在 LoCoMo 和 LongMemEval-S 上、三个 2–7B 开源模型中，CLAM 领先所有智能体式基线 1–45 点，领先所有基于梯度的参数化方法 10–45 点，构建记忆比抽取式系统快 3–151 倍。缓冲区漏掉证据时，巩固后的 adapter 多得 12–15 点；缓冲区是 oracle 时也多得 4–5 点。

### [Continual-ARC: Measuring Skill Acquisition over a Working Lifetime](https://arxiv.org/abs/2611.14505)
- 热度：HF 👍3（入榜 6 天，数据中首次出现时为 9，新增 -6）；仓库 [unifyai/continual-arc](https://github.com/unifyai/continual-arc) ⭐39。
- 问题：现有持续学习基准只覆盖单一领域，每个实例只出一次，记忆式和权重式系统也无法放在同一尺度上比较。
- 方法：基于三个 ARC-AGI 版本构建终身任务流，任务经休眠间隔后带新实例回归，同时不断有新任务出现。学习者可花费预算看演示、提交答案或在 harness 内行动，按消耗的反馈预算占比计分。流结束后冻结学习者，分别在见过的任务（测记忆）和未见任务（测泛化）上测试。
- 结论/意义：冻结权重的 harness 加持久化通常不提升记忆，除非提供明确的专家指导。多数 harness 方法学得比单纯缓存每个任务演示的下限还少，在未见任务上没有任何 harness 方法获益，权重式学习则有明显收益。

### [Invariant-Aware Harness Enforcement to Protect LLM Agents from Silent API Failures](https://arxiv.org/abs/2611.20595)
- 热度：HF 👍5（入榜 4 天，新增 +2）；仓库 [Sajib-006/silentguard](https://github.com/Sajib-006/silentguard) ⭐1。
- 问题：API 可能静默失败，例如忽略一个写错名字的过滤条件，却仍返回 HTTP 200 和看似合理的错误结果；让模型自己检查（清单、审查模型、LLM 判官）效果差。
- 方法：SilentGuard 把决定权从模型移到执行工具调用的 harness。harness 用任何正确 API 都应满足的不变量检查每个结果，并扣下违反不变量的值。
- 结论/意义：15 个公开研究 API 中有 11 个存在静默失败，计数最多被放大 691 倍。在 7 个开源模型上，目标故障下的错误回答从 74.0% 降到 1.7%，无故障任务不受损；三个前沿模型从 70.2% 降到 0.5%。同一检查只发警告时仍有 70.1% 错误，所以起作用的是强制执行。面对新故障类型，仅靠 harness 把错误从 61.1% 降到 24.5%，方式是弃答而不是恢复。

### [Forget the Lineage: Forward-Secure, Lineage-Complete Cryptographic Erasure for LLM-Agent Memory](https://arxiv.org/abs/2611.18133)
- 热度：来源 arxiv，无 HF 点赞，入榜 6 天；无代码仓库。
- 问题：智能体的长期记忆由模型自己写成（摘要、事实、嵌入），只删一条消息不够，衍生物、存储残留和备份仍然存在。
- 方法：LinEra 沿衍生图，用父记忆的密钥派生子记忆的密钥，源密钥来自可穿孔伪随机函数（puncturable PRF）。遗忘只需一次穿孔，所有后代无需定位就变得不可读。已与 mem0 集成。
- 结论/意义：在 LoCoMo 对话上，攻击者持有全部文件和当前密钥时，逻辑删除后能恢复 71 个被遗忘秘密中的 70 个（最大模型写入的 10 段对话），per-object 或 epoch 密钥能恢复 67 个，LinEra 下一个也恢复不了。代价是遗忘半径更大：遗忘 1% 的轮次，会话级摘要下抹掉 73.0% 的衍生记忆，四轮窗口下只抹掉 3.8%，后者回答也更好。

- [System 1 agents: a method for local, reliable and fast agentic AI](https://arxiv.org/abs/2611.21053) · HF 👍6 · 入榜 2 天：确定性编译器把工具 schema 和请求变成选择题，由单次前向的决策模型作答，不生成文本。在 157 个生物医学工具的 1,952 个请求上，选对工具（或正确拒绝）的比例为 97.0%，高于 18 种本地 LLM 智能体设置中最佳的 95.2%，调用中没有编造内容（LLM 为 5.5–19.7%）。仓库 [eltzanis/SystemOneAgents](https://github.com/eltzanis/SystemOneAgents) ⭐15。
- [Do LLM Agents Still Need to Be Told How to Self-Improve?](https://arxiv.org/abs/2611.23219) · HF 👍6 · 入榜 4 天：冻结的 LLM 智能体拿到算力预算和更新文本文档的工具，不设外部循环，在游戏中自建自学习算法。足够强的模型确实会自我改进，学到的文本产物还能迁移到外部基准。仓库 [ssundaram21/self-org](https://github.com/ssundaram21/self-org) ⭐3。
- [More Agents, More Samples, or More Thinking? Untangling Coordination, Ensembling, and Test-Time Compute in Multi-Agent LLMs](https://arxiv.org/abs/2611.17610) · HF 👍6 · 入榜 4 天：综合 9 项实证研究共 516 种多智能体配置。对比匹配采样数或资源预算的基线，多智能体的平均准确率差为 -0.042，74% 的可比对比中持平或更差；要有正收益，需要分割的证据、外部验证或模型间的错误多样性。仓库 [mahmoudsajjadi/pace](https://github.com/mahmoudsajjadi/pace) ⭐3。
- [When Tool Names Are Not Identities: Measuring Provider Misbinding in MCP-Based AI Agents](https://arxiv.org/abs/2611.21577) · 来源 arxiv，无 HF 点赞 · 入榜 5 天：攻击者只需运行另一个 MCP server 并设定工具元数据，就能让原本发给合法提供方的请求落到攻击者的工具上。在受控 MCP 环境、5 个 LLM 客户端上评测，同名、任务对齐的描述和兼容 schema 叠加时失败最严重；带权威口吻的描述加兼容 schema，即使不同名也可能出错。
- [IDEA: Intent-Dominance Evidence Audit for Inference-Time Backdoor Detection in GUI Agents](https://arxiv.org/abs/2611.24102) · HF 👍5 · 入榜 3 天：用意图反事实探测加区域因果审计，在推理时逐步检测 GUI 智能体被视觉触发器激活的后门，无需触发器知识。在 Qwen2.5-VL-3B、5 类攻击上，受控误报率下优于现有检测方法，并能定位触发区域。

## 研究趋势观察

- 今日热度榜上的 Agent Context 论文集中在记忆和经验会不会反噬：[Experience Rot](https://arxiv.org/abs/2611.20922) 显示经验在工具变更后拖累智能体，[Continual-ARC](https://github.com/unifyai/continual-arc) 显示多数 harness 持久化方法学得比缓存演示的下限还少、在未见任务上无增益，[LEDGER](https://arxiv.org/abs/2611.20927) 与 [LinEra](https://arxiv.org/abs/2611.18133) 处理记忆随时间变化、可审计和可遗忘。三者都指向同一点：记忆需要版本、来源和删除机制。
- 上下文管理方法倾向不额外调用 LLM：[CarryOn](https://arxiv.org/abs/2611.17808) 用学习的选择器，[CLAM](https://arxiv.org/abs/2611.20759) 用单次前向把记忆编译进 adapter（零生成调用，构建快 3–151 倍），LEDGER+EP 用 1% 的上下文达到与全历史回放相同的 LongMemEval 准确率。检索侧，[Embeddings vs. Grep](https://arxiv.org/abs/2611.20455) 提醒基线要公平，并建议稠密检索与 BM25 融合。
- Harness 设计的共同做法是让外层确定性逻辑承担校验：[Sajib-006/silentguard](https://github.com/Sajib-006/silentguard) 做不变量检查与强制弃答，[eltzanis/SystemOneAgents](https://github.com/eltzanis/SystemOneAgents) 用确定性编译器加单次决策。与只让模型自己判断相比，两篇论文的实验里错误率都明显更低。
- 数据局限：HF 点赞普遍很低（最高 9），差距主要在个位数，且没有 X 提及数据；今日数据中没有与论文对应的 GitHub 项目增长信息，无法在工程侧做呼应，这里只作说明，不下判断。
