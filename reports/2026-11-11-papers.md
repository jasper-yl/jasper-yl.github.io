### [Flide: Accelerating Decision Inference with Exact State Forking](https://arxiv.org/abs/2610.42148)
- 热度：HF 👍35（入榜 1 天，新增 +6）；无 X 数据；代码 [OmniJev/Flide](https://github.com/OmniJev/Flide) ⭐430
- 问题：现有推理引擎处理 Agent 的决策模型（Jev 这类，一次前向给出类别概率）时，要么重复计算前缀，要么输出概率失真。
- 方法：把一个决策请求的逻辑树结构与物理执行分开，放进一条扁平的 token 流。ForkAttention 通过 GPU 上的索引同时处理标准注意力层和循环的 Gated DeltaNet 层，保证每个分支在精确算术下与单独前向的结果一致。不断增长的 Agent 历史可以从前几次推理保存的 checkpoint 接着算。
- 结论/意义：在公开的混合模型和决策模型上，查询速度最高比 vLLM 和 SGLang 快 9.5 倍，与 float32 参考的总变差距离最小。这是今天 hot 里与前缀复用、缓存最直接相关的一篇，GitHub 星数也远高于同日其他论文。

### [The Last Mile to the Real World: Agent-Native Primitives as Reusable Building Blocks for Solving Real-World Tasks (HEELO)](https://arxiv.org/abs/2611.07461)
- 热度：HF 👍5（入榜 2 天，新增 +2）；无代码仓库数据
- 问题：前沿模型加自带 harness 在真实任务上仍不够，Terminal-Bench 4.0 上 Codex 解决 37.3%，Claude Code 解决 51.8%。失败出在「拿到资源却不会用」。
- 方法：提出 agent-native primitives，给每个资源配一个常驻 LLM，让它在上下文中使用该资源并与其他 primitive 通信。HEELO 为每个任务从 primitive 库里组出任务图，用环境证据验证，修订出问题的 primitive，验证后收入新的或改进的 primitive，共 8 类。
- 结论/意义：Dev-Primitives 把 Terminal-Bench 4.0 从 37.3% 提到 55.5%，Terminal-Bench 2.0 Pass@1 从 60.0% 到 72.2%，ToolBench 通过率从 55.8% 到 75.1%，GAIA-Text-103 从 45.6% 到 58.3%。在 heelo.dev 的 46 个真实任务上，通过 MCP 接入 HEELO 后两个 harness 分别完成 39 和 35 个，原本各 9 个。这篇属于 Harness 设计，点赞很低，入选因为主题贴合。

### [FlyHash for LLM Agent Memory: An Empirical Validation and a New Application](https://arxiv.org/abs/2611.05791)
- 热度：HF 👍4（入榜 6 天，新增 +4）；代码 [mohanji/flyhash-agent-memory](https://github.com/mohanji/flyhash-agent-memory) ⭐1
- 问题：Agent 记忆检索通常用稠密向量加近似最近邻，源自果蝇嗅觉回路的 FlyHash 能否用在这里。
- 方法：首次把 FlyHash（稀疏随机投影加胜者全取）用于 Agent 记忆检索，在匹配比特数的协议下与 SimHash、HNSW 比较，并用真实的记忆相关性标注，而不是「按嵌入找最近邻」的代理标签。
- 结论/意义：质量优势在 10 个随机种子、4 个数据集上成立，真实标注下也成立。但同等比特数下 FlyHash 编码更大、比较更慢，HNSW 在常规规模上优于两种哈希，哈希的实用场景比质量结果显示的更窄。论文自己报告了削弱主结论的负面结果。

### [Ask, Don't Equip: Question-Driven Coding Agents for Deep Kernel Optimization (KernelSeek)](https://arxiv.org/abs/2611.03517)
- 热度：HF 👍4（入榜 6 天，新增 +4）；无代码仓库数据
- 问题：GPU kernel 优化 Agent 要么流程固定，要么完全开放但试错成本高；遇到难目标时两者都靠多装工具（解析 profiler、检索文档、经验库）。
- 方法：用通用编码 Agent 加一个只强制可验证目标的最小 harness，在决策点向 Agent 提短问题，先由人提，再由 Agent 用问题库对自己提问。主张是「给方向，不给信息」。
- 结论/意义：同一任务上，工具丰富的自主 Agent 在 133 步后停在 0.50x FlashAttention-3，KernelSeek 达到 1.13x；产出的 Hopper/Blackwell FlashAttention 前向 kernel 在 182 个场景全部正确，几何平均为 FA3 的 1.16x、FA4 的 1.46x。162 条人类消息、11.5K 次工具调用里，每个大的提升都来自把 Agent 引到系统另一层或否定它所声称限制的问题，而不是提供信息的问题。它与上下文工程的关联是「少装工具、少塞信息」的反向证据，但论文本身不做上下文管理。

### [Sketchpad: certified exact arithmetic with a small vision-language model](https://arxiv.org/abs/2611.04434)
- 热度：HF 👍4（入榜 2 天，新增 +2）；代码 [NeoVand/sketchpad](https://github.com/NeoVand/sketchpad) ⭐1
- 问题：长算术的准确率只能抽样估计，工具调用精确，却把计算移出了网络。
- 方法：每一步只读外部「工作记忆」（一张渲染出的表格）里的三格视野，输出一步（一个数字、进位/借位、下一步操作），由固定的运行时移动视野，不写任何结果数字。用 Lean 证明：模型对任意长度输入都精确，当且仅当它对运行时会呈现的有限个视野集合精确。
- 结论/意义：Qwen3.5-0.8B 加低秩适配器，2,446 个视野全部通过；浏览器里 200/200 预注册题答对，1,000 位以内加法和 20 位以内乘法 220/220 答对，其他十个模型里最强的 GPT-6.1 Sol 答对 217。这篇与「有界视野的外部工作记忆」沾边，但不是 Agent 上下文管理论文。

## 🆕 New：昨晚新公布
- [Don't Just Trust Your Memory (WikiTrace)](https://arxiv.org/abs/2611.14320)：每条经验以简短洞察存储，并链接到成败原因摘要和原始轨迹；新任务中遇到细节不足、相互冲突或来自失败任务的洞察时，Agent 用终端工具顺链接回查原轨迹来补充或纠正；五个 Agent 基准上优于现有记忆方法，并减少记忆导致的退化；代码 [yukyeongleee/wikitrace](https://github.com/yukyeongleee/wikitrace) ⭐4（初步热度 👍43）。
- [When Should Agents Remember? Falsification-Gated Self-Evolution (FGSE)](https://arxiv.org/abs/2611.14326)：把候选经验写成带前提、行为变化、预期效果和验证器的假设，先在临时状态里试用，用迁移、证伪、回归探针检验后再决定提交、修改或拒绝；WebArena 成功率 39.8，AppWorld 平均完成 78.8，有害提交更新降到 3.6%。
- [Coding Agent Memory Post-Training II (CAMP-II)](https://arxiv.org/abs/2611.14009)：长程任务的交互历史超出上下文时，让策略用普通 Bash 和跨上下文替换持续存在的工作区把文件当记忆；采用完全异步的 on-policy 蒸馏，向熟悉文件操作的冻结教师学习；在新环境集 CAMG-II 上比最强 OPD 基线提升 2.97 倍，并迁移到 Terminal-Bench 2.1 和 SWE-Bench Pro V2。
- [TreeAgent](https://arxiv.org/abs/2611.13946)：按子树而非固定长度切分 JSON/HTML 等结构化长输入，给片段附结构路径，并加上从低层子节点到高层父节点的残差记忆链接；输入 8K–1M token，四类记忆 Agent 平均提升 3.61%。
- [SHADOWPREFILL](https://arxiv.org/abs/2611.13176)：Agent 按步在不同模型间路由时，换模型会丢掉前缀缓存；它在空闲容量里提前让「未被选中的下一个模型」预填会话上下文，切换调用延迟降 8.5–21.4%，路由 token 成本降 22.5–46.1%。
- [World In-Context Learning for Agentic Robot Manipulation (RoboScript)](https://arxiv.org/abs/2611.12885)：冻结模型从一个示范出发在仿真中演练，把反馈写进上下文（Task Memory）而不是权重；RoboTwin 2.0 全部 50 个任务平均成功率 83.4%，比最强训练策略高 20 个点以上；代码 [ArcheOne-AI/RoboScript](https://github.com/ArcheOne-AI/RoboScript) ⭐47（初步热度 👍52）。
- [Program-Aided Patchable Skill Evolution (PASE)](https://arxiv.org/abs/2611.14019)：把 Skill 里的流程逻辑拆成可编辑的可执行程序，更新时只给程序打补丁，不反复改自然语言；摘要称提升超过 2.8%。
- [ARE-bench](https://arxiv.org/abs/2611.14364)：75 个任务取自研究者真实会话和未清理的工作区，评测 Agent 能否尊重之前的决策和已有工作区状态；最强模型只在 66.2% 的任务上通过全部检查项，加上历史与工作区要求后，三个模型从约 69% 降到 28.4%–40.0%。
- [MMDM: Measuring Massive Multitask Decision Making](https://arxiv.org/abs/2611.14309)：5,448 道题、16 类，涵盖 Agent 状态跟踪、工具与 Skill 选择，输入长达 64,817 token；评测 28 个决策模型，最佳 Hard 多选准确率仅 36.81%；与 Flide 同属 Jev 类决策模型这条线（初步热度 👍24）。
- [BioMem](https://arxiv.org/abs/2611.13426)：系统评测五种 Agent 记忆方案在生物医学场景的表现，提出免训练的 HMRU，平均相对提升 8.6%，对话答案错误降 24.9%，补上与全上下文推理差距的 48.0%。
- [FINCOSMOS](https://arxiv.org/abs/2611.07464)：金融 Agent 的开放世界评测，模拟用户隐藏策略，150 个会话无一被接受；有持久记忆的 Agent 在得到反馈后学会了全部十个任务（初步热度 👍16）。
- [Tree-Ising](https://arxiv.org/abs/2611.14210)：用比特级 Ising 编辑修复语言模型权重，对标「让 Agent 读权重写修复」的方案，用 0 个 LLM token 在 MATH-500 上达到 54.6%（Agent 编辑为 51.7%）；偏模型修复，与 Agent 关联较弱（初步热度 👍59，new 里最高）。
