## 今日要点
- 长程 Agent 的上下文管理在从"压缩历史"转向"围绕可复用进展组织上下文"。CarryOn 在 OSWorld 2.0 和 BrowseComp-Plus 上分别提升 5.8% 和 7.0%，同时少用 51.9% 和 22.9% 的 token。
- 上下文压缩和子 Agent 分叉开始进入 RL 训练。Mosaic 把"多 session 轨迹"作为训练设定，直接对应推理时的 compaction 和 subagent forking。
- Harness 成为热点主题：自进化 Harness 的理论框架、Harness 与策略交替优化的 Self-HPO、"薄 Harness"的 HexaShell，以及把决策从 Harness 规则转给模型的 OpenGCUA。
- Skill 的学习方式被重新设计：Socratic Skill Learning 让 Student 在专家指导下边练边写 Skill。
- 评测从"终局成功"转向"过程有效性"：BizBench 显示，只看结果会掩盖违规执行。

## 一、🔥 热度榜：Agent Context 精选

### [Pack Light, CarryOn: Building Object-Oriented Context for Long-Horizon Agents](https://arxiv.org/abs/2610.18784)
- 热度：HF 👍122（入榜 1 天，新增 +1）；代码：[Ethannju/carryon](https://github.com/Ethannju/carryon) ⭐5
- 问题：长程 Agent 的任务状态已持久化，却仍要反复处理"进展是怎么取得的"这类交互历史。
- 方法：CarryOn 是面向对象的上下文运行时，围绕可复用的任务对象组织续跑。它的上下文视图由"续跑载体"（continuation carriers）、补充执行上下文和最近交互的 live tail 组成。每次折叠（fold）时，它只根据证据和环境检查修订受影响的载体记录，其余记录原样带入，并同步更新执行上下文，不用重建完整表示。
- 结论/意义：在 OSWorld 2.0 和 BrowseComp-Plus 上分别提升 5.8% 和 7.0%，总 token 用量分别下降 51.9% 和 22.9%。

### [Mosaic: Multi-Session Agentic Reinforcement Learning](https://arxiv.org/abs/2610.22174)
- 热度：HF 👍63（入榜 1 天，新增 +0）；代码：[LARK-AI-Lab/Mosaic](https://github.com/LARK-AI-Lab/Mosaic) ⭐37
- 问题：现有 Agent RL 假设单 session 轨迹，而推理时的上下文压缩和子 Agent 分叉会产生多 session 轨迹，两者不匹配。
- 方法：提出"多 session Agent RL"设定，每条轨迹可含任意多个 session。Mosaic 做无 critic 的分层优化：轨迹层把 session 使用量信号纳入优势估计，session 层按估计的边际贡献调整各 session 的优势。
- 结论/意义：在 BrowseComp（Qwen3.5-4B）上，无论是 context compaction 还是 subagent forking，都优于把轨迹级优势广播给所有 session 的做法，且平均 session 数更少。

### [Socratic Skill Learning: Interleaving Teaching and Practice for Transferable Agent Skills](https://arxiv.org/abs/2610.17860)
- 热度：HF 👍42（入榜 2 天，新增 +12）；代码：[NJU-LINK/Socratic-Skill-Learning](https://github.com/NJU-LINK/Socratic-Skill-Learning) ⭐2
- 问题：成功的单次任务尝试不足以检验一个 Skill 的步骤及其适用条件，所以学到的 Skill 难以迁移。
- 方法：SSL 让 Educator 指导调查，Student 始终是唯一的环境操作者和 Skill 作者，可以质疑、测试和调整建议。Issue-Guided SSL 在 Skill 的多次修订之间跟踪未解决的问题，用来挑选并聚焦评审。作者另建了 SkillTransferBench（35 个任务族、408 个可执行用例）来测试复用。
- 结论/意义：主测试组上 Fixed-Window SSL 的 utility 为 0.801，无 Skill 为 0.723；Issue-Guided 版本达到 0.805，Educator token 少 61.7%。

### [Self-Evolving Agent Harness](https://arxiv.org/abs/2610.18813)
- 热度：HF 👍99（入榜 1 天，新增 +0）；代码：[zgcagi/Harness-RSI](https://github.com/zgcagi/Harness-RSI) ⭐387
- 问题：模型权重不变时，如何系统地修订 Agent 的脚手架（prompt、记忆、工作流、可执行组件），并保证修订可靠。
- 方法：把"被接受的修订跨运行保留"形式化为反馈驱动的过程，并把更新目标与提案、准入机制分开。它区分解释型状态的变更与工具/代码、仓库级控制逻辑、插件组合的修订，再用进化优化和持续 PAC 学习分析可靠性。
- 结论/意义：在明确假设下给出泛化界、受历史回归预算约束的保留界，以及用新鲜独立验证数据的高概率准入规则；另有 66 页综述和持续更新的代码。

### [OpenGCUA: Toward a Fully Open Stack for Generalist Computer Use](https://arxiv.org/abs/2610.22200)
- 热度：HF 👍103（入榜 1 天，新增 +0）；代码：[Tongyi-MAI/OpenGCUA](https://github.com/Tongyi-MAI/OpenGCUA) ⭐441
- 问题：前沿的通用电脑使用 Agent 实现大多闭源，其设计难以系统研究。
- 方法：以代码执行为核心，让中间结果决定后续操作。同时提出"Harness 到模型的决策转移"，把部分观察和任务状态决策从固定的 Harness 规则交给模型。项目开源了实现、prompt、八个模型的评测轨迹，以及真机 Harness 和跨设备 SDK 的初版。
- 结论/意义：在 OSWorld-v2 上，完整配置使八个被测模型的任务分数全部提升，平均部分得分 +19.6，相对批处理的纯 GUI 执行，报告步数平均减少 53.0%。

### [HexaShell: A Thin Harness for Exploring the Limits of VLM Agents as Robot Coding Agents](https://arxiv.org/abs/2610.23479)
- 热度：HF 👍121（入榜 1 天，新增 +2）；代码：[HexaFuture/HexaShell](https://github.com/HexaFuture/HexaShell) ⭐138
- 问题：编码 Agent 控制机器人时能走多远，瓶颈在哪里。
- 方法：Harness 只把 Agent 的命令转成机器人动作。每次失败后，Agent 读日志找原因，再编写或修复小工具，把所学以代码形式保留。工具先在 10 个布局上构建，冻结后在 10 个新布局上测试。
- 结论/意义：在 42 个 RoboDojo 任务上成功率为 39.7%，作者称创该榜新高。瓶颈在接触而非推理：推动任务 92.5%，紧配合插入仅 8.3%。

### [DeltaStreamer: Towards Human-Like Agentic Streaming Video Understanding](https://arxiv.org/abs/2610.19849)
- 热度：HF 👍38（入榜 1 天，新增 +0）；代码：[BBBBchan/DeltaStreamer](https://github.com/BBBBchan/DeltaStreamer) ⭐87
- 问题：流式视频要在不知道未来问题的情况下保留证据，而压缩视频历史会模糊事件转折、丢失细节且无法恢复。
- 方法：查询到来前，持续观察视频流，把视觉变化显式记入结构化记忆。查询到来后，由规划器确定所需证据，指导记忆检索和对历史帧的定向回放，补回观察时遗漏的视觉细节。
- 结论/意义：在 OVO-Bench 和 StreamingBench 上总分分别为 66.07% 和 59.53%，优于对比的流式视频理解方法。

### [Retrieval Augmented Generation Compositionality](https://arxiv.org/abs/2610.29722)
- 热度：HF 👍47（入榜 2 天，新增 +22）；代码：[dolev31/lasagna](https://github.com/dolev31/lasagna) ⭐17
- 问题：RAG 流水线里的各项技术（含上下文压缩）通常单独评测，不清楚组合后收益是否保留。
- 方法：提出开源框架 LASAGNA，在 8 个基准、5K 到 200K 文档的语料上测试 450 种配置。
- 结论/意义：单项收益不一定可叠加，三种检索技术预测合计 +47%，实际只有 +17%；检索质量与忠实度的最优组合不同，最优组合也会随语料规模变化。

## 五、研究趋势观察
- **上下文管理走向"结构化 + 与训练结合"**：CarryOn 用任务对象替代历史摘要，Mosaic 把压缩和分叉带来的多 session 轨迹纳入 RL；DeltaStreamer 则用结构化变化记忆加回放补回压缩丢失的细节。三者都在处理"压缩之后怎么保住有效信息"。
- **Harness 成为一等研究对象**：Self-Evolving Agent Harness（⭐387）、Self-HPO、OpenGCUA（⭐441）、HexaShell（⭐138）都把脚手架的设计或进化当作主问题。这几篇的 GitHub 星数相对较高，说明社区对可复用 Harness 有明显兴趣。
- **评测关注过程与真实场景**：BizBench、FDE-Gym、Into the Unknown 都显示，前沿模型在中间执行有效性、隐含约束发现和研究诚信上仍有明显差距。BizBench 的 Qwen3.8-27B 目标达成率 42.0%、严格成功率只有 32.7%，说明只看结果的评测会高估能力。
- **环境合成是训练侧主线**：MAI-Gym、WildAWM、CoworkEnv、OpenMobile-2 等都在做可验证的合成环境加 RL/SFT，这类工作在 GUI 和电脑使用 Agent 方向尤其集中。
