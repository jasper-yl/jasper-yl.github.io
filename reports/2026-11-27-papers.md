## 🔥 热度榜：Agent Context 精选

### [Letting Models Manage Their Own Context: Where We Stand](https://arxiv.org/abs/2611.34147)
- 热度：HF 👍10（入榜 1 天，新增 +4）；代码 [nvidia-nemo/labs-OO-Agents](https://github.com/nvidia-nemo/labs-OO-Agents) ⭐2335
- 问题：目前由 harness 在窗口写满时触发摘要压缩；改由模型自己决定何时压缩、压缩什么，效果如何？
- 方法：在 NVIDIA 的开源 agent harness（论文中称 nooa）里给模型一个 context API，让它自行决定压缩的时机和内容。任务是文档研究和机器学习工程，上下文预算从 8K 到 512K，对比两种策略。另外，编辑上下文后复用未改动后缀的 KV cache。
- 结论/意义：GPT 6.1 在 32K 预算的 OfficeQA Pro v2 上从 21% 升到 56%，接近三倍；Kimi 输入 token 最多少 41%；复用 KV cache 使每请求 prefill 计算最多少 15%，准确率无可测变化。不同模型使用 API 的频率、压缩力度和起始时机差异很大，改提示词会改变压缩时机。指向模型训练成自己管上下文、推理引擎支持 KV cache 编辑的协同设计。

### [Demystifying the Autoresearch Harness: How Context and Skills Shape Self-Evolving Agents](https://arxiv.org/abs/2611.28244)
- 热度：HF 👍5（入榜 1 天，新增 +1）；无代码仓库
- 问题：长程自进化 autoresearch agent 的 harness 由多种机制叠加，看不出各组件分别贡献了多少。
- 方法：在 MLE-Bench 和 KernelBench 上，以 recency-truncation 为基线，在同一框架内逐项对比两个维度：上下文管理（保留什么）和技能管理（如何存储、复用经验）。
- 结论/意义：保留可单独访问的历史记录优于滚动摘要，context folding 在全部 6 种设置中最好，相对基线最多提升 19.2%；技能上，选择性删除长期不用的经验，平均好于合并或升级为常驻规则。两者合并成 MLEvolver，MLE-Bench Lite 奖牌率 72.7%，KernelBench Level 3 fast_1 为 94%，优于 AIDE 和 OpenEvolve。

### [VideoJSON: A Minimal Harness Beats Purpose-Built Memory for Ultra-Long Video Understanding](https://arxiv.org/abs/2611.28167)
- 热度：HF 👍8（入榜 2 天，新增 0）；代码 [weathon/videojson_release](https://github.com/weathon/videojson_release) ⭐2（代码为发表后开源）
- 问题：数天到数周的超长视频问答依赖复杂记忆图和固定检索流程，限制了 agent 的搜索方式。
- 方法：索引时，VLM 把每分钟视频转成一条 JSON 记录，含稠密 caption 以及事件、实体、地点、语音转写等字段。查询时，coding agent 在沙盒里写 Python/Bash 程序，多步过滤、关联、读取这些记录，不碰原始视频。
- 结论/意义：用 DeepSeek V4.1 Flash，在 EgoLifeQA、Ego-R1-Bench、MM-Lifelong Week 上分别领先 MAGIC-Video 7.0、20.0、24.75 分，在 EgoMemReason 上超过此前最佳 12.6 分。消融显示代码检索和结构化 JSON 都有贡献，加小时摘要、额外工具或视频访问，平均分变化不到 1.5 分。

### [MMMem: Self-Improving Agents with Task-Aware Multimodal Experience Consolidation](https://arxiv.org/abs/2611.30287)
- 热度：HF 👍10（入榜 3 天，新增 +9，是 hot 里涨幅较大的一篇）；代码 [ChenYX24/MMMem](https://github.com/ChenYX24/MMMem) ⭐0
- 问题：现有多模态记忆只管存取，不会从已完成的任务中沉淀经验，同类错误反复出现。
- 方法：记忆是多视图的，包含原文、图像、渲染页面，以及由跨记录整合线索生成的场景图。系统用源数据自动生成任务，先做 warm-up（整合进外部记忆），再做 self-training（调整模型参数中的知识）。同一个 VLM 把完成的任务蒸馏成经验，记录任务上下文、结论和支撑链接；检索时同时召回源视图和相关经验。
- 结论/意义：用 Qwen3.5-9B，相对最佳基线在 LoCoMo、Mem-Gallery、LooGLE v2 上分别提升 36.9%、17.6%、15.2%，优于 8 个基线。

### [VibeVideoAgent: Closing the Perceptual Loop for Code-Driven Video Generation](https://arxiv.org/abs/2611.34237)
- 热度：HF 👍57（入榜 1 天，新增 +3）；代码 [Kling-Keye/VibeVideoAgent](https://github.com/Kling-Keye/VibeVideoAgent) ⭐10
- 问题：代码驱动的视频生成里，程序跑通不代表画面和音频正确；把渲染帧和音频塞回编码会话，又会撑爆长程上下文。
- 方法：免训练。多模态感知在与 coder 隔离的短生命周期上下文里运行，只返回精简、有依据的 Findings。7 个原语作用于统一的多时钟表示，分阶段协议先用最小预览验证风险最高的决策。
- 结论/意义：在 239 个 VibeVideoBench 任务上，Claude Opus 5.5 的整体视听质量（L3）从 4.03 升到 4.43，GPT-6 Astra 从 4.03 升到 4.27，Claude Sonnet 5.5 从 3.97 升到 4.10；音画同步增益最大，最高 +0.56。

### [Agentic LongLive: Asynchronous Agentic Memory for Long Video Generation](https://arxiv.org/abs/2611.34907)
- 热度：HF 👍19（入榜 1 天，新增 +3）；代码 [NVlabs/LongLive](https://github.com/NVlabs/LongLive) ⭐2919（这是基础生成器 LongLive 的仓库，星数不一定属于本论文的新增代码）
- 问题：实时自回归视频生成器在长互动故事里难以保持人物、物体、场景一致；离线 agent 系统要先读完整剧本，实时流做不到。
- 方法：独立 GPU 上的记忆 agent 只读已揭示的提示词，不读生成的视频，为每个人物、物体、场景维护文本状态和不断演化的图像，据此合成全局图和单镜头记忆图。辅助 GPU 在下一镜头开始前把它们预填进生成器的 attention sink，所以视频不等记忆，视频里的错误也不会写回记忆。决定记什么的小型语言模型用 RL 训练。
- 结论/意义：在新基准 LongStory-Online（25 个故事、857 个镜头）上，相对基础生成器 LongLive-2.0，持久状态准确率 +26.3 分，主角身份 +44.9，回访地点一致性 +40.4，额外生成时间约 1%（H100）；在单个 8xB200 节点、BF16 下达到 34.3 FPS，快于实时，14 分钟故事内画质稳定。作者称这是首个由 LLM agent 维护文本和图像记忆的实时视频生成器。

### [SEEK: Self-Evolution through Execution Knowledge for Agentic Robot Manipulation](https://arxiv.org/abs/2611.33915)
- 热度：HF 👍12（入榜 1 天，新增 +2）；代码 [ZeyangGuan/SEEK-Agentic-Robot-Manipulation](https://github.com/ZeyangGuan/SEEK-Agentic-Robot-Manipulation) ⭐9
- 问题：机器人把学到的执行知识只留在模型的工作上下文里，任务一结束就丢，下次重复同样的错误。
- 方法：用可执行程序表示操作策略（SEPP），每个动作由当前观测决定；用 Persistent Action-Effect Bank（PAEB）记录动作的实测效果，包括失败尝试。已保留的程序适用时不再调用模型，遇到未覆盖的条件，则用 PAEB 中的证据指导修订。
- 结论/意义：在 RoboDojo 的 42 个任务上，保留十次尝试的知识后，平均得分从 27.0 升到 54.4，成功率从 19.7% 升到 48.0%；在其中 34 个任务上，GPT-6.2 Astra 五次尝试后得分 80.1，直接行动为 49.6，模型请求少 77.6%。

## 研究趋势观察
- 热度集中在谁来管上下文、记什么。NVIDIA 的论文主张模型自管上下文并配合 KV cache 编辑；Autoresearch Harness 的对比里，保留可单独访问的原始记录优于滚动摘要；VideoJSON 用极简记忆加代码检索胜过复杂记忆图。三篇的共同做法是不过度设计记忆结构，保留可检索的原始记录，把控制权交给模型或代码。
- 记忆正扩展到视频生成、机器人和多模态：[Agentic LongLive](https://arxiv.org/abs/2611.34907) 和 [StateWeaver](https://arxiv.org/abs/2611.34290) 做视频，[SEEK](https://arxiv.org/abs/2611.33915) 和 [RoboEvo^2](https://arxiv.org/abs/2611.34675) 做机器人，[MMMem](https://arxiv.org/abs/2611.30287) 做多模态。它们都把经验沉淀成可复用的程序、记录或技能，下次直接调用，少请求模型；SEEK 少 77.6% 的模型请求就是数据上的例子。
- Harness 是高频词，出现在 Embodied-Harness 和 ReWeave，以及 RoboEvo^2 和 MORSE 等论文里，这些论文热度都不高，目前基本集中在机器人和视频领域。
- 工程侧，Agent Context 论文里代码仓库星数最高的是 [nvidia-nemo/labs-OO-Agents](https://github.com/nvidia-nemo/labs-OO-Agents)（⭐2335），与 NVIDIA 把 context API 直接放进开源 harness 的做法对得上。
- 评测侧，[ICLWorld](https://arxiv.org/abs/2611.32649)、[EgoUseBench](https://arxiv.org/abs/2611.34466)、[OS-Omni](https://arxiv.org/abs/2611.34232) 都显示，Agent 在长程、状态持续变化或需要实体交互的场景里明显落后人类，与上下文和状态管理是瓶颈的方向一致。
