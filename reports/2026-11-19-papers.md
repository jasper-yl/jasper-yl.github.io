## 🔥 热度榜：Agent Context 精选

### [Folio: Recoverable Multi-Resolution Context Folding for Long-Horizon Language Agents](https://arxiv.org/abs/2611.16627)
- 热度：arXiv 来源，HF 👍0（入榜 6 天，无新增）；无代码链接，无 X 数据
- 问题：长程 Agent 的历史超出上下文窗口后，靠模型写摘要压缩，每次压缩都要重读重写历史，还会丢证据。
- 方法：运行时记录三层视图：L1 是模型在正常回复里顺手写的 turn note，L2 是运行时生成的每次调用事件清单，L3 是原始来源记录。折叠时由程序直接给较早的轮次换用更粗的视图，不再调模型，并留下指向 L2/L3 的句柄。恢复工具按页读取、在文件里对全文做计算，把发现存进持久 dossier；折叠触发器按「保留预算加落点」计价。
- 结论/意义：在 75 个 LOCA-bench 任务上（底座均为 DeepSeek-V4-Pro）解决 66 个；同一运行时用模型写压缩的是 54 个，Claude Code、Codex、SoL-Pi 是 49–59 个。耗时约为对手的一半，成本比同运行时的模型压缩低 2.4 倍，每次折叠中位数 0.6 秒。本榜最直接对准上下文折叠的论文，数字也最硬；热度低是因为来源是 arXiv，没有 HF 点赞。

### [Self-Improvement Memory Enables Continual Recursive Self-Improvement](https://arxiv.org/abs/2611.18856)
- 热度：HF 👍31（入榜 1 天，新增 +6）；无代码链接，无 X 数据
- 问题：Harness 优化器换了基准或策略模型后，不知道已演化的 harness 哪些部分该复用、哪些该改，因为 harness 不会说明当初为何这样改。
- 方法：提出 Self-Improvement Memory（SIM），记忆的对象是 harness 优化器，不是做任务的策略模型。SIM 按反复出现的 harness 问题给编辑分组，记录每次编辑的理由、预测结果、实际结果和评测上下文，新尝试在这份历史上继续延伸。
- 结论/意义：四个领域的跨数据集、跨模型对比中，SIM 的最终得分高于只带 harness、只带根因的续跑方式。编码领域十次独立源运行中，配对续跑平均比只带 harness 高 2.36 分（p=0.003）。

### [Discovering Effective Agent Memory Designs through Program Evolution](https://arxiv.org/abs/2611.17068)
- 热度：arXiv 来源，HF 👍0（入榜 6 天）；代码 [ash-ding/MAPE](https://github.com/ash-ding/MAPE)（数据里未给星数）
- 问题：Agent 记忆方案靠人工设计，不知道哪些设计选择真正有效。
- 方法：[ash-ding/MAPE](https://github.com/ash-ding/MAPE) 从最小种子出发，通过标准化的生命周期接口和「诊断—提案」循环演化整套记忆程序。搜索目标同时优化准确率和服务成本，会把计算从 LLM 构建记忆转到查询时的选择性处理。
- 结论/意义：在 LoCoMo 和 LongMemEval 上，准确率最多比人工设计基线高 12%，服务成本为其 35%。归纳出两条设计规律：保留原始对话作为可检索证据，按查询意图组织检索到的证据。把组织模块移植到 5 个现有记忆系统，全部提升。

### [HeMeR: Heterogeneous Memory Reconciliation for Embodied Agents via Structured KV Reuse](https://arxiv.org/abs/2611.16487)
- 热度：arXiv 来源，HF 👍0（入榜 6 天）；无代码链接
- 问题：具身 Agent 的陈述性、程序性、工作记忆经不同接口访问，每次更新都当作新输入，导致 KV cache 整体重算。
- 方法：HeMeR 跟踪三类记忆内容在连续决策间的变化，保留未变化内容的 KV 状态，只对受更新影响的 KV 做重整。
- 结论/意义：真机上任务成功率 83.20%，单步推理时间从 2.94 秒降到 1.87 秒（对比 MemRL）。本批里少见的直接做 KV cache 复用的论文。

### [MemCredit: From Relevance to Utility for Decision-Time Memory in Long-Horizon Web Agents](https://arxiv.org/abs/2611.15600)
- 热度：arXiv 来源，HF 👍0（入榜 6 天）；无代码链接
- 问题：与当前状态语义最相关的记忆，不一定最能改进动作。
- 方法：用受控反事实干预估计每条记忆的边际贡献，再蒸馏成轻量的效用估计器。推理时语义相关性只负责高召回候选，由预测效用在固定 token 预算下决定保留哪些记忆；不改策略，也不需要额外环境交互。
- 结论/意义：ALFWorld 在 500 token 历史记忆预算下，SR@50 为 86.57，BM25 检索为 65.67%。摘要称记忆效用稀疏且强依赖状态。

### [DISCERN: Preserve at Write, Resolve at Read for Persistent LLM-Agent Memory](https://arxiv.org/abs/2611.15729)
- 热度：arXiv 来源，HF 👍0（入榜 6 天）；无代码链接
- 问题：企业 Agent 跨多次会话积累的记忆里，事实互相矛盾、被取代，相似实体在嵌入空间混淆。作者认为召回已基本解决，没解决的是「消解」。
- 方法：写入时建立只增不改的双时态溯源图，不合并易混淆实体，也不丢弃被取代的值。读取时用零 LLM 的工具面驱动 Agent 循环在图上导航，最终必须从四个受控的终止动作里选一个。
- 结论/意义：在 ENT-310 上，弃答 F1 为 0.924（八个基线最高 0.802），宏平均答案正确率 0.861（最强基线 0.806）；实体消解得分 0.800，没有基线超过 0.40。完整 LoCoMo 上宏平均正确率 0.663，对比 0.638。

### [Continual-ARC: Measuring Skill Acquisition over a Working Lifetime](https://arxiv.org/abs/2611.14505)
- 热度：HF 👍2（入榜 3 天，新增 -7，首次出现时为 9）；代码 [unifyai/continual-arc](https://github.com/unifyai/continual-arc) ★38
- 问题：现有基准多为单领域、每个实例只出现一次，也无法在同一尺度上比较基于记忆和基于权重的持续学习。
- 方法：[unifyai/continual-arc](https://github.com/unifyai/continual-arc) 用三代 ARC-AGI 任务构成终身任务流，同一任务隔一段时间带新实例回来。学习器可付费看示范、提交答案或在 harness 内行动，按消耗的反馈预算打分；流结束后冻结，分别测记忆和泛化。
- 结论/意义：冻结权重的 harness 加持久化，一般不提升记忆效果，除非给明确的专家指导。多数基于 harness 的方法学到的东西，比不上只缓存每个任务示范的下限。没有 harness 方法在未见任务上有收益，基于权重的学习有明显收益。这是对「harness 记忆能否持续学习」的负面证据，值得和 SIM、[ARISE](https://arxiv.org/abs/2611.23588) 放在一起看。

### [Reducing Batch Makespan for LLM Agent Workloads through Inference-Environment Coordination](https://arxiv.org/abs/2611.16661)
- 热度：HF 👍3（入榜 6 天，新增 +3）；无代码链接
- 问题：评测、合成数据、RL rollout 的 Agent 任务在 LLM 推理和环境交互间交替，批处理完成时间长。
- 方法：对混合架构 LLM，用负载资源模型在 KV cache 和循环状态间分配 GPU 显存，并给出参考并发度。轨迹感知的路由和调度提升 cache 复用并均衡负载。Chain-Advancing Action Scheduling（CAAS）按观察到的进度优先长链，缩短批尾。
- 结论/意义：在 BFCL、SWE-bench Multilingual、WideSearch、MCP-Atlas 上，makespan 降低 10.4%–65.0%，评测分数保持一致。

## 研究趋势观察

- 上下文管理从「摘要」转向「分层保存、按需取回」。热度榜的 [Folio](https://arxiv.org/abs/2611.16627)（L1/L2/L3 加句柄恢复）、今日 new 的 [Semantic Context Handoff](https://arxiv.org/abs/2611.24357)（状态与证据分离）、[RAA](https://arxiv.org/abs/2611.24422)（按相关性调分辨率）、[DISCERN](https://arxiv.org/abs/2611.15729)（写时保留、读时消解）都不再依赖一次性摘要。共同点是先保留原始证据，再决定取回多少。
- 记忆的评判标准从相关性转向效用，设计过程转向自动搜索。[MemCredit](https://arxiv.org/abs/2611.15600) 用决策效用代替语义相关，[MAPE](https://github.com/ash-ding/MAPE) 用程序演化搜索记忆结构，[SIM](https://arxiv.org/abs/2611.18856) 和 [ARISE](https://arxiv.org/abs/2611.23588) 让记忆在失败或编辑历史中自我演化。反面证据来自 [Continual-ARC](https://github.com/unifyai/continual-arc)：冻结权重的 harness 持久化在未见任务上没有收益。
- 自我进化的瓶颈被指向评估而不是提案。[The Resolution Hypothesis](https://arxiv.org/abs/2611.23068) 称评测噪声使进化方法的排名常常取决于运气，可以放在 SIM、ARISE、MAPE 等论文的结果旁边读。它只是单篇论文的结论，目前只有 HF 👍32 的初步热度。
- Harness 成为主要的工程杠杆。[ForceHarness](https://github.com/showlab/ForceHarness) 和 [SilentGuard](https://github.com/Sajib-006/silentguard) 把控制逻辑放在模型之外；[MLE Agents](https://arxiv.org/abs/2611.23910) 的作者称模型外的循环设计同样关键；[SkillCFI](https://arxiv.org/abs/2611.24185) 把 skill 编译成可强制执行的契约；[AscendGYM](https://github.com/SLAI-AITP/AscendGYM) 的评测同时支持模型和 harness。数据里没有 GitHub 项目增长数据，这里只能说论文侧的趋势，写不了与工程项目的呼应。
