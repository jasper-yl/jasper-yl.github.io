# Agent & Agent Context 论文日报 · 2026-11-25

> 生成于 2026-11-25 08:54 PST

## 今日要点

- Harness 设计是今天最集中的主题：[Embo-Harness](https://arxiv.org/abs/2611.31201)、[AutoPILOT](https://arxiv.org/abs/2611.28202)、[MORSE](https://arxiv.org/abs/2611.30011) 等都在讨论模型之外的循环（看什么、记什么、输出怎么变成动作）对表现的决定作用。
- [Context Has a Price](https://arxiv.org/abs/2611.22238) 测得，有前缀缓存折扣时，删除旧观察可能让成本上升 38–116%。
- [Stopping Is Not the Limit](https://arxiv.org/abs/2611.22888) 的 SCoRe 在 agent 想停下时压缩上下文，MiMo 在 2,000 轮的能力覆盖达到 67.0%，原策略为 32.4%。
- 记忆的评价标准在变：[Leto](https://arxiv.org/abs/2611.33005) 按「对未来回答的效用」组织记忆，[MIMPA](https://arxiv.org/abs/2611.31307) 则指出共享记忆本身是攻击面。
- 系统侧：[LoomKV](https://arxiv.org/abs/2611.32954)、Mayfly、LaFlash 围绕 agent 工作负载做 KV cache 无损压缩与 HBF 闪存管理。

## 一、🔥 热度榜：Agent Context 精选

### [Embo-Harness: Towards Understanding Frontier-Model-as-Policy Harness](https://arxiv.org/abs/2611.31201)
- 热度：HF 👍103（入榜 1 天，新增 +15）；无 X 数据；代码 [DravenALG/Embo-Harness](https://github.com/DravenALG/Embo-Harness) ⭐65
- 问题：前沿模型直接当机器人策略时，harness 该怎么设计、哪些能力在起作用，目前不清楚。
- 方法：把机器人 agent 循环拆成 prompting、planning、动作执行、工具使用四部分，得出 6 条经验结论并整理成配方。配方主张优先利用模型原生的视觉推理和工具使用，少用手写的计划、技能或动作先验；同时给出动作表示、分块、推理强度、视觉观察、短多动作序列、策略精修等选择。
- 结论/意义：RoboLab-120 上成功率 83.3%，比最强已报告基线高 26.2 个百分点；4 个真实任务的 20 次零样本试验成功 15 次。干预实验显示，模型依赖准确的空间目标估计，对低层关节/轨迹生成的依赖较小。

### [AutoPILOT: A Visual Agent Harness for Real-Time Gameplay](https://arxiv.org/abs/2611.28202)
- 热度：HF 👍34（入榜 1 天，新增 +4）；无代码数据
- 问题：游戏不暂停时，harness 让每次模型调用至多产生一个动作，agent 的动作频率被模型思考速度限制。
- 方法：harness 决定模型看什么、记什么、输出如何变成动作，AutoPILOT 改的是第三项。每次调用中，模型可以发原语动作、启动开环宏，或写一个闭环控制器，让它按屏幕画面自行持续运行，不再调用模型，直到交还控制权。
- 结论/意义：在 AFK-Bench（120 个浏览器游戏）上，GPT-6.1 Sol 的实时成功率为 68.6%，VISTA 为 38.3%；达到 VISTA 的最终成功率，只需其 1/5 的 API 成本。

### [Context Has a Price: Adding and Removing Context for LLM Coding Agents under Prefix Caching](https://arxiv.org/abs/2611.22238)
- 热度：仅 arXiv（HF 👍0，入榜 7 天）；无 X、无代码数据
- 问题：给 coding agent 加检索代码，或删旧工具输出，是否真的降低任务成本。
- 方法：在 SWE-bench Verified、SWE-bench、Loc-Bench 上用开源模型跑 20,000+ 次，把未缓存输入、缓存输入、输出 token 分开计费。
- 结论/意义：检索代码使读/搜命令减少 18–34%，但缓存价为未缓存价 1/10 时，成本反而增加 33–42%，解决率无可测提升。删旧观察在无缓存折扣时省 19–36%，在 1/10 缓存价下成本增加 38–116%。更短的 prompt 可能让 agent 多走步数；并发实验中共享缓存前缀会扭曲成本比较。

### [Stopping Is Not the Limit: Understanding and Eliciting Agent Capability in Long-Horizon Vulnerability Exploitation](https://arxiv.org/abs/2611.22888)
- 热度：仅 arXiv（HF 👍0，入榜 7 天）；无 X、无代码数据
- 问题：漏洞利用 agent 常在预算没用完时就停止，停止之后继续执行是否还有收益。
- 方法：在 ExploitBench 上发现停止后继续仍有增益，但逐步递减；产出更少的继续执行有两个特征：同一上下文里停止回复的占比上升，摘要里保留了「某能力不可能实现」的判断。据此提出 SCoRe：连续停止时压缩上下文，并把这些判断标为「未证实」。
- 结论/意义：MiMo 在 2,000 轮达到能力覆盖 67.0%，原停止策略下为 32.4%；据 ExploitBench 300 轮参考结果算出的 GPT-5.5 为 58.6%。

### [When Agent Skills Go Stale: Runtime Behavior and Selective Maintenance in Evolving Environments](https://arxiv.org/abs/2611.22525)
- 热度：仅 arXiv（HF 👍0，入榜 7 天）；无 X、无代码数据
- 问题：环境变化后，原先有用的 skill 状态部分过时，继续复用可能有害。
- 方法：在 4 个任务设定、2 个模型下，比较环境变化前后复用 skill 的效果。提出 selective maintenance：不额外调用模型，重放成功执行中的检查，验证差异是否与 skill 状态冲突，修复受影响内容并验证，局部修复不够时重建；全程不告诉系统变化是什么。
- 结论/意义：过时 skill 可使任务表现下降超过 10 个百分点，或使执行成本比无 skill 时增加近 40%；相对复用过时状态，维护最多提高准确率 67pp，最多减少 37% 的执行步数。

### [MMMem: Self-Improving Agents with Task-Aware Multimodal Experience Consolidation](https://arxiv.org/abs/2611.30287)
- 热度：HF 👍10（入榜 1 天，新增 +9）；无 X 数据；代码 [ChenYX24/MMMem](https://github.com/ChenYX24/MMMem) ⭐0
- 问题：现有多模态记忆只存取记录，不从已完成的任务中沉淀经验。
- 方法：多视图记忆把原文本、图像、渲染页与「合成线索的场景图」放在一起检索。先用源生成任务做 warm-up（把源知识整合成外部记忆经验）和 self-training（让参数知识适应任务）；VLM 再把完成的任务蒸馏成含任务上下文、结论、支撑链接的经验；检索时按任务召回源视图和经验。
- 结论/意义：Qwen3.5-9B 上，LoCoMo、Mem-Gallery、LooGLE v2 相对最佳基线分别提升 36.9%、17.6%、15.2%。

### [MORSE: Optimizing Streaming Memory Design via Open-World Auto-Research](https://arxiv.org/abs/2611.30011)
- 热度：HF 👍4（入榜 1 天，新增 +2）；无 X、无代码数据
- 问题：流式视频系统帧存储有限，又不知道未来会问什么，要决定保留哪些证据。
- 方法：editor 把训练轨迹里的失败按原因分组，再检索论文、模型卡和代码，寻找可改造的方法或预训练感知模型；引入新感知能力时，同时修改 harness 的存储与检索方式。先选提升答案质量的修订，再在容差内找更快的。
- 结论/意义：OVO-Bench 上，Qwen3-VL-8B harness 平均 0.30 秒答题、准确率 75.1%，比同一冻结骨干下次优的 harness 高 3.1 个百分点。

## 四、🆕 New：昨晚新公布

- [Lazy Agents Answer Against Their Own Beliefs (RLVB)](https://arxiv.org/abs/2611.32884)：用模拟器算出的精确后验给奖励，证据不足时鼓励继续探索，充分时才提交答案；九个设定全部优于基础模型，平均 +17.1%（初步 👍85）。
- [Don't Sleep, Keep Watch: Proactive Perception for Computer-Use Agents](https://arxiv.org/abs/2611.28947)：NightWatch 用 0.8B 的 System-1 模型持续监控界面，OSWorld 上非推理耗时减少 33%、浪费时间减少 53%，任务成功率持平（初步 👍83）。
- [ACAP: Asynchronous Coding Agents for Efficient Robot Control](https://arxiv.org/abs/2611.31205)：把一个机器人交给一组持久运行的 coding agent，各管一个控制组，由 hyper-agent 协调；真实 72 次 rollout 的任务均衡耗时比单 agent 少 28.2%（初步 👍60）。
- [Self-Evolving Evaluation Environments for Computer-Use Agents](https://arxiv.org/abs/2611.30962)：CUA-SEE 根据 rollout 证据共同演化任务与可执行验证器，针对静态基准区分度下降的问题（初步 👍44）。
- [RECAP: Training Long-horizon LLM Agents with Context Compaction](https://arxiv.org/abs/2611.31258)：用 RL 联合训练压缩与策略，原则是摘要应保留原历史所诱导的行为；Qwen3.5-4B 上 BrowseComp-plus +4.6%、SWE-bench Verified +4.3%（初步 👍1）。
- [Leto: Utility-Centric Agent Memory](https://arxiv.org/abs/2611.33005)：把记忆当作预测问题，用索引保留细节，回放预判所需的上下文，并根据响应结果迭代选择；PrefEval 上比最强记忆系统高 16.3 个百分点。
- [LoomKV: Lossless KV Cache Compression from GPU Memory to SSD](https://arxiv.org/abs/2611.32954)：对 KV 做无损压缩（BF16 存为原大小的 0.71），在 AgentX 上使压缩层等效于大 1.4 倍的原始层，goodput 提升 2.7–3.6x。
- [Bathys: Advancing Deep Search Agents](https://arxiv.org/abs/2611.32660)：9B/27B 深度搜索 agent，在上下文压缩下做在线 RL（CM-GSPO），BrowseComp 分别为 66.51% 和 80.49%（评测协议含自验证与条件重试）。
- [VISE: Verifier-Independent Skill Self-Evolution](https://arxiv.org/abs/2611.32480)：从工具实现源码出发修订 SKILL.md，不需要任务验证器；SkillsBench 和 SkillLearnBench 上平均成功率提升 9.14–13.35 个百分点。
- [VideoJSON: A Minimal Harness Beats Purpose-Built Memory for Ultra-Long Video Understanding](https://arxiv.org/abs/2611.28167)：每分钟视频存成一条 JSON 记录，让 coding agent 写 Python/Bash 做检索；EgoLifeQA 等基准上超过 MAGIC-Video 7.0–24.75 分（初步 👍8）。
- [EvoViM: Recursively Self-Evolving Visual Agents for Exploration with Deferred Queries](https://arxiv.org/abs/2611.28574)：冻结模型把自身交互经验改写成一个管理记忆与技能的视觉程序；六个任务上比 AutoMem 平均高 31.3–47.6 分（初步 👍1）。
- [When Successful Collaboration Becomes an Attack Surface: Insider Memory Poisoning (MIMPA)](https://arxiv.org/abs/2611.31307)：内部恶意 agent 仅凭正常参与权限，让带毒载荷留在成功的协作记录里，之后误导其他 agent；论文称审计只能部分缓解。

## 五、研究趋势观察

- 热度集中在 harness，也就是上下文之外的那段循环：[Embo-Harness](https://arxiv.org/abs/2611.31201)（👍103）和 [AutoPILOT](https://arxiv.org/abs/2611.28202)（👍34）都用对照实验说明，换接口或换动作产出方式带来的收益很大。[RUIBench](https://arxiv.org/abs/2611.31115) 只换接口，成功率就从 45% 变到 81%。
- 上下文管理开始被量化评估：[Context Has a Price](https://arxiv.org/abs/2611.22238) 测成本，[Stopping Is Not the Limit](https://arxiv.org/abs/2611.22888) 测继续执行的收益，[RECAP](https://arxiv.org/abs/2611.31258) 与 [Bathys](https://arxiv.org/abs/2611.32660) 把压缩放进 RL 训练。这个方向在 New 里继续出现。
- 记忆与 skill 的维护：[When Agent Skills Go Stale](https://arxiv.org/abs/2611.22525)、[VISE](https://arxiv.org/abs/2611.32480)、[MMMem](https://arxiv.org/abs/2611.30287)、[Leto](https://arxiv.org/abs/2611.33005) 处理的都是存下来的经验会过时、未必有用的问题；[MIMPA](https://arxiv.org/abs/2611.31307) 从攻击角度指出共享记忆的风险。
- 与工程侧的呼应：[LoomKV](https://arxiv.org/abs/2611.32954)、Mayfly、LaFlash 针对 agent 的前缀复用与 KV 保留做系统优化，与 Context Has a Price 里缓存价格决定策略优劣的结论互相印证。数据里没有对应的 GitHub 项目热度，不做更多推断。
