## 热度榜：Agent Context 精选

### [Δτ-Bench: Pushing Agents Toward a Moving Capability](https://arxiv.org/abs/2610.34238)
- 热度：HF 👍28（入榜 3 天，新增 +8）；代码 [zjunlp/delta-tau-bench](https://github.com/zjunlp/delta-tau-bench)，5 星
- 问题：工具生态会演化，工具消失、被替换，或出现更高效的替代，已习得的技能和流程性知识随之过时。
- 方法：基准包含 1,588 个已验证的多轮任务、42 个领域、6 个先后出现的生态状态。作者提出 Steward 生态管理器，在执行过程中增量维护 skill，并动态提供工具。
- 结论/意义：最强模型或 harness 的任务成功率只有 42.3%，现有 skill 学习方法的初期收益未必能在生态变化中持续；Steward 在生态变化下成功率更高，skill 维护开销更低。

### [Evolving to Match Capabilities: Improving Harness Self-Evolution via Skill Adaptation](https://arxiv.org/abs/2610.33024)
- 热度：HF 👍32（入榜 3 天，新增 +21）；代码 [zhihaoyang30/skill-adaptation-code](https://github.com/zhihaoyang30/skill-adaptation-code)，6 星
- 问题：同一个 skill 对强模型有益，对弱模型可能有害。
- 方法：在 7 个模型、3 个基准上找到 103 个 task-skill 对，其中 skill 让 GPT-5.6-luna 提升 31.1 分，却让 Gemma-4-E4B 下降 8.8 分；弱模型失败的运行里，86% 的违反项其实已经写在 skill 中。作者把失败归为工具执行、上下文管理、指令遵循、验证四类，蒸馏成固定的 meta-skill，在自进化循环中改写 skill 以适配执行者的能力。
- 结论/意义：外部改写器 Kimi-K3 让 3 个弱执行者比原 skill 提升 5.1–14.1 分；再加五轮自进化，meta-skill 让 7 个执行者的最终分数又提升 2.0–5.1 分。

### [DLite: History-free Speculative Decoding for Agentic AI](https://arxiv.org/abs/2610.23787)
- 热度：HF 👍36（入榜 7 天，新增 +3）；代码 [SJTU-DAI-Sys/DLite](https://github.com/SJTU-DAI-Sys/DLite)，49 星
- 问题：Agent 的长上下文和多轮交互下，现有 draft 模型的接受长度最多下降 80%，而保存历史 KV cache 又带来系统开销。
- 方法：不维护历史上下文，直接复用目标模型的上下文隐藏状态做局部投机预测，再用轻量的顺序头恢复块内因果依赖，配合两阶段训练。
- 结论/意义：接受长度达到 2–6，最多比最先进方法 DSpark 高 70%。

### [Build, Don't Play: Self-Improving LLM Research Agents Develop a Hearthstone Battlegrounds AI (AutoTavern)](https://arxiv.org/abs/2610.33845)
- 热度：HF 👍26（入榜 3 天，新增 +18）；代码 [MCG-NJU/AutoTavern](https://github.com/MCG-NJU/AutoTavern)，165 星
- 问题：LLM Agent 能否把一个复杂的真实问题，从原始数据一路做成能与人类高手竞争的系统。
- 方法：多个专门的研究 Agent 共享一份带类型的「研究记忆」（typed research memory），每条结论都要过验证关口，实战对局的结果再反馈回来。Agent 据此改进模拟器、对手和策略，也改进自己的研究流程，人类只设定目标和规则。
- 结论/意义：20 天内造出 TavernGym 和 23 个版本的 TavernAgent，天梯评分从 6,000 升到约 15,000；最近 20 局平均名次 1.60、首位率 80%，优于服务器前十名玩家的 2.34 和 59%。

### [DeltaStreamer: Towards Human-Like Agentic Streaming Video Understanding](https://arxiv.org/abs/2610.19849)
- 热度：HF 👍38（入榜 7 天，新增 0）；代码 [BBBBchan/DeltaStreamer](https://github.com/BBBBchan/DeltaStreamer)，87 星
- 问题：流式视频要在不知道未来问题的情况下保留证据，压缩历史会模糊事件转换、丢失细节，且无法找回。
- 方法：提问前持续观察视频流，把视觉变化显式写入结构化的变化感知记忆；提问时由查询驱动的规划器决定需要什么证据，指导记忆检索和对历史帧的定向回放。
- 结论/意义：在 OVO-Bench 和 StreamingBench 上总分分别为 66.07% 和 59.53%，优于代表性的流式方法。

## New：昨晚新公布

- [Don't Lose the Thread: Empowering Long-Horizon LLM Agents with Cognitive Resource Self-Allocation](https://arxiv.org/abs/2610.40350)（CORAL）：给 Agent 一个可调用的工作记忆工具，先存档进度和已验证事实，再重置杂乱的上下文开启新回合；GAIA 上 8B 模型得 42.8%，输入 token 比 ReAct 少 6–7 倍。
- [MemSteer: Turning User Histories into Supervision for Agent Memory Optimization](https://arxiv.org/abs/2610.39276)：把无标注的用户历史变成带证据的 QA 监督，用来优化记忆的存储、检索和上下文构建；ATM-Bench Question Score 比 Base-BM25 高 13.4 分。
- [MUSE: Multi-Level Memory with Selective Runtime Injection for Scientific Coding Agents](https://arxiv.org/abs/2610.38332)：从历史轨迹构建全局、方法级、实现级三层记忆，执行时由 LLM 门控决定注入经验还是跳过；4 个基准全部优于检索和记忆基线。代码 [hr-jin/MUSE](https://github.com/hr-jin/MUSE)。
- [Context Compaction for World Models](https://arxiv.org/abs/2610.38980)：把 Agent harness 里的上下文压缩用到世界模型上，无需重训即可检索到上下文窗口 4 倍之外的房间。
- [FlatCake: A Flat KVCache Storage Architecture for LLM Serving](https://arxiv.org/abs/2610.38355)：把 DRAM 与 NVMe 当作对等介质的 KV cache 存储架构；在真实 Claude Code 轨迹（DeepSeek-V4-Flash）上缓存命中率保持 94%（Mooncake 为 64%），峰值负载下平均 TTFT 降低 1.6 倍。
- [HEDGE: Gated Hypergraph Memory for Scalable Multi-Agent Debate](https://arxiv.org/abs/2610.38902)：用语义超图存储辩论轨迹，由学习得到的选择模块决定存储、备份还是丢弃；平均准确率提高 5.0 分，记忆用量减少 48%，辩论轮数减少 34%。
- [Compile Away Uncertainty: Self-Evolving Agent Skills via Programmatic Compilation](https://arxiv.org/abs/2610.39508)（SkillCompiler）：把 skill 里明确的操作编译成经过验证的程序并复用，需要上下文判断的部分仍交给 LLM；任务表现最多提升 32.33%。
- [Before the Next Rollout: Diagnosing Skill Utility Shifts from Policy Updates](https://arxiv.org/abs/2610.39358)：策略更新会改变同一个 skill 的边际效用，用策略更新信号做诊断来指导 skill 进化，同时减少 token 消耗。
- [When Skills Tell Agents Not to Ask: A Large-Scale Study of Oversight Directives in Agent Skills](https://arxiv.org/abs/2610.37734)：分析 153 万个 skill，约每 17 个中有 1 个（约 88,000 个）含有放松监督的指令，例如 `--no-verify`；开源扫描器最多只能抓到 46%。
- [Selective and Hybrid-State Communication for Latent Multi-Agent Systems](https://arxiv.org/abs/2610.37779)：多 Agent 之间通过 KV 状态通信；SelectKV 减少约 9.7–9.9% 的传输 KV 位置，HyLaMAS 同时传 KV 和循环状态，解码 token 减少 53–80%。
- [Finding Is Not Returning, Returning Is Not Reconstructing: A Multi-Dimensional Evaluation of Agent Social Re-entry](https://arxiv.org/abs/2610.39781)：把 Agent 回到旧对话拆成找到、回去、重建上下文三项来评测；持久记忆提高了主动回复率，但没有带来一致的上下文重建增益。
- [Beyond LLM Wrappers: Context Engineering and the Three-Engine Architecture for Reliable Financial AI](https://arxiv.org/abs/2610.39230)：知识图谱、确定性优化引擎加多 Agent LLM 层的架构，其中的「上下文工程」负责上下文的选取、排序、组合和验证；据 15 个部署约 11 个月的观察，幻觉率从约 7–9% 降到 1% 以下（作者强调这是观察性结论，不是因果结论）。

## 研究趋势观察

- Skill 与 harness 的维护，问题已从怎么写 skill 转向怎么让它适配、不过时：[zjunlp/delta-tau-bench](https://github.com/zjunlp/delta-tau-bench) 处理生态变动，[zhihaoyang30/skill-adaptation-code](https://github.com/zhihaoyang30/skill-adaptation-code) 处理模型能力差异，New 里的 SkillCompiler 与 Skill utility shifts 又从编译和策略更新两个角度切入。
- 长程任务的上下文管理分训练侧和推理侧：训练侧有 [LARK-AI-Lab/Mosaic](https://github.com/LARK-AI-Lab/Mosaic)（rising），把压缩和分叉当作多会话 RL 来训；推理侧有 New 里的 CORAL，让 Agent 自己存档、重置。FlatCake 与 [SJTU-DAI-Sys/DLite](https://github.com/SJTU-DAI-Sys/DLite) 则从服务系统角度处理 agentic 长上下文的 KV cache 与投机解码。
- GitHub 星数较高的有 [InternLM/Intern-Decision](https://github.com/InternLM/Intern-Decision)（775）、[Tongyi-MAI/OpenGCUA](https://github.com/Tongyi-MAI/OpenGCUA)（441）、[zgcagi/Harness-RSI](https://github.com/zgcagi/Harness-RSI)（387）、[BinceQu/RoboHarness](https://github.com/BinceQu/RoboHarness)（279）、[MCG-NJU/AutoTavern](https://github.com/MCG-NJU/AutoTavern)（165），主题是 harness、决策分工和计算机使用，与论文热度集中的方向大致一致。
