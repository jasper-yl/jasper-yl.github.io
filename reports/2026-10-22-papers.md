# Agent & Agent Context 论文日报 · 2026-10-22

## 今日要点

- **KV cache 成为 Agent 的可控资源**：Cache Engineering（AKV）让 Agent 直接 drop/repos 活跃 KV，不改前缀也不重新 prefill；MemT-1.0 则把记忆做进模型内部，128K 历史下存储降 66 倍。
- **Harness 是今日最热的词**：OpenVLHarness、CoEvo-RSI、Self-HPO、HarnessPro、Harness Scaling 等多篇围绕"Harness 自进化 / 与模型共进化"，但 Harness-Delta Attribution 指出其收益有相当比例来自过拟合。
- **记忆研究转向"该存什么、该忘什么"**：REM、TokenWorth、Anti-Persistence、MemoryTax 都在质疑"记得越多越好"，强调选择性存储与按需重建。
- **上下文管理的安全与失效面被暴露**：Compaction Laundering 显示压缩时展平角色标签会让伪造的用户指令"洗"进记忆；另有研究显示 harness 的截断、检索选择会直接决定成败。
- **环境合成与评测继续扩张**：WildAWM、CoworkEnv、Interlock 做训练环境合成，AdaExploreBench、MMEnterprise-Bench 等补充评测基准。

## 一、Agent Context 论文精选

### [Cache Engineering for Agents](https://arxiv.org/abs/2610.28577)
- 热度：HF 👍107；代码：https://github.com/thu-nics/AKV
- 问题：Agent 轨迹变长后 KV cache 的 I/O 与存储成为主要开销，而传统的裁剪/摘要会改动前缀，使后续缓存失效并触发昂贵的重新 prefill。
- 方法：提出"cache engineering"，让 Agent 用 drop 将选定缓存排除出后续注意力，用 repos 调整保留 key 的位置编码，全程不修改轨迹、不重新 prefill。并配套设计 AKV 服务引擎：对外保持无状态接口，对内管理有状态的缓存复用、驱逐与恢复（因同一 token 序列在不同缓存操作序列下状态不同，前缀匹配不再足够）。
- 结论/意义：工具响应滚动 drop 策略比阈值触发摘要平均提升 1.7 分、成本降低 27.7%；AKV 最高带来 1.2 倍吞吐和 1.5 倍 P95 延迟加速。

### [MemT-1.0: Towards Memory-Native Evolution](https://arxiv.org/abs/2610.26825)
- 热度：HF 👍132；代码：https://github.com/MemTensor/MemT-1.0
- 问题：外部记忆多为被动检索，希望让记忆成为基础模型自身的内在能力。
- 方法：基于 Gated DeltaNet-2 在每一轮内做稳定的 token 级记忆更新，并用 Mixture-of-Storage 扩展原生记忆容量；经 34B token 的持续预训练 + 后训练，发布 Nano 与 Flash 两个模型。
- 结论/意义：效果优于参数化记忆基线、与检索增强方法相当；128K 历史下相对完整 KV cache，端到端推理加速约 1.86 倍，持久存储减少 66 倍，并能提升 Agent 任务成功率。

### [OpenVLHarness: Real World Visual Agentic Tool-Use with Multimodal Memory](https://arxiv.org/abs/2610.26860)
- 热度：HF 👍111；代码：https://github.com/uclanlp/OpenVLHarness
- 问题：视觉推理任务需要异构工具产出的证据，且这些证据要在多步推理中被保留并可解读。
- 方法：构建能力层（任务级工具接口 + 证据渲染，把工具输出转成模型可读观察）与持久多模态记忆（图像、结构化数据、网页引用作为可寻址 artifact 保存），再用代码接口对存储数据做跨工具计算。
- 结论/意义：在 22 个基准上比同骨干无工具基线平均提升 9.7–12.6 分；GPT-6 Luna 中等推理强度下，以不超过 37% 的 token 成本超过其它方案的最高强度设置 7.7–8.5 分。

### [FlowState: Execution State as Memory for Long-Horizon LLM Agents](https://arxiv.org/abs/2609.34565)
- 热度：HF 👍15
- 问题：保留完整历史成本高，压缩又会丢失之后才显现相关性的细节。
- 方法：把执行状态当作记忆，保存带语义类型的状态节点、关系及指向原始工具观察的引用，将持久保留与按需访问分离；Incremental State Update 维护当前状态，Progressive State Access 在推理中逐步展开历史状态与证据。
- 结论/意义：相对同模型（DeepSeek-V4-Flash）全上下文基线，MemoryArena 成功率 +4.55、τ³-Bench 通过率 +13.95 个百分点，总 token 消耗分别降低 43.2% 和 40.6%。

### [REM: What to Store, When to Recall, What to Forget in Experience Memory for Coding Agents](https://arxiv.org/abs/2610.27377)
- 热度：仅 arXiv
- 问题：现有记忆系统只关注检索，无法观察运行中的 Agent，不知道它是否需要经验、何时需要、需要多久。
- 方法：在 Agent 的思考-行动循环内管理记忆生命周期：把轨迹整合为小两个数量级的分阶段文档（存什么）；任务开始注入文档，更昂贵的实现记录仅在门控检测到 Agent 卡住时才注入（何时召回）；记录单次曝光后即驱逐（忘什么）。
- 结论/意义：在 SWE-ContextBench Lite 上 match@1 为 68.7%（对比 55.6%），解决率 27.6% 对 24.9%，成本低 17%；消融任一决策都会降低解决率。

### [Compaction Laundering: Provenance Destruction in Context-Compacting Coding Agents](https://arxiv.org/abs/2610.29869)
- 热度：仅 arXiv
- 问题：编码 Agent 压缩上下文时若把类型化对话展平成纯字符串，消息来源信息就在摘要前被丢失。
- 方法：在五个展平式 harness（pi、opencode、Cline、Aider、OpenHands）上，攻击者通过 Agent 读取的内容伪造用户回合，使伪造的批准经压缩"洗"成真实指令；对照四个保留角色类型的 harness（Codex、Gemini CLI、Qwen Code、Continue）。
- 结论/意义：展平式 harness 的洗入率为 87–100%，角色类型化 harness 为 0%；代码层的来源检查可拦截 77% 而仅误降级 2% 的合法摘要内容，根本修复是在序列化时转义角色标签。

### [MemoryTax: The Bitter Lesson of Agent Memory](https://arxiv.org/abs/2610.29823)
- 热度：仅 arXiv
- 问题：当模型强到能自己搜索历史时，Mem0、Zep 这类预先设计的记忆还有价值吗？
- 方法：在一段 LoCoMo 对话上比较四种记忆方法（全上下文、BM25、Mem0、Zep）与三种编码 Agent（Pi、Codex、Claude Code），配合三种模型并记录每次 rollout 的成本。
- 结论/意义：设计型记忆更像是弱模型的补丁；其上限由写入记忆的模型决定。强模型下 Pi 以不到全上下文一半的成本达到 99%。注意作者说明这是单对话、每格一次运行的小规模研究。

### [Same Simulation, Different Evidence: Where Retrieved Tool Output Costs LLM Agents Accuracy](https://arxiv.org/abs/2610.26836)
- 热度：仅 arXiv
- 问题：harness 把长工具输出存成文件、让 Agent 按需检索，这会在哪里损失准确率？
- 方法：以 PHREEQC 地球化学模拟器（报告长达 846.8k 字符）和 158 道可执行验证的题目，对比 Agent 通过章节索引读取与上下文内直接读取。
- 结论/意义：GPT-5.1/5.2 通过检索读取分别损失 11.3 和 7.9 分，Claude Opus 4.6/Sonnet 4.6 无明显损失；原因是"证据替代"（跳过报告，改用自己精度更高的输出文件作答）。明确指出权威输出可提升 6.3–7.9 分。

### [More Memory, Worse Agents: Error Reproduction and Anti-Persistence in LLM Agents](https://arxiv.org/abs/2610.27406)
- 热度：HF 👍8
- 问题：存储的规则/摘要/技能中的错误会经抽象-执行-再抽象的循环被反复再生。
- 方法：提出 Anti-Persistence：只累积轨迹与结果，任务相关的指导按需重建，由自适应选择器依据过往结果决定是否及如何合成，用后即弃。
- 结论/意义：在多个基准与骨干上，held-out 成功率更高，且 LLM 调用成本是被比较记忆设计中最低的。

### [When the harness decides success: state that cannot be re-observed](https://arxiv.org/abs/2610.26632)
- 热度：仅 arXiv
- 问题：harness 丢弃/摘要旧回合或重放推理，何时真正改变成败而非只改变成本？
- 方法：预注册的合成探针中截断上下文窗口；在 ARC-AGI-3 上逐组件分解 Standard 与 Provider Adapter 两种 harness 的差距。
- 结论/意义：事实可重新查询时截断几乎无代价，不可重新观察时降到随机水平，两者相差 92.5 个百分点；用摘要替代丢弃并保留记笔记提示可弥补 63 分差距的 86%。作者说明 ARC-AGI-3 部分为单次运行的点估计。

## 二、Agent 方向热门论文

- [CoEvo-RSI: When Harnesses Evolve, Which Models Should Follow?](https://arxiv.org/abs/2610.25078) — HF 👍110 — 用共享演化档案做模型与 harness 的双向历史继承，仅用 SFT 让 Qwen3.5-9B 在多个垂直任务上比肩更大模型。
- [Sage-A1.5](https://arxiv.org/abs/2610.28578) — HF 👍68 — 35B MoE Agent 模型，支持隔离上下文的子 Agent 并行协作、验证与开放科学发现。
- [WildAWM：Computer-Use Agent Environment Synthesis](https://arxiv.org/abs/2610.26828) — HF 👍62 — 用开源模型合成支持 GUI/MCP/CLI 的 341 个长程环境-任务对，训练的 Qwen 模型在 8 个 OOD 基准上均有提升。
- [Self-HPO：Self-Evolving Coding Agents via Harness-Policy Optimization](https://arxiv.org/abs/2610.22791) — HF 👍54 — 交替优化 harness 与策略，Qwen3.5-35B-A3B 平均解决率从 57.8% 升到 64.8%。
- [CoworkEnv](https://arxiv.org/abs/2610.24960) — HF 👍50 — 为 AI 同事合成可执行训练环境，Qwen3-VL-8B 经 SFT 在 Claw-Eval 上从 46.6 升到 64.1。
- [Evolving Agent Interfaces（Agent S4）](https://arxiv.org/abs/2610.28601) — HF 👍21 — 元 Agent 从任务经验中演化接口与用法知识，Qwen3.8-27B 在 OSWorld V2 达 21.3%，为固定接口的 3.8 倍。
- [AdaExploreBench](https://arxiv.org/abs/2610.25950) — HF 👍33 — 测试隐藏规则漂移下的主动探索与测试时适应，最强模型校准准确率仅 61.9%。
- [Harness-Delta Attribution](https://arxiv.org/abs/2610.22466) — HF 👍5 — 21 个显著设置中，过拟合与测试时扩展平均分别解释 54% 与 14% 的 harness 演化收益。
- [Harness Scaling for Generalizable Agentic RL](https://arxiv.org/abs/2610.29458) — HF 👍15 — 把训练从单一 harness 扩展到多样化配置，提升对未见 harness 的泛化。
- [MMEnterprise-Bench](https://arxiv.org/abs/2610.27911) — HF 👍29 — 1,613 题的企业多模态演化记录基准，提高检索预算能提升召回但不一定提升答案准确率。

## 三、研究趋势观察

1. **记忆与上下文管理从"怎么存"转向"该不该存、何时用"**。REM、TokenWorth（学习"值得记住"的经验）、Anti-Persistence、MemoryTax，以及 Uni-Mem、Memory as Code、MHG-Mem 等 LoCoMo/LongMemEval 类工作，共同关注选择性、按需和结构化；同时多篇实证（MemoryTax、Same Simulation、harness decides success）表明，harness 的上下文处理选择会直接决定结果。
2. **Harness 同时是优化对象和风险来源**。一边是 harness 自进化/共进化（CoEvo-RSI、Self-HPO、HarnessPro、RiseHarness、HarnessAdapt-RL）；另一边是归因研究（HDA）提示收益可能被高估，Compaction Laundering、ClawMMU、AutoRedClaw 则揭示压缩、记忆和持久配置里的信任边界问题。
3. **缓存层面的上下文控制开始系统化**。Cache Engineering 与 MemT-1.0 分别从服务端与模型内部降低长历史开销，Weighted State Souping 则用可缓存的状态片段组合上下文；与摘要/裁剪等应用层手段形成对照。
4. **工程侧呼应**：数据中大量论文附带 GitHub 仓库，其中 Sage-A1.5（577 星）、MemT-1.0（301 星）、OpenVLHarness（188 星）关注度较高，说明 harness、记忆与 Agent 模型是当前开源社区的活跃方向（星数仅反映数据快照，不代表质量）。
