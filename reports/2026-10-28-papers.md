## 🔥 热度榜：Agent Context 精选

### [Trial by Trace: Benchmarking AI Agent Harnesses for Reliability and Failure Attribution](https://arxiv.org/abs/2610.32285)
- 热度：HF 👍291（入榜 1 天，新增 +128，首见时 163）；无 X 提及；代码 [TraceLite-AI/TraceTrial-Bench](https://github.com/TraceLite-AI/TraceTrial-Bench) ★21
- 问题：现有基准评的是模型，很少评 agent harness 本身。
- 方法：TraceTrial-Bench 把 harness 可靠性拆成 7 个组件：context、execution、governance、lifecycle、observability、tools、verification。共 95 个任务，配轨迹追踪（TT）模块和 MEA 模块；MEA 从 agent 上下文、harness、执行环境三处取证，再由失败归因（FA）模块做 run 级归因。
- 结论/意义：4 个 harness、9 个模型、3,420 次运行，harness 宏平均分 59.8%–72.0%；31.1% 的运行任务成功，但至少违反一条 harness 标准。

### [Is Complex Agentic Memory Always Needed? Naive RAG Is Stronger Than We Thought](https://arxiv.org/abs/2610.30755)
- 热度：HF 👍38（入榜 5 天，新增 +24，首见时 14）；X 提及 1 次，[@omarsar0 的推文](https://x.com/omarsar0/status/2113635562578178147) ❤896；代码 [Litmeb/RAW-RAG](https://github.com/Litmeb/RAW-RAG) ★33
- 问题：改写、结构化、学习式检索这类复杂的 agentic memory 是否真有必要。
- 方法：Raw-RAG 只对原始历史做稠密检索加重排，再交给 reader LLM，在 LoCoMo、LongMemEval、MEME、MemoryAgentBench 上比较。证据分析显示，它对必要证据的覆盖更高，可以抵消利用率较低的劣势；经过转换的记忆库即使完整可访问，准确率仍低于原始证据。
- 结论/意义：7 个「基准-模型」设置中 6 个排第一，领先最强对比系统 0.13–5.53 分。

### [Memory-Centric Continual Learning for AI Agents](https://arxiv.org/abs/2610.29357)
- 热度：HF 👍43（入榜 6 天，新增 +24，首见时 19）；无代码，无 X 提及
- 问题：外部记忆多被当作被动的检索缓存，能否真正带来持续学习并不清楚。
- 方法：提出 MCCL。三轴分类按存储位置（substrates）、形态（assets）、管理策略（policies）划分；生命周期分内外两层，内环更新记忆，外环按任务反馈改进管理策略。评测协议覆盖干扰下的保留、对变化的适应和任务迁移，另附一个记忆规模化框架。
- 结论/意义：主张评价记忆要看它是否改善未来行动，而不只看检索。

### [MemPilot: Orchestrating On-Demand Multimodal Memory Curation for LLM Agents](https://arxiv.org/abs/2610.06830)
- 热度：HF 👍41（入榜 6 天，新增 +5）；代码 [ViktorAxelsen/MemPilot](https://github.com/ViktorAxelsen/MemPilot) ★7
- 问题：多数记忆系统与 query 无关地预先构建，既浪费预处理，又可能丢掉后来才变重要的细节。
- 方法：用强化学习训练一个多步 LLM 策略，在「从 query-agnostic 记忆中检索」和「把针对 query 的原始多模态历史整理委托给不同 LLM/VLM」之间选择，同时控制证据量、整理指令、模型选择和视觉访问。训练上按目标分别估计 advantage，并做前缀边际效用估计。
- 结论/意义：在 5 个多模态记忆基准上，不同偏好下的性能-成本-延迟前沿，比现有的权衡感知基线更宽。

### [StreamVibe: Proactive Video Agents for Evolving User Intent](https://arxiv.org/abs/2610.34662)
- 热度：HF 👍253（入榜 1 天，新增 +22）；无代码，无 X 提及
- 问题：现有模型依赖显式请求，漏掉隐含意图，也无法随用户请求变化更新状态。
- 方法：StreamVibe-Harness 把用户意图保存为持久状态，生命周期灵活，并用分层记忆跟踪最新的用户意图和环境状态。配套 StreamVibe-Bench（4.1K 评测样本、85K 训练样本）和流式模型 StreamVibe-VL。
- 结论/意义：StreamVibe-VL 的响应时机与回答质量比其他基线好 10.7%；加上 Harness 后主动交互提升 12.3%。

### [DeltaStreamer: Towards Human-Like Agentic Streaming Video Understanding](https://arxiv.org/abs/2610.19849)
- 热度：HF 👍38（入榜 5 天，新增 +0）；代码 [BBBBchan/DeltaStreamer](https://github.com/BBBBchan/DeltaStreamer) ★87
- 问题：流式视频要在不知道未来问题的情况下保留证据，压缩历史又会模糊事件转折，细节也无法找回。
- 方法：query 到来前持续观察，把视觉变化显式记入结构化记忆（change-aware memory）。query 到来后，规划器确定所需证据，引导记忆检索和对历史帧的定向回放（replay）。
- 结论/意义：OVO-Bench 66.07%，StreamingBench 59.53%。

## 🆕 New：昨晚新公布

- [The Trinity](https://arxiv.org/abs/2610.36077)：Creator、Explorer、Evolver 三个角色把任务组织成能力树，沿树演化 harness 模块，并配一个能力感知路由器；28 个训练基准平均 +34，18 个未见基准 +26（初步热度 👍307）。
- [HABIT-Bench](https://arxiv.org/abs/2610.24520)：测 agent 记忆系统能否从数百个会话的弱证据中推断用户习惯并加以应用；最好的记忆方法宏平均准确率仅 33.61%（👍78）。
- [Memory Tax](https://arxiv.org/abs/2610.34073)：把记忆的净价值拆成「记忆收益」和「记忆税」；多数专用记忆系统在多个情形下不如朴素 RAG（👍68；[@omarsar0 的推文](https://x.com/omarsar0/status/2115098954799169970) ❤109）。
- [ReGE](https://arxiv.org/abs/2610.33861)：用一次 coach 调用把多次尝试的执行记录合成指导语，供新一轮尝试使用；4 个基准上准确率平均提升 GPT 9.9、Claude 8.8 个百分点（👍13）。
- [Rethinking Verification in Agent Harnesses](https://arxiv.org/abs/2610.34577)：比较 17 种验证设计，独立 critic 评审的精度-成本权衡最好，Terminal-Bench 平均提升 5.9–9.5 个百分点，成本约为基线的 1.13–1.25 倍（👍9）。
- [HaMo](https://arxiv.org/abs/2610.34724)：把轨迹蒸馏成策略级经验卡片供即时检索，同时用以经验为条件的持续学习目标慢速更新参数（👍5）。
- [Stratum](https://arxiv.org/abs/2610.36153)：面向编码 agent 的跨会话仓库记忆；8 个真实 bug 上，继承记忆的新 agent 24 次中 21 次找到根因文件，仅检索的基线为 6/24，中位 token 成本低 4.5 倍。
- [Context Is a Pipeline, Not a Window](https://arxiv.org/abs/2610.36114)：720 次运行里最大 prompt 只用了窗口的 5.75%，但 3,827/11,189 个工具结果在进模型前被固定长度截断成了坏 JSON；调查的 7 个 agent 框架中有 2 个用同样方式截断（作者也说，截断是否导致准确率下降仍无定论）。
- [TrawMem](https://arxiv.org/abs/2610.36918)：按任务角色而不是单纯按相关性组织记忆；LoCoMo 上 LLM-Judge 比 SimpleMem 高 4.07/4.31 个百分点，上下文 token 少约 12.8%/5.1%。
- [Tessera](https://arxiv.org/abs/2610.37080)：免训练的网页 RAG 证据交付层，把页面重建为带标题、章节路径、表头的细粒度证据单元，相同 token 预算下准确率提升 5–6 个百分点。
- [WAKMan](https://arxiv.org/abs/2610.36355)：按实时流量选择 KV cache 淘汰策略；agentic 请求偏好 recency，LRU 在 agentic 偏多的混合负载上命中率比 S3FIFO 高 12%，其他情形最多落后 22%；WAKMan 比 LRU 平均高 5 个百分点。
- [Your Policy Is Secretly a Harness](https://arxiv.org/abs/2610.37255)：理论上说明训练后的策略带有其 harness 的偏好；在 MiniWoB++ 中仅调换观察字段的顺序，成功率就从 85.0% 降到 19.2%（👍6）。

## 研究趋势观察

- 记忆方向向原始证据收敛：[Litmeb/RAW-RAG](https://github.com/Litmeb/RAW-RAG) 对应的 Raw-RAG（7 个设置中 6 个第一）、Memory Tax、HABIT-Bench（最好的记忆方法仅 33.61%）都在追问记忆加工是否丢了证据。Tessera 与「Context Is a Pipeline, Not a Window」则在量化证据到达模型之前的损失。
- Harness 本身被评测、被训练、被自进化：[TraceLite-AI/TraceTrial-Bench](https://github.com/TraceLite-AI/TraceTrial-Bench)、[zgcagi/Harness-RSI](https://github.com/zgcagi/Harness-RSI)、[pzs19/HarnessPro](https://github.com/pzs19/HarnessPro)、[RUCAIBox/Harness-Scaling](https://github.com/RUCAIBox/Harness-Scaling) 之外，The Trinity、Rethinking Verification、「Your Policy Is Secretly a Harness」也在同一方向，今日 New 里 harness 相关论文不少。
- 工程侧呼应：[Tongyi-MAI/OpenGCUA](https://github.com/Tongyi-MAI/OpenGCUA)（★441）和 [zgcagi/Harness-RSI](https://github.com/zgcagi/Harness-RSI)（★387）是持续升温里星数最高的两个，但 HF 点赞自首次报道以来没有增长，热度主要来自代码仓库一侧；[amiya-special/Dynaflow](https://github.com/amiya-special/Dynaflow)（★107）、[pzs19/HarnessPro](https://github.com/pzs19/HarnessPro)（★110）星数也较高。
