## 一、🔥 热度榜：Agent Context 精选

### [Self-Evolving Agent Harness](https://arxiv.org/abs/2610.18813)
- 热度：HF 👍99（入榜 2 天，新增 +0）；代码仓库 [zgcagi/Harness-RSI](https://github.com/zgcagi/Harness-RSI)，387★
- 问题：模型权重不变时，如何让 Agent 的脚手架（prompt、记忆、工作流、可执行组件）通过反馈持续、可靠地演化。
- 方法：把"更新对象"与"提议/准入机制"分开形式化，区分解释性状态的变更与工具、代码、仓库级控制逻辑、插件组合的修订。用进化优化刻画搜索，用持续 PAC 学习分析可靠性，给出泛化界、保留界和基于新鲜独立验证数据的准入规则。
- 结论/意义：长期部署需要持续验证，并对学习、运行权限和高后果动作设独立保护。论文为 66 页的综述加理论。

### [Mosaic: Multi-Session Agentic Reinforcement Learning](https://arxiv.org/abs/2610.22174)
- 热度：HF 👍63（入榜 2 天，新增 +0）；代码仓库 [LARK-AI-Lab/Mosaic](https://github.com/LARK-AI-Lab/Mosaic)，37★
- 问题：上下文压缩和子智能体分叉会让一条轨迹跨多个会话，而现有 Agentic RL 默认单会话上下文，训练与推理错配。
- 方法：提出多会话 Agentic RL 设定，并给出无 critic 的分层优化方法。轨迹层把会话使用量信号纳入优势估计，会话层按估计的边际贡献调整各会话的优势，而不是把轨迹级优势广播给所有会话。
- 结论/意义：在 BrowseComp（Qwen3.5-4B）上，上下文压缩和子智能体分叉两种场景都优于广播基线，且平均使用的会话更少。

### [Focused Omni-Modal GUI Agents](https://arxiv.org/abs/2610.26203)
- 热度：HF 👍96（入榜 3 天，新增 +65）；代码仓库 [fyzhang1/FocusGUI](https://github.com/fyzhang1/FocusGUI)，31★
- 问题：流式全模态观测（截图、音频、视频、历史、设备状态）在每一步被统一暴露，相关性是瞬时且稀疏的，无关信息会累积成"序列性分心"，导致轨迹漂移。
- 方法：提出 FocusGUI 轻量适配器，按当前步的决策参照动态给各模态通道排序，把最相关的证据压缩成紧凑 latent，再注入冻结解码器的 embedding。只用动作监督训练，不需要模态相关性标注，也不微调骨干。
- 结论/意义：在四个全模态骨干上，Type Match 平均提升 +33.2，Exact Match 为冻结骨干的 3.0 倍。

### [Socratic Skill Learning: Interleaving Teaching and Practice for Transferable Agent Skills](https://arxiv.org/abs/2610.17860)
- 热度：HF 👍47（入榜 3 天，新增 +17）；代码仓库 [NJU-LINK/Socratic-Skill-Learning](https://github.com/NJU-LINK/Socratic-Skill-Learning)，2★
- 问题：成功的任务尝试不一定检验了流程的适用条件，难以学到可迁移的 Skill。
- 方法：SSL 让专家 Educator 引导，Student 独自操作环境并撰写 Skill，可以提问、测试和修改建议。另建 SkillTransferBench（35 个任务族、408 个可执行用例）测试 Skill 复用。Issue-Guided 版本跨 Skill 修订追踪未解决问题，据此选择和聚焦评审。
- 结论/意义：Fixed-Window SSL 效用 0.801，无 Skill 为 0.723。Issue-Guided 版本效用 0.805，Educator token 减少 61.7%。

### [Memory-Centric Continual Learning for AI Agents](https://arxiv.org/abs/2610.29357)
- 热度：HF 👍42（入榜 3 天，新增 +23）；暂无代码仓库
- 问题：外部记忆多是被动检索缓存，只评估能否回忆事实，不能说明记忆是否带来持续学习。
- 方法：提出 MCCL，包含三轴分类（状态存放位置、形态、管理策略）和内外双环生命周期，内环更新记忆状态，外环据任务反馈改进管理策略。另有评测协议（干扰下的保留、对变化的适应、任务迁移），以及对经验、存储和算力的记忆扩展框架。
- 结论/意义：主张记忆应以"是否改进未来行动"来衡量。这是框架性论文，摘要未给实验数字。

### [MemPilot: Orchestrating On-Demand Multimodal Memory Curation for LLM Agents](https://arxiv.org/abs/2610.06830)
- 热度：HF 👍39（入榜 3 天，新增 +3）；代码仓库 [ViktorAxelsen/MemPilot](https://github.com/ViktorAxelsen/MemPilot)，7★
- 问题：多数记忆系统与查询无关地预先构建，预处理有浪费，还可能丢掉后来才重要的细节。
- 方法：用 RL 训练多步策略，在"从查询无关记忆检索"和"把原始多模态历史交给异构 LLM/VLM 做查询定制整理"之间选择，同时控制证据量、整理指令、模型选择和视觉访问。训练上采用目标级优势解耦和基于前缀的边际效用估计做信用分配。
- 结论/意义：在五个多模态记忆基准上，不同偏好下的性能-成本-延迟前沿比现有权衡感知基线更宽。

### [Retrieval Augmented Generation Compositionality](https://arxiv.org/abs/2610.29722)
- 热度：HF 👍54（入榜 3 天，新增 +29）；代码仓库 [dolev31/lasagna](https://github.com/dolev31/lasagna)，18★
- 问题：RAG 流水线中的分块、重排、上下文压缩等技术通常单独评估，组合后收益是否保留不清楚。
- 方法：提出开源评测框架 LASAGNA，在 8 个基准、5K–200K 文档的语料上测试 450 种配置，并预先声明三个假设。
- 结论/意义：三种检索技术预测合计 +47%，组合后实测仅 +17%。检索质量与答案忠实度可能互相冲突，最佳组合也会随语料规模变化。

### [DeltaStreamer: Towards Human-Like Agentic Streaming Video Understanding](https://arxiv.org/abs/2610.19849)
- 热度：HF 👍38（入榜 2 天，新增 +0）；代码仓库 [BBBBchan/DeltaStreamer](https://github.com/BBBBchan/DeltaStreamer)，87★
- 问题：流式视频需要在不知道未来问题的情况下保留证据，压缩历史会模糊事件转折，也无法找回缺失的视觉细节。
- 方法：在查询到来前，持续观察并把视觉变化显式写入结构化的变化感知记忆。查询到来后，规划器确定所需证据，指导记忆检索和对历史帧的定向回放。
- 结论/意义：在 OVO-Bench 和 StreamingBench 上总分分别为 66.07% 和 59.53%，优于对比的流式方法。
