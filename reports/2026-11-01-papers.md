## 一、🔥 热度榜：Agent Context 精选

### [Harness-Model Collaboration for Long-Horizon Continual Learning](https://arxiv.org/abs/2610.34724)
- 热度：HF 👍21（入榜 4 天，新增 +16，首次出现时为 5）；无代码仓库；无 X 数据。
- 问题：长程 Web Agent 要么靠模型适配，要么靠外部记忆，持续学习和快速复用只能二选一。
- 方法：HaMo 把轨迹蒸馏成「策略级经验卡片」，供即时检索（非参数，速度快）；同时用以经验为条件的持续学习目标训练模型，让它学会解释、落地并执行检索到的策略（参数，速度慢）。再用「检索覆盖率」挑出紧凑且互补的轨迹来更新参数。
- 结论/意义：在域内和跨域迁移下都优于仅用 harness 或仅做模型适配，经验的保留与适应能力都有提升。今日增长最快的上下文类论文，入选依据是涨幅最大。

### [Δτ-Bench: Pushing Agents Toward a Moving Capability](https://arxiv.org/abs/2610.34238)
- 热度：HF 👍24（入榜 5 天，新增 +4）；代码 [zjunlp/delta-tau-bench](https://github.com/zjunlp/delta-tau-bench) ★5。
- 问题：工具生态持续演化（工具消失、被替换、出现更高效的替代），现有基准测不出 Agent 能否更新自己的程序性知识。
- 方法：基准含 1,588 个多轮任务、42 个领域、6 个连续的生态状态。作者同时提出 Steward，在任务执行中增量维护技能，并动态供给工具与技能。
- 结论/意义：最强的模型/harness 组合成功率仅 42.3%；现有技能学习方法的初期收益无法随生态演化持续。Steward 在生态变化下成功率更高，技能维护开销更低。

### [ReGE: Stronger Agents through Experience Synthesis](https://arxiv.org/abs/2610.33861)
- 热度：HF 👍14（入榜 4 天，新增 +1）；代码 [TIGER-AI-Lab/ReGE](https://github.com/TIGER-AI-Lab/ReGE) ★1。
- 问题：多次尝试留下的执行记录，如何变成下一次尝试的指导。
- 方法：ReGE-Syn 用一次 coach 调用，把有界的执行记录和产物联合合成为自包含的指导（任务发现、建议动作、陷阱）；学生从初始环境状态出发，结合当前观察使用这份指导。不更新参数，也不需要更强的教师模型。
- 结论/意义：四个基准的平均准确率，GPT 提高 9.9 个百分点，Claude 提高 8.8；在 BrowseComp-Plus 上，指导构建的 token 比 AggAgent 少 98.2%（GPT）/95.5%（Claude）；联合合成的指导比直接使用历史或独立摘要明显更短。

### [Skill^{infty}: Recursive Self-Improvement for Agent Skill Optimization](https://arxiv.org/abs/2610.35434)
- 热度：HF 👍8（入榜 5 天，新增 +5）；代码 [taowangcheng/Skill-Infinity](https://github.com/taowangcheng/Skill-Infinity) ★6。
- 问题：现有技能优化器的流程靠手工设计，元技能固定，每个任务都要重新学习。
- 方法：meta agent 按元技能优化任务技能，再用同一流程优化元技能本身。Agent 自主诊断轨迹、提出候选、请求独立评审、分配搜索预算；技能以标准包的形式，通过原生技能发现机制加载。
- 结论/意义：在 83 个 SkillsBench 任务上通过率 60.7%，人工技能为 56.4%，SkillEvolver 为 54.5%。

### [Rare, Relevant, and Still Wrong: How Memory Fails LLM Group Decisions](https://arxiv.org/abs/2610.37624)
- 热度：HF 👍8（入榜 4 天，新增 +4）；无代码仓库。
- 问题：多个 LLM 的群聊被压缩成短记忆交给最终决策者时，应该保留什么。
- 方法：提出 CrossProfile 诊断基准（60 个模板、480 个任务），在文本不变的前提下交叉安排支持、诱饵、无关事实的持有者，测试「最稀有优先」和「最相关优先」两种保留策略。
- 结论/意义：相关性过滤会把诱饵放进记忆，完美的相关过滤在经典配置下比稀有优先低 23–31 分；稀有优先平均不优于随机；准确率取决于所保留证据的平衡，而非策略本身。决策模型存在「社会认同」偏差，去掉归属标签后经典配置提升 13–24 分。自然讨论中保留完整记录的准确率，反而低于不做笔记。

### [DraMaze: A Multi-Agent Pipeline with Future-Aware Memory for Diverse Microdrama Script Generation](https://arxiv.org/abs/2610.32002)
- 热度：HF 👍19（入榜 6 天，新增 +11）；无代码仓库。
- 问题：长篇短剧剧本生成中，情节机制越来越集中；常规检索会强化套路复用，忽略对未来情节重要的历史。
- 方法：用套路记忆引导的进化树搜索与变异，探索多样的因果路径；构建「反向叙事依赖树」，按未来的叙事目标来组织、保留和检索历史记忆。
- 结论/意义：在 60 集、最长 6 万字的剧本上，因果模式重复降低 32.1%，Logic 得分 82.5，超过最佳基线 8.5 分。

### [Rethinking Verification in Agent Harnesses](https://arxiv.org/abs/2610.34577)
- 热度：HF 👍9（入榜 4 天，新增 0）；无代码仓库。
- 问题：harness 该如何组织验证（何时介入、谁来检查、如何修订），目前缺乏指导。
- 方法：提出四层生命周期框架（初始指令、执行中提醒、完成闸门、独立复审），在 7 个前沿编码模型上比较 17 种设计（Terminal-Bench、SWE-bench Verified），并提出 VisualBench。
- 结论/意义：独立 critic 复审的性价比最优：Terminal-Bench 准确率 +5.9–9.5 个百分点（成本 1.13–1.25 倍），SWE-bench +3.9–6.6（成本 1.00–1.04 倍）；完成闸门收益更大，但成本明显上升。

### [Your Policy Is Secretly a Harness: The Decision Geometry of Agent Interfaces](https://arxiv.org/abs/2610.37255)
- 热度：HF 👍8（入榜 4 天，新增 +2）；代码 [2020-qqtcg/HRP](https://github.com/2020-qqtcg/HRP) ★0。
- 问题：训练好的策略从 harness 中学到了什么，换了 harness 后还剩下什么。
- 方法：在 KL 正则控制下证明，最优策略的对数几率反映 harness 对各动作的偏好；部署回报等于 harness 上限减去策略失配。
- 结论/意义：MiniWoB++ 中仅反转观察字段的顺序，已训练模型的成功率就从 85.0% 降到 19.2%；在 Terminal-Bench Lite 上，「上限减失配」能复现准确率排序，单独一项不能。

## 五、研究趋势观察
- 经验与技能复用是上下文类的热点：[HaMo](https://arxiv.org/abs/2610.34724)（非参数经验卡加参数适应）、[ReGE](https://arxiv.org/abs/2610.33861)（经验合成，指导构建 token 省 95% 以上）、[Skill^∞](https://arxiv.org/abs/2610.35434)、[Δτ-Bench](https://arxiv.org/abs/2610.34238)（技能维护）都在回答同一个问题：怎样把过去的轨迹变成可复用的程序性知识。Δτ-Bench 还提示，技能会随环境变化而过时。
- harness 成为独立研究对象：验证设计（[2610.34577](https://arxiv.org/abs/2610.34577)）、策略与 harness 的耦合（[2610.37255](https://arxiv.org/abs/2610.37255)）、[h1](https://arxiv.org/abs/2610.35962) 的结论「高效接口决定成本和解题率」，指向同一个方向：harness 与接口设计的影响不小于模型本身。
- 记忆压缩需要专门诊断：[2610.37624](https://arxiv.org/abs/2610.37624) 与 [DraMaze](https://arxiv.org/abs/2610.32002) 都发现检索和压缩策略存在系统性偏差（诱饵、套路重复），保留的历史越多不一定越好。
- 工程侧呼应：今日仓库星数最高的是 [tettethu/VibeGame](https://github.com/tettethu/VibeGame) ★300，其余多数不到 50；数据中没有 X 提及或 HN 数据，无法判断与工程热度的对应关系。
