## 热度榜：Agent Context 精选

### [Switch-SWE: Do Coding Agents Hold Focus When Switching Between Unfinished Tasks?](https://arxiv.org/abs/2611.02017)
- 热度：HF 👍9（入榜 3 天，新增 +9）；代码 [Miraclecsc/Switch-SWE](https://github.com/Miraclecsc/Switch-SWE) ⭐26
- 问题：编码 Agent 在同一仓库的多个未完成任务间切换后，能否恢复先前任务的需求和进度。
- 方法：200 个 focus 任务、19 个 Python 仓库，构造 400 个配对会话（不被打断 vs 被其他任务穿插）。轨迹分析发现两类典型问题：跨任务需求混淆和任务状态丢失。作者提出插件式上下文管理模块，负责选取与任务相关的历史，并维护简洁的任务状态摘要。
- 结论/意义：7 个 Agent 平均因任务穿插损失 11.5 个百分点（范围 6.0–15.0）；在 OpenCode 上该模块把 focus 任务完成率提高 5.5–15.5 个百分点。

### [EvoMemState: Evolving Memory State for Personal Agents](https://arxiv.org/abs/2611.03743)
- 热度：HF 👍20（入榜 2 天，新增 +20）；代码 [XMUDeepLIT/EvoMemState](https://github.com/XMUDeepLIT/EvoMemState) ⭐3
- 问题：现有长期记忆系统把记忆当独立事实，忽略新事实如何更新、约束或冲突旧事实，也没说明这些事实对当前请求的适用性。
- 方法：以「状态」为中心。先用本体引导的方式抽取持久事实，并建立记录有效性、范围和演化关系的 Relational States；再用 RL 训练策略，生成针对当前请求的 Reasoning State；最后把相关事实、关系状态和推理状态一起用于回答。
- 结论/意义：在长期对话和记忆使用基准上，检索完整性和基于记忆的回答准确率都稳定优于现有记忆系统。

### [MemSteer: Turning User Histories into Supervision for Agent Memory Optimization](https://arxiv.org/abs/2610.39276)
- 热度：HF 👍8（入榜 7 天，新增 +8）；无代码仓库
- 问题：新用户的历史没有标注，手工构造 QA 和证据太贵，无法据此优化记忆设计。
- 方法：MemSteer 把无标注的用户历史转成带证据的 QA 监督：先建立证据支撑的答案计划，再生成问题，并用来源审计和盲答恢复检查把关。MemSteer-Opt 用这些 QA 评估记忆设计并做失败诊断，不更新模型参数，直接修改记忆存储、检索和上下文构造。
- 结论/意义：相对 Base-BM25，ATM-Bench Question Score +13.4 分，RHELM 准确率 +4.1（无外部数据）/ +6.6（有外部数据）；效果与官方 QA 引导的优化相当。

### [GEPA-Curator: Curated Learning for Self Improving Agents](https://arxiv.org/abs/2610.37651)
- 热度：HF 👍8（入榜 3 天，新增 +3）；无代码仓库
- 问题：GEPA 这类反思式 prompt 优化器从失败 rollout 学习，但失败可能源于 harness 局限、随机性或评判噪声，未必是有用信号，甚至有害。
- 方法：先做任务筛选，滤掉可能带噪声的任务；再做先验成功检索，为任务取回过往成功轨迹，作为额外上下文交给优化器。
- 结论/意义：在 GoBrowse、ALFWorld、AppWorld、τ-bench 上持平或超过基线，最高比 GEPA 高 20.7%，比 ACE 高 21.2%。

### [RoboArchitect: Automating the Design of Robotic Agents with Persistent Memory](https://arxiv.org/abs/2610.42141)
- 热度：HF 👍8（入榜 4 天，新增 +3）；代码 [roboarchitect-ai/RoboArchitect](https://github.com/roboarchitect-ai/RoboArchitect) ⭐9
- 问题：冻结的机器人策略放进 Agent harness 后表现更好，但 harness 靠手工为每个机器人或基准重新设计。
- 方法：编码模型观察 rollout、诊断失败，迭代修改冻结策略外层的 harness，不更新任何权重。harness 还会演化出自己的持久记忆，把学到的经验（如有效抓取深度）带入后续决策。
- 结论/意义：未见场景成功率从 9.7% 提高到 43.3%，未见任务从 12.7% 提高到 40.2%；摘要称演化出的 harness 常优于微调版本。

### [Hybrid Computer Use: A Unified Programmatic, Semantic, and Visual Interface for General Agents](https://arxiv.org/abs/2610.41432)
- 热度：HF 👍14（入榜 1 天，新增 +8）；代码 [microsoft/Hybrid-Computer-Use](https://github.com/microsoft/Hybrid-Computer-Use) ⭐33
- 问题：以截图加键鼠为中心的接口带有人类交互偏置，要反复解读屏幕，电脑的语义和编程能力没有被暴露出来。
- 方法：统一接口含三个通道：代码/命令行、无障碍（AX）语义、GUI 视觉。AX 工具返回紧凑观察，批量执行动作，并以 AX diff 报告效果，减少交互轮数；通道切换时防止作用于过期状态。另有一个 HCU skill 指导模型选择和协调通道。
- 结论/意义：在 OSWorld 2.0 上，HCU 的 Partial 和 Binary 分数在对比系统中最高。

## 🆕 New：昨晚新公布
- [Harness-S: Learning from Sibling Harnesses for Generalizable Agent Training](https://arxiv.org/abs/2611.04277)：从同一基础 harness 演化出一池「兄弟 harness」，仅当基础 harness 下全部失败时才调用，用这些轨迹做 RL，把能力迁移回单一策略，在 AppWorld、SWE-Gym、DBBench 上明显优于只训练策略（初步热度 👍51，代码 [DeepExperience/Harness-S](https://github.com/DeepExperience/Harness-S) ⭐20）。
- [QRAE: Query-Relevant Attention Entropy for Context Compression in DeepSearch Agents](https://arxiv.org/abs/2611.07976)：用稀疏的证据评估注意力头决定哪些检索块留在上下文，不确定的块放进候选缓存待复评；成功率平均 +2.35 个百分点，延迟平均降 30%，token 用量平均降 45%。
- [CORE: Coarse-to-Fine Search with Context Management for Deep Research](https://arxiv.org/abs/2611.07859)：免训练 harness，每个段落只返回最相关片段，并允许 Agent 扩展已检索来源的上下文、抑制重复片段；在 BrowseComp-Plus 等三个基准、最多 5.53 亿文档的语料上取得最好的准确率和证据召回。
- [Octopus: One Brain, Many Branches for Latent-KV Multi-Agent Reinforcement Learning](https://arxiv.org/abs/2611.06956)：多个线程共享一个骨干，在 GPU 上的 KV 状态 DAG 里 fork、读取、回滚，分支零拷贝；Qwen3.5-4B 在 BrowseComp-Plus 达 49.6%（比单 Agent GRPO 高 17.5 分），峰值 KV 内存降 2.8×。
- [SwarmEvolve: Latent Agent Swarms for Evolutionary Discovery and Optimization](https://arxiv.org/abs/2611.08483)：数百个低成本 Agent 在潜空间推理，并通过传递 KV cache 共享信息，中位 3–8 分钟达到其他框架 60 分钟的最好成绩。
- [CacheGraft: Enhancing Retrieval-Augmented Generation via Latent-Space Document Enrichment](https://arxiv.org/abs/2611.07393)：把语料段落离线编码成大小模型融合的 KV cache，查询时注入小模型；5 个 QA 基准上 30 次对比中 29 次优于纯文本基线。
- [MCPHallu: Benchmarking Reasoning, Execution, and Memory Hallucinations in MCP Agents](https://arxiv.org/abs/2611.07689)：358 个任务、36 个真实 MCP 服务器，14 个前沿 Agent 平均 0.642；「不可达目标」任务通过率仅 23.2%。
- [Don't Prompt Your Agents. Equip Them: Skillware](https://arxiv.org/abs/2611.07652)：把 skill 做成带类型化 JSON 契约、确定性 Python 代码和单元测试的版本化能力包；摘要称 3B–8B 小模型配上后在多步流程上超过未配备的前沿模型，token 最多降 84.8%。
- [Signed but Not Safe: Requirement Integrity in Multi-Agent LLM Handoffs](https://arxiv.org/abs/2611.07483)：子 Agent 交接时用签名的需求清单，攻击下不安全提交从 69.4% 降到 9.0%；但签名前注入攻击仍可绕过，抽取步骤是信任边界。
- [A Sharp Additive Bound for the Threshold Rule in Repeated Rent-or-Buy](https://arxiv.org/abs/2611.06955)：从 LLM Agent 上下文管理（何时重置历史）抽象出理论模型，证明阈值规则相对最优多付 (2P-1)K，且系数紧。
- [tok: a textual concrete syntax of BPMN and DMN for humans and AI agents](https://arxiv.org/abs/2611.07945)：为 BPMN/DMN 设计纯文本语法并提供 MCP 服务，比 BPMN XML 省 2.2× token；Agent 写出有效 tok 的比例为 97.6–100%。
- [Towards Foundation Decision Models: Drex](https://arxiv.org/abs/2611.07854)：给定状态（含 Agent 上下文）和选项，直接输出选项概率分布而无需自回归解码，Max 一次请求约 183 ms（对比 GPT-6 Sol 约 2.0 s）（初步热度 👍15，代码 [nace-ai/drex-decision-models](https://github.com/nace-ai/drex-decision-models) ⭐98）。
