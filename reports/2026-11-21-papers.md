## 🔥 热度榜：Agent Context 精选

### [CarryOn: Learning What to Keep in Context for Long-Horizon LLM Agents](https://arxiv.org/abs/2611.17808)
- 热度：仅 arXiv，无 HF 点赞（👍0），入榜 5 天（11-16 首次出现），热度 0.0，无代码仓库。因为是今天最直接的上下文管理论文，仍然入选。
- 问题：长程 Agent 的历史越来越长。摘要和剪枝会丢掉后续动作需要的精确细节，保留全部历史又带入太多无关信息。
- 方法：轻量的上下文管理器，把紧凑的执行状态和细粒度、可溯源的证据配成一对。由学出来的 selector 加自适应保留策略决定留什么，管理上下文时不需要额外的 LLM 调用。另提出两个指标：S_α（优先任务成功率，同时计入资源消耗）和 NCS（每次成功任务的归一化成本）。
- 结论/意义：在 AppWorld、OfficeBench、Tau2 Telecom 上，用 3 个 LLM Actor，宏平均任务成功率 75.7%，比最强基线高 6.7 个百分点，两个指标的平均分也最好。

### [Continual-ARC: Measuring Skill Acquisition over a Working Lifetime](https://arxiv.org/abs/2611.14505)
- 热度：HF 👍2，入榜 5 天，点赞从首次出现时的 9 回落到 2（-7）；代码仓库 [unifyai/continual-arc](https://github.com/unifyai/continual-arc) ★38。热度只有 2.8，入选因为主题贴合。
- 问题：现有持续学习基准只有单一领域，每个实例只出现一次，记忆型和权重型系统没法放在同一尺度上比较。
- 方法：用三个 ARC-AGI 版本构建终身任务流，旧任务隔一段时间带新实例回来，新任务不断出现。学习者可以付费看示例、提交答案或在 harness 里行动，按消耗的反馈预算打分；结束后冻结，分别测记忆（见过的任务）和泛化（没见过的任务）。对比对象包括带持久化和不带持久化的冻结权重 harness（Qwen3.5-9B、GLM-5.3 Flash）、两个提示基线、程序归纳方法，以及蒸馏出来的 Qwen3.5-9B 权重。
- 结论/意义：harness 持久化一般不能提升记忆，除非有明确的专家指导。多数 harness 方法学到的比「只缓存每个任务示例」的基线还少；没有任何 harness 方法在未见任务上提升，权重学习则有明显提升。

### [Embeddings vs. Grep: Rethinking the Dense Advantage in Code Search](https://arxiv.org/abs/2611.20455)
- 热度：HF 👍7，入榜 1 天，新增 +4；无代码仓库。
- 问题：代码搜索基准里稠密编码器远胜 BM25，但 coding agent 用 grep 就做得很好，这个优势到底在测什么？
- 方法：构建仓库级代码搜索基准 Repo-Premium，覆盖 Python、JS、TS、Go、Rust、Java，PR 时间 2022–2026，预注册的测试池涵盖 91 个仓库。作者把稠密检索的优势归因到两类来源：偏向稠密检索的评测选择（给 BM25 切 chunk、把被编辑的测试文件算作相关），以及查询缺少代码里的稀有标识符。用 LLM 写标识符来扩展查询（generate-then-grep），对 BM25 的帮助远大于对稠密检索，在每个 Python 池里都追平稠密检索，包括 LLM 发布之后才开的 PR。
- 结论/意义：没有任何方法能预测某个查询上哪个检索器会赢。论文给出三条建议：跟公平的词法基线比，稠密和 BM25 融合，给缺词的查询补上代码里的词。

### [Forget the Lineage: Forward-Secure, Lineage-Complete Cryptographic Erasure for LLM-Agent Memory (LinEra)](https://arxiv.org/abs/2611.18133)
- 热度：仅 arXiv（cs.CR），无点赞，入榜 5 天，热度 0.0，无代码链接。
- 问题：Agent 的长期记忆由模型自己写（摘要、抽取的事实、嵌入）。删掉原始消息不够，它的衍生物、存储残留和备份都还在。
- 方法：LinEra 把每条记忆用父节点密钥派生出的密钥加密，沿派生图传递。源密钥来自可穿孔伪随机函数（puncturable PRF），遗忘只需一次穿孔，所有后代无需定位就变得不可读。谱系规则把写入者看到的一切都记为父节点。已与 mem0 集成，并证明了安全性和谱系完整性。
- 结论/意义：在 LoCoMo 对话上用 1.5B–7B 的真实 LLM 写记忆。最大模型写的 10 段对话里，攻击者拿到所有文件和当前密钥后，逻辑删除下能恢复 71 个被遗忘秘密中的 70 个，按对象或按 epoch 密钥时能恢复 67 个，LinEra 下恢复 0 个。代价是遗忘半径变大，取决于写入者的 fan-in：遗忘 1% 的轮次，会话级摘要下抹掉 73.0% 的衍生记忆，四轮窗口下只抹掉 3.8%，且四轮窗口回答得也更好；重新派生可以恢复被抹掉的部分。

### [AutoMaster: Autonomous Post-Training by Making the Same Model a Better Teacher](https://arxiv.org/abs/2611.26510)
- 热度：HF 👍14（本榜 Context 类最高），入榜 1 天，新增 +4；代码仓库 [RUCAIBox/AutoMaster](https://github.com/RUCAIBox/AutoMaster) ★16。
- 问题：任务成功不能说明该强化哪些行为。成功的教师轨迹里也可能有无依据的假设、无效重复和表面验证。
- 方法：提出 Skill-FT，在教师 rollout 时用自然语言 skill 压制坏习惯、引出缺失的有效行为，再用这些轨迹微调目标模型。AutoMaster 是让 LLM Agent 自主完成轨迹分析、skill 设计、数据选择并根据反馈迭代的系统。
- 结论/意义：在 Terminal、Search、软件工程任务上，4B 和 9B 目标模型平均比对成功的无引导教师轨迹做普通 SFT 高 1.42–8.99 个百分点。SFT 时保留 skill 指令，在全部 6 个设置里都比去掉更好，尽管评测时没有它们、监督输出也相同；把 skill 上下文留在训练示范里，有助于行为内化。

### [Do LLM Agents Still Need to Be Told How to Self-Improve?](https://arxiv.org/abs/2611.23219)
- 热度：HF 👍6，入榜 3 天，新增 +3；代码仓库 [ssundaram21/self-org](https://github.com/ssundaram21/self-org) ★3。作者含 Phillip Isola。
- 问题：能力更强的模型，还需要人规定它怎么自我改进吗？
- 方法：冻结的 LLM Agent 拿到算力预算，以及收集经验和更新文本文档的工具，在游戏里自由实验，没有外部强加的循环，也不接触真实数据。它自己构建「基于上下文的优化」算法，学到的是文本文档（上下文），不改权重。
- 结论/意义：足够强的模型确实会自我改进，策略与自我调节学习、自生成课程的概念吻合；学到的文本产物可以迁移到不同的游戏时长、机制，以及 3D 导航外部基准。

### [Invariant-Aware Harness Enforcement to Protect LLM Agents from Silent API Failures (SilentGuard)](https://arxiv.org/abs/2611.20595)
- 热度：HF 👍5，入榜 3 天，新增 +2；代码仓库 [Sajib-006/silentguard](https://github.com/Sajib-006/silentguard) ★1。
- 问题：API 可能静默失败，例如忽略拼错的过滤器，却返回 HTTP 200 和看似合理的错误结果。清单、审阅模型、LLM judge 都让模型自己去发现，但模型常常看到问题还照样回答。
- 方法：把判断从模型移到执行工具调用的 harness。harness 用任何正确 API 都必须满足的不变量检查每个结果，违反就扣留数值。
- 结论/意义：15 个公开研究 API 中 11 个有静默故障，计数最高被放大 691 倍；现有修复让超过 70% 的回答仍然错误。7 个开源模型上目标故障的错误率从 74.0% 降到 1.7%，无故障任务无损失；3 个前沿模型从 70.2% 降到 0.5%。同一检查只给警告时仍有 70.1% 错误，所以关键在强制执行。新故障类型上 harness 单独把错误率从 61.1% 降到 24.5%，靠弃答而不是恢复来避免错误。

### [System 1 agents: a method for local, reliable and fast agentic AI](https://arxiv.org/abs/2611.21053)
- 热度：HF 👍6，入榜 1 天，新增 +4；代码仓库 [eltzanis/SystemOneAgents](https://github.com/eltzanis/SystemOneAgents) ★12。
- 问题：本地 LLM 会幻觉，工具调用里编造的值会传播到后续每一步。
- 方法：确定性编译器把每个工具的 schema 和请求转成多选题，选项来自请求和 schema，再由一次前向的决策模型作答，全程不生成文本。
- 结论/意义：在 157 个生物医学工具的 1,952 个请求上，最佳 System 1 Agent 选对工具（或正确拒绝）的比例是 97.0%，高于全部 18 种本地 LLM Agent 设置（最好 95.2%）；6,056 个给定参数值填对 97.0%。System 1 调用里没有编造内容，LLM 调用是 5.5–19.7%。

## 研究趋势观察

- 上下文管理的问题从压缩多少转向留什么。[CarryOn](https://arxiv.org/abs/2611.17808) 用执行状态加可溯源证据，由 selector 选择（75.7%，+6.7pp）；[AutoMaster](https://github.com/RUCAIBox/AutoMaster) 把 skill 指令留在训练示范里反而更好；[LinEra](https://arxiv.org/abs/2611.18133) 关注记忆怎么删。
- harness 带记忆的负面证据：[Continual-ARC](https://github.com/unifyai/continual-arc) 里多数 harness 方法不如缓存示例的基线，未见任务上无提升；[Embeddings vs. Grep](https://arxiv.org/abs/2611.20455) 显示稠密检索的优势被评测选择夸大，BM25 加 LLM 扩展词即可追平。数据里没有与之对应的 GitHub 项目。
- 可靠性问题集中到 harness 层强制执行，不再依赖模型自己判断：[SilentGuard](https://github.com/Sajib-006/silentguard) 只警告仍有 70.1% 错误，[System 1 agents](https://github.com/eltzanis/SystemOneAgents) 用不生成文本的工具选择避免编造，[Unfinished-Bench](https://github.com/naver-ai/unfinished-bench) 里规则显示后仍被违反。
- 热度分布：前三名（👍51/49/35）是视频检测、具身基准和视频生成，Agent Context 类最高仅 👍14，多篇 Context 论文是 arXiv 直接收录、无点赞。数据中没有 X 提及次数，社交传播层面的趋势无从判断。
