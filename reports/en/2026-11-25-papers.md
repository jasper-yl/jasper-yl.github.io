## Hot list: Agent Context picks

### [Embo-Harness: Towards Understanding Frontier-Model-as-Policy Harness](https://arxiv.org/abs/2611.31201)
- Heat: HF 👍103 (1 day on the list, +15); no X data; code [DravenALG/Embo-Harness](https://github.com/DravenALG/Embo-Harness) ⭐65
- Problem: When a frontier model acts directly as a robot policy, it is unclear how to design the harness and which capabilities are doing the work.
- Method: Breaks the robot agent loop into four parts (prompting, planning, action execution, tool use) and distills 6 empirical findings into a recipe. The recipe favors the model's native visual reasoning and tool use over hand-written plans, skills or action priors. It also gives choices for action representation, chunking, reasoning effort, visual observation, short multi-action sequences and policy refinement.
- Result: 83.3% success on RoboLab-120, 26.2 points above the strongest reported baseline; 15 of 20 zero-shot trials succeeded across 4 real tasks. Intervention experiments show the model depends on accurate spatial goal estimates; low-level joint/trajectory generation matters less.

### [AutoPILOT: A Visual Agent Harness for Real-Time Gameplay](https://arxiv.org/abs/2611.28202)
- Heat: HF 👍34 (1 day on the list, +4); no code data
- Problem: In games that don't pause, a harness that allows one action per model call caps the agent's action rate at the model's thinking speed.
- Method: A harness decides what the model sees, what it remembers and how its output becomes actions. AutoPILOT changes the third: per call, the model can emit a primitive action, launch an open-loop macro, or write a closed-loop controller that keeps running off the screen without calling the model until it hands control back.
- Result: On AFK-Bench (120 browser games), GPT-6.1 Sol reaches 68.6% real-time success versus 38.3% for VISTA, and matches VISTA's final success rate at one fifth of the API cost.

### [Context Has a Price: Adding and Removing Context for LLM Coding Agents under Prefix Caching](https://arxiv.org/abs/2611.22238)
- Heat: arXiv only (HF 👍0, 7 days on the list); no X or code data
- Problem: Does adding retrieved code, or deleting old tool outputs, actually lower a coding agent's task cost?
- Method: 20,000+ runs of open-source models on SWE-bench Verified, SWE-bench and Loc-Bench, with uncached input, cached input and output tokens priced separately.
- Result: Retrieved code cuts read/search commands by 18–34%, but when the cached price is 1/10 of uncached, cost rises 33–42% with no measurable gain in resolve rate. Deleting old observations saves 19–36% with no cache discount and raises cost 38–116% at a 1/10 cache price. Shorter prompts can make the agent take more steps. In concurrent runs, a shared cached prefix distorts cost comparisons.

### [Stopping Is Not the Limit: Understanding and Eliciting Agent Capability in Long-Horizon Vulnerability Exploitation](https://arxiv.org/abs/2611.22888)
- Heat: arXiv only (HF 👍0, 7 days on the list)
- Problem: Exploitation agents often stop before the budget is spent. Does continuing after the stop still pay off?
- Method: On ExploitBench, continuing after a stop still helps, with diminishing returns. Less productive continuations share two traits: stop replies take up a growing share of the context, and summaries keep the judgment that some capability is impossible. SCoRe compresses context on consecutive stops and marks those judgments as "unconfirmed".
- Result: MiMo reaches 67.0% capability coverage at 2,000 turns, versus 32.4% under the original stopping policy; GPT-5.5 is at 58.6%, computed from ExploitBench's 300-turn reference results.

### [When Agent Skills Go Stale: Runtime Behavior and Selective Maintenance in Evolving Environments](https://arxiv.org/abs/2611.22525)
- Heat: arXiv only (HF 👍0, 7 days on the list)
- Problem: After the environment changes, a previously useful skill can be partly outdated, and reusing it may hurt.
- Method: Compares skill reuse before and after environment change across 4 task settings and 2 models. Proposes selective maintenance: with no extra model calls, it replays checks from successful runs, tests whether differences conflict with the skill's state, repairs and verifies the affected parts, and rebuilds the skill if a local fix isn't enough. The system is not told what changed.
- Result: Stale skills can cut task performance by more than 10 points, or raise execution cost by nearly 40% versus using no skill. Maintenance improves accuracy by up to 67pp and cuts steps by up to 37% relative to reusing stale state.

### [MMMem: Self-Improving Agents with Task-Aware Multimodal Experience Consolidation](https://arxiv.org/abs/2611.30287)
- Heat: HF 👍10 (1 day on the list, +9); code [ChenYX24/MMMem](https://github.com/ChenYX24/MMMem) ⭐0
- Problem: Existing multimodal memory stores and retrieves records but doesn't distill experience from completed tasks.
- Method: A multi-view memory retrieves over original text, images, rendered pages and a scene graph with synthesized cues. Source-generated tasks drive a warm-up (consolidating source knowledge into external memory experiences) and self-training (adapting parametric knowledge to tasks). A VLM distills each completed task into an experience with task context, conclusion and supporting links. At retrieval time, source views and experiences are recalled per task.
- Result: On Qwen3.5-9B, gains over the best baseline are 36.9% on LoCoMo, 17.6% on Mem-Gallery and 15.2% on LooGLE v2.

### [MORSE: Optimizing Streaming Memory Design via Open-World Auto-Research](https://arxiv.org/abs/2611.30011)
- Heat: HF 👍4 (1 day on the list, +2); no code data
- Problem: A streaming video system with limited frame storage must decide what evidence to keep without knowing future questions.
- Method: An editor groups failures in training trajectories by cause, then searches papers, model cards and code for methods or pretrained perception models to adapt. When a new perception capability is added, the harness's storage and retrieval change with it. It first picks revisions that improve answer quality, then looks for faster ones within a tolerance.
- Result: On OVO-Bench, the Qwen3-VL-8B harness answers in 0.30 s on average at 75.1% accuracy, 3.1 points above the next-best harness on the same frozen backbone.

- [VideoJSON: A Minimal Harness Beats Purpose-Built Memory for Ultra-Long Video Understanding](https://arxiv.org/abs/2611.28167): Stores each minute of video as one JSON record and has a coding agent write Python/Bash to retrieve. ## Observations

- Attention clusters on the harness and the loop around the model. Embo-Harness (👍103) and AutoPILOT (👍34) use controlled experiments to show that changing the interface or how actions are produced gains more than changing the model. RUIBench shows the same: changing only the interface moves success from 45% to 81%.
- Context management is now being measured. Context Has a Price measures cost and SCoRe measures the payoff of continuing past a stop, while RECAP and Bathys put compression inside RL training. The theme continues in the New list.
- Memory and skill maintenance: Skills Go Stale, VISE, MMMem and Leto all deal with stored experience going stale or proving less useful than assumed. MIMPA raises the attack-side risk of shared memory.
- On the systems side, LoomKV, Mayfly and LaFlash optimize for agents' prefix reuse and KV retention, which fits Context Has a Price's finding that cache pricing decides which strategy wins. The data has no matching GitHub project heat, so there is nothing more to infer.
