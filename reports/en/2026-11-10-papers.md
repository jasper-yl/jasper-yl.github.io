## Hot list: Agent Context picks

### [Tools Need Not Speak in Text: Latent Context Compression for Agents](https://arxiv.org/abs/2611.06500)
- Heat: HF 👍7 (on the list 5 days, +7); code at [THU-Agent/Coca-cola](https://github.com/THU-Agent/Coca-cola), 8 stars; no X mention data.
- Problem: agents append raw tool output to the context, so long, noisy observations eat budget and dilute attention. Text-level pruning and summarization compress poorly.
- Method: Coca-Cola compresses tool observations into latent tokens embedded directly in the agent's input embedding space. Action-Preserving Training aligns the agent's next-action distribution under full and compressed observations, which forces the compressor to keep what the decision needs.
- Result: on web-search agents across 4 QA benchmarks and 2 model families, token use drops 70.01%–89.24% and end-to-end time drops 24.45%–55.97%, while task performance keeps improving. It is the most direct context-compression paper of the day, and it has code.

### [Do Agents Still Follow the Rules? Benchmarking Rule Compliance under Agent Context Compaction](https://arxiv.org/abs/2611.03223)
- Heat: HF 👍0; on the list 7 days; no code link.
- Problem: after an agent compacts its history, do rules still constrain later actions? Earlier work tested outside a full harness and couldn't say where violations come from.
- Method: ARCBench is built on the open-source pi agent harness. It measures rule compliance from actions actually executed, attributes each violation to a source, and covers different compaction setups and adversarial settings.
- Result: compaction rarely deletes rules. Most violations occur while the rule is still in the compressed history, because the agent treats a later request as permission. The strongest compactor-targeted attack more than doubles violations, and compaction runs that keep the rules violate them at more than double the rate of full history. Keeping a rule in the summary doesn't mean it takes effect.

### [Can Large Language Model Agents Learn by Watching Tutorial Videos?](https://arxiv.org/abs/2611.01460)
- Heat: HF 👍6 (on the list 7 days, +4); no code.
- Problem: agent capability freezes after training. How can an agent learn from large numbers of tutorial videos without updating parameters?
- Method: Tutorial Agentic Learning (TAL) distills tutorial videos into a persistent, structured "tutorial book" memory through a two-stage adversarial process: mine hard, video-grounded questions, then use them to correct the memory. At inference it retrieves through a table-of-contents (TOC) tree, tying retrieval to model reasoning instead of embedding similarity.
- Result: on VidLearn, built from 72 chess tutorial videos, it improves on the raw MLLM by up to 113% (train split) and 91% (test split), and 69% of live games have a stronger position after the opening. Non-parametric continual learning with TOC-tree retrieval is a distinctive memory design, but it is validated only on chess (plus a second domain).

### [A State Change Is Local, Its Consequences Are Not: Dependency-Aware State Revision for Long-Term Agent Memory](https://arxiv.org/abs/2611.02912)
- Heat: HF 👍0; on the list 7 days; no code.
- Problem: when an upstream fact changes, memory systems fix only the directly contradicted entry. Beliefs, plans and actions that depend on it are still treated as valid.
- Method: StateGraph keeps a state-dependency graph recovered from interaction history. It tests each candidate edge with counterfactual verification (does the dependent state still hold without the premise?) and invalidates downstream state only when a strong dependency fails and no independent support path exists.
- Result: on StateChangeBench, the authors' own 50-case benchmark, Impact-F1 beats a CUPMem reimplementation by +6.9 points at depth 1 and +26.0 at depth 3+. On public long-term memory benchmarks, point estimates are equal or higher than baselines. The abstract itself calls this "initial evidence" and the benchmark is a small self-built sample, so treat the claim conservatively.

### [Parallelism-Aligned Pruning and Round-Aware Context Reuse for On-Device Multimodal Agents](https://arxiv.org/abs/2611.02601)
- Heat: HF 👍0; on the list 7 days; no code.
- Problem: with prefix caching on-device, historical visual tokens stay in the persistent KV cache and capacity runs out after enough turns. The attention structure also doesn't divide evenly across edge-accelerator cores.
- Method: PARC separates the system prompt, persistent text history and transient visual observations by lifecycle. It updates text history during tool execution and moves historical images out of the persistent cache, so the same budget holds more turns. It also adds structured pruning aligned to core count.
- Result: on 2,062 GUI actions the incremental interface shows no accuracy regression. On a seven-core deployment, visual-encoding latency drops 11.4%, decode throughput rises 23.8%, and peak per-heap memory falls 12.7%.

### [When Cache Pressure Becomes a Trap: Metastability in Agent Serving](https://arxiv.org/abs/2611.02543)
- Heat: HF 👍0; on the list 7 days; no code.
- Problem: agents repeatedly send growing conversations, so prefix reuse drives serving efficiency. A short burst can break reuse and leave service degraded long after load recovers.
- Method: on SGLang, a ten-minute burst cut goodput by about 88% over the following hour. The mechanism is a population-cache feedback loop: sessions slow down, total context grows, the cache misses, recomputation slows things further. The proposed fix, Basin, fixes session priority, reserves an admission budget based on predicted peak context, uses idle decode memory to extend the cache, and trims excess demand.
- Result: on a real H200 1P3D deployment, goodput is 1.20–1.70× Continuum and 2.35–3.59× HiCache alone.

### [FlyHash for LLM Agent Memory: An Empirical Validation and a New Application](https://arxiv.org/abs/2611.05791)
- Heat: HF 👍3 (on the list 5 days, +3); code at [mohanji/flyhash-agent-memory](https://github.com/mohanji/flyhash-agent-memory), 1 star.
- Problem: does FlyHash, a locality-sensitive hash modeled on the fruit fly's olfactory circuit, actually help agent memory retrieval?
- Method: tested under a matched-bit-count protocol. The quality advantage holds (10 seeds, 4 datasets) and also holds on real memory-relevance labels. At equal bits, though, the codes are larger and comparisons slower, and HNSW still beats both hash methods at ordinary scale.
- Result: the authors report two findings that weaken the headline result, so the hashing approach applies more narrowly than the quality numbers suggest. It is an honest negative-result paper.

## Observations

- "Is the agent still reliable after compression?" is now its own question. [Coca-Cola](https://arxiv.org/abs/2611.06500) (latent-token compression), [ARCBench](https://arxiv.org/abs/2611.03223) (rule compliance after compaction) and [StateGraph](https://arxiv.org/abs/2611.02912) (downstream dependencies in memory revision) all ask whether decisions hold up after compression or memory updates, not only how many tokens were saved.
- KV cache and agent context management are starting to be designed together. [Metastability](https://arxiv.org/abs/2611.02543) and [PARC](https://arxiv.org/abs/2611.02601) on the hot list, and last night's [Evolving Infra](https://arxiv.org/abs/2611.12304), [Hibana](https://arxiv.org/abs/2611.10469), [VerKV](https://arxiv.org/abs/2611.11319) and [Flide](https://arxiv.org/abs/2610.42148), all address how an agent's growing multi-turn context affects caching and serving. Evolving Infra explicitly uses agent context-management signals to drive cache eviction.
- The reliability of self-evolving harnesses is being questioned. [Beneath the Surface](https://arxiv.org/abs/2611.07624) and [Continual evolution](https://arxiv.org/abs/2611.03219) landed on the list the same day, and both find that higher scores mask forgetting and rising cost. Harness papers such as [HEELO](https://arxiv.org/abs/2611.07461) and Auriga still report large gains.
- Memory systems keep competing on LoCoMo and LongMemEval. [MIRIX-2.0](https://arxiv.org/abs/2611.12068) and [SoMem](https://arxiv.org/abs/2611.11929) appeared the same day with clearly different approaches: typed multi-agent memory with a hypergraph versus plain linked documents. Today's input has no GitHub project data, so there is no engineering-side comparison.
