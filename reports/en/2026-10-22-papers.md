## 1. Selected Agent Context Papers

### [Cache Engineering for Agents](https://arxiv.org/abs/2610.28577)
- Popularity: HF 👍107; code: https://github.com/thu-nics/AKV
- Problem: As agent trajectories grow longer, KV cache I/O and storage become the main overhead, while traditional pruning/summarization alters the prefix, invalidating later caches and triggering expensive re-prefilling.
- Method: Proposes "cache engineering": the agent uses drop to exclude selected cache entries from later attention and repos to adjust the position encoding of retained keys, all without modifying the trajectory or re-prefilling. It also designs the AKV serving engine: a stateless external interface, with stateful cache reuse, eviction and recovery managed internally (since the same token sequence has different states under different cache-operation sequences, prefix matching is no longer sufficient).
- Result/significance: A rolling drop policy for tool responses improves scores by 1.7 on average over threshold-triggered summarization and cuts cost by 27.7%; AKV delivers up to 1.2x throughput and 1.5x P95 latency speedup.

### [MemT-1.0: Towards Memory-Native Evolution](https://arxiv.org/abs/2610.26825)
- Popularity: HF 👍132; code: https://github.com/MemTensor/MemT-1.0
- Problem: External memory is mostly passive retrieval; the goal is to make memory an intrinsic capability of the foundation model itself.
- Method: Built on Gated DeltaNet-2, it performs stable token-level memory updates within each turn, and uses Mixture-of-Storage to expand native memory capacity; after 34B tokens of continued pretraining plus post-training, it releases two models, Nano and Flash.
- Result/significance: Outperforms parametric-memory baselines and matches retrieval-augmented methods; at 128K history, relative to a full KV cache, end-to-end inference is about 1.86x faster and persistent storage is reduced 66x, and agent task success rates improve.

### [OpenVLHarness: Real World Visual Agentic Tool-Use with Multimodal Memory](https://arxiv.org/abs/2610.26860)
- Popularity: HF 👍111; code: https://github.com/uclanlp/OpenVLHarness
- Problem: Visual reasoning tasks need evidence produced by heterogeneous tools, and that evidence must be retained and remain interpretable across multi-step reasoning.
- Method: Builds a capability layer (task-level tool interfaces + evidence rendering, which turns tool outputs into model-readable observations) and persistent multimodal memory (images, structured data and web references saved as addressable artifacts), then uses a code interface to compute across tools over the stored data.
- Result/significance: Across 22 benchmarks, it improves on same-backbone no-tool baselines by 9.7–12.6 points on average; with GPT-6 Luna at medium reasoning effort, it beats the other approaches' highest-effort settings by 7.7–8.5 points at no more than 37% of the token cost.

### [FlowState: Execution State as Memory for Long-Horizon LLM Agents](https://arxiv.org/abs/2609.34565)
- Popularity: HF 👍15
- Problem: Keeping the full history is costly, while compression loses details whose relevance only emerges later.
- Method: Treats execution state as memory, storing semantically typed state nodes, relations and references to the original tool observations, separating persistent retention from on-demand access; Incremental State Update maintains the current state, and Progressive State Access gradually expands historical state and evidence during reasoning.
- Result/significance: Relative to the full-context baseline with the same model (DeepSeek-V4-Flash), MemoryArena success rate is +4.55 and τ³-Bench pass rate is +13.95 percentage points, while total token consumption drops by 43.2% and 40.6%, respectively.

### [REM: What to Store, When to Recall, What to Forget in Experience Memory for Coding Agents](https://arxiv.org/abs/2610.27377)
- Popularity: arXiv only
- Problem: Existing memory systems focus only on retrieval; they cannot observe a running agent, so they don't know whether it needs experience, when, or for how long.
- Method: Manages the memory lifecycle inside the agent's think-act loop: consolidates trajectories into staged documents two orders of magnitude smaller (what to store); injects the document at task start, and injects the more expensive implementation notes only when a gate detects the agent is stuck (when to recall); evicts records after a single exposure (what to forget).
- Result/significance: On SWE-ContextBench Lite, match@1 is 68.7% (vs. 55.6%), resolve rate is 27.6% vs. 24.9%, and cost is 17% lower; ablating any one decision lowers the resolve rate.

### [Compaction Laundering: Provenance Destruction in Context-Compacting Coding Agents](https://arxiv.org/abs/2610.29869)
- Popularity: arXiv only
- Problem: When a coding agent compacts context by flattening typed conversation into plain strings, message provenance is lost before summarization.
- Method: On five flattening harnesses (pi, opencode, Cline, Aider, OpenHands), an attacker forges user turns through content the agent reads, so that a forged approval is "laundered" through compaction into a genuine instruction; four harnesses that preserve role types (Codex, Gemini CLI, Qwen Code, Continue) serve as controls.
- Result/significance: The laundering rate is 87–100% for flattening harnesses and 0% for role-typed harnesses; a code-level provenance check can block 77% while demoting only 2% of legitimate summary content, and the root fix is to escape role labels at serialization.

### [MemoryTax: The Bitter Lesson of Agent Memory](https://arxiv.org/abs/2610.29823)
- Popularity: arXiv only
- Problem: When models are strong enough to search history on their own, do pre-designed memories like Mem0 and Zep still have value?
- Method: On one LoCoMo conversation, compares four memory approaches (full context, BM25, Mem0, Zep) with three coding agents (Pi, Codex, Claude Code), paired with three models, recording the cost of each rollout.
- Result/significance: Designed memory looks more like a patch for weak models; its ceiling is set by the model that writes the memory. With strong models, Pi reaches 99% at less than half the cost of full context. Note that the authors state this is a small-scale study with a single conversation and one run per cell.

### [Same Simulation, Different Evidence: Where Retrieved Tool Output Costs LLM Agents Accuracy](https://arxiv.org/abs/2610.26836)
- Popularity: arXiv only
- Problem: When a harness stores long tool output as files and lets the agent retrieve it on demand, where does accuracy get lost?
- Method: Using the PHREEQC geochemical simulator (reports up to 846.8k characters) and 158 executably verified questions, compares agents reading through a section index with reading directly in context.
- Result/significance: GPT-5.1/5.2 lose 11.3 and 7.9 points, respectively, when reading via retrieval, while Claude Opus 4.6/Sonnet 4.6 show no significant loss; the cause is "evidence substitution" (skipping the report and answering from their own, more precise output files). It explicitly notes that authoritative output can add 6.3–7.9 points.

### [More Memory, Worse Agents: Error Reproduction and Anti-Persistence in LLM Agents](https://arxiv.org/abs/2610.27406)
- Popularity: HF 👍8
- Problem: Errors in stored rules/summaries/skills get repeatedly regenerated through an abstract-execute-reabstract loop.
- Method: Proposes Anti-Persistence: only trajectories and outcomes are accumulated, task-relevant guidance is reconstructed on demand, and an adaptive selector decides from past outcomes whether and how to synthesize it, to be discarded after use.
- Result/significance: Across multiple benchmarks and backbones, held-out success rates are higher, and the LLM call cost is the lowest among the memory designs compared.

### [When the harness decides success: state that cannot be re-observed](https://arxiv.org/abs/2610.26632)
- Popularity: arXiv only
- Problem: When does a harness discarding/summarizing old turns or replaying reasoning actually change success or failure, rather than just cost?
- Method: Truncates the context window in a preregistered synthetic probe; on ARC-AGI-3, decomposes the gap between the Standard and Provider Adapter harnesses component by component.
- Result/significance: Truncation costs almost nothing when facts can be re-queried, but drops to chance level when they cannot be re-observed, a gap of 92.5 percentage points; replacing discarding with summarization while keeping a note-taking prompt recovers 86% of a 63-point gap. The authors note that the ARC-AGI-3 parts are single-run point estimates.

## 3. Research Trend Observations

1. **Memory and context management shift from "how to store" to "whether to store, and when to use"**. REM, TokenWorth (learning which experiences are "worth remembering"), Anti-Persistence, MemoryTax, and LoCoMo/LongMemEval-style work such as Uni-Mem, Memory as Code and MHG-Mem all focus on selectivity, on-demand use and structure; meanwhile several empirical studies (MemoryTax, Same Simulation, harness decides success) show that a harness's context-handling choices directly determine outcomes.
2. **Harness is both an optimization target and a source of risk**. On one side is harness self-evolution/co-evolution (CoEvo-RSI, Self-HPO, HarnessPro, RiseHarness, HarnessAdapt-RL); on the other, attribution research (HDA) suggests gains may be overestimated, while Compaction Laundering, ClawMMU and AutoRedClaw reveal trust-boundary problems in compaction, memory and persistent configuration.
3. **Context control at the cache level is becoming systematic**. Cache Engineering and MemT-1.0 reduce long-history overhead from the serving side and from inside the model, respectively, while Weighted State Souping composes context from cacheable state fragments; this contrasts with application-layer approaches such as summarization/pruning.
4. **Engineering-side echo**: Many papers in the data come with GitHub repos, among which Sage-A1.5 (577 stars), MemT-1.0 (301 stars) and OpenVLHarness (188 stars) draw relatively high attention, suggesting that harnesses, memory and agent models are active directions in the open-source community right now (star counts only reflect a data snapshot, not quality).
