## Hot list: Agent Context picks

### [Trial by Trace: Benchmarking AI Agent Harnesses for Reliability and Failure Attribution](https://arxiv.org/abs/2610.32285)
- Heat: HF 👍291 (1 day on the list, +128; 163 when first seen); no X mentions; code: [TraceLite-AI/TraceTrial-Bench](https://github.com/TraceLite-AI/TraceTrial-Bench) ★21
- Problem: Existing benchmarks grade models and rarely grade the agent harness itself.
- Method: TraceTrial-Bench splits harness reliability into 7 components: context, execution, governance, lifecycle, observability, tools, verification. It has 95 tasks, a trace-tracking (TT) module and an MEA module. MEA collects evidence from the agent's context, the harness and the execution environment. A failure-attribution (FA) module then attributes failures per run.
- Result: Across 4 harnesses, 9 models and 3,420 runs, harness macro-average scores range from 59.8% to 72.0%. In 31.1% of runs the task succeeded but at least one harness standard was violated.
- Take: The fastest-rising harness benchmark today. The "task success ≠ harness reliability" number is the most shareable part.

### [Is Complex Agentic Memory Always Needed? Naive RAG Is Stronger Than We Thought](https://arxiv.org/abs/2610.30755)
- Heat: HF 👍38 (5 days on the list, +24; 14 when first seen); 1 X mention ([@omarsar0's post](https://x.com/omarsar0/status/2113635562578178147), ❤896; follower count and date not provided); code: [Litmeb/RAW-RAG](https://github.com/Litmeb/RAW-RAG) ★33
- Problem: Are complex agentic memory designs (rewriting, structuring, learned retrieval) actually necessary?
- Method: Raw-RAG runs dense retrieval plus reranking over the raw history and hands the result to a reader LLM. It is compared on LoCoMo, LongMemEval, MEME and MemoryAgentBench. The evidence analysis finds that its higher coverage of the needed evidence offsets its lower utilization. Transformed memory stores stay less accurate than raw evidence even when fully accessible.
- Result: First in 6 of 7 benchmark-model settings, ahead of the strongest compared system by 0.13–5.53 points.
- Take: The only memory paper today with X traction. Its X engagement (❤896) is well above its HF likes, so the spread is mostly on X.

### [Memory-Centric Continual Learning for AI Agents](https://arxiv.org/abs/2610.29357)
- Heat: HF 👍43 (6 days on the list, +24; 19 when first seen); no code, no X
- Problem: External memory is mostly treated as a passive retrieval cache, and it is unclear whether it delivers continual learning.
- Method: Proposes MCCL. It has a three-axis taxonomy (where memory lives: substrates; its form: assets; how it is managed: policies) and a two-level lifecycle: an inner loop updates memory, and an outer loop improves the management policy from task feedback. An evaluation protocol tests retention under interference, adaptation to change and task transfer. A memory-scaling framework is added.
- Result: Argues memory should be judged by whether it improves future actions, not only by retrieval.
- Take: A position/framework paper with no experimental numbers.

### [MemPilot: Orchestrating On-Demand Multimodal Memory Curation for LLM Agents](https://arxiv.org/abs/2610.06830)
- Heat: HF 👍41 (6 days on the list, +5); code: [ViktorAxelsen/MemPilot](https://github.com/ViktorAxelsen/MemPilot) ★7
- Problem: Most memory systems are built ahead of time, independent of the query. That wastes preprocessing and can drop details that only matter later.
- Method: Trains a multi-step LLM policy with reinforcement learning. At each step it chooses between retrieving from query-agnostic memory and delegating query-specific curation of the raw multimodal history to different LLMs/VLMs. It controls evidence volume, curation instructions, model choice and visual access. It also uses per-objective advantage estimation and prefix marginal-utility estimation.
- Result: On 5 multimodal memory benchmarks, the performance-cost-latency frontier under different preferences is wider than that of existing trade-off-aware baselines.
- Take: A counterpoint to Raw-RAG: it argues for curating the raw history on demand rather than compressing it in advance.

### [StreamVibe: Proactive Video Agents for Evolving User Intent](https://arxiv.org/abs/2610.34662)
- Heat: HF 👍253 (1 day on the list, +22); no code, no X
- Problem: Current models rely on explicit requests, miss implicit intent, and can't update their state as the user's request changes.
- Method: StreamVibe-Harness stores user intent as persistent state with a flexible lifecycle, and uses hierarchical memory to track the latest user intent and environment state. It comes with StreamVibe-Bench (4.1K evaluation samples, 85K training samples) and a streaming model, StreamVibe-VL.
- Result: StreamVibe-VL beats other baselines by 10.7% on response timing and answer quality. Adding the harness improves proactive interaction by 12.3%.
- Take: Mostly a video/multimodal paper. Its Agent Context relevance is the hierarchical memory, so it ranks fourth.

### [DeltaStreamer: Towards Human-Like Agentic Streaming Video Understanding](https://arxiv.org/abs/2610.19849)
- Heat: HF 👍38 (5 days on the list, +0); code: [BBBBchan/DeltaStreamer](https://github.com/BBBBchan/DeltaStreamer) ★87
- Problem: Streaming video agents must keep evidence without knowing future questions. Compressing history blurs event transitions and loses details that can't be recovered.
- Method: Before a query arrives, the model keeps watching and writes visual changes explicitly into structured memory (change-aware memory). Once a query arrives, a planner decides what evidence is needed, which guides memory retrieval and targeted replay of past frames.
- Result: 66.07% on OVO-Bench and 59.53% on StreamingBench.
- Take: "Compress, then replay to recover" matches how text agents approach context compression.

## New: announced last night

- [The Trinity](https://arxiv.org/abs/2610.36077): Three roles (Creator/Explorer/Evolver) organize tasks into a capability tree and evolve harness modules along it, with a capability-aware router. +34 on average across 28 training benchmarks, +26 on 18 unseen ones (early heat 👍307).
- [HABIT-Bench](https://arxiv.org/abs/2610.24520): Tests whether agent memory systems can infer user habits from weak evidence across hundreds of sessions and apply them. The best memory method reaches only 33.61% macro-average accuracy (👍78).
- [Memory Tax](https://arxiv.org/abs/2610.34073): Splits memory's net value into "memory gain" and "memory tax". Most dedicated memory systems lose to naive RAG in several cases (👍68; [@omarsar0 post](https://x.com/omarsar0/status/2115098954799169970) ❤109).
- [ReGE](https://arxiv.org/abs/2610.33861): One coach call turns the execution records of several attempts into guidance for the next round. Accuracy across 4 benchmarks improves by 9.9 points on average for GPT and 8.8 for Claude (👍13).
- [Rethinking Verification in Agent Harnesses](https://arxiv.org/abs/2610.34577): Compares 17 verification designs. An independent critic review has the best precision-cost trade-off, gaining 5.9–9.5 points on Terminal-Bench at about 1.13–1.25x the baseline cost (👍9).
- [HaMo](https://arxiv.org/abs/2610.34724): Distills trajectories into strategy-level experience cards retrieved on the fly, while an experience-conditioned continual-learning objective slowly updates parameters (👍5).
- [Stratum](https://arxiv.org/abs/2610.36153): Cross-session repository memory for coding agents. On 8 real bugs, fresh agents that inherit the memory found the root-cause file in 21 of 24 tries, versus 6/24 for a retrieval-only baseline, at 4.5x lower median token cost.
- [Context Is a Pipeline, Not a Window](https://arxiv.org/abs/2610.36114): Across 720 runs the largest prompt used only 5.75% of the window, yet 3,827 of 11,189 tool results were cut by a fixed length into broken JSON. 2 of the 7 agent frameworks surveyed truncate the same way. The authors also say whether truncation lowers accuracy is still unsettled.
- [TrawMem](https://arxiv.org/abs/2610.36918): Organizes memory by task role instead of relevance alone. On LoCoMo, LLM-Judge scores are 4.07/4.31 points above SimpleMem, with about 12.8%/5.1% fewer context tokens.
- [Tessera](https://arxiv.org/abs/2610.37080): A training-free evidence-delivery layer for web RAG. It rebuilds pages into fine-grained evidence units with titles, section paths and table headers, gaining 5–6 points of accuracy at the same token budget.
- [WAKMan](https://arxiv.org/abs/2610.36355): Picks a KV cache eviction policy from live traffic. Agentic requests favor recency: LRU's hit rate beats S3FIFO by 12% on mixes with more agentic traffic and trails by up to 22% elsewhere. WAKMan beats LRU by 5 points on average.
- [Your Policy Is Secretly a Harness](https://arxiv.org/abs/2610.37255): Argues in theory that a trained policy carries its harness's preferences. In MiniWoB++, merely reordering observation fields drops success from 85.0% to 19.2% (👍6).

## Observations

- Memory research is converging on raw evidence. [Raw-RAG](https://arxiv.org/abs/2610.30755) (first in 6 of 7 settings), [Memory Tax](https://arxiv.org/abs/2610.34073) (new tonight) and [HABIT-Bench](https://arxiv.org/abs/2610.24520) (best memory method at 33.61%) all ask whether memory processing throws evidence away. [Tessera](https://arxiv.org/abs/2610.37080) and [Context Is a Pipeline](https://arxiv.org/abs/2610.36114) also quantify evidence lost before it reaches the model.
- The harness itself is now being benchmarked, trained and self-evolved: [TraceTrial-Bench](https://arxiv.org/abs/2610.32285), [Self-Evolving Agent Harness](https://arxiv.org/abs/2610.18813), [HarnessPro](https://arxiv.org/abs/2610.26770), [Harness Scaling](https://arxiv.org/abs/2610.29458), [The Trinity](https://arxiv.org/abs/2610.36077), [Rethinking Verification](https://arxiv.org/abs/2610.34577) and [Your Policy Is Secretly a Harness](https://arxiv.org/abs/2610.37255). Several harness papers also appear in today's New list.
- On the engineering side, [OpenGCUA](https://github.com/Tongyi-MAI/OpenGCUA) (★441) and [Harness-RSI](https://github.com/zgcagi/Harness-RSI) (★387) have the most GitHub stars among the rising papers. Their HF likes haven't grown since first reported, so their heat comes mainly from the repo side. [DynaFlow](https://github.com/amiya-special/Dynaflow) (★107) and [HarnessPro](https://github.com/pzs19/HarnessPro) (★110) also have relatively high star counts.
- Continual learning and experience reuse is becoming its own topic. [Continual Learning Exam](https://arxiv.org/abs/2610.33956), [MCCL](https://arxiv.org/abs/2610.29357), [HaMo](https://arxiv.org/abs/2610.34724), [ReGE](https://arxiv.org/abs/2610.33861) and [Stratum](https://arxiv.org/abs/2610.36153) all center on carrying experience into the next attempt.
