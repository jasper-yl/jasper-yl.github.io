## Today's highlights
- Context management is moving from compressing text to passing KV state in latent space. [Octopus](https://arxiv.org/abs/2611.06956) (a DAG of forked KV states), [SwarmEvolve](https://arxiv.org/abs/2611.08483) (agents pass KV cache to each other) and [CacheGraft](https://arxiv.org/abs/2611.07393) (documents pre-encoded as KV) all appeared on the same day, in the New section.
- The harness is now an optimization target. [Harness-S](https://arxiv.org/abs/2611.04277) (👍51 in New, the day's highest), [ParetoSaddler](https://arxiv.org/abs/2611.02079) and [RoboArchitect](https://arxiv.org/abs/2610.42141) all improve or evolve harnesses automatically.
- Memory work is getting deeper. [EvoMemState](https://arxiv.org/abs/2611.03743) turns memory from independent facts into facts with relational state, and [MemSteer](https://arxiv.org/abs/2610.39276) generates supervision from user histories to tune memory design.
- Long-horizon context problems now have a direct benchmark. [Switch-SWE](https://arxiv.org/abs/2611.02017) tests whether an agent recovers after switching tasks, and its context-management plugin adds 5.5 to 15.5 percentage points.
- Many benchmark papers ([FrontierPhysics](https://arxiv.org/abs/2611.06910), [MCPHallu](https://arxiv.org/abs/2611.07689) and others) conclude that frontier agents still have clear gaps.

## 🔥 Trending: Agent Context picks

### [Switch-SWE: Do Coding Agents Hold Focus When Switching Between Unfinished Tasks?](https://arxiv.org/abs/2611.02017)
- Heat: HF 👍9 (listed 3 days, +9 since); code [Miraclecsc/Switch-SWE](https://github.com/Miraclecsc/Switch-SWE) ⭐26.
- Problem: after a coding agent switches among several unfinished tasks in one repo, can it recover each earlier task's requirements and progress?
- Method: 200 focus tasks across 19 Python repos, built into 400 paired sessions (uninterrupted vs. interleaved with other tasks). Trajectory analysis found two typical failures: requirements mixed up across tasks, and lost task state. The authors add a plug-in context-management module that selects task-relevant history and keeps a concise task-state summary.
- Result: across 7 agents, interleaving costs 11.5 percentage points on average (range 6.0 to 15.0). On OpenCode the module raises focus-task completion by 5.5 to 15.5 points.

### [EvoMemState: Evolving Memory State for Personal Agents](https://arxiv.org/abs/2611.03743)
- Heat: HF 👍20 (listed 2 days, +20 since); code [XMUDeepLIT/EvoMemState](https://github.com/XMUDeepLIT/EvoMemState) ⭐3.
- Problem: current long-term memory systems treat memories as independent facts. They ignore how a new fact updates, constrains or conflicts with an old one, and don't say whether the facts apply to the current request.
- Method: memory is organized around "state." Persistent facts are first extracted with ontology guidance, and Relational States record each fact's validity, scope and evolution. An RL-trained policy then produces a request-specific Reasoning State. The answer uses the relevant facts, relational states and reasoning state together.
- Result: on long-conversation and memory-use benchmarks, retrieval completeness and memory-based answer accuracy are consistently better than existing memory systems.

### [MemSteer: Turning User Histories into Supervision for Agent Memory Optimization](https://arxiv.org/abs/2610.39276)
- Heat: HF 👍8 (listed 7 days, +8 since); no code repo.
- Problem: a new user's history has no labels, and hand-building QA pairs and evidence is too expensive to use for tuning memory design.
- Method: MemSteer turns unlabeled user histories into evidence-backed QA supervision. It builds an evidence-grounded answer plan first, then generates questions, checked by source audit and blind-answer recovery. MemSteer-Opt uses these QA pairs to evaluate memory designs and diagnose failures. It changes memory storage, retrieval and context construction directly, without updating model parameters.
- Result: versus Base-BM25, ATM-Bench Question Score is +13.4 points and RHELM accuracy is +4.1 (no external data) / +6.6 (with external data). Performance matches optimization guided by the official QA.

### [GEPA-Curator: Curated Learning for Self Improving Agents](https://arxiv.org/abs/2610.37651)
- Heat: HF 👍8 (listed 3 days, +3 since); no code repo.
- Problem: reflective prompt optimizers like GEPA learn from failed rollouts, but a failure may come from harness limits, randomness or judge noise. Such failures may not be useful signal and can even hurt.
- Method: task curation filters out tasks likely to be noisy. Prior-success retrieval fetches past successful trajectories for each task and hands them to the optimizer as extra context.
- Result: matches or beats baselines on GoBrowse, ALFWorld, AppWorld and τ-bench, up to 20.7% above GEPA and 21.2% above ACE.

### [RoboArchitect: Automating the Design of Robotic Agents with Persistent Memory](https://arxiv.org/abs/2610.42141)
- Heat: HF 👍8 (listed 4 days, +3 since); code [roboarchitect-ai/RoboArchitect](https://github.com/roboarchitect-ai/RoboArchitect) ⭐9.
- Problem: a frozen robot policy performs better inside an agent harness, but the harness is hand-redesigned for each robot or benchmark.
- Method: a coding model watches rollouts, diagnoses failures and iteratively edits the harness around the frozen policy, with no weight updates. The harness also evolves its own persistent memory, carrying learned experience (such as effective grasp depth) into later decisions.
- Result: success on unseen scenes goes from 9.7% to 43.3%, and on unseen tasks from 12.7% to 40.2%. The abstract says the evolved harness often beats fine-tuned versions.

### [Hybrid Computer Use: A Unified Programmatic, Semantic, and Visual Interface for General Agents](https://arxiv.org/abs/2610.41432)
- Heat: HF 👍14 (listed 1 day, +8 since); code [microsoft/Hybrid-Computer-Use](https://github.com/microsoft/Hybrid-Computer-Use) ⭐33.
- Problem: interfaces built around screenshots plus mouse and keyboard carry a human-interaction bias and force the model to re-read the screen repeatedly. The computer's semantic and programmatic capabilities go unused.
- Method: one interface with three channels: code/command line, accessibility (AX) semantics, and GUI vision. AX tools return compact observations, run actions in batches and report effects as AX diffs, which cuts interaction rounds. The interface also guards against acting on stale state when switching channels. An HCU skill guides the model in choosing and coordinating channels.
- Result: on OSWorld 2.0, HCU has the highest Partial and Binary scores among the compared systems.

## 🆕 New: announced last night
- [Harness-S: Learning from Sibling Harnesses for Generalizable Agent Training](https://arxiv.org/abs/2611.04277): evolves a pool of "sibling harnesses" from one base harness, called only when every attempt under the base harness fails. RL on those trajectories transfers the capability back into a single policy, clearly beating policy-only training on AppWorld, SWE-Gym and DBBench (preliminary 👍51; code [DeepExperience/Harness-S](https://github.com/DeepExperience/Harness-S) ⭐20).
- [QRAE: Query-Relevant Attention Entropy for Context Compression in DeepSearch Agents](https://arxiv.org/abs/2611.07976): sparse evidence-scoring attention heads decide which retrieved chunks stay in context, and uncertain chunks go to a candidate cache for re-evaluation. Success rises 2.35 points on average, latency falls 30% and token use falls 45%.
- [CORE: Coarse-to-Fine Search with Context Management for Deep Research](https://arxiv.org/abs/2611.07859): a training-free harness that returns only the most relevant snippet per passage and lets the agent expand context around retrieved sources while suppressing duplicate snippets. Best accuracy and evidence recall on three benchmarks including BrowseComp-Plus, on corpora up to 553 million documents.
- [Octopus: One Brain, Many Branches for Latent-KV Multi-Agent Reinforcement Learning](https://arxiv.org/abs/2611.06956): several threads share one backbone and fork, read and roll back inside a DAG of KV states on the GPU, with zero-copy branching. Qwen3.5-4B reaches 49.6% on BrowseComp-Plus (+17.5 points over single-agent GRPO) and peak KV memory drops 2.8×.
- [SwarmEvolve: Latent Agent Swarms for Evolutionary Discovery and Optimization](https://arxiv.org/abs/2611.08483): hundreds of low-cost agents reason in latent space and share information by passing KV cache. The median run matches other frameworks' 60-minute best in 3 to 8 minutes.
- [CacheGraft: Enhancing Retrieval-Augmented Generation via Latent-Space Document Enrichment](https://arxiv.org/abs/2611.07393): encodes corpus passages offline into a KV cache fused across a large and a small model, then injects it into the small model at query time. Beats the text-only baseline in 29 of 30 comparisons on 5 QA benchmarks.
- [MCPHallu: Benchmarking Reasoning, Execution, and Memory Hallucinations in MCP Agents](https://arxiv.org/abs/2611.07689): 358 tasks on 36 real MCP servers. 14 frontier agents average 0.642, and the pass rate on "unreachable goal" tasks is only 23.2%.
- [Don't Prompt Your Agents. Equip Them: Skillware](https://arxiv.org/abs/2611.07652): packages skills as versioned capability bundles with typed JSON contracts, deterministic Python code and unit tests. The abstract says 3B to 8B models equipped with them beat unequipped frontier models on multi-step workflows, with token use down by up to 84.8%.
- [Signed but Not Safe: Requirement Integrity in Multi-Agent LLM Handoffs](https://arxiv.org/abs/2611.07483): subagent handoffs carry a signed requirements list, cutting unsafe commits under attack from 69.4% to 9.0%. Attacks injected before signing still get through, so the extraction step is the trust boundary.
- [A Sharp Additive Bound for the Threshold Rule in Repeated Rent-or-Buy](https://arxiv.org/abs/2611.06955): a theoretical model abstracted from LLM-agent context management (when to reset history). It proves the threshold rule pays (2P-1)K more than optimal, and the coefficient is tight.
- [tok: a textual concrete syntax of BPMN and DMN for humans and AI agents](https://arxiv.org/abs/2611.07945): a plain-text syntax for BPMN/DMN (business process and decision notations) with an MCP server. It uses 2.2× fewer tokens than BPMN XML, and agents write valid tok 97.6% to 100% of the time.
- [Towards Foundation Decision Models: Drex](https://arxiv.org/abs/2611.07854): given a state (including agent context) and a set of options, outputs a probability distribution over options without autoregressive decoding. Max takes about 183 ms per request vs. about 2.0 s for GPT-6 Sol (preliminary 👍15; code [nace-ai/drex-decision-models](https://github.com/nace-ai/drex-decision-models) ⭐98).
