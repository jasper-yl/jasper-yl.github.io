## 🔥 Hot list: Agent Context picks

### [Embeddings vs. Grep: Rethinking the Dense Advantage in Code Search](https://arxiv.org/abs/2611.20455)
- Heat: HF 👍8 (2 days on the list, +5); no code repo.
- Problem: Code search benchmarks show dense encoders far ahead of BM25, yet coding agents do well with grep. What is that advantage measuring?
- Method: The authors build Repo-Premium, a repo-level code search benchmark: 6 languages, PRs from 2022 to 2026, preregistered test pools covering 91 repos, with both curated and raw queries. The dense advantage traces to two sources: evaluation choices that favor dense retrieval (chunking for BM25, counting edited tests as relevant) and queries that lack the rare identifiers found in code. Expanding queries with LLM-written identifiers (generate-then-grep) helps BM25 far more than dense retrieval.
- Takeaway: BM25 matches dense retrieval on every Python pool, including PRs opened after the LLM's release. The authors recommend measuring dense gains against a fair lexical baseline, fusing dense retrieval with BM25, and adding code vocabulary to queries that lack it. No method predicts which retriever wins on a given query.

### [CarryOn: Learning What to Keep in Context for Long-Horizon LLM Agents](https://arxiv.org/abs/2611.17808)
- Heat: arXiv only, no HF upvotes (6 days on the list); no code repo.
- Problem: Summary-style compression drops exact details later actions need, while keeping the full history drags in a lot of irrelevant material.
- Method: A lightweight context manager pairs a compact execution state with fine-grained evidence that keeps source links. A learned selector and an adaptive retention policy manage context without extra LLM calls. The authors also propose two metrics: Sα (success first, resource-aware) and NCS (normalized cost per success).
- Takeaway: On AppWorld, OfficeBench and Tau2 Telecom, across three LLM actors, macro-average success is 75.7%, 6.7 points above the strongest baseline, and it also scores best on both metrics.

### [Experience Rot: Experienced Agents Fail Where Novices Succeed](https://arxiv.org/abs/2611.20922)
- Heat: arXiv only, no HF upvotes (5 days on the list); no code repo.
- Problem: Agents reuse conversation history, memory files, retrieved notes and skills as experience. What happens when a tool (an MCP definition) is silently changed?
- Method: Across a range of models, the authors compare agents with and without experience after a silent tool change. Experienced agents copy earlier calls without checking the current interface, even when the tool definition shows the change, and then report success.
- Takeaway: After the change, experienced agents fail most tasks while inexperienced ones mostly succeed. The failure shows up in every memory form tested and worsens with more experience. Announcing the update barely helps, and telling the agent to read the docs does not help when the docs don't state the answer.

### [LEDGER: Auditable Agent Memory Under Change](https://arxiv.org/abs/2611.20927)
- Heat: arXiv only, no HF upvotes (5 days on the list); no code repo.
- Problem: Most memory systems are evaluated on fixed histories, but in practice facts change, sources differ in reliability, and users ask to be forgotten.
- Method: The language model only proposes facts. Explicit rules decide which value is current, which source to trust and what to delete, and each fact keeps its source and validity period. LEDGER+EP searches raw conversation turns for questions the ledger can't cover, and also purges those turns on deletion.
- Takeaway: On the authors' own synthetic coding-agent workload, LEDGER+EP answers 94.3% correctly (5 dev seeds) and 91.1% (5 held-out seeds), against 82.1% and 83.3% for the strongest baseline, full-history replay. On a 210-question LongMemEval subset it ties full-history replay at 74.8% accuracy using 1% of the context. Caveats: the synthetic workload is self-built, and on LongMemEval the gaps among the strongest systems fall within confidence intervals.

### [Instant Weight-Space Consolidation for Long-Term Memory in LLMs](https://arxiv.org/abs/2611.20759)
- Heat: arXiv only, no HF upvotes (5 days on the list); no code repo.
- Problem: Text-based agent memory does not make the model itself evolve. Extraction errors accumulate, cross-session patterns stay hidden, and build cost grows with the conversation.
- Method: CLAM (Carried Latent Adapter Memory) uses a recurrent hypernetwork for parametric consolidation. One forward pass compiles a stream of session activations into a low-rank adapter, with no gradient steps and no language-model generation calls. A gated latent state carries knowledge across sessions at fixed size, and an episodic buffer supplies verbatim detail at inference time.
- Takeaway: On LoCoMo and LongMemEval-S, across three 2B to 7B open models, CLAM beats all agentic baselines by 1 to 45 points and all gradient-based parametric methods by 10 to 45 points, and builds memory 3 to 151 times faster than extraction-based systems. The consolidated adapter adds 12 to 15 points when the buffer misses the evidence, and 4 to 5 points even when the buffer is an oracle.

### [Continual-ARC: Measuring Skill Acquisition over a Working Lifetime](https://arxiv.org/abs/2611.14505)
- Heat: HF 👍3 (6 days on the list; 9 when first seen in the data, change -6); repo [unifyai/continual-arc](https://github.com/unifyai/continual-arc) ⭐39.
- Problem: Existing continual-learning benchmarks cover one domain, show each instance once, and can't put memory-based and weight-based systems on the same scale.
- Method: Built on three ARC-AGI versions, it creates a lifetime task stream. Tasks return after dormant gaps with new instances while new tasks keep arriving. A learner can spend budget on viewing demonstrations, submitting answers or acting inside a harness, and is scored by the share of feedback budget consumed. After the stream ends, the learner is frozen and tested on seen tasks (memory) and unseen tasks (generalization).
- Takeaway: A frozen-weights harness with persistence usually doesn't improve memory unless explicit expert guidance is provided. Most harness methods learn less than the floor of simply caching each task's demonstrations. No harness method gains on unseen tasks, while weight-based learning shows clear gains.

### [Invariant-Aware Harness Enforcement to Protect LLM Agents from Silent API Failures](https://arxiv.org/abs/2611.20595)
- Heat: HF 👍5 (4 days on the list, +2); repo [Sajib-006/silentguard](https://github.com/Sajib-006/silentguard) ⭐1.
- Problem: An API can fail silently, for example by ignoring a misnamed filter while still returning HTTP 200 and a plausible wrong result. Asking the model to check itself (checklists, reviewer models, LLM judges) works poorly.
- Method: SilentGuard moves the decision from the model to the harness that executes tool calls. The harness checks every result against invariants any correct API should satisfy, and withholds values that violate them.
- Takeaway: 11 of 15 public research APIs show silent failures, with counts inflated up to 691 times. On 7 open models, wrong answers under targeted faults drop from 74.0% to 1.7% with no harm to fault-free tasks. For three frontier models the drop is from 70.2% to 0.5%. The same check as a warning only still leaves 70.1% wrong, so enforcement is what matters. On new fault types, the harness alone cuts errors from 61.1% to 24.5%, by abstaining rather than recovering.

### [Forget the Lineage: Forward-Secure, Lineage-Complete Cryptographic Erasure for LLM-Agent Memory](https://arxiv.org/abs/2611.18133)
- Heat: arXiv only, no HF upvotes (6 days on the list); no code repo.
- Problem: Agent long-term memory is written by the model itself (summaries, facts, embeddings). Deleting one message is not enough, because derivatives, storage remnants and backups remain.
- Method: LinEra derives each child memory's key from its parent's key along the derivation graph, with the source key coming from a puncturable PRF (pseudorandom function). Forgetting takes a single puncture, and every descendant becomes unreadable without having to be located. It is integrated with mem0.
- Takeaway: On LoCoMo conversations, an attacker holding all files and the current key can recover 70 of 71 forgotten secrets after logical deletion (10 conversations written by the largest model) and 67 with per-object or epoch keys. Under LinEra the attacker recovers none. The cost is a larger forgetting radius: forgetting 1% of turns erases 73.0% of derived memories under session-level summaries but only 3.8% under a four-turn window, which also answers better.

## Observations

- The Agent Context papers on today's hot list cluster around whether memory and experience backfire. Experience Rot shows experience dragging agents down after a tool change. Continual-ARC finds most harness-persistence methods learn less than the floor of caching demonstrations and gain nothing on unseen tasks. LEDGER and LinEra deal with memory that changes over time and that must be auditable and erasable. All of them point to memory needing versions, provenance and deletion.
- Context management is leaning toward methods that make no extra LLM calls. CarryOn uses a learned selector. CLAM compiles memory into an adapter in one forward pass (zero generation calls, 3 to 151 times faster to build). LEDGER+EP matches full-history replay on LongMemEval accuracy with 1% of the context. On the retrieval side, "Embeddings vs. Grep" calls for fair baselines and suggests fusing dense retrieval with BM25.
- Harness designs share one pattern: deterministic outer logic does the checking. SilentGuard uses invariant checks and enforced abstention, and System 1 agents use a deterministic compiler plus a single decision pass. In each paper's own experiments, error rates are much lower than with the model judging alone.
