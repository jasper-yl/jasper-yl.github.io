### [Gamer: A Generalist Vision-Language-Action Foundation Model for Long-Horizon Real-Time Game Agent](https://arxiv.org/abs/2611.18397)
- Heat: HF 👍116 (1 day on the list, +30); code [RainBowLuoCS/Gamer](https://github.com/RainBowLuoCS/Gamer) ⭐243 (⭐124 in the 11-16 report). No X data. Reported as a new paper in the 11-16 report (👍86; see the 11-16 report).
- Problem: In long-horizon, real-time game and GUI tasks, a limited context window, accumulated errors and sparse rewards make it hard for an agent to keep going.
- Method: An end-to-end architecture combines perception, memory management and multi-step reasoning. It is continually pretrained on tens of thousands of hours of keyboard-and-mouse interaction data, then instruction-tuned with sparse thinking to cut redundant reasoning. Stable multi-turn RL trains long-horizon interaction and explicitly targets the limited context window. A cloud-edge inference engine supports "unbounded context execution."
- Result: It generalizes well across several 3D open-world games with efficiency comparable to skilled players, and is competitive on 2D game benchmarks.

### [Envisioning Agentic Robotics: A New Era of Robotic Systems](https://arxiv.org/abs/2611.18359)
- Heat: HF 👍123 (1 day on the list, +16), top of the hot list. No code. Reported as a new paper in the 11-16 report (👍107).
- Problem: Agentic robotics has no shared definition, no reliable evaluation framework and no research roadmap.
- Method: It proposes an "embodied System 2": a foundation model plus an embodied harness as the decision core. Inside the harness, a closed loop observes, understands intent, reasons, calls skills and tools, verifies results and adjusts strategy. It gives an evaluation framework that measures both model capability and closed-loop system performance, and summarizes which principles carry over from digital agents to physical ones.
- Result: A roadmap toward "sustained autonomy," from executing single primitives to holding standing roles. This is a position paper with no experimental numbers.

### [Continual-ARC: Measuring Skill Acquisition over a Working Lifetime](https://arxiv.org/abs/2611.14505)
- Heat: HF 👍10 (1 day on the list, +1); code [unifyai/continual-arc](https://github.com/unifyai/continual-arc) ⭐37.
- Problem: Existing continual-learning benchmarks are mostly single-domain and show each instance once, so memory-based and weight-based systems can't be compared on one scale.
- Method: Three ARC-AGI versions form a lifetime task stream, and the same tasks return after a gap with fresh instances. A learner can pay to see a demonstration, submit an answer or act in a harness, and is scored on the feedback budget it spends. The learner is frozen at test time, and "seen tasks" (memory) and "unseen tasks" (generalization) are measured separately. The authors ran Qwen3.5-9B and GLM-5.3 Flash as frozen-weight harnesses with and without persistence, and compared them against two prompting floors, program induction and imitation-trained weights.
- Result: Harness persistence generally doesn't improve memory performance unless explicit expert guidance is given. Most harness methods learn less than the floor of just caching each task's demonstrations. Harness methods show no gain on unseen tasks, while weight learning gains clearly.

### [Can LLM Agents Organize Their Own Memory? (SoMem)](https://arxiv.org/abs/2611.11929)
- Heat: source arXiv, no HF upvotes (7 days on the list); code [Qi202/SoMem](https://github.com/Qi202/SoMem), no star count in the data. Appeared in the 11-10 and 11-16 reports (see the 11-10 report). Appeared the same day as MIRIX-2.0 but takes a different approach.
- Problem: Memory with fixed records and fixed organizing rules adapts poorly to changing tasks.
- Method: Memory is stored as plain documents linked to each other. The agent decides what to summarize, how to categorize and when to revise a topic, and every summary links back to the original interaction as evidence. Updates are validated at runtime, and three views (temporal, relational, recency) are derived automatically. At query time the agent chooses what to search and read, and follows links back to the raw evidence.
- Result: It beats the strongest baseline by 2.66, 3.10 and 2.00 points on LoCoMo, BEAM-100K and LongMemEval-S. Memory transfers across models, and more inference effort improves it further.

### [Review the Episodes, Refine the Lessons: Simple Memory Evolution for Embodied Agents (SimplEvo)](https://arxiv.org/abs/2611.11509)
- Heat: source arXiv, no upvotes (7 days on the list); no code link.
- Problem: Nobody has verified whether harnesses stacked around an MLLM (post-training strategies, recursive self-improvement loops) really beat the MLLM's own ability.
- Method: No weight updates, no post-training, no privileged information. The MLLM first writes a coordinate-free task memory from one demonstration, then maintains a bounded working memory over training episodes, distilling lessons after each episode along "procedure, completion, recovery." Both memories are frozen at test time.
- Result: On EBench, GPT-6-Astra's direct-control success rate rises from 46.7% to 81.7%. It ranks first on RoboDojo with SR 69.63% and score 75.32. Text-only memory matches the success rate of memory that stores past frames while using fewer tokens, and working memory written by GPT-6-Astra can be handed to weaker MLLMs to improve them.

### [When Should Agents Remember? Falsification-Gated Self-Evolution for LLM Agents (FGSE)](https://arxiv.org/abs/2611.14326)
- Heat: source arXiv, no upvotes (6 days on the list); no code link.
- Problem: Self-improvement often writes a lesson from a single episode straight into memory, but local success is unreliable.
- Method: Each candidate lesson is written as a structured hypothesis (precondition, behavior change, expected effect, verifier). It is applied only in temporary state and tested with three kinds of probes: target transfer, falsification and archived regression. Commit, refine or reject is then decided from measured gain and risk.
- Result: WebArena success 39.8, AppWorld average completion 78.8, τ-Retail / τ-Airline Pass^1 of 0.724 / 0.487. Falsification failures fall to 5.0%, regression damage to 1.3%, and harmful committed updates to 3.6%.

### [Verify Before You Fetch: Reliable KV Cache Compression for LLM Inference (VerKV)](https://arxiv.org/abs/2611.11319)
- Heat: source arXiv, no upvotes (7 days on the list); no code link. Appeared in the 11-10 report.
- Problem: For long-context, long-lived agents, the KV cache outgrows GPU memory and is offloaded to CPU, where CPU-to-GPU transfer dominates latency. Query-independent compression can't guarantee accuracy for every query.
- Method: The GPU holds a small set of query-independent key tokens (picked by PoissonComp random sampling) plus a token-level sketch of the whole KV cache, while the full cache stays on the CPU. At inference, KVFetch uses these to estimate the relative error of attention. If it meets the user-set (ε, δ) tolerance, host memory is not touched. Otherwise more tokens are fetched from the CPU per query.
- Result: At 32K context, averaged over RULER and LOFT, it reaches 90–100% of dense quality, cuts GPU memory 8–32×, and holds CPU-to-GPU fetching per generated token to 2–23% of the cache.

## 4. 🆕 New: announced last night

- [Sage S2.1 Flash Technical Report](https://arxiv.org/abs/2611.21072): a 320B-parameter MoE model for scientific reasoning and agent work, initial 👍81 (highest among new papers). Results: OfficeQA Pro 72.2, MLE-bench Lite 90.3 HumanRank, OSWorld-Verified 85.2 (second), WebArena-Verified 67.6 (second). Code: [InternLM/Sage-S2.1-Flash](https://github.com/InternLM/Sage-S2.1-Flash) ⭐22. The title says S2.1 but the abstract body says S1.5.
- [SPILLWAY](https://arxiv.org/abs/2611.07222): uses typed fields in tool returns to judge whether an action's target is trustworthy, deterministically stopping prompt injection from redirecting email or payments to an attacker. The abstract says no standard templated injection succeeds, and an RL-trained attacker reaches an average in-scope attack success rate of .007 (initial 👍46).
- [SWE-CoWork](https://arxiv.org/abs/2611.20218): 101 tasks where an agent must piece together requirements in an organization with 26 simulated colleagues, then implement them. The top two models satisfy about 63% of F2P tests, but fully deliver fewer than 8% of tasks (initial 👍43).
- [Experience Rot: Experienced Agents Fail Where Novices Succeed](https://arxiv.org/abs/2611.20922): After an MCP tool is silently modified, agents with history, memory or skills copy the old call and still report success, failing most tasks, while novice agents mostly succeed. Announcing the update barely helps, and more experience makes it worse.
- [LEDGER: Auditable Agent Memory Under Change](https://arxiv.org/abs/2611.20927): A language model proposes facts, and explicit rules decide the current value, source trust and deletion. Each fact keeps its source and validity period. On a synthetic coding workload, LEDGER+EP scores 94.3% (dev seeds) / 91.1% (held-out seeds) against 82.1% / 83.3% for full replay. On LongMemEval it ties full replay at 74.8% using 1% of the context. Limitation: the workload is synthetic data built by the authors.
- [Instant Weight-Space Consolidation for Long-Term Memory in LLMs (CLAM)](https://arxiv.org/abs/2611.20759): A recurrent hypernetwork compresses session activations into a low-rank adapter in one forward pass, alongside an episodic buffer that keeps the original text. It leads agentic baselines by 1–45 points on LoCoMo and LongMemEval-S and builds memory 3–151× faster than extraction-based systems, with no gradient steps or generation calls.
- [HEAMS: Holistic Evaluation of Agent Memory Systems](https://arxiv.org/abs/2611.20144): evaluates memory systems on performance, efficiency, safety, privacy and user sovereignty. No system leads on all performance benchmarks, and high performance scores can coexist with poor privacy and safety scores. Code: [milatechtransfer/heams](https://github.com/milatechtransfer/heams).
- [EfficientSkill](https://arxiv.org/abs/2611.19823): learns reliable skills first, then prunes instructions with an accuracy guard, caps agent turns and moves reusable code into workspace tools. In 11 of 12 configurations it outputs fewer tokens than EvoSkill (up to 80% fewer), and gains +14.3 and +17.5 points on SpreadsheetBench.
- [Where Should LLM Agents Adapt at Test Time? In Context, in Weights, or Both](https://arxiv.org/abs/2611.19700): Compares ICL, GRPO and SDPO on Qwen3.5-9B across 109 tasks in 4 environments. ICL alone lifts average success from 28.8% to 49.4%, and adding GRPO reaches 51.6%. ICL also often skips checking and verification, and GRPO restores those behaviors.
- [Beyond Plain MCP: Do Decision Models and Code Mode Make Tool Use Cheaper and Faster?](https://arxiv.org/abs/2611.19123): Code mode uses 70–90% fewer tokens than plain MCP with higher utility. Declaring the return structure in the stub shifts weaker agents by up to 39.5 points. The hypothesis that adding a decision (routing) layer before code mode helps was not confirmed.
- [Building Fully On-Device GUI Agents with Mobile NPUs (DroidPrefill)](https://arxiv.org/abs/2611.20772): GUI agents have long inputs and short outputs, and NPUs are good at prefill but weak at decoding. Prefill-centered inference plus context management within a fixed context budget cuts per-step latency by up to 85.0% and raises task success by up to 24.6%.
- [Omni-Workspace](https://arxiv.org/abs/2611.19202): 380 multimodal workspace tasks, with the best of 18 models averaging 65.93. It identifies two problems, "multimodal context bloat" and "task state drift," and proposes OmniFocus (multimodal working-memory management plus explicit task-state tracking).

## 5. Research trend observations

- Memory research is moving from "how to store and retrieve" to "when to write and what to do when things change." [FGSE](https://arxiv.org/abs/2611.14326) (falsification gate), [EGE](https://arxiv.org/abs/2611.16378) (audit before adoption), [LEDGER](https://arxiv.org/abs/2611.20927) (fact validity and deletion) and Read Boundaries in Agent Memory (memory read consistency) all address the reliability of writes and updates. [HEAMS](https://arxiv.org/abs/2611.20144) also adds privacy, deletion and poisoning resistance to evaluation.
- Evidence that experience doesn't always help is growing: [Experience Rot](https://arxiv.org/abs/2611.20922) (experience hurts after tool changes), [Continual-ARC](https://arxiv.org/abs/2611.14505) (harness persistence loses to cached demonstrations) and [Where Should Agents Adapt](https://arxiv.org/abs/2611.19700) (ICL often skips verification). The three are similar only in showing side effects of experience or memory, so their conclusions shouldn't be applied to each other.
- Context and tool cost remain an engineering focus: [Beyond Plain MCP](https://arxiv.org/abs/2611.19123) (70–90% fewer tokens), [EfficientSkill](https://arxiv.org/abs/2611.19823) (up to 80% fewer output tokens), [VerKV](https://arxiv.org/abs/2611.11319) (8–32× less GPU memory) and [DroidPrefill](https://arxiv.org/abs/2611.20772) (fixed context budget).
