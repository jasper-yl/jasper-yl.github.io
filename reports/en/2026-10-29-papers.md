## 🔥 Hot list: Agent Context picks

### [The Trinity: Capability-Driven Recursive Self-Improvement for Multimodal Agents](https://arxiv.org/abs/2610.36077)
- Heat: HF 👍543 (1 day on the list, +236, 307 when first seen); code [InfRec-Cardinal/The-Trinity](https://github.com/InfRec-Cardinal/The-Trinity) ⭐26; no X mentions.
- Problem: Building verifiable environments is expensive, and hand-tuning harnesses can't keep up with task diversity.
- Method: Three roles: Creator, Explorer, Evolver. The Evolver uses verified execution traces to regroup tasks by shared capability needs into a layered "capability tree". The Creator abstracts simplified, verifiable simulated worlds for heterogeneous tasks at the same node (Capability-Driven Real2Sim2Real). The Explorer evolves reusable capability modules down the tree through selective inheritance, producing a harness tree. A Capability-Aware Harness Router picks a module configuration from the tree using only public task information.
- Result: The evolved harnesses gain 34 points on average across 28 training benchmarks and 26 points on 18 unseen benchmarks (including 2 real embodied tasks).
- Take: The hottest harness-design paper today.

### [Memory Tax: Dissecting the Net Value of Agent Memory](https://arxiv.org/abs/2610.34073)
- Heat: HF 👍149 (1 day on the list, +81); 1 X mention, [@omarsar0's post](https://x.com/omarsar0/status/2115098954799169970) ❤487; code [hexuan21/MemoryTax](https://github.com/hexuan21/MemoryTax) ⭐10.
- Problem: Is a dedicated memory system's net value positive or negative compared with retrieving raw history directly?
- Method: A large-scale evaluation across several benchmarks and backbone models, with naive RAG as the reference. It splits net value into memory benefit (gain) and memory tax (cost). The tax comes from memory processing changing how the original information is organized: restructuring facts and distilling preferences can also delete or blur evidence. The paper then analyzes the causes from the system side and the evaluation side, and extends the analysis to more settings.
- Result: Many dedicated memory systems do worse than naive RAG in a good number of cases, meaning their net value is negative.
- Take: Forms a memory group with HABIT-Bench and MemPilot today, and has the most buzz of the three (it spread on X).

### [HABIT-Bench: Evaluating Habit Induction from Longitudinal Weak Evidence in Agent Memory](https://arxiv.org/abs/2610.24520)
- Heat: HF 👍83 (1 day on the list, +5); code [LUMIA-Group/habit-bench](https://github.com/LUMIA-Group/habit-bench) ⭐4.
- Problem: Keeping past interactions doesn't guarantee an agent can infer user habits from weak evidence and use them appropriately.
- Method: Builds synthetic user histories spanning hundreds of sessions from task-oriented dialogue data and controlled habit graphs, covering dining, finance, software and travel. The four-choice questions include temporary exceptions, habit changes and suggestions the user didn't accept. Sampled questions were manually reviewed. Eight memory methods are evaluated.
- Result: The best memory method reaches only 33.61% macro-average accuracy across the four domains, and performance stays limited even when annotated evidence is supplied directly.

### [MemPilot: Orchestrating On-Demand Multimodal Memory Curation for LLM Agents](https://arxiv.org/abs/2610.06830)
- Heat: HF 👍41 (7 days on the list, +5); code [ViktorAxelsen/MemPilot](https://github.com/ViktorAxelsen/MemPilot) ⭐7.
- Problem: Most memory systems build memory without knowing the query. That wastes preprocessing and drops details that only matter later.
- Method: An RL-trained multi-step policy chooses at each step between retrieving from query-agnostic memory and handing the raw multimodal history to a heterogeneous LLM/VLM for query-specific curation. The policy jointly controls how much evidence to use, the curation instructions, model choice and visual access. Training uses objective-decomposed advantages and prefix-based marginal-utility estimates for credit assignment.
- Result: On 5 multimodal memory benchmarks, the performance-cost-latency frontier under different preferences is wider than that of existing trade-off-aware baselines.

### [DeLoop: Repeated Actions as Self-Supervision for Long-Horizon Agents](https://arxiv.org/abs/2610.19376)
- Heat: HF 👍33 (7 days on the list, +16); code [cskyl/deloop](https://github.com/cskyl/deloop) ⭐3.
- Problem: On long tasks, agents repeat the same tool call and get the same observation (a loop). It happens more often once history is compressed.
- Method: Looping actions from the agent's own rollouts serve as negatives, and the first non-looping action later in the same rollout serves as the positive, trained with DPO. No task reward, ground truth or LLM judge is needed.
- Result: In the CodeGym compression setting, the share of tasks containing loops for Qwen3-8B falls from 57.3% to 6.1%, and steps drop to about a third. Qwen3-32B's success rate rises from 37.7% to 44.8%.
- Take: Speaks directly to behavior degradation after context compression.

### [DeltaStreamer: Towards Human-Like Agentic Streaming Video Understanding](https://arxiv.org/abs/2610.19849)
- Heat: HF 👍38 (6 days on the list, +0); code [BBBBchan/DeltaStreamer](https://github.com/BBBBchan/DeltaStreamer) ⭐87.
- Problem: Streaming video requires keeping evidence without knowing future questions. Compressing history blurs event transitions and loses detail irrecoverably.
- Method: Observes continuously before a query arrives and records visual changes explicitly in a structured, change-aware memory. When a query arrives, a query-driven planner decides what evidence is needed and guides memory retrieval and targeted replay of past frames.
- Result: 66.07% on OVO-Bench and 59.53% on StreamingBench, ahead of representative streaming methods.

### [DLite: History-free Speculative Decoding for Agentic AI](https://arxiv.org/abs/2610.23787)
- Heat: HF 👍36 (6 days on the list, +3); code [SJTU-DAI-Sys/DLite](https://github.com/SJTU-DAI-Sys/DLite) ⭐49.
- Problem: The long, evolving contexts in agent workloads cut existing draft models' acceptance length by up to 80%, and maintaining a historical KV cache adds heavy system overhead.
- Method: Reuses the target model's contextual hidden states directly and makes only local speculative predictions, without explicitly maintaining history. A lightweight sequential head restores causal dependencies within a block, and training runs in two stages.
- Result: Acceptance length of 2 to 6, up to 70% faster than DSpark, the SOTA speculative decoding method.

## Observations
- The harness is now a first-class optimization target. [The Trinity](https://arxiv.org/abs/2610.36077), [HarnessPro](https://arxiv.org/abs/2610.26770), [Harness Scaling](https://arxiv.org/abs/2610.29458) and [SERA](https://arxiv.org/abs/2610.29560) all evolve or scale harnesses, and Self-Evolving Harness (see the 10-25 report; repo [zgcagi/Harness-RSI](https://github.com/zgcagi/Harness-RSI) ⭐387) supplies a theoretical framework.
- Memory research is moving from building systems to measuring net value. [Memory Tax](https://arxiv.org/abs/2610.34073) compares against naive RAG, [HABIT-Bench](https://arxiv.org/abs/2610.24520) tests habit inference, and [MemPilot](https://arxiv.org/abs/2610.06830) curates memory on demand per query. MMEnterprise-Bench (👍33) also finds that a larger retrieval budget raises evidence recall but not necessarily answer accuracy.
- Context compression and multi-session work are becoming training problems. [DeLoop](https://arxiv.org/abs/2610.19376) handles loops after compression. Mosaic (👍63, first seen 10-23, no further growth in upvotes) does multi-session RL for context compression and sub-agent forking.
- On the engineering side, [Tongyi-MAI/OpenGCUA](https://github.com/Tongyi-MAI/OpenGCUA) ⭐441 and [InternLM/Intern-Decision](https://github.com/InternLM/Intern-Decision) ⭐775 have relatively high star counts, so harnesses and open-source stacks are drawing attention.
