### [MemT-1.0: Towards Memory-Native Evolution](https://arxiv.org/abs/2610.26825)
- Popularity: HF 👍134 (1 day on the chart, +2 new); code: [MemTensor/MemT-1.0](https://github.com/MemTensor/MemT-1.0) ⭐361
- Problem: External memory is mostly passive retrieval; the goal is to make memory a capability of the foundation model itself.
- Method: Built on Metis, it uses Gated DeltaNet-2 for stable token-level memory updates within each turn, and introduces Mixture-of-Storage to expand native memory capacity. Training has two stages, continued pre-training and post-training, on 34B tokens of data in total; two models, Nano and Flash, are released.
- Result / significance: Outperforms parametric-memory baselines and matches retrieval-augmented methods; at 128K history, Nano's end-to-end inference is about 1.86× faster, persistent storage is 66× smaller than a full-context KV cache, and agent task success improves by internalizing retrieved procedural experience.

### [Cache Engineering for Agents](https://arxiv.org/abs/2610.28577)
- Popularity: HF 👍130 (1 day on the chart, +21 new); code: [thu-nics/AKV](https://github.com/thu-nics/AKV) ⭐48
- Problem: Trimming or summarizing history changes the trajectory prefix, invalidating later caches and triggering expensive re-prefill.
- Method: Proposes cache engineering: the agent uses `drop` to exclude selected cache from later attention and `repos` to adjust the position encoding of retained keys, with no need to modify the trajectory or re-prefill. It also points out that "the same token sequence has different states under different cache-operation sequences," so prefix matching is not enough to guarantee correct reuse, and designs the AKV serving engine accordingly (a stateless external interface, with stateful cache reuse, eviction and recovery managed internally).
- Result / significance: A rolling tool-response drop strategy scores 1.7 higher on average and costs 27.7% less than threshold-triggered summarization; AKV delivers up to 1.2× output throughput and 1.5× P95 latency speedup; recursive self-improvement of the cache policy cuts cost a further 7.1%.

### [OpenVLHarness: Real World Visual Agentic Tool-Use with Multimodal Memory](https://arxiv.org/abs/2610.26860)
- Popularity: HF 👍113 (1 day on the chart, +2 new); code: [uclanlp/OpenVLHarness](https://github.com/uclanlp/OpenVLHarness) ⭐210
- Problem: Visual reasoning tasks need evidence from multiple tools, and that evidence must be retained and interpretable across multi-step reasoning.
- Method: The harness is organized as a "capability layer + persistent multimodal memory." The capability layer renders heterogeneous tool outputs into observations the model can read; persistent memory stores images, structured data and web citations as addressable artifacts; a code interface then performs cross-tool computation over the stored data.
- Result / significance: Across 22 benchmarks and 8 backbones, it beats the no-tool baseline by 9.7–12.6 points on average; with GPT-6 Luna at medium reasoning effort, it outperforms other approaches run at the highest effort by 7.7–8.5 points, using at most 37% of the token cost.

### [FlowState: Execution State as Memory for Long-Horizon LLM Agents](https://arxiv.org/abs/2609.34565)
- Popularity: HF 👍21 (1 day on the chart, +3 new); no code repo yet
- Problem: In long-horizon tasks, keeping all history is costly, while compression may discard details that only become important later.
- Method: Treats execution state as memory, storing semantically typed state nodes, relations between nodes, and references to the raw tool observations, separating "persistent retention" from "on-demand access." ISU incrementally updates the current state at each step from new input and feedback, and PSA progressively expands historical states and evidence on demand during reasoning.
- Result / significance: With the same DeepSeek-V4-Flash, versus the full-context baseline, MemoryArena average success rate is +4.55 and τ³-Bench average pass rate is +13.95 percentage points, while total token consumption drops 43.2% and 40.6%, respectively.

### [MemPilot: Orchestrating On-Demand Multimodal Memory Curation for LLM Agents](https://arxiv.org/abs/2610.06830)
- Popularity: HF 👍36 (1 day on the chart, +0 new); code: [ViktorAxelsen/MemPilot](https://github.com/ViktorAxelsen/MemPilot) ⭐6
- Problem: Most memory systems build memory independently of the query, which wastes preprocessing and may discard details that later turn out to be critical.
- Method: Trains a multi-step LLM policy with RL that iteratively chooses between "retrieving query-agnostic memory" and "handing the raw multimodal history to heterogeneous LLMs / VLMs for query-dependent curation," jointly controlling evidence volume, curation instructions, model selection and visual access. Training estimates advantages separately per objective and then aggregates them, and uses prefix-based marginal-utility estimation for credit assignment.
- Result / significance: On 5 multimodal agent memory benchmarks, the performance–cost–latency frontier obtained by sweeping different preferences is wider than that of existing baselines.

### [DeLoop: Repeated Actions as Self-Supervision for Long-Horizon Agents](https://arxiv.org/abs/2610.19376)
- Popularity: HF 👍22 (1 day on the chart, +5 new); code: [cskyl/deloop](https://github.com/cskyl/deloop) ⭐0
- Problem: Agents repeatedly issue the same tool call and get the same observation (a loop), which becomes more common once history is compressed.
- Method: Self-supervised training that treats looping actions in rollouts as negative examples and the first non-looping action later in the same trajectory as the positive example, learned with DPO, with no need for task rewards, ground-truth answers or an LLM judge.
- Result / significance: In the CodeGym compression setting, the share of tasks containing loops for Qwen3-8B drops from 57.3% to 6.1%, with steps per task cut to about one third; Qwen3-32B success rate rises from 37.7% to 44.8%.

### [Socratic Skill Learning: Interleaving Teaching and Practice for Transferable Agent Skills](https://arxiv.org/abs/2610.17860)
- Popularity: HF 👍37 (1 day on the chart, +7 new); code: [NJU-LINK/Socratic-Skill-Learning](https://github.com/NJU-LINK/Socratic-Skill-Learning) ⭐2
- Problem: A single successful task attempt does not necessarily test the procedure and the conditions under which it applies, making transferable Skills hard to learn.
- Method: SSL alternates expert (Educator) guidance with student (Student) practice; the Student is the sole environment operator and Skill author, and can question, test and adjust the advice. It also builds SkillTransferBench (35 task families, 408 executable cases) to test transfer; Issue-Guided SSL tracks unresolved issues across versions and uses them to select and focus reviews.
- Result / significance: On the main cohort, Fixed-Window SSL reaches a utility of 0.801, above 0.723 with no Skill and above the adapted Trace2Skill (0.761) and SKILL-KD (0.751); the Issue-Guided version reaches a utility of 0.805 with 61.7% fewer Educator tokens.

### [Memory-Centric Continual Learning for AI Agents](https://arxiv.org/abs/2610.29357)
- Popularity: HF 👍25 (1 day on the chart, +6 new); no code repo yet
- Problem: External memory is mostly a passive retrieval cache, and whether it can truly drive continual learning is still unresolved.

## 5. Research trend observations

- **Context management shifts from "pruning" to "preserving the prefix and staying traceable"**: Cache Engineering (drop / repos without changing the prefix), FlowState (state nodes + references to raw observations) and CarryOn (revising only affected records when folding) all stress keeping continuity or enabling on-demand backtracking after compression; Skip the Compressor, meanwhile, points out that compression alters the code text to be edited, making patches harder to apply.
- **The memory approaches diverge**: MemT-1.0 internalizes memory into the model, MemPilot curates on demand, and Raw-RAG shows that simple retrieval is competitive on the dialogue tasks evaluated; MCCL tries to redefine the evaluation criteria. Taken together, these suggest that "whether complex memory is worth it" remains an open question.
- **The harness becomes a first-class research object**: CoEvo-RSI, Self-HPO, Harness Scaling, Self-Evolving Agent Harness and HarnessPro all optimize or evolve the harness itself; on the training side, work centers on synthetic environments (WildAWM, CoworkEnv) and multi-session RL (Mosaic).
- **Echoes on the engineering side**: By stars, MemT-1.0 (⭐361) and OpenVLHarness (⭐210) on the trending chart, along with OpenGCUA (⭐441), Harness-RSI (⭐387) and Microsoft's TokenEconomizer (⭐211) among the new entries, draw the most attention, covering memory, harness, computer use and cost control, largely consistent with the hot topics on the paper side.
