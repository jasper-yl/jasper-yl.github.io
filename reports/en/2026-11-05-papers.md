### [Switch-SWE: Do Coding Agents Hold Focus When Switching Between Unfinished Tasks?](https://arxiv.org/abs/2611.02017)
- Heat: HF 👍6 (on the list 2 days, +6); code [Miraclecsc/Switch-SWE](https://github.com/Miraclecsc/Switch-SWE) ⭐26.
- Problem: after a coding agent is interrupted and works on another unfinished task in the same repo, can it recover the original task's requirements and progress?
- Method: the benchmark has 200 focus tasks, 19 Python repos and 400 paired sessions (uninterrupted vs. interrupted). Trajectory analysis found two recurring failures: mixing up requirements across tasks, and losing task state. The authors add a plug-and-play context-management module that selects task-relevant history and keeps a concise task-state summary.
- Result: seven coding agents lose 11.5 points on average (range 6.0–15.0). On OpenCode, the module raises task completion by 5.5–15.5 points.

### [ParetoSaddler: Pareto-Guided Optimization of Agent Harnesses for Quality and Cost](https://arxiv.org/abs/2611.02079)
- Heat: HF 👍16 (on the list 1 day, +0); no code repo.
- Problem: harness optimization usually looks at quality only. When quality and cost are optimized together, applying deployment preferences at intermediate steps discards candidates that would have been useful later.
- Method: it separates promoting intermediate candidates from choosing the final deployment. Each round, a candidate is run repeatedly against its parent harness. Using Bayesian bootstrap Pareto support, it is promoted if either quality or cost shows credible improvement. Promoted candidates become parents for later rounds.
- Result: on ClawMark, quality goes 70.86%→81.35% and cost $1.17→$1.01 per task. On GAIA2, quality goes 56.22%→62.89% and cost $0.78→$0.45 per task.

### [MemSteer: Turning User Histories into Supervision for Agent Memory Optimization](https://arxiv.org/abs/2610.39276)
- Heat: HF 👍8 (on the list 6 days, +8); no code repo.
- Problem: a new user's history has no labels, so memory designs can't be evaluated or improved, and building QA and evidence by hand is too expensive.
- Method: MemSteer first builds evidence-backed answer plans, then generates questions, and checks label quality with provenance audits and blind-answer recovery. The companion MemSteer-Opt uses QA evaluation plus evidence-guided failure diagnosis to change memory storage, retrieval and context construction without updating model parameters.
- Result: versus Base-BM25, ATM-Bench Question Score is +13.4 points, and RHELM accuracy is +4.1 (no external data) and +6.6 (with external data). The auto-generated supervision performs on par with optimization guided by official QA.

### [GEPA-Curator: Curated Learning for Self Improving Agents](https://arxiv.org/abs/2610.37651)
- Heat: HF 👍8 (on the list 2 days, +3); no code repo.
- Problem: reflective prompt optimizers such as GEPA learn from all failed rollouts, but some failures come from harness limits, randomness or noisy judges, and learning from them hurts.
- Method: two parts. Task filtering removes tasks likely to give noisy signals. Successful-trajectory retrieval pulls past successes for each task and gives them to the prompt optimizer as extra context.
- Result: on GoBrowse, ALFWorld, AppWorld and τ-bench, the mean matches or beats two baselines, up to 20.7% over GEPA and 21.2% over ACE.

### [RoboArchitect: Automating the Design of Robotic Agents with Persistent Memory](https://arxiv.org/abs/2610.42141)
- Heat: HF 👍8 (on the list 3 days, +3); code [roboarchitect-ai/RoboArchitect](https://github.com/roboarchitect-ai/RoboArchitect) ⭐9.
- Problem: a frozen robot policy performs much better inside an agent harness, but the harness is rebuilt by hand for each robot or benchmark.
- Method: a coding model watches rollouts, diagnoses failures and iteratively edits the harness, with no weight updates. The harness also evolves its own persistent memory, carrying learned experience (such as effective grasp depth) into later decisions.
- Result: success on unseen scenes goes 9.7%→43.3% (4.5x), and on unseen tasks 12.7%→40.2% (3.2x).

### [Can Large Language Model Agents Learn by Watching Tutorial Videos?](https://arxiv.org/abs/2611.01460)
- Heat: HF 👍5 (on the list 2 days, +3); no code repo.
- Problem: deployed LLM agents have frozen abilities. How can they keep learning from tutorial videos without parameter updates?
- Method: Tutorial Agentic Learning (TAL) folds tutorial videos into a persistent, structured "tutorial book" memory and refines it with an adversarial process that generates hard video-related questions. At inference it retrieves through a table-of-contents (TOC) tree, so retrieval is driven by model reasoning rather than embedding similarity.
- Result: on VidLearn (72 chess tutorial videos), it improves up to 113% (train) and 91% (test) over the raw MLLM, and keeps getting better as videos are added. In live play, 69% of games start from opening positions stronger than the base model's.

### [Can Coding Agents Sustain Continual Evolution without Forgetting?](https://arxiv.org/abs/2611.03219)
- Heat: HF 👍6 (on the list 2 days, +5); code [THU-Agent/continual-harness-evolution](https://github.com/THU-Agent/continual-harness-evolution) ⭐1.
- Problem: can a harness keep evolving itself across many tasks without catastrophic forgetting?
- Method: three software engineering datasets form six evolution directions, and two representative harness-evolution methods are studied empirically under continual evolution.
- Result: evolving on later datasets badly hurts earlier performance. With DeepSeek-V4-Flash-0731 and Meta-Harness, SWE-Bench scores 94.0% after evolution, then drops to 32.0% by round five of evolving on FeatureBench (a 66% relative drop).

## 4. 🆕 New: just published last night

- [SpecCompact](https://arxiv.org/abs/2611.06876): a small drafter generates summary slots in parallel and the target model verifies them line by line, speeding up agent context compression. It is 2.04–5.63x faster than Hermes-style summarization on AppWorld and τ³, and 8.68x faster at the median in a user study inside Hermes.
- [SumOne](https://arxiv.org/abs/2611.06445): trains a task-agnostic summarizer with GRPO, using a frozen reconstructor to recover masked trajectory segments and rewarding reconstruction quality minus a length penalty. Inference cost drops about 78% (DeepSearchQA) and 75% (SWE-bench Verified) for a 0.04 absolute score drop, and it transfers across models and harnesses.
- [Coca-Cola: Tools Need Not Speak in Text](https://arxiv.org/abs/2611.06500): compresses tool output into continuous latent tokens fed into the agent's input embedding space, aligning the next-action distribution with Action-Preserving Training. Web-search agents use 70.01%–89.24% fewer tokens and run 24.45%–55.97% faster. Code: [THU-Agent/Coca-cola](https://github.com/THU-Agent/Coca-cola).
- [Visual Token Routing](https://arxiv.org/abs/2611.06854): a lightweight spatiotemporal router decides which screenshot regions' visual tokens reach the language model. It matches full resolution on OSWorld and other tasks with 2.5–5.8x fewer visual tokens and up to 3.3x lower inference cost.
- [Route to Remember: Adaptive Memory Selection for LLM Agents](https://arxiv.org/abs/2611.05636): writes user memory into weights with on-policy self-distillation, and a "verify-then-generate" router chooses between weight memory and text memory. On HaluMem it matches or beats text-memory baselines while reading fewer tokens per query.
- [Why Pay for Long Reasoning When Rewrite Do Trick?](https://arxiv.org/abs/2611.03852): rewrites existing reasoning into a compact state record before tool results return. Later reasoning is shorter in most cases. In software-agent deployments total spend can fall, but task quality depends on the target model and the compressor.
- [FlyHash for LLM Agent Memory](https://arxiv.org/abs/2611.05791): the first use of FlyHash, inspired by the fruit fly olfactory circuit, for agent memory retrieval. It holds a quality advantage at equal bit counts, but codes are larger and comparisons slower, and HNSW still beats both hash methods at ordinary scale.
- [Hybrid Computer Use](https://arxiv.org/abs/2610.41432): unifies code/CLI, accessibility (AX) and visual GUI channels into one interface. AX tools return compact observations and report effects as AX diffs. It gets the highest Partial and Binary scores among compared systems on OSWorld 2.0 (early 👍6). Code: [microsoft/Hybrid-Computer-Use](https://github.com/microsoft/Hybrid-Computer-Use).
- [FrontierPhysics](https://arxiv.org/abs/2611.06910): 56 end-to-end research tasks built by 42 physicists from their own research. Across 22 models and 26 configurations, no configuration passes more than 46 of 168 rollouts (early 👍32, highest among new papers).
- [What Does Multi-Turn Reinforcement Learning Really Improve in LLM Agents?](https://arxiv.org/abs/2611.06483): the advantage of multi-turn agentic RL depends on having enough turn budget and shows up mainly in error recovery and long-horizon resilience. The authors propose BudgetMix RL, which varies the interaction budget during training (early 👍28).
- [SlackBench](https://arxiv.org/abs/2611.05512): 140 queries that require reasoning jointly over workplace communication and repo state. Among 33 frontier models and harnesses the best scores about 80% and most fall below 66%.
- [Mechanical Engineering Skills](https://arxiv.org/abs/2611.05758): an open-source library of 33 agent skills, loaded on demand and installed with one command, covering CAD, CFD, additive manufacturing and more. The authors say controlled comparisons with other agents are left for future work.

## 5. Research trends

- Automatic optimization of harnesses and memory is the main thread. [ParetoSaddler](https://arxiv.org/abs/2611.02079), [MemSteer](https://arxiv.org/abs/2610.39276), [GEPA-Curator](https://arxiv.org/abs/2610.37651) and [RoboArchitect](https://arxiv.org/abs/2610.42141) all optimize a harness, memory or prompt without changing weights. [Continual harness evolution](https://arxiv.org/abs/2611.03219) finds that this kind of evolution forgets old tasks (94.0%→32.0%).
- Context compression is taking several forms: parallel-accelerated summarization ([SpecCompact](https://arxiv.org/abs/2611.06876)), a task-agnostic trained summarizer ([SumOne](https://arxiv.org/abs/2611.06445)), continuous latent tokens ([Coca-Cola](https://arxiv.org/abs/2611.06500)), visual token sparsification ([Visual Token Routing](https://arxiv.org/abs/2611.06854)) and weight memory ([Route to Remember](https://arxiv.org/abs/2611.05636)). Most of these just appeared with upvotes near 0, so their traction can't be judged for a few days.
- Context loss in long-horizon tasks is getting dedicated benchmarks: [Switch-SWE](https://arxiv.org/abs/2611.02017) (task switching), [SlackBench](https://arxiv.org/abs/2611.05512) (information spread across communication and code) and [CrossSWE](https://arxiv.org/abs/2611.01484) (cross-repo consistency).
