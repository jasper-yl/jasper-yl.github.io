## 1. 🔥 Trending: Agent Context Picks

### [Pack Light, CarryOn: Building Object-Oriented Context for Long-Horizon Agents](https://arxiv.org/abs/2610.18784)
- Trending: HF 👍122 (on the chart for 1 day, +1 new); Code: [Ethannju/carryon](https://github.com/Ethannju/carryon) stars 5
- Problem: Long-horizon agents persist task state, yet still have to repeatedly process interaction history such as "how progress was made".
- Method: CarryOn is an object-oriented context runtime that organizes continuation around reusable task objects. Its context view consists of "continuation carriers", supplementary execution context, and a live tail of recent interactions. At each fold, it revises only the affected carrier records based on evidence and environment checks, carries the remaining records over unchanged, and updates the execution context in sync, without rebuilding the full representation.
- Result/significance: Improves results on OSWorld 2.0 and BrowseComp-Plus by 5.8% and 7.0%, and reduces total token usage by 51.9% and 22.9%, respectively.

### [Mosaic: Multi-Session Agentic Reinforcement Learning](https://arxiv.org/abs/2610.22174)
- Trending: HF 👍63 (on the chart for 1 day, +0 new); Code: [LARK-AI-Lab/Mosaic](https://github.com/LARK-AI-Lab/Mosaic) stars 37
- Problem: Existing agent RL assumes single-session trajectories, while context compression and subagent forking at inference time produce multi-session trajectories, so the two do not match.
- Method: Proposes a "multi-session agent RL" setting in which each trajectory can contain any number of sessions. Mosaic performs critic-free hierarchical optimization: the trajectory level folds session-usage signals into advantage estimation, and the session level adjusts each session's advantage by its estimated marginal contribution.
- Result/significance: On BrowseComp (Qwen3.5-4B), for both context compaction and subagent forking, it outperforms the approach of broadcasting trajectory-level advantages to all sessions, with fewer sessions on average.

### [Socratic Skill Learning: Interleaving Teaching and Practice for Transferable Agent Skills](https://arxiv.org/abs/2610.17860)
- Trending: HF 👍42 (on the chart for 2 days, +12 new); Code: [NJU-LINK/Socratic-Skill-Learning](https://github.com/NJU-LINK/Socratic-Skill-Learning) stars 2
- Problem: A single successful task attempt is not enough to test a skill's steps and the conditions under which it applies, so learned skills transfer poorly.
- Method: In SSL, an Educator guides the investigation, while the Student always remains the sole operator in the environment and the author of the skill, and can question, test, and adapt the advice. Issue-Guided SSL tracks unresolved issues across multiple skill revisions and uses them to select and focus reviews. The authors also built SkillTransferBench (35 task families, 408 executable cases) to test reuse.
- Result/significance: On the main test set, Fixed-Window SSL reaches a utility of 0.801, versus 0.723 with no skill; the Issue-Guided version reaches 0.805 with 61.7% fewer Educator tokens.

### [Self-Evolving Agent Harness](https://arxiv.org/abs/2610.18813)
- Trending: HF 👍99 (on the chart for 1 day, +0 new); Code: [zgcagi/Harness-RSI](https://github.com/zgcagi/Harness-RSI) stars 387
- Problem: With model weights fixed, how can an agent's scaffolding (prompts, memory, workflows, executable components) be revised systematically and reliably?
- Method: Formalizes "accepted revisions persisting across runs" as a feedback-driven process, and separates the update target from the proposal and admission mechanisms. It distinguishes changes to interpretive state from revisions to tools/code, repo-level control logic, and plugin composition, then analyzes reliability using evolutionary optimization and continual PAC learning.
- Result/significance: Under explicit assumptions, it gives a generalization bound, a retention bound constrained by a historical regression budget, and a high-probability admission rule using fresh independent validation data; it also comes with a 66-page survey and continuously updated code.

### [OpenGCUA: Toward a Fully Open Stack for Generalist Computer Use](https://arxiv.org/abs/2610.22200)
- Trending: HF 👍103 (on the chart for 1 day, +0 new); Code: [Tongyi-MAI/OpenGCUA](https://github.com/Tongyi-MAI/OpenGCUA) stars 441
- Problem: Most frontier implementations of generalist computer-use agents are closed-source, so their designs are hard to study systematically.
- Method: Centers on code execution, letting intermediate results determine subsequent actions. It also proposes "harness-to-model decision transfer", moving some observation and task-state decisions from fixed harness rules to the model. The project open-sources the implementation, the prompts, evaluation trajectories for eight models, and an initial version of a real-device harness and cross-device SDK.
- Result/significance: On OSWorld-v2, the full configuration improves task scores for all eight tested models, with an average partial score of +19.6, and reports an average 53.0% reduction in steps relative to batched GUI-only execution.

### [HexaShell: A Thin Harness for Exploring the Limits of VLM Agents as Robot Coding Agents](https://arxiv.org/abs/2610.23479)
- Trending: HF 👍121 (on the chart for 1 day, +2 new); Code: [HexaFuture/HexaShell](https://github.com/HexaFuture/HexaShell) stars 138
- Problem: How far can a coding agent go when controlling a robot, and where is the bottleneck?
- Method: The harness only converts the agent's commands into robot actions. After each failure, the agent reads the logs to find the cause, then writes or fixes small tools, keeping what it learned in the form of code. Tools are first built on 10 layouts, frozen, and tested on 10 new layouts.
- Result/significance: Achieves a 39.7% success rate on 42 RoboDojo tasks, which the authors say sets a new high on that leaderboard. The bottleneck is contact, not reasoning: 92.5% on pushing tasks, but only 8.3% on tight-fit insertion.

### [DeltaStreamer: Towards Human-Like Agentic Streaming Video Understanding](https://arxiv.org/abs/2610.19849)
- Trending: HF 👍38 (on the chart for 1 day, +0 new); Code: [BBBBchan/DeltaStreamer](https://github.com/BBBBchan/DeltaStreamer) stars 87
- Problem: Streaming video has to retain evidence without knowing future questions, while compressing video history blurs event transitions, loses detail, and cannot be recovered.
- Method: Before a query arrives, it continuously watches the video stream and explicitly records visual changes in structured memory. After a query arrives, a planner determines the evidence needed and guides memory retrieval and targeted replay of past frames, recovering visual details missed during observation.
- Result/significance: Overall scores of 66.07% and 59.53% on OVO-Bench and StreamingBench, outperforming the compared streaming video understanding methods.

### [Retrieval Augmented Generation Compositionality](https://arxiv.org/abs/2610.29722)
- Trending: HF 👍47 (on the chart for 2 days, +22 new); Code: [dolev31/lasagna](https://github.com/dolev31/lasagna) stars 17
- Problem: The techniques in a RAG pipeline (including context compression) are usually evaluated in isolation, so it is unclear whether their gains persist when combined.
- Method: Proposes LASAGNA, an open-source framework, which tests 450 configurations on 8 benchmarks with corpora from 5K to 200K documents.
- Result/significance: Individual gains are not necessarily additive: three retrieval techniques were predicted to give +47% combined, but the actual gain was only +17%; the best combination for retrieval quality differs from the best for faithfulness, and the best combination also changes with corpus size.

## 5. Research trend observations
- **Context management is moving toward "structure + integration with training"**: CarryOn replaces history summaries with task objects, and Mosaic brings the multi-session trajectories produced by compression and forking into RL; DeltaStreamer uses structured change memory plus replay to recover details lost to compression. All three address "how to preserve useful information after compression".
- **Harness has become a first-class research object**: Self-Evolving Agent Harness (stars 387), Self-HPO, OpenGCUA (stars 441), and HexaShell (stars 138) all treat the design or evolution of the scaffold as the main problem. These papers have relatively high GitHub star counts, which suggests clear community interest in reusable harnesses.
- **Evaluation is focusing on process and real-world settings**: BizBench, FDE-Gym, and Into the Unknown all show that frontier models still have clear gaps in intermediate execution validity, discovery of implicit constraints, and research integrity. On BizBench, Qwen3.8-27B has a 42.0% goal achievement rate but only a 32.7% strict success rate, which suggests that outcome-only evaluation overestimates capability.
- **Environment synthesis is the main line on the training side**: MAI-Gym, WildAWM, CoworkEnv, OpenMobile-2, and others are all building verifiable synthetic environments for RL/SFT, and this work is especially concentrated in GUI and computer-use agents.
