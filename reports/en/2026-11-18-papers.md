### [Folio: Recoverable Multi-Resolution Context Folding for Long-Horizon Language Agents](https://arxiv.org/abs/2611.16627)
- Heat: not on HF (arXiv source), no HF upvotes yet; on the list 5 days; no code repo, no X data.
- Problem: long-horizon agents compress history by having the model summarize it, which rereads and rewrites the history each time and is expensive.
- Method: the runtime records three views as it goes. L1 is a turn note the model writes alongside its reply, L2 is a per-call event list written by the runtime, and L3 is the raw source record. When compressing, it picks a coarser view for older content and leaves handles pointing to L2/L3 in the context. A recovery tool reads pages on demand and computes over the full text in files, logging findings to a persistent dossier. When folding triggers, the retained budget is priced into the landing point.
- Result: on LOCA-bench (75 tasks, all runs on DeepSeek-V4-Pro), Folio solves 66. The same runtime with model-written compression solves 54, and Claude Code, Codex and SoL-Pi solve 49–59. It takes about half the time of the alternatives, costs 2.4x less than model-written compression, and a fold takes a median 0.6 seconds.

### [Coding Agent Memory Post-Training II (CAMP-II)](https://arxiv.org/abs/2611.14009)
- Heat: arXiv source, no HF upvotes; on the list 7 days; no repo.
- Problem: on long tasks the history outgrows the context, so the agent must decide what to write and what to read. Existing on-policy distillation (OPD) relies on memory tools the teacher has never seen, so its guidance doesn't help.
- Method: the CAMG-II environment suite (Shop, Coding, AutoResearch, General, Visual) gives the agent plain Bash and a workspace that persists across context replacements, so it treats files as memory. CAMP-II trains one policy jointly across the five environments with fully asynchronous OPD, learning this file-based memory behavior from a frozen teacher that is fluent with file operations.
- Result: on CAMG-II the gain is 2.97x that of the strongest OPD baseline, and the behavior transfers to Terminal-Bench 2.1 and SWE-Bench Pro V2.

### [When Should Agents Remember? Falsification-Gated Self-Evolution (FGSE)](https://arxiv.org/abs/2611.14326)
- Heat: arXiv source, no HF upvotes; on the list 7 days.
- Problem: writing a single experience straight into memory is unreliable, because a local success may not hold.
- Method: each candidate lesson is a hypothesis with a precondition, a behavior change, an expected effect and a verifier. It is applied to a temporary state and tested with three kinds of probes (target transfer, falsification, archive regression). Gain and risk then decide whether to commit, rewrite or reject it.
- Result: WebArena 39.8, AppWorld 78.8, τ-Retail/τ-Airline Pass^1 of 0.724/0.487. Falsification failures are 5.0%, regression harm 1.3%, and harmful committed updates 3.6%.

### [Discovering Effective Agent Memory Designs through Program Evolution (MAPE)](https://arxiv.org/abs/2611.17068)
- Heat: arXiv source, no HF upvotes; on the list 5 days; code: [ash-ding/MAPE](https://github.com/ash-ding/MAPE) (star count not given).
- Problem: memory systems are hand-designed, and it is unclear which design choices actually matter.
- Method: starting from a minimal seed, it evolves a whole memory program using a standardized lifecycle interface and a diagnose-then-propose loop. Two patterns emerge: keep raw dialogue as retrievable evidence, and organize retrieved evidence by query intent.
- Result: up to +12% absolute accuracy on LoCoMo and LongMemEval at 35% of the serving cost of hand-built baselines. Porting the combined modules into five existing memory systems improved all five.

### [SHADOWPREFILL: Keeping Your Next Model Warm for Per-Step Model Routing](https://arxiv.org/abs/2611.13176)
- Heat: arXiv source, no HF upvotes; on the list 7 days.
- Problem: switching models at each step loses the prefix cache (KV caches are per model). Prefix hit rate falls from 80–89% with the same model to 44–65%, and switching calls take 1.5–3.2x longer. Production coding-agent trajectories average 63K tokens of context.
- Method: it prefills the session context for the not-chosen model in advance on idle capacity, using the SLO headroom of in-flight requests, and spills the shadow KV cache to host memory. If the shadow is incomplete, it falls back to a cold switch.
- Result: across 24 model pairs and five agentic benchmark suites, switching-call latency drops 8.5–21.4%, LLM-call latency 3.7–17.7%, and routing token cost 22.5–46.1%, with only +0.4% energy per request.

### [Continual-ARC: Measuring Skill Acquisition over a Working Lifetime](https://arxiv.org/abs/2611.14505)
- Heat: HF 👍2 (on the list 2 days; 9 at first appearance, then −7); code: [unifyai/continual-arc](https://github.com/unifyai/continual-arc) ⭐38.
- Problem: existing benchmarks test a single domain and show each instance once, so memory-based and weight-based continual learning can't be compared on one scale.
- Method: three ARC-AGI versions form a lifetime task stream. Tasks return after a delay with new instances and are scored by feedback budget consumed. After learning, the agent is frozen and tested on seen tasks (memory) and unseen tasks (generalization). Compared systems: frozen-weight agent harnesses (with and without persistence), two prompting baselines, program induction, and distilled weights.
- Result: harness persistence usually doesn't improve memory unless an expert guides it. Most harness methods learn less than a baseline that simply caches each task's examples. Harness methods show no gain on unseen tasks, while weight learning shows a clear gain.

### [MemCredit: From Relevance to Utility for Decision-Time Memory in Long-Horizon Web Agents](https://arxiv.org/abs/2611.15600)
- Heat: arXiv source, no HF upvotes; on the list 5 days.
- Problem: the memory most semantically relevant to the current state isn't necessarily the one that best improves the action.
- Method: it estimates each memory's marginal contribution through controlled counterfactual interventions and distills that into a lightweight utility estimator. Semantic relevance is used only to recall candidates; under a fixed token budget, predicted utility decides which memories to keep.
- Result: on ALFWorld with a 500-token history-memory budget, SR@50 is 86.57 vs 65.67% for BM25 retrieval. Counterfactual analysis shows memory utility is sparse and strongly state-dependent, which semantic relevance fails to capture.

### [DISCERN: Preserve at Write, Resolve at Read for Persistent LLM-Agent Memory](https://arxiv.org/abs/2611.15729)
- Heat: arXiv source, no HF upvotes; on the list 5 days.
- Problem: in enterprise agents' memory across many sessions, facts contradict each other or get superseded, and similar entities blur together in embedding space.
- Method: at write time it builds a strictly append-only, bitemporal provenance graph that never merges confusable entities and never discards superseded values. At read time an agentic loop navigates using a tool surface with no LLM calls, and must finish with one of four controlled terminal actions.
- Result: on the authors' own ENT-310, abstention F1 is 0.924 vs 0.802 for the best of eight baselines, and macro-averaged answer correctness is 0.861 vs 0.806 for the strongest baseline. With zero tuning on full LoCoMo, it scores 0.663 vs 0.638.

## 🆕 New: announced last night
Heat figures are preliminary.
- [Context Has a Price: Adding and Removing Context for LLM Coding Agents under Prefix Caching](https://arxiv.org/abs/2611.22238): across 20,000+ runs, it prices uncached input, cached input and output separately. Retrieving code cuts read/search commands by 18–34% but raises cost 33–42% when cached tokens cost a tenth as much. Deleting old observations saves 19–36% with no cache discount but raises cost 38–116% at a tenth-price cache.
- [Stopping Is Not the Limit (SCoRe)](https://arxiv.org/abs/2611.22888): in exploit tasks, agents often stop before the budget is used up. SCoRe compresses context at consecutive stop replies and marks "impossible" verdicts as unconfirmed. MiMo reaches 67.0% capability coverage at 2,000 turns, vs 32.4% under the original stopping policy.
- [When Agent Skills Go Stale](https://arxiv.org/abs/2611.22525): after the environment changes, a previously helpful skill can cut task performance by more than 10 points or raise execution cost by nearly 40%. Selective maintenance (replay checks, repair, validation) raises accuracy by up to 67pp and cuts execution steps by up to 37%.
- [RAG in a Trenchcoat](https://arxiv.org/abs/2611.22179): a minimal memory called BRIDGE ties SOTA on LongMemEval-S and BEAM and leads by 5.7–6.3 points on EverMemBench, using about 5–7K reader-prompt tokens. The authors argue memory should be judged by what it lets the agent do, not by what it retrieves.
- [SkillBuffBench](https://arxiv.org/abs/2611.22017): splits Skill access into three levels (no Skill, assigned Skill, auto-invoked from an installed library), crossed with memory on/off, four harnesses and several models. Tasks come from experts in materials science and biology. Results are not yet published; the evaluation is still running.
- [Multi-Agent Memory Inconsistency](https://arxiv.org/abs/2611.22245): forced delegation raises the share of runs where both conflicting claims are retrieved from 50.2% to 68.7%, but conflict detection falls from 16.2% to 13.2%. Workers reported only 35.2% of the conflicting pairs they retrieved.
- [Self-Improvement Memory Enables Continual Recursive Self-Improvement](https://arxiv.org/abs/2611.18856): gives the harness optimizer (not the task policy) a memory that groups edit rationales, predictions and observed outcomes by recurring problem. Across ten coding-source runs it averages +2.36 points over harness-only continuation (p=0.003) (preliminary 👍25).
- [TeleChat to Xing4](https://arxiv.org/abs/2611.22115): the Xing 4 model family, with a 285B-parameter model pretrained on 8,192 Huawei Ascend 910C chips and TeleGym, a unified agent execution platform (preliminary 👍147).
- [AscendGYM](https://arxiv.org/abs/2611.17621): a benchmark for Ascend NPU kernel optimization with 48 kernels at three difficulty levels and a Speedup-Token Score that measures speedup against token cost; repo [SLAI-AITP/AscendGYM](https://github.com/SLAI-AITP/AscendGYM) ⭐25 (preliminary 👍91).
- [ForceHarness](https://arxiv.org/abs/2611.21099): lets a frozen frontier model use force information through force-control primitives and a "physical translation layer". On a real robot arm, GPT-6 Astra's zero-shot success rises from 3.3% to 90.0%; repo [showlab/ForceHarness](https://github.com/showlab/ForceHarness) ⭐24 (preliminary 👍38).
- [VideoNexus](https://arxiv.org/abs/2611.21392): a long-video agent that hands perception to sub-agents with separate contexts, which return only compact temporal evidence. 88.6% on LVBench at 44% of the cost of built-in agentic processing (preliminary 👍18).
- [RepoFactory](https://arxiv.org/abs/2611.21152): turns real repositories into verifiable training environments, producing 10,159 environments across 17 software domains. Training Qwen3.5-35B-A3B on them adds 22.6 points on NL2Repo-Bench; repo [IQuestLab/RepoFactory](https://github.com/IQuestLab/RepoFactory) (preliminary 👍10).

## Research trends
- Upvotes on the hot list cluster around model technical reports (Sage, K2-Horizon) and agent benchmarks (SWE-CoWork, Accelerate Bench, OutfitterBench). The benchmarks all test long-horizon tasks with collaboration or organizational context, and full-completion rates sit far below partial-pass rates (SWE-CoWork: about 63% of F2P tests, under 8% fully complete).
- Agent Context papers have almost no upvotes, so community attention hasn't caught up with this batch of new arXiv papers. The topics are concentrated: compression (Folio), what to write to memory and what to keep (FGSE, MemCredit, DISCERN), KV/prefix cache and routing (SHADOWPREFILL), and continual learning (Continual-ARC).
- A recurring result is that complex mechanisms don't always pay off. In Continual-ARC, harness persistence loses to caching examples. In RAG in a Trenchcoat, minimal RAG ties SOTA. In Context Has a Price, deleting context can cost more under cache discounts. Context-management methods need to be evaluated against real prices and downstream behavior.
- Engineering side: almost none of the Agent Context papers in this batch have a repo with meaningful star counts (Continual-ARC at ⭐38 is the exception), so no comparison to GitHub projects is made.
