## 🔥 Trending: Agent Context picks

### [Flide: Accelerating Decision Inference with Exact State Forking](https://arxiv.org/abs/2610.42148)
- Heat: HF 👍35 (1 day on the list, +6); GitHub [OmniJev/Flide](https://github.com/OmniJev/Flide) ⭐430. No X data.
- Problem: when inference engines serve an agent's decision model (the Jev kind, which returns class probabilities in one forward pass), they either recompute the prefix or distort the output probabilities.
- Method: it separates the logical tree of a decision request from its physical execution and packs it into one flat token stream. ForkAttention handles both standard attention layers and recurrent Gated DeltaNet layers through GPU indexing, so each branch matches a standalone forward pass under exact arithmetic. A growing agent history can resume from checkpoints saved by earlier inference calls.
- Result: on public hybrid and decision models, queries run up to 9.5x faster than vLLM and SGLang, with the smallest total variation distance to a float32 reference.
- Of today's hot papers, this is the closest to prefix reuse and caching. Its star count is also far above the other papers from the same day.

### [The Last Mile to the Real World: Agent-Native Primitives as Reusable Building Blocks for Solving Real-World Tasks (HEELO)](https://arxiv.org/abs/2611.07461)
- Heat: HF 👍5 (2 days on the list, +2); no repo data.
- Problem: frontier models with their own harness still fall short on real tasks. On Terminal-Bench 4.0, Codex solves 37.3% and Claude Code 51.8%. Failures happen when the agent has a resource but doesn't know how to use it.
- Method: agent-native primitives give each resource a resident LLM that uses the resource in context and talks to other primitives. For each task, HEELO composes a task graph from a primitive library, checks it against environment evidence, revises any failing primitive, and after verification adds new or improved primitives. There are 8 primitive types.
- Result: Dev-Primitives lifts Terminal-Bench 4.0 from 37.3% to 55.5%, Terminal-Bench 2.0 Pass@1 from 60.0% to 72.2%, ToolBench pass rate from 55.8% to 75.1%, and GAIA-Text-103 from 45.6% to 58.3%. On 46 real tasks at heelo.dev, two harnesses connected to HEELO over MCP finish 39 and 35, up from 9 each.
- This is harness design, not context management. Votes are low; it is here for topic fit.

### [FlyHash for LLM Agent Memory: An Empirical Validation and a New Application](https://arxiv.org/abs/2611.05791)
- Heat: HF 👍4 (6 days on the list, +4); code [mohanji/flyhash-agent-memory](https://github.com/mohanji/flyhash-agent-memory) ⭐1.
- Problem: agent memory retrieval usually uses dense vectors plus approximate nearest-neighbor search. Can FlyHash, modeled on the fruit fly's olfactory circuit, replace it?
- Method: the first use of FlyHash (sparse random projection plus winner-take-all) for agent memory retrieval. It is compared with SimHash and HNSW under a matched-bit protocol, using real memory-relevance labels instead of proxy labels from embedding nearest neighbors.
- Result: the quality advantage holds across 10 random seeds and 4 datasets, and with real labels. At equal bit counts, though, FlyHash codes are larger and comparisons slower, and HNSW beats both hashes at ordinary scale. The practical use case is narrower than the quality numbers suggest.
- The paper reports negative results that weaken its own headline claim.

### [Ask, Don't Equip: Question-Driven Coding Agents for Deep Kernel Optimization (KernelSeek)](https://arxiv.org/abs/2611.03517)
- Heat: HF 👍4 (6 days on the list, +4); no repo data.
- Problem: GPU kernel optimization agents either follow a fixed pipeline or are fully open-ended and costly to debug. On hard targets, both respond by adding tools (profiler parsing, doc retrieval, experience libraries).
- Method: a general coding agent runs in a minimal harness that enforces only a verifiable goal. At decision points it gets short questions, first from a human, then from the agent itself using a question bank. The central claim is to give direction, not information.
- Result: on the same task, a tool-rich autonomous agent stalls at 0.50x FlashAttention-3 after 133 steps, while KernelSeek reaches 1.13x. Its Hopper/Blackwell FlashAttention forward kernels are correct in all 182 scenarios, at a geometric mean of 1.16x FA3 and 1.46x FA4. Across 162 human messages and 11.5K tool calls, every large gain came from a question that pointed the agent to another layer of the system or rejected a limit it had claimed, not from a question that supplied information.
- This is evidence against loading agents with more tools and information. The paper itself is not about context management.

### [Sketchpad: certified exact arithmetic with a small vision-language model](https://arxiv.org/abs/2611.04434)
- Heat: HF 👍4 (2 days on the list, +2); code [NeoVand/sketchpad](https://github.com/NeoVand/sketchpad) ⭐1.
- Problem: accuracy on long arithmetic can only be estimated by sampling, and tool calls are exact but move the computation out of the network.
- Method: at each step the model reads a three-cell window of an external "working memory" (a rendered table) and outputs one step (a digit, a carry/borrow, the next operation). A fixed runtime moves the window and writes no result digits. A Lean proof shows the model is exact on inputs of any length if and only if it is exact on the finite set of windows the runtime can present.
- Result: Qwen3.5-0.8B with a low-rank adapter passes all 2,446 windows. In the browser it gets 200/200 preregistered problems right, and 220/220 on additions up to 1,000 digits and multiplications up to 20 digits. Of ten other models, the strongest, GPT-6.1 Sol, gets 217.
- It touches bounded-window external working memory but is not an agent context-management paper.

## 📈 Still climbing

- [From Autonomous Agents to Cognitive Symbionts: Toward AI-Augmented Human Intelligence](https://arxiv.org/abs/2611.05376) · 👍 from 40 at first coverage (11-07) to 105. The 11-08 report had 114 and the 11-10 report 104; the counts differ slightly by source, and today's 105 is the figure used here. It is 7 days on the list, first seen 11-04.
  - A single-author (Hao Fei) vision and position paper. It proposes "cognitive symbionts": lifelong, embedded, real-time, private, low-friction, proactive companion AI that keeps a user's context across years. The core idea is the cognitive gap between what a person can bring to a situation and what working memory can hold. The design space is a loop of sense, retain, understand, co-exist, act and think on the user's behalf, and grow, surrounded by a personal runtime and trust. It also discusses governance risks such as covert help during exams and pressure on everyone to adopt.
  - The abstract reports no experiments and there is no code. It is on the list because the concept is attractive. It has been listed for several days (see the 11-07, 11-08 and 11-10 reports and the W45 weekly), and it still has no experiments.

## 🆕 New: announced last night

Ordered by relevance, with Agent Context papers first.

- [Don't Just Trust Your Memory (WikiTrace)](https://arxiv.org/abs/2611.14320) (👍43): each experience is stored as a short insight linked to a summary of why it succeeded or failed and to the raw trajectory. On a new task, when an insight is thin, conflicting or from a failed task, the agent follows the links back with a terminal tool to supplement or correct it. It beats existing memory methods on five agent benchmarks and reduces memory-induced degradation. Code: [yukyeongleee/wikitrace](https://github.com/yukyeongleee/wikitrace) ⭐4.
- [When Should Agents Remember? Falsification-Gated Self-Evolution (FGSE)](https://arxiv.org/abs/2611.14326): candidate experiences are written as hypotheses with preconditions, behavior change, expected effect and a verifier. They are tried in a temporary state and tested with transfer, falsification and regression probes before being committed, revised or rejected. It gets 39.8 success on WebArena and 78.8 average completion on AppWorld, and harmful committed updates drop to 3.6%.
- [Coding Agent Memory Post-Training II (CAMP-II)](https://arxiv.org/abs/2611.14009): when a long-horizon task's interaction history outgrows the context, the policy uses plain Bash and a workspace that persists across context replacements, treating files as memory. It trains with fully asynchronous on-policy distillation from a frozen teacher fluent in file operations. On the new CAMG-II environment set it improves 2.97x over the strongest OPD baseline, and transfers to Terminal-Bench 2.1 and SWE-Bench Pro V2.
- [TreeAgent](https://arxiv.org/abs/2611.13946): splits long structured inputs such as JSON and HTML by subtree instead of fixed length, attaches structural paths to chunks, and adds residual memory links from low-level child nodes to higher-level parents. On inputs of 8K to 1M tokens, four memory agents improve 3.61% on average.
- [SHADOWPREFILL](https://arxiv.org/abs/2611.13176): when an agent routes between models step by step, switching models throws away the prefix cache. It uses idle capacity to prefill the session context on the next model that was not selected. Switch-call latency drops 8.5% to 21.4% and routing token cost 22.5% to 46.1%.
- [World In-Context Learning for Agentic Robot Manipulation (RoboScript)](https://arxiv.org/abs/2611.12885) (👍52): a frozen model rehearses in simulation from one demonstration and writes the feedback into context (Task Memory) instead of weights. Average success across all 50 RoboTwin 2.0 tasks is 83.4%, over 20 points above the strongest trained policy. Code: [ArcheOne-AI/RoboScript](https://github.com/ArcheOne-AI/RoboScript) ⭐47.
- [Program-Aided Patchable Skill Evolution (PASE)](https://arxiv.org/abs/2611.14019): splits the procedural logic in a Skill into editable executable programs, so updates patch the program instead of repeatedly rewriting natural language. The abstract claims gains above 2.8%.
- [ARE-bench](https://arxiv.org/abs/2611.14364): 75 tasks taken from researchers' real sessions and uncleaned workspaces, testing whether agents respect earlier decisions and existing workspace state. The best model passes every check on only 66.2% of tasks. With history and workspace requirements added, three models fall from about 69% to 28.4%–40.0%.
- [MMDM: Measuring Massive Multitask Decision Making](https://arxiv.org/abs/2611.14309) (👍24): 5,448 questions in 16 categories covering agent state tracking and tool and Skill selection, with inputs up to 64,817 tokens. Across 28 decision models, the best Hard multiple-choice accuracy is 36.81%. It belongs to the same Jev-style "decision model" line as [Flide](https://arxiv.org/abs/2610.42148).
- [BioMem](https://arxiv.org/abs/2611.13426): benchmarks five agent memory schemes in biomedical settings and proposes HMRU, which needs no training. It improves 8.6% on average relative to baselines, cuts dialogue answer errors by 24.9%, and closes 48.0% of the gap to full-context reasoning.
- [FINCOSMOS](https://arxiv.org/abs/2611.07464) (👍16): an open-world benchmark for finance agents in which a simulated user hides its strategy. None of 150 sessions was accepted, but agents with persistent memory learned all ten tasks after feedback.
- [Tree-Ising](https://arxiv.org/abs/2611.14210) (👍59, highest in the new batch): repairs language-model weights with bit-level Ising edits, against the approach of having an agent read weights and write fixes. With 0 LLM tokens it reaches 54.6% on MATH-500 (agent edits: 51.7%). It is model repair and only loosely tied to agents.

## Observations

- Memory writes get verified first. In the new batch, WikiTrace (checking against the original trajectory) and FGSE (falsify, then commit) both address bad experiences polluting memory. ARE-bench also shows pass rates dropping sharply once history and workspace requirements are added. This is the clearest theme today, but most of these papers have few votes (WikiTrace's 👍43 is the exception), so it is an early signal.
- Prefix caching and the inference side: [Flide](https://arxiv.org/abs/2610.42148) (⭐430, the most stars among hot papers) and the new SHADOWPREFILL both deal with prefix reuse over long agent histories, which matches engineering demand for KV cache and prompt cache.
- Evaluation is moving to long horizons and real workspaces. Infrathon (24-hour budget), ARE-bench (real sessions and workspaces), AutoVend (180 simulated days) and Longtail-SWE all test agents over long horizons in realistic environments.
- Today's input has no GitHub project data, so this section covers papers only.
- Most hot-list vote counts are low. Apart from Flide, every Context pick has 5 or fewer, so none of these are breakout hits.
