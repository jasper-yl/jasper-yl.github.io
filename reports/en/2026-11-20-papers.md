## 🔥 Trending: Agent Context picks

### [The Resolution Hypothesis: Agent Evolution's Key Is Identifying Improvements](https://arxiv.org/abs/2611.23068)
- Heat: HF 👍36 (1 day on the list, +4, 32 when first seen); no code repo.
- Problem: Why does agent self-evolution (evolving prompts, skills, memories) so often stall, with papers' methods trading wins?
- Method: Experiments on 7 evolution methods and 6 models, over 10M LLM calls. Two levels of testing: at the candidate level, whether selection can tell good artifacts from bad; at the method level, whether method rankings are stable.
- Result: Helpful candidate artifacts exist, but selection is no better than random at telling good from bad, and errors accumulate round after round. Gaps of a few percentage points between methods are smaller than the difference between two independent runs of the same method, so published rankings often come down to luck. The bottleneck is identifying improvements, not proposing them.

### [Thinking Fast, Anywhere: One System-1 for the Decision Points of Any Agent Workflow (AnyS1)](https://arxiv.org/abs/2611.23751)
- Heat: HF 👍14 (1 day on the list, +11, 3 when first seen); code [middle-chunjie/AnyS1](https://github.com/middle-chunjie/AnyS1) ⭐3.
- Problem: Agents call a large model (System-2) at every step, which is slow and expensive. Existing dual-system designs need hand-written hooks for each environment.
- Method: Mines "enumerable decision points" from 1,000+ public Skills, collects execution traces in isolated containers, builds the Any-DP dataset, and trains a 4B pointer-style System-1 model. At runtime, a compiled workflow resolves routine decisions in one forward pass and falls back to System-2 when confidence drops below a calibrated threshold.
- Result: Task reliability holds on 3 unseen benchmarks, with per-episode cost down 75-91% and model-call time down 63-92%.
- Our take: A rare use of Skills as a source of decision structure. The link to context itself is indirect.

### [Folio: Recoverable Multi-Resolution Context Folding for Long-Horizon Language Agents](https://arxiv.org/abs/2611.16627)
- Heat: from arXiv, no HF upvotes (7 days on the list), no code repo. Heat is 0, but it is today's most direct context-folding paper, so it made the list.
- Problem: Long-horizon agents compress history by having the model summarize it, which means rereading and rewriting history every time. That is expensive.
- Method: The runtime records three views as it goes: short per-turn notes the model writes alongside its replies (L1), a per-call event manifest written by the runtime (L2), and the captured raw records (L3). When folding, the system programmatically picks a coarser view for older turns and prints handles that index L2/L3. Recovery tools read in pages and compute over full text inside files, and findings go into a persistent dossier. The fold trigger counts the retained budget toward where the context will land.
- Result: On 75 LOCA-bench tasks with DeepSeek-V4-Pro, Folio solves 66. The same runtime with model-written compression solves 54, and Claude Code, Codex and SoL-Pi solve 49-59. Folio takes about half their time, costs 2.4x less than the same runtime, and a fold takes 0.6 seconds at the median.

### [Discovering Effective Agent Memory Designs through Program Evolution (MAPE)](https://arxiv.org/abs/2611.17068)
- Heat: from arXiv, no HF upvotes (7 days on the list); code [ash-ding/MAPE](https://github.com/ash-ding/MAPE), star count not given in the data.
- Problem: Agent memory is designed by hand, and nobody knows which design choices actually matter.
- Method: MAPE starts from a minimal seed and evolves entire memory programs through a standardized lifecycle interface and an iterative diagnose-and-propose loop.
- Result: On LoCoMo and LongMemEval, it beats hand-designed baselines by up to 12% absolute accuracy at 35% of the serving cost. Two design rules emerge: keep raw conversation as retrievable evidence, because extractive memory loses detail; and organize retrieved evidence by query intent. Porting the organization module into 5 existing memory systems improved all 5.

### [Continual-ARC: Measuring Skill Acquisition over a Working Lifetime](https://arxiv.org/abs/2611.14505)
- Heat: HF 👍2 (4 days on the list, -7, 9 when first seen); code [unifyai/continual-arc](https://github.com/unifyai/continual-arc) ⭐38. Upvotes fell on net; it made the list because its findings bear directly on memory.
- Problem: Continual-learning benchmarks are mostly single-domain, with each instance appearing once, so memory-based and weight-based systems can't be compared on one scale.
- Method: Builds a lifetime task stream from three ARC-AGI versions. The same task returns after a gap with new instances, new tasks keep arriving, and the learner pays from a feedback budget for demonstrations, submissions or retries. After the stream ends, the learner is frozen and tested on seen tasks (memory) and unseen tasks (generalization).
- Result: Persistence in a harness usually doesn't improve memory without explicit expert guidance. Most harness methods learn less than a "just cache each task's demonstrations" floor. No harness method gains on unseen tasks, while weight learning shows clear gains.

### [Reducing Batch Makespan for LLM Agent Workloads through Inference-Environment Coordination](https://arxiv.org/abs/2611.16661)
- Heat: HF 👍3 (7 days on the list, +3); no code repo.
- Problem: Batch agent jobs (evaluation, synthetic data, RL rollouts) alternate between LLM inference and environment interaction, so batches take long to finish.
- Method: For hybrid-architecture LLMs, a load-aware resource model splits GPU memory between KV cache and recurrent state. Trajectory-aware routing and scheduling encourage cache reuse and balance load. When environment capacity is limited, it decouples sample admission from environment execution, and it proposes CAAS, which schedules long chains first to shorten the batch tail.
- Result: Makespan drops 10.4%-65.0% on BFCL, SWE-bench Multilingual, WideSearch and MCP-Atlas, with evaluation scores unchanged.

### [AstroMemBench: A Benchmark for Memory Systems in Embodied Spacecraft Agents](https://arxiv.org/abs/2611.16590)
- Heat: from arXiv, no HF upvotes (7 days on the list); code [flyingView/AstroMemBench-v1](https://github.com/flyingView/AstroMemBench-v1).
- Problem: Long-term autonomy for spacecraft depends on using operation history, and there is no matching memory test.
- Method: A scenario-challenge-capability approach turns requirements into executable memory tests: 16 memory sub-challenges, 140 templates, 2,240 instances, 9 tasks. A deterministic environment scores task completion, state change, safety and resource use.
- Result: Mem0, Chain-of-Memory, LightMem and RAG all beat the vanilla Pi Agent within a session, and none of the three memory systems clearly beats RAG. After a session restart, Mem0 leads RAG by 12.25 points. Gains come mainly from instruction retention and result reuse, not from continuous state tracking or energy reservation.

### [BLIP-Live: Balancing Timeliness & Firing Precision in Proactive Streaming Video Agents](https://arxiv.org/abs/2611.21553)
- Heat: HF 👍9 (1 day on the list, +4, 5 when first seen); no code repo (the abstract says one will be released).
- Problem: A streaming video agent should respond as soon as the evidence is sufficient, without responding too early, repeatedly or wrongly.
- Method: Builds the human-annotated BLIP-Live-780K dataset and the PAUC-F metric, and studies a model-agnostic inference harness and training recipe.
- Result: Sliding visual windows, online interaction memory and structured response output work best together. BLIP-Live-Qwen reaches SOTA on 4 proactive streaming benchmarks, beating baselines by up to 44% and several closed API models.
- Our take: The context angle is the online interaction memory component, a supporting piece.

## Observations
- Context management trade-offs: Folio (keep recoverable multi-level views) and GrepMem (lossless log plus grep) both try to avoid the lossy compression of model-written summaries, in opposite ways. [Embeddings vs. Grep](https://arxiv.org/abs/2611.20455) also points toward grep-style retrieval, which matches dense retrieval in code search.
- Skills and self-evolution reliability: The Resolution Hypothesis paper on the trending list and the two Skills self-evolution papers in the new batch ([SkillPlumber](https://arxiv.org/abs/2611.25429) and the [feedback-free study](https://arxiv.org/abs/2611.25534)) all concern how to judge improvements reliably, not how to propose more candidates. [Continual-ARC](https://arxiv.org/abs/2611.14505) separately shows that learning through harness persistence yields limited gains, while weight learning works better on unseen tasks.
- KV cache serving for agent workloads: The [batch makespan paper](https://arxiv.org/abs/2611.16661) on the trending list and [Aggron](https://arxiv.org/abs/2611.26435), [TripleKV](https://arxiv.org/abs/2611.25112) and [FrontierReplay](https://arxiv.org/abs/2611.26020) in the new batch all tune caching and scheduling for agents' multi-turn, tool-waiting pattern. This is the clearest cluster on the systems side.
