## Hot list: Agent Context picks

### [Folio: Recoverable Multi-Resolution Context Folding for Long-Horizon Language Agents](https://arxiv.org/abs/2611.16627)
- Heat: from arXiv, HF 👍0, 6 days on the list, no gain; no code link, no X data.
- Problem: once a long-horizon agent's history outgrows the context window, model-written summaries must reread and rewrite history on every compression, and they lose evidence.
- Method: the runtime keeps three views. L1 is a turn note the model writes in its normal reply, L2 is a runtime-generated event list per call, and L3 is the raw source record. To fold, a program picks a coarser view for older turns without calling the model, leaving handles that point to L2/L3. A recovery tool reads by page, computes over full files, and stores findings in a persistent dossier. The fold trigger is priced as "retained budget plus landing point."
- Result: on 75 LOCA-bench tasks (DeepSeek-V4-Pro base throughout), Folio solves 66. The same runtime with model-written compression solves 54, and Claude Code, Codex and SoL-Pi solve 49–59. It takes about half the time of the alternatives, costs 2.4x less than model compression in the same runtime, and the median fold takes 0.6 seconds.
- Our take: the paper closest to "context folding" on this list, with the hardest numbers, so it ranks first. Its heat is low only because arXiv papers carry no HF upvotes.

### [Self-Improvement Memory Enables Continual Recursive Self-Improvement](https://arxiv.org/abs/2611.18856)
- Heat: HF 👍31 (1 day on the list, +6); no code link, no X data.
- Problem: when a harness optimizer moves to a new benchmark or policy model, it can't tell which parts of an already-evolved harness to reuse or change, because the harness doesn't record why it was edited.
- Method: Self-Improvement Memory (SIM) remembers on behalf of the harness optimizer, not the policy model that does the tasks. It groups edits by recurring harness problem and records each edit's rationale, predicted outcome, actual outcome and evaluation context. New attempts extend that history.
- Result: across four domains, in cross-dataset and cross-model comparisons, SIM's final scores beat continuing with only the harness or only root causes. Over ten independent source runs in the coding domain, paired continuation averages 2.36 points above harness-only (p=0.003).

### [Discovering Effective Agent Memory Designs through Program Evolution](https://arxiv.org/abs/2611.17068)
- Heat: from arXiv, 👍0, 6 days on the list; code [ash-ding/MAPE](https://github.com/ash-ding/MAPE) (star count not in the data).
- Problem: agent memory schemes are designed by hand, and it is unclear which design choices matter.
- Method: MAPE starts from a minimal seed and evolves a whole memory program through a standardized lifecycle interface and a diagnose-then-propose loop. The search optimizes accuracy and serving cost together, and shifts compute from LLM-built memory to selective processing at query time.
- Result: on LoCoMo and LongMemEval, accuracy is up to 12% above human-designed baselines at 35% of their serving cost. Two design rules emerge: keep raw conversation as retrievable evidence, and organize retrieved evidence by query intent. Transplanting the organizing module into 5 existing memory systems improved all of them.

### [HeMeR: Heterogeneous Memory Reconciliation for Embodied Agents via Structured KV Reuse](https://arxiv.org/abs/2611.16487)
- Heat: from arXiv, 👍0, 6 days on the list; no code link.
- Problem: an embodied agent's declarative, procedural and working memory go through different interfaces, and every update is treated as new input, so the whole KV cache is recomputed.
- Method: HeMeR tracks how the three kinds of memory content change between consecutive decisions. KV states for unchanged content are kept, and only KV affected by an update is reconciled.
- Result: 83.20% task success on a real robot, and per-step inference time drops from 2.94 s to 1.87 s (versus MemRL).
- Our take: one of the few papers in this batch that directly targets KV cache reuse.

### [MemCredit: From Relevance to Utility for Decision-Time Memory in Long-Horizon Web Agents](https://arxiv.org/abs/2611.15600)
- Heat: from arXiv, 👍0, 6 days on the list; no code link.
- Problem: the memory most semantically similar to the current state is not necessarily the one that best improves the next action.
- Method: controlled counterfactual interventions estimate each memory's marginal contribution, which is then distilled into a lightweight utility estimator. At inference, semantic relevance only produces a high-recall candidate set, and predicted utility decides which memories to keep under a fixed token budget. No policy change and no extra environment interaction.
- Result: on ALFWorld with a 500-token history-memory budget, SR@50 is 86.57 versus 65.67% for BM25 retrieval. The abstract says memory utility is sparse and strongly state-dependent.

### [DISCERN: Preserve at Write, Resolve at Read for Persistent LLM-Agent Memory](https://arxiv.org/abs/2611.15729)
- Heat: from arXiv, 👍0, 6 days on the list; no code link.
- Problem: memory that enterprise agents accumulate over many sessions contains contradicting and superseded facts, and similar entities blur together in embedding space. The authors argue recall is largely solved and "resolution" is not.
- Method: at write time, it builds an append-only bitemporal provenance graph that neither merges confusable entities nor discards superseded values. At read time, an agent loop with a zero-LLM tool surface navigates the graph and must end with one of four controlled terminal actions.
- Result: on ENT-310, abstention F1 is 0.924 (best of eight baselines: 0.802) and macro answer accuracy is 0.861 (strongest baseline: 0.806). Entity resolution scores 0.800, and no baseline exceeds 0.40. On full LoCoMo, macro accuracy is 0.663 versus 0.638.

### [Continual-ARC: Measuring Skill Acquisition over a Working Lifetime](https://arxiv.org/abs/2611.14505)
- Heat: HF 👍2 (3 days on the list, -7, from 9 when first seen); code [unifyai/continual-arc](https://github.com/unifyai/continual-arc) ★38.
- Problem: existing benchmarks are mostly single-domain, show each instance once, and can't compare memory-based and weight-based continual learning on one scale.
- Method: three generations of ARC-AGI tasks form a lifelong task stream, and the same task returns after a gap with new instances. A learner can pay to see demonstrations, submit answers or act inside a harness, and is scored on the feedback budget it uses. After the stream ends, the learner is frozen and memory and generalization are tested separately.
- Result: a frozen-weight harness with persistence generally doesn't improve memory unless given explicit expert guidance. Most harness-based methods learn less than a floor that simply caches each task's demonstration. No harness method gains on unseen tasks, while weight-based learning gains clearly.
- Our take: negative evidence on whether harness memory can learn continually. Worth reading alongside SIM and ARISE.

### [Reducing Batch Makespan for LLM Agent Workloads through Inference-Environment Coordination](https://arxiv.org/abs/2611.16661)
- Heat: HF 👍3 (6 days on the list, +3); no code link.
- Problem: agent tasks for evaluation, synthetic data and RL rollouts alternate between LLM inference and environment interaction, so batches take long to finish.
- Method: for hybrid-architecture LLMs, a load-resource model splits GPU memory between KV cache and recurrent state and suggests a concurrency level. Trajectory-aware routing and scheduling improve cache reuse while balancing load. Chain-Advancing Action Scheduling (CAAS) prioritizes long chains by observed progress, shortening the batch tail.
- Result: on BFCL, SWE-bench Multilingual, WideSearch and MCP-Atlas, makespan falls 10.4%–65.0% with evaluation scores unchanged.

## Observations

- **Context management is moving from summaries to layered storage with on-demand retrieval.**
  - Folio (L1/L2/L3 with handle-based recovery), today's [Semantic Context Handoff](https://arxiv.org/abs/2611.24357) (state separated from evidence), [Resolution as Attention](https://arxiv.org/abs/2611.24422) (resolution tuned by relevance) and DISCERN (preserve at write, resolve at read) all avoid one-shot summarization.
  - They share one pattern: keep the raw evidence first, then decide how much to bring back.
- **Memory is judged by utility instead of relevance, and its design is being automated.**
  - MemCredit swaps semantic relevance for decision utility. MAPE searches memory structure by program evolution. SIM and ARISE let memory evolve from failures and edit history.
  - Counter-evidence comes from Continual-ARC: persistence in a frozen-weight harness brings no gain on unseen tasks.
- **Evaluation, not proposal generation, is named as the bottleneck for self-evolution.**
  - [The Resolution Hypothesis](https://arxiv.org/abs/2611.23068) says evaluation noise often makes method rankings a matter of luck. That is worth reading next to the results from SIM, ARISE and MAPE.
  - It is a single paper's claim, with only preliminary heat (HF 👍32).
- **The harness is the main engineering lever, and practitioners say so too.**
  - ForceHarness and SilentGuard put control logic outside the model. The MLE Agents authors say the loop design around the model matters as much. SkillCFI compiles skills into enforceable contracts. AscendGYM evaluates models and harnesses side by side.
  - The data has no GitHub project growth figures, so this covers the paper side only, with no link to engineering projects.
