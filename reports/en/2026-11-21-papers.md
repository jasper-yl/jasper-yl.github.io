## Hot list: Agent Context picks

### [CarryOn: Learning What to Keep in Context for Long-Horizon LLM Agents](https://arxiv.org/abs/2611.17808)
- Heat: arXiv only, no HF upvotes (👍0); on the list 5 days (first seen 11-16); heat 0.0; no code repo. Included because it is the most direct context-management paper today.
- Problem: Long-horizon agent histories keep growing. Summarizing and pruning drop exact details that later actions need, while keeping everything drags in irrelevant material.
- Method: A lightweight context manager pairs a compact execution state with fine-grained, traceable evidence. A learned selector plus an adaptive retention policy decides what stays, and managing context needs no extra LLM calls. The paper proposes two metrics: S_α (task success first, with resource use factored in) and NCS (normalized cost per successful task).
- Result: On AppWorld, OfficeBench and Tau2 Telecom with 3 LLM actors, macro-average task success is 75.7%, 6.7 points above the strongest baseline, and it also has the best average on both metrics.

### [Continual-ARC: Measuring Skill Acquisition over a Working Lifetime](https://arxiv.org/abs/2611.14505)
- Heat: HF 👍2; on the list 5 days; was 9 at first sighting, now 2 (-7); [unifyai/continual-arc](https://github.com/unifyai/continual-arc) ★38. Upvotes fell back and heat is only 2.8, so it made the list for topic fit, not heat.
- Problem: Existing continual-learning benchmarks are single-domain and show each instance once, so memory-based and weight-based systems can't be compared on one scale.
- Method: Builds a lifetime task stream from three ARC-AGI versions. Old tasks return after a gap with new instances, and new tasks keep arriving. The learner can pay to see examples, submit answers or act in a harness, and is scored on the feedback budget it spends. After the stream ends it is frozen, then tested separately on memory (seen tasks) and generalization (unseen tasks). Compared systems: frozen-weight harnesses with and without persistence (Qwen3.5-9B, GLM-5.3 Flash), two prompting baselines, a program-induction method, and distilled Qwen3.5-9B weights.
- Result: Harness persistence generally doesn't improve memory unless there is explicit expert guidance. Most harness methods learn less than a baseline that only caches each task's examples. No harness method improves on unseen tasks, while weight learning improves clearly.

### [Embeddings vs. Grep: Rethinking the Dense Advantage in Code Search](https://arxiv.org/abs/2611.20455)
- Heat: HF 👍7; on the list 1 day, +4; no code repo.
- Problem: Dense encoders beat BM25 by a wide margin on code-search benchmarks, yet coding agents do well with grep. What is that advantage measuring?
- Method: Builds Repo-Premium, a repo-level code-search benchmark covering Python, JS, TS, Go, Rust and Java, with PRs from 2022 to 2026 and a preregistered test pool of 91 repos. It attributes the dense advantage to two sources: evaluation choices that favor dense retrieval (chunking for BM25, counting edited test files as relevant) and queries that lack the rare identifiers found in code. Having an LLM write identifiers to expand the query (generate-then-grep) helps BM25 far more than dense retrieval and matches dense retrieval in every Python pool, including PRs opened after LLM release.
- Result: No method predicts which retriever will win on a given query. The paper gives three recommendations: compare against a fair lexical baseline, fuse dense and BM25, and add the missing code vocabulary to queries.

### [Forget the Lineage: Forward-Secure, Lineage-Complete Cryptographic Erasure for LLM-Agent Memory (LinEra)](https://arxiv.org/abs/2611.18133)
- Heat: arXiv only (cs.CR), no upvotes; on the list 5 days; heat 0.0; no code link.
- Problem: An agent's long-term memory is written by the model itself (summaries, extracted facts, embeddings). Deleting the original message isn't enough, because derivatives, storage remnants and backups remain.
- Method: LinEra encrypts each memory with a key derived from its parent's key, passed down the derivation graph. The root key comes from a puncturable PRF, so forgetting takes one puncture and every descendant becomes unreadable without having to locate it. A sound lineage rule records everything the writer saw as a parent. It is integrated with mem0, with proofs of security and lineage completeness.
- Result: Tested on LoCoMo conversations with real 1.5B–7B LLMs writing the memories. On 10 conversations written by the largest model, an attacker with all files and the current key recovers 70 of 71 forgotten secrets after logical deletion, 67 under per-object or per-epoch keys, and 0 under LinEra. The cost is a larger forgetting radius that depends on the writer's fan-in. Forgetting 1% of turns erases 73.0% of derived memories under session-level summaries but only 3.8% under four-turn windows, which also answer better. Re-derivation can restore what was erased.

### [AutoMaster: Autonomous Post-Training by Making the Same Model a Better Teacher](https://arxiv.org/abs/2611.26510)
- Heat: HF 👍14 (highest among the Context picks); on the list 1 day, +4; [RUCAIBox/AutoMaster](https://github.com/RUCAIBox/AutoMaster) ★16.
- Problem: Task success doesn't say which behaviors to reinforce. Successful teacher trajectories can still contain unfounded assumptions, pointless repetition and superficial verification.
- Method: Proposes Skill-FT. During teacher rollouts, natural-language skills suppress bad habits and elicit missing useful behaviors, and the resulting trajectories are used to fine-tune the target model. AutoMaster is an LLM-agent system that does the trajectory analysis, skill design and data selection on its own and iterates on feedback.
- Result: On Terminal, Search and software-engineering tasks with 4B and 9B target models, it beats plain SFT on successful unguided teacher trajectories by 1.42–8.99 points on average. Keeping the skill instructions during SFT beat dropping them in all 6 settings, even though they are absent at evaluation and the supervised outputs are identical. Keeping the skill context as part of the training demonstration seems to help the behavior sink in.

### [Do LLM Agents Still Need to Be Told How to Self-Improve?](https://arxiv.org/abs/2611.23219)
- Heat: HF 👍6; on the list 3 days, +3; [ssundaram21/self-org](https://github.com/ssundaram21/self-org) ★3. Authors include Phillip Isola.
- Problem: Do more capable models still need humans to prescribe how they improve themselves?
- Method: A frozen LLM agent gets a compute budget plus tools to collect experience and update text documents. It experiments freely in games, with no externally imposed loop and no contact with real data. It builds its own "context-based optimization" algorithm, and what it learns is the text documents (the context), not the weights.
- Result: Sufficiently strong models do self-improve. Their strategies match the ideas of self-regulated learning and self-generated curricula, and the learned text artifacts transfer to different game lengths, different mechanics and an external 3D-navigation benchmark.

### [Invariant-Aware Harness Enforcement to Protect LLM Agents from Silent API Failures (SilentGuard)](https://arxiv.org/abs/2611.20595)
- Heat: HF 👍5; on the list 3 days, +2; [Sajib-006/silentguard](https://github.com/Sajib-006/silentguard) ★1.
- Problem: APIs can fail silently, ignoring part of a request (a misspelled filter, say) while returning HTTP 200 and a plausible wrong result. Checklists, reviewer models and LLM judges all leave the model to catch it, and models often see the problem and answer anyway.
- Method: Moves the judgment from the model to the harness that executes tool calls. The harness checks every result against invariants any correct API must satisfy and withholds the value on a violation.
- Result: 11 of 15 public research APIs have silent failures, with counts inflated up to 691x. Existing fixes still leave over 70% of answers wrong. Across 7 open-source models, error on targeted failures drops from 74.0% to 1.7% with no loss on failure-free tasks; for 3 frontier models it drops from 70.2% to 0.5%. The same check used only as a warning still leaves 70.1% errors, so enforcement is what matters. On new failure types the harness alone cuts error from 61.1% to 24.5%, by abstaining rather than recovering.

### [System 1 agents: a method for local, reliable and fast agentic AI](https://arxiv.org/abs/2611.21053)
- Heat: HF 👍6; on the list 1 day, +4; [eltzanis/SystemOneAgents](https://github.com/eltzanis/SystemOneAgents) ★12.
- Problem: Local LLMs hallucinate, and invented values in a tool call propagate into every later step.
- Method: A deterministic compiler turns each tool's schema and the request into a multiple-choice question, with options drawn from the request and schema. A single-forward-pass decision model answers it, with no text generation at all.
- Result: On 1,952 requests across 157 biomedical tools, the best System 1 agent picks the right tool (or correctly refuses) 97.0% of the time, above all 18 local-LLM agent setups (best 95.2%). It fills 97.0% of 6,056 given parameter values correctly. System 1 calls contain no fabricated content, versus 5.5–19.7% for LLM calls.

## Observations

- Context management is moving from "how much to compress" to "what to keep". CarryOn pairs execution state with traceable evidence and a selector (75.7%, +6.7 points). In AutoMaster, keeping skill instructions in the training demonstrations works better. LinEra addresses how to delete memory.
- Negative or cautious evidence on harnesses with memory: Continual-ARC (most harness methods trail the example-caching baseline, no gain on unseen tasks) and Embeddings vs. Grep (the dense advantage is inflated by evaluation choices, and BM25 with LLM-expanded terms catches up). This could be compared with the grep-heavy practice of real coding agents, but the data has no matching GitHub project.
- Reliability work centers on enforcement in the harness layer rather than leaving the model to judge: SilentGuard (warnings alone still leave 70.1% errors), System 1 agents (tool selection without text generation, no fabricated content) and Unfinished-Bench (rules violated even after being displayed).
- The top three by heat (👍51/49/35) are video detection, an embodied benchmark and video generation. The best Agent Context paper has 👍14, and several context papers came straight from arXiv with no upvotes. The data has no X mention counts, so nothing can be said about social-media spread.
