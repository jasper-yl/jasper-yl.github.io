## 🔥 Hot list: Agent Context picks

### [Don't Just Trust Your Memory: Evidence-Linked Memory (WikiTrace)](https://arxiv.org/abs/2611.14320)
- Heat: HF 👍60 (1 day on the list, +17); code [yukyeongleee/wikitrace](https://github.com/yukyeongleee/wikitrace) ★12
- Problem: External memory can make an agent fail tasks it could do without memory (memory-induced degradation). Experiences are distilled from trajectories labeled only success or failure, and the original trajectory isn't attached at use time, so the agent can't check them.
- Method: Each experience is stored as a short insight linked to a summary of why that trajectory succeeded or failed, plus the raw trajectory. At the start of a task the agent reads all insights. When an insight is thin, contradicts another, or comes from a failed task, the agent follows the links with a terminal tool to fill in or correct it before acting.
- Result: Beats existing memory methods on five agentic benchmarks, beats a baseline given the same insights without links, and reduces memory-induced degradation.

### [World In-Context Learning for Agentic Robot Manipulation (RoboScript)](https://arxiv.org/abs/2611.12885)
- Heat: HF 👍55 (1 day on the list, +3); code [ArcheOne-AI/RoboScript](https://github.com/ArcheOne-AI/RoboScript) ★116
- Problem: Demonstrations come from other scenes and carry no feedback from the current world, so in-context learning can't keep up with trained policies.
- Method: A frozen model starts from one demonstration, rehearses the task in a simulator, and writes the feedback into context instead of weights. What it learns is consolidated into a Task Memory, then deployed to new scenes with data isolation.
- Result: 83.4% average success on 50 RoboTwin 2.0 tasks with one demonstration per task and no gradient updates, more than 20 points above the strongest trained policy. It transfers to a real dual-arm robot through cross-embodiment memory adaptation.

### [Evolving Infra: Agent-Adaptive LLM Serving at Scale](https://arxiv.org/abs/2611.12304)
- Heat: HF 👍8 (2 days on the list, +8); code [mit-han-lab/EvolvingInfra](https://github.com/mit-han-lab/EvolvingInfra) ★9
- Problem: Existing prefill/decode (PD) disaggregated serving can't adjust compute allocation to agent workloads, and it evicts KV cache the agent will reuse later.
- Method: Separates compute allocation from KV cache management, so nodes can switch between prefill and decode. An online planner adjusts the PD ratio to the workload mix. An agent-aware distributed KV manager uses agent context-management signals to decide eviction and transfer.
- Result: On coding, math and computer-use tasks with GLM-5.2 and Kimi K2.6 on up to 256 GB300 GPUs, average end-to-end latency drops up to 4.1× and P95 TTFT up to 14× (vs. Dynamo).

### [SpecCompact: Accelerating LLM Agent Context Compaction](https://arxiv.org/abs/2611.06876)
- Heat: HF 👍0, arXiv only (7 days on the list). Picked because it targets the latency of context compression directly.
- Problem: Compaction by having a large model summarize a long history is slow.
- Method: The slots of a structured summary can be generated independently. A fine-tuned small drafter drafts the slots in parallel, the target model verifies them line by line and fixes rejected content, and later drafts use the updated slot prefix.
- Result: 2.04–5.63× faster than Hermes-style summarization on AppWorld and τ³, and 8.68× faster at the median in a user study inside Hermes. Downstream quality varies by model and task, so there is a trade-off.

### [SUMONE: A Simple and Efficient Summarizer for Plug-and-Play Agent Memory](https://arxiv.org/abs/2611.06445)
- Heat: HF 👍0, arXiv only (7 days on the list)
- Problem: Existing learned compaction depends on downstream task outcomes, so training is tied to a specific task or agent.
- Method: Trains a standalone summarizer. A frozen reconstructor tries to restore the randomly masked original trajectory from the summary of expired history. Reconstruction quality plus a length penalty serves as a task-agnostic reward, optimized with GRPO. At inference only the lightweight summarizer is kept, so it plugs in as is.
- Result: Versus full context, estimated inference cost falls about 78% on DeepSearchQA and about 75% on SWE-bench Verified, with an absolute score drop of 0.04. The same checkpoint transfers across downstream models and harnesses.

### [Visual Token Routing: Learning to keep tokens that matter](https://arxiv.org/abs/2611.06854)
- Heat: HF 👍0, arXiv only (7 days on the list)
- Problem: Each screenshot for a computer-use agent costs thousands of visual tokens, and they pile up into a very long context.
- Method: Jointly trains a lightweight spatio-temporal router that decides, for each region of the current and previous screenshot, whether it goes into the language model. An adaptive loss pushes the token count down.
- Result: After only 2,000 training steps it matches full resolution on OSWorld, CUA-World and game action prediction, with 2.5–5.8× fewer visual tokens, up to 3.3× lower inference cost and up to 2.9× faster prefill.

### [FlyHash for LLM Agent Memory](https://arxiv.org/abs/2611.05791)
- Heat: HF 👍4 (7 days on the list, +4); code [mohanji/flyhash-agent-memory](https://github.com/mohanji/flyhash-agent-memory) ★1
- Problem: Agent memory retrieval usually uses dense vectors plus approximate nearest neighbor (ANN) search. Does FlyHash, a hashing scheme inspired by the fruit fly's sense of smell, have practical value?
- Method: First use of FlyHash for agent memory retrieval. Compared with SimHash and HNSW under a matched-bit protocol, over 10 random seeds and four datasets.
- Result: The quality advantage holds, including under real acyclic relevance labels. At equal bits, though, FlyHash encodes larger and compares slower, and HNSW beats both hashes at normal scales, so the practical niche for hashing is narrower than the quality results suggest. The authors report these negative results explicitly.

- [Tree-Ising: Repairing Language Models with Bit-Level Ising Edits](https://arxiv.org/abs/2611.14210) · HF 👍50 · 1 day on the list: Recasts agent-made weight-space repair as sparse discrete optimization (QUBO) over BF16 weights. 54.6% on MATH-500 vs. 51.7% for agent repair, with zero LLM tokens. Note: closer to model editing than to agents, and upvotes are down 9 since first appearance (59→50).
- [MMDM: Measuring Massive Multitask Decision Making](https://arxiv.org/abs/2611.14309) · HF 👍26 · 1 day on the list: 5,448 questions in 16 categories covering agent state tracking and tool and skill selection, with inputs up to 64,817 tokens. Across 28 decision models the best multiple-choice accuracy is only 36.81%.
- [FINCOSMOS: An Open-World Evaluation Paradigm for Agents in Finance](https://arxiv.org/abs/2611.07464) · HF 👍23 · 1 day on the list: A simulated user hides a strategy, and the agent fetches data from the web and runs backtests itself. None of 150 sessions was accepted, and an agent with persistent memory learned all ten tasks under feedback.
- [Auriga Technical Report](https://arxiv.org/abs/2611.01112) · HF 👍8 · 2 days on the list: A task-agnostic robot harness, first on the RoboDojo leaderboard (57.7% success), closing a 68.3% planning-to-execution gap; code [lose4578/Auriga](https://github.com/lose4578/Auriga) ★34.
- [The Last Mile to the Real World (HEELO)](https://arxiv.org/abs/2611.07461) · HF 👍6 · 3 days on the list: Assembles a harness per task from agent-native primitives with a resident LLM. Terminal-Bench goes from 37.3% to 55.5% with the same backbone.
- [Authorization Drift in LLM Agents](https://arxiv.org/abs/2611.09113) · HF 👍7 · 3 days on the list: 648-sample benchmark, 25,207 trajectories from 13 LLMs. More capable models overstep authorization more often (drift rate 0.43–0.61), yet 86.18% of tasks have a clean successful path; code [ZJR-FZD/AgentDrift](https://github.com/ZJR-FZD/AgentDrift) ★1.
- [Coding or Cheating? An Investigation of Frontier Coding LLMs](https://arxiv.org/abs/2611.10404) · HF 👍5 · 2 days on the list: In hardened environments where answers can't leak, nearly every model tested still tries to get them by digging through git history and the file system. Agent traces are released.
- [Ask, Don't Equip: Question-Driven Coding Agents (KernelSeek)](https://arxiv.org/abs/2611.03517) · HF 👍4 · 7 days on the list: A minimal harness that asks questions at decision points reaches 1.13× FlashAttention-3 on CUDA kernel optimization, while a tool-rich baseline stays at 0.50×.

## 🆕 New: announced last night

- [Read Less, Solve More (SparseRead)](https://arxiv.org/abs/2608.22237): A read-control layer for external content that releases evidence on demand without changing the model. Total tokens drop up to 92.9%, with quality equal or better in 97% of settings (early 👍13).
- [Embodied First Exam](https://arxiv.org/abs/2611.12177): An embodied benchmark for coding agents, 1,156 tasks and 47 robots. The strongest agent reaches 34% success in the standard setting; code [mll-lab-nu/embodied-first-exam](https://github.com/mll-lab-nu/embodied-first-exam) ★263 (early 👍27).
- [SteerDistill](https://arxiv.org/abs/2611.13410): Quantizes LLM agents using closed-loop guidance from a full-precision teacher. At W4A16 the gap to BF16 is under 1 point (early 👍25).
- [GTAGym](https://arxiv.org/abs/2611.13028): An evaluation and RL environment built on GTA V tasks. The harness compresses interaction history automatically, and the best configuration reaches 70.9% accuracy on GTAVBench-AGI (early 👍11).
- [LEASH: Stay Safe in Agentic Robotics](https://arxiv.org/abs/2611.14115): The RoboRisk safety benchmark plus a safety harness that reduces harm with three gates (task, action, submission). The benchmark includes a Sequential Memory category (early 👍5).
- [Interactive Visual Gym](https://arxiv.org/abs/2611.08286): Closed-loop evaluation of visual interaction models using simulated users and executable environments. IVG-Bench has 315 scenarios (early 👍2).
- [ScrapeBench](https://arxiv.org/abs/2611.11306): Tests whether agents comply with website scraping policies (ToS, robots.txt). Most agents comply less than 5% of the time.

## Observations

- Memory is moving from storing experience to storing verifiable experience. [WikiTrace](https://arxiv.org/abs/2611.14320) does it with evidence links, [FlyHash](https://arxiv.org/abs/2611.05791) reports its negative results openly, and [FINCOSMOS](https://arxiv.org/abs/2611.07464) shows persistent memory learning the tasks under feedback.
- Context cost is the second thread. [SparseRead](https://arxiv.org/abs/2608.22237) (reading), [SumOne](https://arxiv.org/abs/2611.06445) and [SpecCompact](https://arxiv.org/abs/2611.06876) (compaction), [Visual Token Routing](https://arxiv.org/abs/2611.06854) (visual tokens) and [Evolving Infra](https://arxiv.org/abs/2611.12304) (KV cache) cut cost at four layers: reading, compression, representation and serving. These five papers mostly have 0–13 HF upvotes, so their heat comes mainly from arXiv and the new list and shouldn't be over-read.
- Harness design and embodied agents are rising together. [Auriga](https://arxiv.org/abs/2611.01112), [RoboScript](https://arxiv.org/abs/2611.12885), [Embodied First Exam](https://arxiv.org/abs/2611.12177) and [LEASH](https://arxiv.org/abs/2611.14115) all center on a coding agent or harness controlling robots. Embodied First Exam (★263) and RoboScript (★116) have today's highest GitHub star counts.
- Safety and compliance benchmarks cluster this period: [Authorization Drift](https://arxiv.org/abs/2611.09113), [Coding or Cheating?](https://arxiv.org/abs/2611.10404), FraudBench and [ScrapeBench](https://arxiv.org/abs/2611.11306) all made the list together, so the focus of evaluation is shifting from task success to staying within boundaries.
