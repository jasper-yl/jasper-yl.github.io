## 🔥 Hot list: Agent Context picks

### [Who Remembers What? Multi-Granularity Memory Extraction for Multi-User, Multi-Agent Interaction](https://arxiv.org/abs/2611.10439)
- Heat: HF 👍8 (on the list 1 day, +1); no X mentions; no code repo.
- Problem: when self-evolving agents share experience, nothing decides who benefits from each piece or which details must stay private.
- Method: MixUA distills each user-agent trajectory into lessons, then files each one under one of four scopes: user-agent pair, user, agent, or global, based on who benefits and what may be disclosed. It is evaluated on a new benchmark, CrossLearnBench, which pairs existing agent tasks with user preferences and privacy probes to check whether private facts leak into memory others can read. The setup has 5 users and 7 agents.
- Result: pass rate is up to 16 points above no memory and 5 points above a single global memory. It keeps up to 90% of declared preferences, and privacy probes find the protected content in forbidden scopes at most 0.02% of the time.
- Take: the most-upvoted Agent Context paper today. Its appeal is scoped memory and privacy, beyond retrieval accuracy.

### [Experience-Handoff Reinforcement Learning for Recursive Self-Improvement](https://arxiv.org/abs/2611.16409)
- Heat: HF 👍5 (on the list 2 days, +4); no X mentions; code [doyoungkim-ml/ehrl](https://github.com/doyoungkim-ml/ehrl) ⭐3.
- Problem: existing harnesses reflect on or compress experience and pass it to later rollouts, but the generation of those handoff artifacts (such as a playbook) is not itself learned.
- Method: with the Agentic Context Engineering (ACE) harness held fixed, one model is trained to play three roles: action generator, insight reflector and playbook curator. Candidate experience artifacts are scored by their downstream effect on later actor rollouts, and the three roles are optimized together.
- Result: held-out performance beats baselines on several agentic benchmarks. The abstract's point is that training should optimize not only the current action but also the model-written experience that later rollouts inherit.

### [HiVe-Mem: Interleaving Horizontal Memory Expansion and Vertical Evidence Composition for Multimodal Agents](https://arxiv.org/abs/2611.12872)
- Heat: HF 👍4 (on the list 2 days, +1); no X mentions; code [ViktorAxelsen/HiVe-Mem](https://github.com/ViktorAxelsen/HiVe-Mem) ⭐0.
- Problem: as multimodal agents accumulate long interaction histories, semantic retrieval over compressed memory misses relevant items and can't adapt to the different evidence forms different queries need.
- Method: horizontally, text and visual anchors link memory fragments into a relation graph, and retrieval expands from semantic-search seeds to related neighbors. Vertically, each memory keeps several evidence forms (summary, caption, grounded visual view, original image, interaction history), and a lightweight trainable selector picks the evidence subset per memory.
- Result: on 3 multimodal memory benchmarks, every base model improves, and token use is about 90% lower than the most economical competing multimodal baseline.

### [Can LLM Agents Organize Their Own Memory?](https://arxiv.org/abs/2611.11929)
- Heat: HF upvotes 0 in the data (arXiv-sourced, on the list 5 days); no X mentions; code [Qi202/SoMem](https://github.com/Qi202/SoMem) (star count not provided).
- Problem: current memory relies on predefined records and fixed organization rules, which adapt poorly to changing tasks.
- Method: SoMem stores memory as plain documents that link to each other. The agent decides what to summarize, how to group, and when to revise a topic, and every summary links back to the raw interaction as evidence. The runtime validates updates and derives time, relation and recency views automatically. At query time the agent chooses what to search and read, and follows links back to raw evidence.
- Result: it beats the strongest baseline by 2.66, 3.10 and 2.00 points on LoCoMo, BEAM-100K and LongMemEval-S, and the memory it builds is reusable across models.

### [MIRIX-2.0: Multi-Agent Memory System](https://arxiv.org/abs/2611.12068)
- Heat: HF upvotes 0 in the data (arXiv-sourced, on the list 5 days); no X mentions; the abstract says code is public, but the data has no link.
- Problem: in long-term memory, parametric memory needs training, merging permanently loses detail, and keeping every record makes storage grow without bound.
- Method: 6 typed memory agents keep full records as the source of truth. A provenance hypergraph indexes episodic and semantic records, with n-ary frames referencing source lines. Retrieval runs under an explicit budget, so the amount retrieved does not grow with history. AutoDream merges duplicate anchors off the write path (without rewriting records) and distills task sessions into skills.
- Result: 91.4% on LoCoMo and 72.6% on LongMemEval-S (14.3 points ahead of the strongest baseline). On MetaClaw-Bench it scores 49.2% against 44.0% for the MetaClaw skill library. It is most accurate on 4 of 5 QA benchmarks. With AutoDream off, it is faster than HyperMem on all 5 timed benchmarks.

### [Compaction, decay and reinforcement in a two-tier conversational memory: a paired evaluation against retrieval-augmented generation](https://arxiv.org/abs/2611.09807)
- Heat: HF upvotes 0 in the data (arXiv-sourced, on the list 6 days); no X mentions; no code repo.
- Problem: should a conversational agent keep raw transcripts and retrieve from them (RAG), or compress each turn into atomic facts and retrieve those?
- Method: a paired comparison on the 1,985 LoCoMo questions, with the same generator, judge and store, and an exact McNemar test on the 512 questions where the two disagree.
- Result: on the 4 categories where comparable work reports results, compaction scores 71.4% against 64.6% for RAG, a 6.8-point lead (p = 5.5e-08), with 34% fewer prompt tokens. Counting all 5 categories, including adversarial, the lead shrinks to 2.0 points and is not significant, because RAG leads by 14.6 on adversarial questions. Compaction keeps factual assertions and drops wording, so it wins when the answer is a value and loses when the answer needs the original phrasing.
- Take: a bounded empirical answer to "compress or keep the original", worth picking.

## Observations

- Memory research is shifting from "is retrieval accurate" to governance and boundaries. MixUA handles scope and privacy. [MemoryDojo](https://arxiv.org/abs/2611.09721) handles poisoning risk: 155 multi-session long-horizon trajectories, 4 domains, 5 memory systems. Its finding is that every memory system can be poisoned, to very different degrees (arXiv-sourced, upvotes 0).
- The compress-versus-keep-the-original tradeoff is clearer. [2611.09807](https://arxiv.org/abs/2611.09807) shows compaction wins when the answer is a value and loses when the answer needs the original wording. SoMem keeps every summary linked to the raw interaction. MIRIX-2.0 keeps full records as the system of record and budgets retrieval. None of the three throws away the original.
- Experience and skills are being treated as things to learn. EHRL trains playbook generation. [From LoRA to Language](https://arxiv.org/abs/2611.09454) asks whether skill documents encoded into a LoRA can be written back out as text: the Executing Writer recovers 39-44% of key instructions, and Llama-3.1-8B on ALFWorld goes from 5% to 55% (arXiv-sourced, upvotes 0).
- Long-horizon evaluation and harness simplification: Infrathon shows evaluation length changes the conclusions, and JustRUA shows a lean harness with full history gives a large score gain.
- Engineering side: this run has no GitHub project data, so no link to engineering projects is drawn. The repo data that exists is all small (Infrathon's ⭐37 is the highest, the rest are ≤10).
