### [Evolving to Match Capabilities: Improving Harness Self-Evolution via Skill Adaptation](https://arxiv.org/abs/2610.33024)
- Heat: HF 👍32 (4 days on the list, +21); code [zhihaoyang30/skill-adaptation-code](https://github.com/zhihaoyang30/skill-adaptation-code) ⭐6
- Problem: a skill in a harness helps strong models but can be useless or harmful for weak ones.
- Method: Across 7 models and 3 benchmarks, the authors found 103 task-skill pairs. The same skill added 31.1 points for GPT-5.6-luna and cost Gemma-4-E4B 8.8 points. In runs where weak models failed, 86% of the violated requirements were already written in the skill. From failures in tool execution, context management, instruction following and verification, the authors distilled a fixed meta-skill. Kimi-K3 uses it to rewrite skills so they are easier to follow. The rewrite then goes into a five-round self-evolution loop, where each model rewrites its own skill from trajectories and verifier feedback.
- Result: rewriting lifts 3 weak executors by 5.1–14.1 points. Inside the self-evolution loop, the final scores of 7 executors beat the loop without the meta-skill by 2.0–5.1 points.
- Take: part of the "adapt skills to the executor's ability" line of work, and directly tied to context management.

### [Skill^∞: Recursive Self-Improvement for Agent Skill Optimization](https://arxiv.org/abs/2610.35434)
- Heat: HF 👍11 (4 days on the list, +8); code [taowangcheng/Skill-Infinity](https://github.com/taowangcheng/Skill-Infinity) ⭐6
- Problem: existing skill optimizers use hand-designed pipelines. Even when the meta-skill evolves, it stays locked into one pipeline and has to be relearned for every task.
- Method: A meta agent follows a meta-skill to diagnose execution traces, propose candidates, request independent review and allocate search budget. The same procedure optimizes both task skills and the meta-skill itself. The meta-skill is decoupled from task skills, so after being refined on several skill-optimization tasks it can be reused across domains. Both layers are standard packages loaded through native skill discovery.
- Result: on 83 SkillsBench tasks, the pass rate is 60.7%, against 56.4% for human-written skills and 54.5% for SkillEvolver.

### [Harness-Model Collaboration for Long-Horizon Continual Learning (HaMo)](https://arxiv.org/abs/2610.34724)
- Heat: HF 👍21 (3 days on the list, +16); no code repo
- Problem: long-horizon agents rely either on model adaptation or on external memory, so continual learning and fast reuse can't both be had.
- Method: Trajectories are distilled into strategy-level "experience cards" for immediate retrieval (non-parametric, fast). The model is trained with an experience-conditioned continual-learning objective, so it learns to interpret, ground and execute the retrieved strategies (parametric, slow). Compact, complementary trajectories are picked by retrieval coverage for parameter updates.
- Result: in-domain and under cross-domain transfer, it beats both harness-only and model-only adaptation, with better retention and adaptation.

### [ReGE: Stronger Agents through Experience Synthesis](https://arxiv.org/abs/2610.33861)
- Heat: HF 👍18 (3 days on the list, +5); code [TIGER-AI-Lab/ReGE](https://github.com/TIGER-AI-Lab/ReGE) ⭐1
- Problem: multiple attempts leave execution records full of facts, useful actions and failures. How do you turn them into guidance for the next attempt?
- Method: ReGE-Syn makes one coach call that turns bounded execution records and artifacts into self-contained guidance, linking task findings to suggested actions and common pitfalls. The student starts from the initial environment and adapts that guidance to its current observations. Generation, synthesis and execution all use the same base model, with no parameter updates and no stronger teacher.
- Result: Average accuracy across four benchmarks rises 9.9 points for GPT and 8.8 points for Claude. On a BrowseComp-Plus subset, guidance construction uses 98.2% fewer tokens than AggAgent (GPT) and 95.5% fewer (Claude). Joint synthesis yields much shorter guidance than stuffing in the raw history or summarizing each record independently.

### [Δτ-Bench: Pushing Agents Toward a Moving Capability](https://arxiv.org/abs/2610.34238)
- Heat: HF 👍28 (4 days on the list, +8); code [zjunlp/delta-tau-bench](https://github.com/zjunlp/delta-tau-bench) ⭐5
- Problem: large tool ecosystems evolve (tools disappear, get replaced, or gain more efficient alternatives), and current benchmarks don't test whether an agent can update the procedural knowledge it has accumulated.
- Method: The benchmark has 1,588 verified multi-turn tasks across 42 domains and 6 successive ecosystem states. The authors also propose Steward, an ecosystem manager that handles tools and procedural knowledge together through incremental skill maintenance and dynamic provisioning during task execution.
- Result: the strongest model or harness tested reaches only 42.3% task success. The early gains of existing skill-learning methods don't hold up once the ecosystem evolves. Steward has higher success under ecosystem change and lower skill-maintenance overhead.

### [Beyond Benchmarks: Can Small Open-Weight Models Get Real Coding Work Done?](https://arxiv.org/abs/2610.34241)
- Heat: HF 👍13 (4 days on the list, +12); no code repo
- Problem: once served locally, how far are small open-weight models from doing real coding work?
- Method: A systems experience report covering vLLM, SGLang, llama.cpp, MLX and several coding clients. The data comes from 4,165 coding-agent gateway turns, 623 debugging tasks and three delegated-research studies.
- Context-related evidence:
  - Models behind compatible endpoints differ in tool-call format, turn control, context behavior and cache reuse.
  - Median TTFT (time to first token) for saved cold-prefix requests is about 69.4 s, versus about 2.8 s for high-reuse requests (observational data).
  - In the two studies with a direct-coding comparison, direct coding had a lower frontier-model cost per verified success.
- Result: the authors say explicitly that the studies are not pooled and that they do not rank models or runtimes.

### [TAO: Tool-Aware Joint Scheduling for LLM-Based Agentic Serving](https://arxiv.org/abs/2610.37230)
- Heat: HF 👍58 (2 days on the list, +43); no code repo
- Problem: agent serving alternates between GPU inference and CPU tools. Existing systems ignore whether a tool result is ready and use heuristics for admission and placement, which wastes resources.
- Method: A value interface combines three signals: near-term tool readiness, node-level cache credit with time decay, and token footprint. Dynamic programming then jointly selects and places waiting sessions under capacity constraints.
- Result: across 12 model-workload-concurrency settings, against the best SOTA baseline on each metric, latency drops by up to 26.8%, TTFT by up to 36.3%, and decode throughput rises by up to 29.5%.
- Take: this combines KV cache with agent scheduling, and it is the most-upvoted context-related paper this period.

### [DraMaze: A Multi-Agent Pipeline with Future-Aware Memory for Diverse Microdrama Script Generation](https://arxiv.org/abs/2610.32002)
- Heat: HF 👍20 (5 days on the list, +12); no code repo
- Problem: in long-form script generation, plot mechanisms converge as generation proceeds. Conventional retrieval reinforces clichéd patterns and ignores history that matters for future plot.
- Method: Evolutionary tree search and mutation, guided by a trope memory, explore diverse causal paths. A "reverse narrative dependency tree" organizes, retains and retrieves historical memory according to future narrative goals.
- Result: on scripts of 60 episodes and up to 60,000 characters, repeated causal patterns fall 32.1%, and the Logic score is 82.5, 8.5 points above the best baseline.

## 5. Research trend observations

- Skills and experience are the main vehicle for self-evolution.
  - [2610.33024](https://arxiv.org/abs/2610.33024), [2610.35434](https://arxiv.org/abs/2610.35434), [2610.34724](https://arxiv.org/abs/2610.34724) and [2610.33861](https://arxiv.org/abs/2610.33861) all ask how to turn execution traces into reusable guidance.
  - They share an approach: no parameter updates (or only light ones), with experience compressed into short, self-contained text. ReGE's guidance construction uses over 95% fewer tokens, the most direct number for the gains from compression.
  - They also share a finding: a skill's effect depends on the executor's ability, and more text is not better ([2610.33024](https://arxiv.org/abs/2610.33024)).
- Cost and cache are entering mainstream agent research.
  - [2610.37230](https://arxiv.org/abs/2610.37230) adds cache credit to scheduling. [2610.34241](https://arxiv.org/abs/2610.34241) measures a roughly 25x TTFT gap between cold-prefix and high-reuse requests (69.4 s vs 2.8 s, observational data). [2610.34491](https://arxiv.org/abs/2610.34491) questions the value of a fixed top effort setting.
  - Results and cost are being evaluated together.
- Evaluations show agents that can execute but aren't reliable enough.
  - [Δτ-Bench](https://arxiv.org/abs/2610.34238) tops out at 42.3%. [Agent Mosaic](https://arxiv.org/abs/2610.30418) still leaks 32.37% with safeguards in place. [EPSBench](https://arxiv.org/abs/2610.38293) intervals undercover.
- A simple harness with a good tool interface.
  - [RoboHarness](https://github.com/BinceQu/RoboHarness) (⭐280) and [h1](https://arxiv.org/abs/2610.35962) both suggest interface design matters more than complex workflows.
  - Among papers with repos, the higher star counts also include [AutoTavern](https://github.com/MCG-NJU/AutoTavern) (⭐179) and [VibeGame](https://github.com/tettethu/VibeGame) (⭐297, HF 👍22, a team of game-development agents; an Agent-other paper not listed this period). These are data observations only, with no further inference.
