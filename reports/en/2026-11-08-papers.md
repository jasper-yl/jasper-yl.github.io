## Today's highlights

- Context compression is following two routes. One rewrites reasoning history into compact state records ([Reasoning History Compaction](https://arxiv.org/abs/2611.03852), 👍13). ## 1. 🔥 Hot list: Agent Context picks

### [Why Pay for Long Reasoning When Rewrite Do Trick?](https://arxiv.org/abs/2611.03852)
- Heat: HF 👍13 (on the list 3 days, +13); no code, no X data.
- Problem: Long reasoning traces are expensive. Can an agent save tokens by rewriting its own earlier reasoning, without retraining?
- Method: Before a tool result comes back, the earlier reasoning is rewritten into "compact state records". The authors then compare later generation under the original and compact histories. They tested open-weight models and also ran a software-agent deployment experiment.
- Result: Accepted compact histories usually shorten later reasoning, and a coding case showed less repeated verification. In agent deployments total cost drops, but task quality and latency (including the rewrite step) depend on the target model and the compressor. The authors call for per-model compression strategies.

### [Tools Need Not Speak in Text: Latent Context Compression for Agents (Coca-Cola)](https://arxiv.org/abs/2611.06500)
- Heat: HF 👍5 (on the list 3 days, +5); code: [THU-Agent/Coca-cola](https://github.com/THU-Agent/Coca-cola) ⭐7.
- Problem: Agents append raw tool output straight into context, which is costly and dilutes attention. Text-level pruning and summarization compress only so far.
- Method: Tool observations are compressed into latent tokens placed in the agent's input embedding space. Action-Preserving Training aligns the next-action distribution under full and compressed observations, so the latent tokens keep the information that decisions depend on.
- Result: On a web-search agent, 4 QA benchmarks and 2 model families, token use fell 70.01%–89.24% and end-to-end latency fell 24.45%–55.97%, with task performance improving consistently.

### [Switch-SWE: Do Coding Agents Hold Focus When Switching Between Unfinished Tasks?](https://arxiv.org/abs/2611.02017)
- Heat: HF 👍10 (on the list 5 days, +10); code: [Miraclecsc/Switch-SWE](https://github.com/Miraclecsc/Switch-SWE) ⭐26.
- Problem: When several unfinished tasks are interleaved in one repo, can an agent recover the requirements and progress of an earlier task?
- Method: The benchmark has 200 focus tasks across 19 Python repos, paired into 400 matched sessions (interrupted vs. uninterrupted). Trajectory analysis shows the common failures are mixing up requirements across tasks and losing task state. The authors propose a plug-in context-management module that picks task-relevant history and keeps a short task-state summary.
- Result: Across 7 coding agents, the focus-task solve rate fell 11.5 points on average (range 6.0–15.0). On OpenCode the module raised completion by 5.5–15.5 points.

### [Can Large Language Model Agents Learn by Watching Tutorial Videos? (TAL)](https://arxiv.org/abs/2611.01460)
- Heat: HF 👍5 (on the list 5 days, +3); no code.
- Problem: Can an agent keep learning from tutorial videos without updating its parameters?
- Method: Tutorial videos are turned into a persistent, structured "tutorialbook" memory. An adversarial two-stage process poses hard, video-grounded questions to refine that memory. At inference, retrieval walks a table-of-contents (TOC) tree, so the model's reasoning drives retrieval instead of embedding similarity.
- Result: On VidLearn (72 chess tutorial videos, 12 openings), gains over the raw MLLM reach 113% on the training set and 91% on the test set. In live play, 69% of games had a better opening-phase position than the raw model's.

### [GEPA-Curator: Curated Learning for Self Improving Agents](https://arxiv.org/abs/2610.37651)
- Heat: HF 👍8 (on the list 5 days, +3); no code.
- Problem: Reflective prompt optimizers such as GEPA learn from failed rollouts, but some failures come from harness limits, randomness or noisy judges and carry no useful signal.
- Method: Two components. Task filtering removes tasks that give noisy signal. Successful-trajectory retrieval selects past successes for a given task and hands them to the prompt optimizer as extra context.
- Result: On GoBrowse, ALFWorld, AppWorld and τ-bench, up to 20.7% better than GEPA and up to 21.2% better than ACE.

### [Dory1.0-4B: A Looped Normalized-GPT](https://arxiv.org/abs/2611.03998)
- Heat: HF 👍12 (on the list 4 days, +9); no code link.
- Problem: How can one checkpoint adjust its depth to the inference budget without growing the KV cache?
- Method: A 4B latent-recurrent (looped) model whose shared recurrent block can be applied repeatedly. Only the last loop's KV is cached, so KV-cache use is the same as a non-looped model no matter how many loops run. Context length extends to 256K.
- Result: With 2 or more loops, it beats Qwen3.5-9B, Gemma 4 12B and Gemma 4 26B-A4B on average across 12 benchmarks. At 4 loops it generates 1.3–2.5x fewer tokens than at 1 loop on agentic benchmarks.

### [The SIMPLE Law for Energy Cost of LLM Inference](https://arxiv.org/abs/2611.03330)
- Heat: HF 👍9 (on the list 5 days, +9); no code.
- Problem: Energy per token is not constant, and there is no analytical model for it.
- Method: The authors derive closed-form compute and memory-access complexity for MHA/GQA, giving a four-parameter SIMPLE model. It separates prefill from decode and splits decode into a KV-cache term and a next-token compute term.
- Result: On 13 dense LLMs on H100, R²=0.969 and MAPE 11.97%, 3.1–3.5x lower error than SOTA. An agentic request uses 13.0x the energy of a non-agentic one. Prefix caching removes about 93% of prefill cost but leaves the KV-cache term unchanged, so a cached agentic request still costs 4.8x more.

## 2. 🔥 Hot list: other Agent topics

- [Can Coding Agents Sustain Continual Evolution without Forgetting?](https://arxiv.org/abs/2611.03219) · HF 👍7 · 5 days on the list: A study of catastrophic forgetting in self-evolving harnesses. Meta-Harness reached 94.0% on SWE-Bench after evolving, then fell to 32.0% (a 66% relative drop) by round 5 of evolving on FeatureBench. Code: [THU-Agent/continual-harness-evolution](https://github.com/THU-Agent/continual-harness-evolution) ⭐4.
- ["Shall We Approve?" Consequence-Aware Approval (Caper)](https://arxiv.org/abs/2610.40753) · HF 👍15 · 4 days on the list: Pre-executes a command in a snapshot sandbox and lets a separate approver judge the observed effects. Approved commands are committed, blocked ones are rolled back with a reason. Harmful-outcome rate is 6.7% on SABER (vs. at least 14.8% for baselines) and 7.8% on YoloFS-Ext (vs. at least 35.3%). Code: [wudaoz/Caper](https://github.com/wudaoz/Caper) ⭐6.
- [LEANGUARD: Lean-Verified Guardrails for Tool-Using Agents](https://arxiv.org/abs/2611.02332) · HF 👍12 · 5 days on the list: Policies are written in Lean4 and checked before a tool call reaches the environment. On Tau-Bench, unguarded agents made at least 33 policy-forbidden calls; LeanGuard made 0. On DTap, direct prompt-injection success fell from 57.9% to 5.9%. Code: [DebarghaG/LeanGuard](https://github.com/DebarghaG/LeanGuard) ⭐8.
- [When Requirements Interact (CodeSpecWeave)](https://arxiv.org/abs/2610.40256) · HF 👍11 · 6 days on the list: Synthesizes long-horizon coding tasks with interdependent specs, producing 4,670 training tasks (2,865 repos). After RL, the model beats baselines on DeepSWE-v1.1. The paper also adds a 100-task, 1,044-spec benchmark.
- [Terminal-style Mathematical Modeling Bench (TB-MathModel)](https://arxiv.org/abs/2611.08237) · HF 👍11 · 2 days on the list: An agentic, verifiable benchmark of 18 real math-modeling competition problems with 624 Lean 4 feasibility proof obligations. The strongest model scores 64.58% on O-Eval. Code: [wxj630/terminal-bench-math-modeling](https://github.com/wxj630/terminal-bench-math-modeling) ⭐5.
- [SwarmEvolve: Latent Agent Swarms](https://arxiv.org/abs/2611.08483) · HF 👍9 · 2 days on the list: Hundreds of low-cost agents reason in latent space and share information by passing KV cache (a summarizer agent receives the merged KV cache of all members). It scores highest on 21 problems and reaches in a median of 3–8 minutes what the best other framework needs 60 minutes for. Code: [Qile-J/SwarmEvolve](https://github.com/Qile-J/SwarmEvolve) ⭐9.
- [Is Your Long-Horizon Benchmark Really Deep?](https://arxiv.org/abs/2611.01927) · HF 👍4 · 4 days on the list: Audits 734 terminal tasks across 6 datasets and finds that synthesis methods mostly add workload, not depth (94% of solved synthetic tasks pass within 3 rounds). It proposes DEPTH, a synthesis method that generates 105 deeper tasks. Code: [AlanRosston/Depth](https://github.com/AlanRosston/Depth) ⭐12.
- [RoboArchitect: Automating the Design of Robotic Agents with Persistent Memory](https://arxiv.org/abs/2610.42141) · HF 👍8 · 6 days on the list: A coding model watches rollouts, diagnoses failures and iteratively edits the harness around a frozen policy, while the harness evolves its own persistent memory (e.g. effective grasp depth). Success on unseen scenes goes from 9.7% to 43.3%. Code: [roboarchitect-ai/RoboArchitect](https://github.com/roboarchitect-ai/RoboArchitect) ⭐10.

## 4. Observations

- Context compression splits into two routes: the text level (rewriting reasoning history into state records, [2611.03852](https://arxiv.org/abs/2611.03852)) and the latent level (tool outputs compressed into latent tokens, [Coca-Cola](https://arxiv.org/abs/2611.06500)). Both stress keeping decision-making intact after compression, and both report efficiency gains (tokens down 70.01%–89.24%; lower cost, but with quality depending on the model).
- "State loss" in long-horizon work now has quantitative benchmarks. [Switch-SWE](https://arxiv.org/abs/2611.02017) measured an 11.5-point average loss from task switching, and [the continual-evolution study](https://arxiv.org/abs/2611.03219) measured forgetting as a harness keeps evolving (94.0%→32.0%). Both point to how memory and context get selected and retained.
- KV cache is both a communication medium and a cost item. [SwarmEvolve](https://arxiv.org/abs/2611.08483) uses it to pass ideas between agents, [Dory1.0-4B](https://arxiv.org/abs/2611.03998) caches only the last loop's KV to hold memory down, and the [SIMPLE law](https://arxiv.org/abs/2611.03330) measures a cached agentic request at still 4.8x the energy of a normal one.
