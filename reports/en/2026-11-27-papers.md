## 🔥 Hot list: Agent Context picks

### [Letting Models Manage Their Own Context: Where We Stand](https://arxiv.org/abs/2611.34147)
- Heat: HF 👍10 (1 day on the list, +4); code: [nvidia-nemo/labs-OO-Agents](https://github.com/nvidia-nemo/labs-OO-Agents) ⭐2335. No X mentions in the data.
- Problem: Today the harness triggers summarization when the window fills. What happens if the model decides when to compress and what to compress?
- Method: NVIDIA's open-source agent harness (called nooa in the paper) gives the model a context API for deciding when and what to compress. The paper compares the two strategies on document research and ML engineering tasks, with context budgets from 8K to 512K. It also reuses the KV cache for the unchanged suffix after an edit.
- Results: GPT 6.1 goes from 21% to 56% on OfficeQA Pro v2 at a 32K budget, nearly 3x. Kimi uses up to 41% fewer input tokens. Reusing the KV cache after edits cuts prefill compute per request by up to 15% with no measurable accuracy change.
- Caveat: Models differ widely in how often they use the API, how hard they compress and when they start, and changing the prompt changes the timing.
- Significance: Points toward co-designing models trained to manage their own context with inference engines that support KV cache editing. This is the most on-topic paper today, so it goes first.

### [Demystifying the Autoresearch Harness: How Context and Skills Shape Self-Evolving Agents](https://arxiv.org/abs/2611.28244)
- Heat: HF 👍5 (1 day on the list, +1); no code repo.
- Problem: Harnesses for long-horizon, self-evolving autoresearch agents stack many mechanisms, so the contribution of each component is unclear.
- Method: On MLE-Bench and KernelBench, with recency truncation as the baseline, the paper compares components one by one in a single framework along two axes: context management (what to keep) and skill management (how experience is stored and reused).
- Results: Keeping individually accessible history beats rolling summaries, and context folding is best in all 6 settings, up to 19.2% over the baseline. For skills, selectively deleting long-unused experience beats merging it or promoting it to always-on rules on average. Combined as MLEvolver, the two reach a 72.7% medal rate on MLE-Bench Lite and 94% fast_1 on KernelBench Level 3, ahead of AIDE and OpenEvolve.
- Significance: The design rule is to keep retrievable raw records and prune unused skills. Heat is low, but the content is directly on topic.

### [VideoJSON: A Minimal Harness Beats Purpose-Built Memory for Ultra-Long Video Understanding](https://arxiv.org/abs/2611.28167)
- Heat: HF 👍8 (2 days on the list, +0); code: [weathon/videojson_release](https://github.com/weathon/videojson_release) ⭐2.
- Problem: Question answering over ultra-long video (days to weeks) relies on complex memory graphs and fixed retrieval pipelines, which limit how an agent can search.
- Method: At indexing time, a VLM turns each minute of video into one JSON record with a dense caption plus fields for events, entities, locations and speech transcript. At query time, a coding agent writes Python/Bash in a sandbox to filter, join and read those records over multiple steps, without touching the raw video.
- Results: With DeepSeek V4.1 Flash, it leads MAGIC-Video by 7.0, 20.0 and 24.75 points on EgoLifeQA, Ego-R1-Bench and MM-Lifelong Week, and beats the previous best by 12.6 points on EgoMemReason. In ablations, both code retrieval and structured JSON contribute. Adding hourly summaries, extra tools or video access moves the average by under 1.5 points.
- Significance: Simple memory plus an agent that writes code for retrieval beats purpose-built memory structures. The code is to be released after publication, and the repo has only 2 stars so far.

### [MMMem: Self-Improving Agents with Task-Aware Multimodal Experience Consolidation](https://arxiv.org/abs/2611.30287)
- Heat: HF 👍10 (3 days on the list, +9, one of the larger gains on the hot list); code: [ChenYX24/MMMem](https://github.com/ChenYX24/MMMem) ⭐0.
- Problem: Existing multimodal memory only stores and retrieves. It doesn't distill experience from finished tasks, so the same mistakes recur.
- Method: Memory has multiple views: original text, images, rendered pages, and a scene graph built from cross-record consolidation cues. Tasks are generated automatically from source data and used for warm-up (consolidating into external memory) and self-training (adjusting the model's parametric knowledge). The same VLM distills each completed task into an experience record holding task context, conclusion and supporting links. Retrieval returns both source views and related experiences.
- Results: With Qwen3.5-9B, it improves on the best baseline by 36.9%, 17.6% and 15.2% on LoCoMo, Mem-Gallery and LooGLE v2, and beats 8 baselines.

### [VibeVideoAgent: Closing the Perceptual Loop for Code-Driven Video Generation](https://arxiv.org/abs/2611.34237)
- Heat: HF 👍57 (1 day on the list, +3); code: [Kling-Keye/VibeVideoAgent](https://github.com/Kling-Keye/VibeVideoAgent) ⭐10.
- Problem: In code-driven video generation, a program that runs doesn't guarantee correct picture and audio, and feeding rendered frames and audio back into the coding session would blow up a long-horizon context.
- Method: Training-free. Multimodal perception runs in a short-lived context isolated from the coder and returns only compact, grounded Findings. Seven primitives operate on a unified multi-clock representation, and a staged protocol validates the riskiest decisions with a minimal preview first.
- Results: On 239 VibeVideoBench tasks, overall audiovisual quality (L3) rises from 4.03 to 4.43 for Claude Opus 5.5, from 4.03 to 4.27 for GPT-6 Astra, and from 3.97 to 4.10 for Claude Sonnet 5.5. Audio-video sync gains most, up to +0.56.
- Note: The data tags the topic as agent, but putting perception in an isolated context that returns only summaries is a standard context-isolation design, so it sits here. Its HF score is among the highest on today's hot list.

### [Agentic LongLive: Asynchronous Agentic Memory for Long Video Generation](https://arxiv.org/abs/2611.34907)
- Heat: HF 👍19 (1 day on the list, +3); code: [NVlabs/LongLive](https://github.com/NVlabs/LongLive) ⭐2919. That repo belongs to the base generator LongLive, so the stars don't necessarily reflect this paper's new code.
- Problem: Real-time autoregressive video generators struggle to keep characters, objects and scenes consistent across long interactive stories. Offline agent systems must read the full script first, which a real-time stream can't do.
- Method: A memory agent on a separate GPU reads only the prompts revealed so far, not the generated video. It keeps a text state and an evolving image for each character, object and scene, and from these composes a global map and a per-shot memory map. An auxiliary GPU prefills these into the generator's attention sink before the next shot starts, so video never waits on memory and video errors never get written back to memory. The small language model that decides what to remember is trained with RL.
- Results: On the new LongStory-Online benchmark (25 stories, 857 shots), versus the base generator LongLive-2.0, persistent-state accuracy is +26.3 points, protagonist identity +44.9, and revisited-location consistency +40.4, with about 1% extra generation time on H100. On a single 8xB200 node in BF16 it runs at 34.3 FPS, faster than real time, with stable quality over 14-minute stories.
- Significance: The authors call it the first real-time video generator whose text and image memory is maintained by an LLM agent.

### [SEEK: Self-Evolution through Execution Knowledge for Agentic Robot Manipulation](https://arxiv.org/abs/2611.33915)
- Heat: HF 👍12 (1 day on the list, +2); code: [ZeyangGuan/SEEK-Agentic-Robot-Manipulation](https://github.com/ZeyangGuan/SEEK-Agentic-Robot-Manipulation) ⭐9.
- Problem: Robots keep what they learn about execution only in the model's working context. It is lost when the task ends, and the next run repeats the same mistakes.
- Method: Manipulation policies are expressed as executable programs (SEPP), where each action is decided by the current observation. A Persistent Action-Effect Bank (PAEB) records the measured effect of actions, failed attempts included. When a retained program applies, the model isn't called. When a condition isn't covered, evidence in the PAEB guides the revision.
- Results: On 42 RoboDojo tasks, after keeping knowledge from ten attempts, average score rises from 27.0 to 54.4 and success rate from 19.7% to 48.0%. On 34 of those tasks, GPT-6.2 Astra with five attempts reaches 80.1 versus 49.6 for direct action, with 77.6% fewer model requests.

## Observations

- Heat clusters around who manages context and what gets remembered. NVIDIA's paper argues for model-managed context with KV cache editing. [Autoresearch Harness](https://arxiv.org/abs/2611.28244) finds that keeping individually accessible raw records beats rolling summaries. [VideoJSON](https://arxiv.org/abs/2611.28167) beats complex memory graphs with minimal memory plus code retrieval. The three agree: don't over-engineer memory structure, keep retrievable raw records, and hand control to the model or to code.
- Memory is spreading to video generation, robotics and multimodal work: [Agentic LongLive](https://arxiv.org/abs/2611.34907) and [StateWeaver](https://arxiv.org/abs/2611.34290) (video), [SEEK](https://arxiv.org/abs/2611.33915) and [RoboEvo^2](https://arxiv.org/abs/2611.34675) (robotics), [MMMem](https://arxiv.org/abs/2611.30287) (multimodal). They share one approach: distill experience into reusable programs, records or skills and call the model less. SEEK's 77.6% reduction in model requests is the data point.
- "Harness" is a frequent word, appearing in Embodied-Harness, ReWeave, RoboEvo^2 and MORSE (none with high heat). Interest is rising, but so far it is mostly robotics and video research.
- On the engineering side, the largest repo among the Agent Context papers is [nvidia-nemo/labs-OO-Agents](https://github.com/nvidia-nemo/labs-OO-Agents) (⭐2335), which fits NVIDIA putting the context API directly into an open-source harness.
- On evaluation, [ICLWorld](https://arxiv.org/abs/2611.32649), [EgoUseBench](https://arxiv.org/abs/2611.34466) and [OS-Omni](https://arxiv.org/abs/2611.34232) all show agents falling well behind humans in long-horizon settings, with changing state or physical interaction. That is consistent with context and state management being the bottleneck.
