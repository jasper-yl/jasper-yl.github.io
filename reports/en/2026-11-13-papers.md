### [Read Less, Solve More: Token-Efficient Sparse Reading of External Content for AI Agents (SparseRead)](https://arxiv.org/abs/2608.22237)
- Heat: HF 👍21 (on the list 1 day, +8 since first seen, up from 13; see the 11-12 report, where it ran as a New paper at 👍13). No X data. Code: [Liuzedooong/SparseReading](https://github.com/Liuzedooong/SparseReading) ⭐15.
- Problem: Web agents repeatedly read pages, documents, repos and tool outputs, often pulling in the whole object when they need only a little evidence. That costs tokens and latency and dilutes the relevant evidence.
- Method: A read-control layer that doesn't touch the model. It has three parts:
  - Read Intent Protocol tracks changing needs and source coverage.
  - Adaptive Reader Backends choose how to locate and present evidence.
  - Budgeted Read Gate caps the raw content exposed per episode, with a faithful full-view fallback.
  - A unified Reader interface adapts to different resource types.
- Result: Across 6 models (including Claude Opus 5) and 5 settings, total tokens drop by up to 92.9% and time by up to 89.0%, with equal or better quality in 97% of configurations. Web deep-search tasks see tokens down 31.0–43.0% and completion time down 23.0–37.0%. Portability was checked on 3 agent frameworks.

### [CORE: Coarse-to-Fine Search with Context Management for Deep Research](https://arxiv.org/abs/2611.07859)
- Heat: arXiv feed, HF 👍0, on the list 7 days. No code link. Picked for topic fit, not heat.
- Problem: Deep research agents retrieve well by matching long passages, but every returned observation stays in context until the end, so the returned evidence should be short.
- Method: A training-free harness. A dense retriever finds passages, then the token-level similarity from a late-interaction reranker is reused to return only the most relevant snippet of each passage. Context management lets the agent expand the context around sources it has already retrieved and suppresses duplicate snippets.
- Result: Compared with the Tongyi DeepResearch and OpenResearcher harnesses (controlled closed-search setup), it reaches SOTA answer accuracy and evidence recall on 3 models and 3 benchmarks (BrowseComp-Plus, BrowseComp-Wikipedia, BrowseComp-Plus-CM), with corpora of up to 553 million documents.

### [QRAE: Query-Relevant Attention Entropy for Context Compression in DeepSearch Agents](https://arxiv.org/abs/2611.07976)
- Heat: arXiv feed, HF 👍0, on the list 7 days. No code link.
- Problem: DeepSearch agents keep accumulating retrieved sources, which adds tokens and latency, and many results contribute nothing to later reasoning.
- Method: Online context compression. Sparse evidence-evaluation attention heads decide which whole retrieved chunks stay in context. Scoring uses paired prefill: one pass without the query serves as a control to cancel the shared attention response, then normalized entropy measures how broad the positive response is within a chunk. High-scoring chunks go into a persistent evidence whitelist. Uncertain chunks stay in a candidate cache and can be re-evaluated later. It needs no extra generative compression and doesn't change the attention operator.
- Result: Across several DeepSearch benchmarks and reasoning models, task success rises 2.35 points on average, end-to-end latency falls 30% on average, and reported token usage falls 45% on average. It also holds on a model of nearly 100B parameters.

### [Octopus: One Brain, Many Branches for Latent-KV Multi-Agent Reinforcement Learning](https://arxiv.org/abs/2611.06956)
- Heat: arXiv feed, HF 👍0, on the list 7 days. No code link.
- Problem: Existing multi-agent frameworks store the prefix KV cache separately in each branch and exchange findings by re-prefilling text summaries. In RL they also flatten or drop the dependencies between branches.
- Method: Single-model multi-agent RL. All threads share one backbone and cooperate through a directed acyclic graph of KV states on the GPU, with five primitives: fork, read_thread, wait_threads, rewind, commit.
  - Zero-Copy Radix Forking: a branch is an O(1) cursor view over shared physical KV pages.
  - Attention-Only KV Mounting: sibling threads' KV blocks are mounted directly into full-attention layers, bypassing linear recurrent state.
  - Packed DAG-GRPO: all branches are packed into one block-sparse attention pass, with counterfactual credit assigned by leave-one-branch-out marginal reward.
- Result: After training on Qwen3.5-4B, BrowseComp-Plus accuracy is 49.6% (+17.5 points over single-agent GRPO, +12.5 over text-summary multi-agent RL), and OpenResearcher is 51.2%. It beats dense retrieval agents up to 250× larger in parameters, with 3.3× training throughput and 2.8× lower peak KV memory. The mounting design cuts drift from 57.9% to 2.7% (21×) while keeping 92.2% of the full-text mutual information.

### [Compaction, decay and reinforcement in a two-tier conversational memory: a paired evaluation against retrieval-augmented generation](https://arxiv.org/abs/2611.09807)
- Heat: arXiv feed, HF 👍0, on the list 4 days. No code link.
- Problem: A conversational agent has to decide what to keep: raw text to retrieve from (RAG), or each turn compressed into atomic facts to retrieve from.
- Method: A paired comparison on the 1,985 questions of LoCoMo. Both approaches use the same store, generator and judge. A McNemar exact test covers the 512 questions where the two disagree.
- Result: On the four categories that comparable work reports, compaction scores 71.4% against RAG's 64.6%, a 6.8-point lead (p = 5.5e-08), with 34% fewer prompt tokens. Across all five categories, including adversarial, the lead shrinks to 2.0 and is no longer significant, because RAG leads by 14.6 on adversarial. The paper's explanation: compaction keeps factual assertions and loses wording, so it wins when the answer is a value and loses when the answer needs the original phrasing.

### [Micius-Flash: Lightweight Agentic Intelligence for Engineering](https://arxiv.org/abs/2611.10015)
- Heat: HF 👍9 (on the list 2 days, +5). No code link.
- Mostly a domain model. Only the 256K context and the Micius Harness touch Agent Context.
- Problem: Engineering domains (semiconductors, hardware coding, PCB) lack lightweight agent models that can use tools.
- Method: A 27B multimodal model with 256K context. A knowledge-tree-driven data flywheel synthesizes data, several expert models are trained, then merged through multi-teacher on-policy distillation (MOPD). The Micius Harness connects EDA tools, KiCad and execution environments.
- Result: 64.2% average on hardware-code benchmarks (15.0 points above same-size baselines) and 62.4% on a semiconductor agent benchmark (17.2 points higher).

## 🆕 New: announced last night

- [Folio](https://arxiv.org/abs/2611.16627): Recoverable multi-resolution context folding for long-horizon agents. The runtime records three views (model-written turn notes L1, runtime-written event lists L2, raw records L3), folds them programmatically, and restores them on demand through handles. Solves 66 of 75 LOCA-bench tasks, against 54 for the same runtime with model-written summaries and 49–59 for Claude Code, Codex and SoL-Pi. It takes about half the time at 2.4× lower cost, with a median of 0.6 seconds per fold.
- [Discovering Effective Agent Memory Designs through Program Evolution (MAPE)](https://arxiv.org/abs/2611.17068): Searches for memory designs through program evolution. On LoCoMo and LongMemEval, accuracy is up to 12% above hand-designed baselines at 35% of the serving cost. Two patterns worked: keeping raw conversation as retrievable evidence, and composing evidence by query intent.
- [HiVe-Mem](https://arxiv.org/abs/2611.12872) (👍3): Multimodal memory. It expands memories along a relation graph horizontally, and a trainable selector composes the evidence form of each memory vertically. On 3 multimodal memory benchmarks it uses about 90% fewer tokens than the most economical multimodal baseline. Code: [ViktorAxelsen/HiVe-Mem](https://github.com/ViktorAxelsen/HiVe-Mem).
- [MemCredit](https://arxiv.org/abs/2611.15600): Selects memories by decision utility instead of semantic relevance. It estimates each memory's marginal contribution with counterfactual intervention, then distills that into a lightweight estimator. On ALFWorld with a 500-token memory budget, SR@50 is 86.57, against 65.67% for BM25 retrieval.
- [DISCERN](https://arxiv.org/abs/2611.15729): Persistent memory that keeps at write time and disambiguates at read time. Writing builds an append-only bitemporal provenance graph, and reading navigates it with a zero-LLM tool surface. On ENT-310 abstention F1 is 0.924, against 0.802 for the best of 8 baselines. On LoCoMo, macro-averaged answer accuracy is 0.663 against 0.638.
- [Experience-Handoff RL (ACE-RL)](https://arxiv.org/abs/2611.16409) (👍1): Fixes the Agentic Context Engineering (ACE) harness and trains one model to act, reflect and curate the task playbook, optimizing by how much these experience handoffs actually affect later rollouts. Beats baselines on several agent benchmarks. Code: [doyoungkim-ml/ehrl](https://github.com/doyoungkim-ml/ehrl).
- [HeMeR](https://arxiv.org/abs/2611.16487): Structured KV reuse over heterogeneous memory (declarative, procedural, working) for embodied agents, recomputing only the KV affected by memory updates. Real-robot task success is 83.20%, and per-step inference time drops from 2.94 s to 1.87 s relative to MemRL.
- [Recompute or Restore?](https://arxiv.org/abs/2611.15126): For multi-model agent workflows on a static-graph NPU (Rebellions ATOM+), compares restoring KV from host memory against recomputing it. Workflow SLO attainment rises from 22.8% to 100% and from 9.4% to 99.8% under two overload conditions. When default serving collapses, 89.5% of planner prompt tokens had been computed before.
- [Wayfinder](https://arxiv.org/abs/2611.16053): Routes adaptively across resources such as chat, tickets, email and knowledge bases, using the documents the downstream agent cites as feedback. Routing works best when resource contents overlap semantically. When resources come from different corpora, description-based tool retrieval is enough.
- [AstroMemBench](https://arxiv.org/abs/2611.16590): A memory benchmark for spacecraft embodied agents, with 140 templates, 2,240 instances and 16 sub-challenges. Within a session, Mem0, Chain-of-Memory, LightMem and RAG all beat the vanilla Pi agent, and none of the three memory systems clearly beats RAG. After a session restart, Mem0 is 12.25 points above RAG.
- [Actor, Judge, or Teacher?](https://arxiv.org/abs/2611.17167) (👍29): Uses a decision model as teacher. A Qwen2.5-1.5B policy improves over GRPO from 72.8% to 82.9% on ALFWorld and from 56.8% to 71.4% on WebShop. The paper's conclusion is that a poor executor can still be a good teacher. Code: [ZJU-REAL/decision-agents](https://github.com/ZJU-REAL/decision-agents) ⭐3.
- [Agent-R^2](https://arxiv.org/abs/2611.08219) (👍3): Synthesizes productivity-task data from real sources. A 4B model trained on 4k instances scores 51.0% on GDPval, against 48.0% for Qwen3-235B-A22B-Thinking. Code: [ZJU-REAL/Agent-R2](https://github.com/ZJU-REAL/Agent-R2) ⭐6.

Left out: PhysLoop (video generation) and WorldDraft (video rendering) are unrelated to agents. Alloy and ORCHID-SAGE lean toward physics engines and materials. Together Compiler mentions a context-management ablation but is about inference compilation. JustRUA (robotics) wasn't strong enough to include.

## Observations

- Context cost work has moved from compression to admission. SparseRead controls what gets read, CORE and QRAE control what stays, and Folio (in New) controls how context is folded and restored. These papers lead with token and latency numbers while success rates stay roughly level: QRAE gains 2.35 points on average, and SparseRead holds quality in 97% of settings.
- Memory research is shifting from storing and fetching to choosing which memory and how to evaluate. MemCredit replaces semantic relevance with decision utility. DISCERN argues disambiguation and abstention are the hard part, since recall is already near saturation at about 0.93–0.98. MAPE uses search to find designs. Two conversational-memory papers compare on LoCoMo, and both point the same way: compaction keeps values and loses wording.
- KV cache is meeting agent workflows. Octopus treats KV as shared state across branches, HeMeR reuses KV for embodied memory, and Nebula (position-independent caching, median TTFT down 61.4% on average) and the NPU host-tiered KV paper both go after repeated prefill in workflows. None of these papers maps to a GitHub project in the data, so there is no engineering-side match to report.
- Safety and reliability form another thread on the hot list: authorization drift, Coding or Cheating, and MemoryDojo (every memory system tested is vulnerable to poisoning). The data has no matching GitHub projects for these either.
