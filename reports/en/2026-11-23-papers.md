## Hot list: Agent Context picks

### [Continual-ARC: Measuring Skill Acquisition over a Working Lifetime](https://arxiv.org/abs/2611.14505)
- Heat: HF 👍3 (7 days on the list; 9 when first seen, now 3, so −6, falling); 0 X mentions; code [unifyai/continual-arc](https://github.com/unifyai/continual-arc) ⭐39 (most stars in today's hot list).
- Problem: Existing continual-learning benchmarks cover one domain, show each instance once, and compare one kind of learner. Memory-based and weight-based systems are rarely compared on the same scale.
- Method: It builds a lifelong task stream from three ARC-AGI versions. The same task returns after a gap with new instances, and new tasks keep arriving. A learner can spend budget to view examples, submit answers, or act in a harness, and is scored on the feedback budget it uses. After the stream ends, the system is frozen and tested separately on memory of seen tasks and generalization to unseen ones. Tested systems are frozen-weight agent harnesses (with and without persistence; Qwen3.5-9B and GLM-5.3 Flash), against two prompting floors, a program-induction method, and Qwen3.5-9B weights trained to imitate GLM-5.3 Flash.
- Result: Harness persistence usually doesn't improve memory without explicit expert guidance. Most harness-based methods learn less than a baseline that just caches each task's examples. No harness method improves on unseen tasks; weight learning improves clearly.

### [Experience Rot: Experienced Agents Fail Where Novices Succeed](https://arxiv.org/abs/2611.20922)
- Heat: arXiv-only, no HF upvotes, heat=0, no GitHub. 6 days on the list.
- Problem: Agents save conversation history, memory files, retrieval notes, and skills to reuse experience. Does that experience hurt when a tool (an MCP definition) is silently changed?
- Method: Tools defined via MCP are silently modified, across several models. Experienced agents are compared with novice agents that have never done the task. The paper tests many forms of memory, plus remedies such as notifying the agent of the update or pointing it to documentation.
- Result: After the change, experienced agents fail most tasks while novices mostly succeed. Experienced agents copy earlier calls without checking the current interface, and still report success. Every memory form tested shows this, and it worsens with more experience. Notifications barely help, and pointing to documentation doesn't help when the docs are unclear.

### [CarryOn: Learning What to Keep in Context for Long-Horizon LLM Agents](https://arxiv.org/abs/2611.17808)
- Heat: arXiv-only, no HF upvotes, heat=0. 7 days on the list.
- Problem: Summaries drop exact details that later actions need, while keeping the full history brings in a lot of irrelevant material.
- Method: A lightweight context manager pairs a compact execution state with fine-grained evidence that links back to its source. A learned selector and an adaptive retention policy manage context without extra LLM calls. It also proposes two metrics: S_α, which prioritizes task success while accounting for resource use, and NCS, the normalized cost per success.
- Result: On AppWorld, OfficeBench, and Tau2 Telecom, with three LLM actors, macro-average task success is 75.7%, 6.7 points above the strongest baseline. It also has the best average on both metrics.

### [LEDGER: Auditable Agent Memory Under Change](https://arxiv.org/abs/2611.20927)
- Heat: arXiv-only, heat=0. 6 days on the list.
- Problem: Memory systems are mostly evaluated on fixed histories, but in practice facts change, sources differ in reliability, and users ask to be forgotten.
- Method: The language model only proposes facts. Explicit rules decide which value is current, which source to trust, and what to delete. Each fact stores its source and validity period. LEDGER+EP adds search over raw conversation turns as a fallback when the ledger has no coverage, and deletion also purges those turns.
- Result: On the authors' own synthetic multi-session coding-agent workload, LEDGER+EP (fallback mode) answers 94.3% correctly (5 development seeds) and 91.1% (5 held-out seeds), against 82.1% and 83.3% for the strongest baseline, full replay. On a 210-question LongMemEval subset, augment mode matches full replay (74.8%) using 1% of the context. Limits: the synthetic workload is self-built, and on LongMemEval the differences among the strongest systems fall within confidence intervals.

### [Instant Weight-Space Consolidation for Long-Term Memory in LLMs (CLAM)](https://arxiv.org/abs/2611.20759)
- Heat: arXiv-only, heat=0. 6 days on the list.
- Problem: In text-based agent memory the model itself doesn't evolve, extraction errors accumulate, implicit cross-session patterns never surface, and build cost grows with conversation length.
- Method: A recurrent hypernetwork compiles a sequence of session activations into a low-rank adapter in one forward pass, with no gradient updates and no language-model generation, as parametric memory. An episodic buffer supplies verbatim detail at inference time. A gated latent state of fixed size carries across sessions.
- Result: On LoCoMo and LongMemEval-S with three 2–7B open models, it leads all agentic baselines by 1–45 points and all gradient-based parametric methods by 10–45 points, and builds memory 3–151× faster than extraction-based systems. When the buffer misses evidence, the adapter adds 12–15 points; even with an oracle buffer it adds 4–5.

### [Where Should LLM Agents Adapt at Test Time? In Context, in Weights, or Both](https://arxiv.org/abs/2611.19700)
- Heat: arXiv-only, heat=0. 6 days on the list.
- Problem: An agent working repeatedly in one environment can adapt by keeping experience in context (ICL) or by updating weights. The two are usually studied separately, so their individual contributions and complementarity are unclear.
- Method: Under a shared online protocol, it compares ICL, GRPO (RL with verifiable rewards), SDPO (self-distillation), and their combinations: 14 adaptation mechanisms plus a stateless baseline. It uses Qwen3.5-9B on 109 tasks across SWE-bench Verified, AppWorld, ScienceWorld, and BIRD-Critic-SQLite, with five task orderings per environment.
- Result: ICL alone gives the largest gain; the best strategy lifts average success from 28.8% to 49.4%. Adding GRPO reaches 51.6%. SDPO is mixed. Trace analysis shows ICL often skips checking and verifying the current task, and GRPO helps restore those behaviors.

### [Beyond Plain MCP: Do Decision Models and Code Mode Make Tool Use Cheaper and Faster?](https://arxiv.org/abs/2611.19123)
- Heat: arXiv-only, heat=0. 6 days on the list.
- Problem: When an MCP gateway manages a large tool catalog, which works better: code mode (the agent writes scripts that call tool stubs) or a decision layer (a cheap router preselects a tool subset)?
- Method: A preregistered evaluation with 12 servers, up to 1,958 distractor tools, and three open-source agents (Qwen, Gemma, Nemotron), scored on a sealed test set. It releases the harness, a fine-tuned 4B tool-selection model, and all evaluation traces.
- Result: Code mode saves 70–90% of tokens versus plain MCP and raises utility significantly. Declaring return-structure hints in the code-mode stubs is a first-order variable: it can swing success by up to 39.5 points for weaker agents, more than adding a router. The central hypothesis, that a decision layer plus code mode beats code mode alone, was not confirmed.

### [EfficientSkill: Learning Skills for Token-Efficient Multi-Turn Agents](https://arxiv.org/abs/2611.19823)
- Heat: arXiv-only, heat=0. 6 days on the list.
- Problem: Reflective skill optimizers keep piling up edge-case rules, which bloats prompts, inflates token use, and traps agents in long, error-prone loops.
- Method: Two steps. First find a reliable skill with no token penalty. Then warm-start from that skill and prune with an accuracy guard: compress instructions, cap the number of turns, and turn reusable code into workspace tools that cost nothing in the prompt.
- Result: On MATH-500, ALFWorld, and SpreadsheetBench across four models, 11 of 12 configurations emit fewer output tokens than unconstrained EvoSkill (up to 80% fewer), and average accuracy rises on every benchmark. On SpreadsheetBench, Gemini 3.8 Flash and Grok 4.1 Fast gain 14.3 and 17.5 points. Total tokens and serving cost drop in every evaluated configuration, with or without a full-prefix KV cache.

## Observations

- **Experience and memory can go stale and backfire.** Experience Rot (experienced agents fail after silent tool changes) and Continual-ARC (harness persistence loses to cached examples and gives no gain on unseen tasks) both point the same way: more memory doesn't mean a stronger agent. Related work includes LEDGER's rule-based handling of changing facts, trusted sources, and deletion, plus [2611.19264](https://arxiv.org/abs/2611.19264) and [2611.19859](https://arxiv.org/abs/2611.19859) on read consistency after updates and dependency repair. Today's hot list has more of these reliability and governance papers than methods that just push scores up.
- **Context management is splitting into two ends.** On the agent side, learned selection and retention (CarryOn, EfficientSkill). On the serving side, KV and runtime eviction (Contexture, which targets history resending in harnesses such as Hermes, OpenClaw, and Codex). Both trade less resent history for lower cost and higher throughput, and both stress adding no extra LLM calls.
- **Harnesses enforce; models don't judge for themselves.** SilentGuard's warning-only mode still has 70.1% errors, and only enforcement works. Intent Contracts keeps tools away from the planner. Epistemic Guard runs receipts out of process. On the MCP tool-metadata side there are attack papers, GRAFT and [2611.21577](https://arxiv.org/abs/2611.21577) (provider misbinding). This is a common direction among the papers; no GitHub project data was checked today, so no specific engineering tie-ins are claimed.
- **Data limits.** The top HF count is 5, and most Agent Context papers are heat=0 arXiv entries, so the ranking separates papers poorly. Clover, the most-upvoted paper in the new list (34), has little to do with Agent Context. The heat signal is weak today.
