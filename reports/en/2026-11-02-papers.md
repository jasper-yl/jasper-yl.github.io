## 1. 🔥 Hot list: Agent Context picks

### [ReGE: Stronger Agents through Experience Synthesis](https://arxiv.org/abs/2610.33861)
- Heat: HF 👍14 (on the list 5 days, +1); code: [TIGER-AI-Lab/ReGE](https://github.com/TIGER-AI-Lab/ReGE), 1 star
- Problem: how to turn an agent's records from several attempts at the same task into guidance the next attempt can use directly.
- Method: ReGE-Syn makes one coach call that jointly synthesizes bounded run records and available artifacts into self-contained guidance covering task discovery, suggested actions and known pitfalls. The student starts from the initial environment state and adapts the guidance to what it observes. The same base model is used throughout, with no parameter updates and no stronger teacher.
- Result: averaged over four benchmarks, +9.9 points for GPT and +8.8 for Claude. On a BrowseComp-Plus subset, guidance construction uses 98.2% fewer tokens than AggAgent (GPT) and 95.5% fewer (Claude). Jointly synthesized guidance is clearly shorter than concatenated history or per-run summaries.
- Take: the most direct "experience compressed into context" paper here. The like count barely moved (+1), but the numbers are clear.

### [Rare, Relevant, and Still Wrong: How Memory Fails LLM Group Decisions](https://arxiv.org/abs/2610.37624)
- Heat: HF 👍9 (on the list 5 days, +5); no code
- Problem: when an LLM group discussion is compressed into a short memory for a final decision-maker, what should the memory keep?
- Method: a diagnostic benchmark, CrossProfile (60 templates, 480 tasks), crosses who holds the supporting, decoy and irrelevant facts while keeping the text fixed. It compares two heuristics, "keep the rarest" and "keep what's relevant to the decision criteria", on Qwen2.5-7B, Llama-3.1-8B and two DeepSeek models.
- Result: both heuristics fail in predictable places. Relevance filtering lets decoys in; even a perfect relevance filter scores 23–31 points below rarest-first in the classic hidden-profile setup. Rarest-first is no better than random on average. Accuracy depends on the balance of evidence the memory keeps, not on the selection strategy. Removing attribution labels (facts mentioned by several agents get extra weight) improves accuracy by 13–24 points. In natural discussions, a full transcript scores lower than taking no notes at all.

### [MemSteer: Turning User Histories into Supervision for Agent Memory Optimization](https://arxiv.org/abs/2610.39276)
- Heat: HF 👍5 (on the list 3 days, +5); no code
- Problem: a new user's history has no labels, so memory designs can't be evaluated or improved.
- Method: MemSteer turns unlabeled user history into evidence-backed QA supervision. It first builds an "evidence-grounded answer plan", then generates questions, with source checking and blind answer recovery. MemSteer-Opt uses these QA pairs to evaluate memory designs and, with evidence-guided failure diagnosis, rewrites memory storage, retrieval and context construction. No model parameters are updated.
- Result: against Base-BM25, +13.4 points on ATM-Bench Question Score; RHELM accuracy +4.1 without and +6.6 with external data. Performance is on par with optimization guided by official QA.

### [Skill^{infty}: Recursive Self-Improvement for Agent Skill Optimization](https://arxiv.org/abs/2610.35434)
- Heat: HF 👍8 (on the list 6 days, +5); code: [taowangcheng/Skill-Infinity](https://github.com/taowangcheng/Skill-Infinity), 6 stars
- Problem: existing skill optimizers use hand-designed pipelines, the meta-skill is frozen into the pipeline, and every task is learned from scratch.
- Method: a meta agent optimizes task skills using a meta-skill, then applies the same process to optimize the meta-skill itself. The agent drives the optimization: it diagnoses execution traces, proposes candidates, requests independent review and allocates search budget. Meta-skill and task skills are decoupled; both are standard skill packages loaded through native skill discovery.
- Result: 60.7% pass rate on 83 SkillsBench tasks, versus 56.4% for human-written skills and 54.5% for SkillEvolver.

### [Matched Capabilities, Different Behaviors: A Controlled Study of MCP and CLI Interfaces for Language Agents](https://arxiv.org/abs/2610.34298)
- Heat: HF 👍5 (on the list 6 days, +5); code: [ModalityDance/MICA](https://github.com/ModalityDance/MICA), 0 stars
- Problem: with identical capabilities, does the model-facing interface (MCP vs. CLI) change agent behavior?
- Method: MICA renders MCP and CLI from the same semantic action contract and runs both through the same runtime, with six models and three interactive environments. The authors also propose DART, which keeps verified semantic decisions and repairs only interface-specific implementation.
- Result: with matched interfaces, performance and interaction cost differ significantly. 94.3% of 2,004 episodes show structural divergence. DART improves all six settings by up to 9.0 points and cuts MCP token cost by up to 27.1k per task across the three environments.

### [Rethinking Verification in Agent Harnesses](https://arxiv.org/abs/2610.34577)
- Heat: HF 👍10 (on the list 5 days, +1); no code
- Problem: how a harness should organize verification: when to step in, who checks, how to revise.
- Method: the framework has four layers: initial instruction, mid-run reminder, completion gate and independent reviewer. It compares 17 designs across seven frontier coding models on Terminal-Bench and SWE-bench Verified, and introduces VisualBench.
- Result: the independent reviewer has the best accuracy/cost tradeoff: +5.9–9.5 points average accuracy on Terminal-Bench (1.13–1.25x baseline cost) and +3.9–6.6 on SWE-bench (1.00–1.04x). Completion gates gain more but cost more.

### [Your Policy Is Secretly a Harness: The Decision Geometry of Agent Interfaces](https://arxiv.org/abs/2610.37255)
- Heat: HF 👍8 (on the list 5 days, +2); code: [2020-qqtcg/HRP](https://github.com/2020-qqtcg/HRP), 1 star
- Problem: after a policy is trained under one harness, how much survives a change of harness?
- Method: under KL-regularized control, the paper proves that the optimal policy's log odds recover its harness's preference over actions. Deployment return equals the harness ceiling minus policy mismatch. Training changes only the mismatch, while swapping harnesses changes both terms, so comparing harnesses with a fixed model confounds the two.
- Result: in MiniWoB++, merely reversing the order of observation fields drops a trained model's success rate from 85.0% to 19.2%. On Terminal-Bench Lite, "ceiling minus mismatch" reproduces the accuracy ranking; neither term alone does.

### [Beyond Benchmarks: Can Small Open-Weight Models Get Real Coding Work Done?](https://arxiv.org/abs/2610.34241)
- Heat: HF 👍9 (on the list 6 days, +8); no code
- Problem: can small open-weight models actually get coding work done?
- Method: a single-engineer experience report (July–October 2026) covering vLLM, SGLang, llama.cpp and MLX. Evidence includes 4,165 coding-agent gateway turns and three delegation studies. It looks at tool-call formats, context behavior, cache reuse and session continuity.
- Result: saved cold-prefix requests have a median time to first token of about 69.4 s, versus 2.8 s for high-reuse requests (observational data). Workers delegated to quantized Qwen3-Coder 30B-A3B passed 12/15 and 14/15; direct coding passed 15/15. The author says the studies are not pooled and the paper does not rank models.

## 2. 🔥 Hot list: other Agent topics

- [WeVisCut](https://arxiv.org/abs/2610.38352) · HF 👍24 · 3 days: a long-video editing agent with a single 9B policy, which derives 130K+ training samples from 3,750 finished videos. Quality is close to Claude Opus 5, with about 33x fewer generated tokens per successful output minute. Code: [Tencent/WeVisCut](https://github.com/Tencent/WeVisCut), 56 stars.
- [WebAnything](https://arxiv.org/abs/2610.37786) · HF 👍24 · 3 days: fully automatic reconstruction of resettable web environments from real URLs (244 sites, 12,984 tasks). Fine-tuning Qwen3.5-9B gives +13.33 points overall success on WebArena-Verified.
- [Investor's Last Exam](https://arxiv.org/abs/2610.38342) · HF 👍14 · 3 days: a buy-side research benchmark on a frozen information set (3.43M document versions, 86 tasks). GPT-6 Astra scores 68.1 and Claude Opus 5.5 66.9; Astra gets only 52.5 on forecasting and modeling. Code: [Prophetlab/Investor-Last-Exam](https://github.com/Prophetlab/Investor-Last-Exam), 134 stars.
- [PAWM, a trap-anticipating world model](https://arxiv.org/abs/2610.29139) · HF 👍15 · 6 days: steps in only where traps are likely and predicts imminent failure to steer a black-box agent. Claude Sonnet 4.5 gains 24.3% on ScienceWorld and 7.7% on WebArena-Lite.
- [Thinking-in-Bets](https://arxiv.org/abs/2610.34654) · HF 👍14 · 6 days: training-free. The agent writes a private list of claims before reading user feedback, which sharply reduces blind reversals when the feedback is wrong. Writing the list afterward does almost nothing.
- [ParetoRSI-Gym](https://arxiv.org/abs/2610.34386) · HF 👍12 · 5 days: evaluates agents on recursive self-improvement through data-driven post-training across five domains. The strongest setup, Claude Code + Opus-5, improves its generalization score by 9.2%, and the harness matters as much as the model.
- [Online RL for iOS UI navigation](https://arxiv.org/abs/2610.39264) · HF 👍11 · 3 days: online reinforcement learning on real iOS apps, with planning and grounding decoupled, and a proposed method called GiGPPO. The 8B agent's out-of-distribution generalization on Android is about seven times the SFT baseline's.
- [MultiAgent-OPD](https://arxiv.org/abs/2610.23234) · HF 👍13 · 7 days: jointly trains a Leader-Searcher-Answerer hierarchical multi-agent system with on-policy distillation plus reinforcement learning. It reaches 38.68% macro avg@4 across seven datasets.

## 3. 📈 Still climbing

- [TAO: Tool-Aware Joint Scheduling for LLM-Based Agentic Serving](https://arxiv.org/abs/2610.37230) · 👍 from 15 at first listing (10-29; reported 10-31) to 95: puts tool-return readiness, time-decaying per-node cache credit and token occupancy into one value interface, then uses dynamic programming to jointly select and place waiting sessions. Across 12 settings, latency drops by up to 26.8%, TTFT by up to 36.3%, and decoding throughput rises by up to 29.5%. It gained the most (+80), and cache-aware scheduling on the serving side bears directly on context engineering.

It builds 112,686 tasks across 612 occupations. The fine-tuned WorkPilot-35B-A3B rises from 879 to 1565 Elo on GDPval-AA v2.1. Code: [IQuestLab/WorkFactory](https://github.com/IQuestLab/WorkFactory), 19 stars.

## 4. 🆕 New: announced last night

- [R^2Orch](https://arxiv.org/abs/2610.22740): uses skill withdrawal plus self-play to move an orchestrator step by step toward "zero-skill deployment", beating baselines on 12 datasets (preliminary 👍85, the highest among today's new papers).
- [KITE](https://arxiv.org/abs/2610.41521): vector-free long-term conversation memory that compiles retrieval into an inspectable retrieval plan. 93.5% on LoCoMo and 86.0% on LongMemEval-S, using only about 1.6k reader context tokens per question.
- [In-Model Context Compression with Agentic Soft Tokens (ASTC)](https://arxiv.org/abs/2610.41291): training-free. It uses the native recurrent state of a hybrid GDN-attention model to keep absorbed information as soft tokens and exact values as hard tokens; end-to-end Attention Pairs fall by up to 50.68%.
- [Context as Infrastructure](https://arxiv.org/abs/2610.41172): the RAGFlow team proposes a "knowledge compilation" layer. A claim-evidence navigation tree cuts query tokens by 91% when evidence is sufficient and 38% on average. Repo: [infiniflow/ragflow](https://github.com/infiniflow/ragflow).
- [Completeness and Cost of Retrieval Structures for Multi-Tool Requests](https://arxiv.org/abs/2610.41905): studies retrieval completeness for multi-tool requests. Tasks succeed 21/21 when the retrieved set is complete and only 2/39 when it is not.
- [Ask on Demand](https://arxiv.org/abs/2610.41378): parallel agents ask peers about their execution history on demand, with a lightweight gate deciding whether a question is worth asking. It beats independent parallel runs on AppWorld and WebShop, at lower inference cost than information-sharing baselines.
- [Latent Sparse Attention](https://arxiv.org/abs/2610.42147): hierarchically clusters keys in a learned latent space. At 10M tokens, a single attention layer is up to 72.4x faster in prefill than full attention.
- [Subquadratic Attention with a Hierarchical Tree-Structured Indexer (ZHA)](https://arxiv.org/abs/2610.42112): builds a recursively compressed tree index over the KV cache for subquadratic total cost, and can be applied to pretrained models with a small amount of KL distillation.
- [MEMIG](https://arxiv.org/abs/2610.41245): indexable, quantized, structured agent memory for antibody optimization. It stores numeric values measured by an oracle rather than text descriptions.
- [RoboArchitect](https://arxiv.org/abs/2610.42141): a coding model automatically iterates on a harness built around a frozen robot policy, and the harness carries persistent memory. Success on unseen scenes goes from 9.7% to 43.3% (preliminary 👍5).
- [EvoMCP](https://arxiv.org/abs/2610.41479): an MCP agent and its training data co-evolve, gaining +16.5%, +10.2% and +12.6% on Toolathlon, MCPMark and MCP-Atlas.
- [PrivacyTrace](https://arxiv.org/abs/2610.41885): MCP tool-call traces alone leak user profiles. The attack succeeds 26.25% of the time, against 17.97% for a prior-only guess.

## Observations

- Harnesses are now a research subject in their own right. At least three hot papers (verification strategy, MCP vs. CLI, policy-as-harness) quantify how much results change when only the harness changes. Reversing field order alone moves success from 85.0% to 19.2%. In the new batch, RoboArchitect extends automated harness design to robotics.
- Context compression is following two parallel routes. One works at the text level, synthesizing experience or history into short guidance (ReGE, KITE, knowledge compilation). The other works inside the model, with soft tokens and sparse attention (ASTC, LSA, ZHA). The evidence adds a caution: CrossProfile finds that the compression strategy doesn't decide the outcome, the balance of retained evidence does, and a full transcript did worse than no notes.
- Cache and scheduling work is arriving from the engineering side. TAO's cache credit and Beyond Benchmarks' 69.4 s vs. 2.8 s time to first token both point to cache reuse as the main variable in agent serving. On the engineering side, [RAGFlow](https://github.com/infiniflow/ragflow) puts the harness and "minimal sufficient context" in the same paper.
- Tool-selection completeness is being measured again. The multi-tool retrieval study finds that single-tool evaluation overstates performance (top-10 completeness on multi-target queries is only .08–.17). That fits the MCP-vs-CLI result that interface representation changes behavior.
