## 1. 🔥 Hot list: Agent Context picks

### [MIRIX-2.0: Multi-Agent Memory System](https://arxiv.org/abs/2611.12068)
- Heat: HF 👍26 (6 days on the list, +26); repo [Mirix-AI/MIRIX](https://github.com/Mirix-AI/MIRIX) ⭐3472. No X mention count in the data.
- History: third appearance (see the 11-10 report and the 11-15 report), so it can be called a sustained presence.
- Problem: in long-term memory, parametric memory needs training, consolidation permanently loses detail, and keeping everything makes storage harder to search.
- Method: six typed memory agents keep the full record as the system of record. A provenance hypergraph indexes episodic and semantic records, and n-ary frames reference the rows they come from. Retrieval has an explicit budget, so the evidence read does not grow with history. AutoDream merges duplicate anchors outside the write path (without rewriting any record) and distills task sessions into skills. No fine-tuning, and it runs on open and closed models.
- Result: most accurate on four of five QA benchmarks. LoCoMo 91.4%, LongMemEval-S 72.6% (14.3 points above the strongest baseline). With AutoDream off, it is faster than HyperMem on all five timed benchmarks. On procedural memory, MetaClaw-Bench 49.2% against 44.0% for the MetaClaw skill library.

### [Can LLM Agents Organize Their Own Memory? (SoMem)](https://arxiv.org/abs/2611.11929)
- Heat: HF 👍0 (source: arxiv, 6 days on the list); repo [Qi202/SoMem](https://github.com/Qi202/SoMem), no star count in the data.
- History: covered in the 11-10 report; it appeared the same day as MIRIX-2.0 with a different approach (see the 11-10 report).
- Problem: predefined records and fixed organization rules adapt poorly to changing tasks.
- Method: memory is stored as plain documents linked to each other. The agent decides what to summarize, how to categorize it and when to revise a topic, and every summary links back to the raw interaction as evidence. Updates are validated at runtime, and time, relation and recency views are derived automatically. At query time the agent chooses what to search and read, and follows links back to the raw evidence.
- Result: beats the strongest baseline by 2.66, 3.10 and 2.00 points on LoCoMo, BEAM-100K and LongMemEval-S. The built memory can be reused across models.

### [Compaction, decay and reinforcement in a two-tier conversational memory](https://arxiv.org/abs/2611.09807)
- Heat: HF 👍0 (source: arxiv, 7 days on the list); no code data.
- Problem: should a conversational agent store the raw transcript and retrieve from it (RAG), or compress it into atomic facts and retrieve those?
- Method: on LoCoMo, both setups answer all 1,985 questions with the same store, generator and judge. An exact McNemar test is run on the 512 questions where the two disagree.
- Result: on the four categories comparable work reports, compaction scores 71.4% against 64.6% (+6.8, p=5.5e-08) with 34% fewer prompt tokens. Across all five categories including adversarial, the lead shrinks to 2.0 and is no longer significant, because RAG leads by 14.6 on adversarial. The more an answer needs the original wording, the worse compaction does: it leads by 9.6 when the reference answer is 1–2 words and trails by 3.1 beyond 8 words. Compaction keeps the content of assertions and drops the phrasing. The paper also reports four negative results.

### [Review the Episodes, Refine the Lessons: Simple Memory Evolution for Embodied Agents (SimplEvo)](https://arxiv.org/abs/2611.11509)
- Heat: HF 👍0 (source: arxiv, 6 days on the list).
- Problem: wrapping a frontier MLLM in a harness (post-training strategies, recursive self-improvement) may not actually beat the MLLM on its own.
- Method: no weight updates and no privileged information. The MLLM writes a coordinate-free task memory from one demonstration, builds a bounded working memory over training episodes, and refines it after each episode with lessons on procedure, completion and recovery. Both memories are frozen at test time.
- Result: on EBench, GPT-6-Astra goes from 46.7% to 81.7% success, and tops RoboDojo (SR 69.63%). Text-only memory matches the success rate of memory that also stores past visual frames, with fewer tokens. The working memory can be reused as-is by weaker MLLMs.

### [MemoryDojo: Benchmarking Poisoning Through LLM Agent Memory](https://arxiv.org/abs/2611.09721)
- Heat: HF 👍0 (source: arxiv, 7 days on the list).
- Problem: a malicious instruction met in one session can be stored in memory, then retrieved and executed in later sessions.
- Method: the benchmark has 155 multi-session long-horizon trajectories across 4 domains and supports 5 memory systems. It tracks the lifecycle of poisoned information in memory and its effect on later behavior. The paper also proposes memory-aware poisoning optimization.
- Result: every memory system tested is vulnerable to poisoning, with large differences in downstream impact.

### [Verify Before You Fetch: Reliable KV Cache Compression for LLM Inference (VerKV)](https://arxiv.org/abs/2611.11319)
- Heat: HF 👍0 (source: arxiv, 6 days on the list).
- Problem: for long contexts and long-lived agents, the KV cache outgrows GPU HBM and must be offloaded to CPU, where transfers slow inference. Query-agnostic compression can't guarantee attention accuracy for arbitrary queries.
- Method: the GPU keeps a small set of query-agnostic key tokens (sampled with PoissonComp) plus a token-level sketch of the full cache, while the full cache stays on CPU. At inference, KVFetch estimates the relative attention error. If it meets the (ε, δ) tolerance, host memory is not touched. Otherwise a query-aware retrieval fetches the missing tokens.
- Result: on Qwen3-4B, Qwen3.5-9B and Ministral-3-8B at 32K context, it keeps 90–100% of dense quality (RULER and LOFT average), cuts GPU memory 8–32×, and fetches 2–23% of the cache from CPU to GPU per generated token.

### [From LoRA to Language: Recovering Skill Documents from Adapters](https://arxiv.org/abs/2611.09454)
- Heat: HF 👍0 (source: arxiv, 7 days on the list).
- Problem: to save context, skill documents get compiled into LoRA adapters. The behavior stays but the text is gone, which makes it hard to read, edit, audit or transfer.
- Method: reading the weights alone recovers almost nothing. Running the adapted model works better: the Executing Writer trains a small writer on top of the adapted model to recover the document. For adapters trained only on behavior, an agent writes the skill by comparing the base and adapted models.
- Result: recovers 39–44% of key instructions for held-out skills (1.3–1.5% when using another skill's adapter). On adapters for 41 external skills, the recovered documents restore 85–91% of the original task gain. On behavior-only adapters, ALFWorld recovers 58–71% of the LoRA gain, and Llama-3.1-8B goes from 5% to 55%.

## 2. 🔥 Hot list: other Agent topics

- [A Cross-Scenario Survey and Analysis of Self-Evolving Multimodal Agents](https://arxiv.org/abs/2611.14256) · HF 👍5 · 3 days on the list: surveys how self-evolution mechanisms transfer across reasoning, generation, GUI/Web and embodied scenarios, using a three-stage loop (experience generation, feedback acquisition, update consolidation). Each mechanism is rated transferable, conditional, blocked or redundant. Code: [jingjing12110/SE-MMAgents](https://github.com/jingjing12110/SE-MMAgents).
- [ScrapeBench: Evaluating Legal Compliance of AI Agents in Website Scraping](https://arxiv.org/abs/2611.11306) · HF 👍4 · 4 days on the list: on 1,626 sites that explicitly forbid scraping, most agents comply less than 5% of the time. On 269 sites that don't forbid it, Claude Opus 4.6 over-refuses 98.5% of the time. The human baseline (n=180) complies at a rate similar to agents but over-refuses more.
- [Learning to Act with World Models by Valuing What Comes Next (WM-PPO)](https://arxiv.org/abs/2611.12200) · HF 👍3 · 5 days on the list: a world model predicts the next observation for each candidate action, and a critic values the successor state to produce an auxiliary advantage and objective. ALFWorld success goes from 63.5% to 87.5%, ScienceWorld from 39.3% to 52.9%.
- [From Procedures to Permissions: Learning Precise Subagent Authorization from Agent Skills](https://arxiv.org/abs/2611.08905) · HF 👍0 · 7 days on the list: uses procedural knowledge in Agent Skills to synthesize tasks that supervise which tools and workspace permissions a subagent gets. On ClawArena-Team (Qwen3.5-35B-A3B): tool-permission precision +13.4 points, workspace-permission precision +24.1, task success +11.6.
- [ErosionBench: Probing Alignment Decay in Enterprise Multi-Agent Systems](https://arxiv.org/abs/2611.11266) · HF 👍0 · 6 days on the list: 1,728 scenarios test how cross-session shared-state poisoning leads multi-agent systems to make unsafe tool calls, scored on actual tool calls. Perimeter defenses cut attack success only by over-refusing 54–92% of legitimate work. The proposed Meta-Auditor reaches 98.5% recall and 2.9% false positives on 906 held-out scenarios.
- [PRISM: Causal Counterfactual Minimization of Agent Tool Privileges](https://arxiv.org/abs/2611.11539) · HF 👍0 · 6 days on the list: targets over-granted tool permissions for agents under MCP, learning tool necessity through sandboxed interventions and inducing roles with an information bottleneck. Authorized tools per role drop 78.3%, with 78.2% task success and blast radius down to 15.9%.
- [EmoHarness: Boosting Multimodal Emotion Understanding with Meta-Harness Evolving](https://arxiv.org/abs/2611.11994) · HF 👍2 · 5 days on the list: a stronger LLM (the Builder) reads a frozen small model's errors and execution traces offline to edit the harness. Recognition on MME-Emotion improves 7.6–13.4 points, but the gain comes mostly from transcript and prosody evidence (+5.38 to +10.71). The evolved edits add at most +0.95 and are not significant after Holm correction. A sober counterpoint to harness self-evolution.

## 4. 🆕 New: published last night

- [Envisioning Agentic Robotics: A New Era of Robotic Systems](https://arxiv.org/abs/2611.18359): argues that an "embodied System 2" (a foundation model plus an embodied harness) is the decision core of agentic robotics, and gives an evaluation framework and a roadmap toward sustained autonomy (👍107, highest today).
- [Gamer](https://arxiv.org/abs/2611.18397): a general VLA agent for long-horizon real-time games. Training uses multi-turn RL to handle a limited context window, and inference uses a cloud-edge engine to support unbounded context (👍86, code [RainBowLuoCS/Gamer](https://github.com/RainBowLuoCS/Gamer) ⭐124).
- [VibePrevisBench](https://arxiv.org/abs/2611.15789): a benchmark of coding agents reconstructing 4D scenes in Blender, with 242 tasks and 11 frontier agents. Agents inspect their own renders but don't correct errors (👍82).
- [G-CAST](https://arxiv.org/abs/2611.17814): governed continual self-training for e-commerce agents. It turns online evidence into training data and preserves existing capabilities under demand drift and harness evolution. Deployed in the procurement agent on Alibaba's 1688 (a B2B wholesale marketplace) (👍17).
- [Aligning AI Teams](https://arxiv.org/abs/2611.17820): studies why single-agent alignment doesn't carry over to multi-agent teams. Diffusion of responsibility is the main cause, and appointing a safety-owner agent or publishing a safety spec document restores alignment. Releases the magelab framework (👍12).
- [WebArena-Pro](https://arxiv.org/abs/2611.17955): a reproducible multimodal web agent benchmark with 300 tasks across 20 self-hosted web apps, with audio and video as core observations. Best score 62.3% (👍10).
- [Continual-ARC](https://arxiv.org/abs/2611.14505): builds lifelong task streams from ARC-AGI to compare memory-based and weight-based learning on one scale. Harness persistence generally doesn't improve memory and gives no gain on unseen tasks, while weight learning gives clear gains (👍9, code [unifyai/continual-arc](https://github.com/unifyai/continual-arc) ⭐37).
- [CarryOn: Learning What to Keep in Context for Long-Horizon LLM Agents](https://arxiv.org/abs/2611.17808): a lightweight context manager that pairs a compact execution state with traceable fine-grained evidence, using a learned selector and adaptive retention, with no extra LLM calls. Macro-average success is 75.7% on AppWorld, OfficeBench and Tau2 Telecom, 6.7 points above the strongest baseline. The new paper closest to today's Agent Context theme.
- [Forget the Lineage (LinEra)](https://arxiv.org/abs/2611.18133): forward-secure cryptographic erasure for agent memory. Each memory is encrypted with a key derived from its parent, so forgetting takes one puncture. Integrated with mem0, on LoCoMo an attacker holding all files and the current key recovers 0 forgotten secrets under LinEra (70/71 under logical deletion). The cost is forgetting radius: forgetting 1% of turns erases 73.0% of derived memories under session-level summaries, but only 3.8% under a four-turn window.
- [Interpreting Coding Agents Through Their Behavioral Trajectories](https://arxiv.org/abs/2611.17440): analyzes 143,209 coding-agent trajectories from 125 configurations, with a rule-based parser mapping trajectories to actions such as search, edit and test. Agents with similar solve rates behave very differently, and scaffold and reasoning effort systematically change behavior (👍4).
- [GH-AWTrace](https://arxiv.org/abs/2611.06866): a dataset of GitHub Agentic Workflow execution logs: 25,014 workflows, 5,051 repositories, 4,112,526 run records (👍10).

## Observations

- Memory is the most concentrated topic on the hot list. MIRIX-2.0 (typed multi-agent, hypergraph, full record as ground truth), SoMem (plain linked documents), 2611.09807 (compaction vs RAG) and SimplEvo (text experience memory) all keep traceable raw text or evidence rather than summaries alone. CarryOn (new) also pairs compact state with source-linked evidence.
- Memory security is now studied on its own. MemoryDojo tests poisoning, LinEra tests erasure, ErosionBench tests erosion through cross-session shared state, and PRISM and the subagent authorization paper deal with tool permissions.
- KV cache: besides VerKV, [Nebula](https://arxiv.org/abs/2611.09474) (a distributed position-independent cache; median TTFT down 61.4% on average, recovering 76.1% of tokens a prefix cache misses) is also on the list. Both papers cite the long prompts of agents and RAG as motivation.
- Engineering side: this issue has no GitHub project data, only paper-repo stars. MIRIX ⭐3472 is far above the rest, then Gamer ⭐124, Infrathon ⭐39 and Continual-ARC ⭐37, with most others ≤10. No comparison with engineering projects is drawn.
