## Hot list: Agent Context picks

### [Rare, Relevant, and Still Wrong: How Memory Fails LLM Group Decisions](https://arxiv.org/abs/2610.37624)
- Heat: HF 👍8 (6 days on the list, +4); no repo.
- Problem: when a discussion among several LLMs is compressed into a short memory for a final decision-maker, what should be kept?
- Method: a diagnostic benchmark, CrossProfile (60 templates, 480 tasks), that varies which party holds the supporting, distracting and irrelevant facts while the text stays the same. It compares two heuristics, keep-by-relevance and keep-by-rarity, on Qwen2.5-7B, Llama-3.1-8B and two DeepSeek models.
- Takeaway: both heuristics fail.
  - Relevance filtering brings distractors back, because distractors are also on topic. Even a perfect relevance filter scores 23–31 points below rarity-first in the classic hidden-profile setup.
  - Rarity-first is no better than random on average.
  - The decision model is biased toward facts that several agents share ("social proof"). Removing attribution labels raises accuracy by 13–24 points.
  - In natural discussions, the full transcript scores lower than having no notes at all.
- Why it leads: counterintuitive memory results with solid evidence.

### [MemSteer: Turning User Histories into Supervision for Agent Memory Optimization](https://arxiv.org/abs/2610.39276)
- Heat: HF 👍6 (4 days, +6); no repo.
- Problem: a new user's history is unlabeled, which makes it hard to tune an agent's memory design.
- Method: MemSteer turns unlabeled user histories into evidence-backed QA supervision. It first builds an evidence-grounded answer plan, then generates questions, and checks the labels with source audits and blind answer recovery. Its companion MemSteer-Opt uses QA evaluation plus failure diagnosis to change how memory is stored, retrieved and assembled into context, without updating model parameters.
- Takeaway: versus Base-BM25, ATM-Bench Question Score rises 13.4 points. RHELM accuracy rises 4.1 (no external data) and 6.6 (with external data). Results match optimization guided by official QA supervision.

### [Your Policy Is Secretly a Harness: The Decision Geometry of Agent Interfaces](https://arxiv.org/abs/2610.37255)
- Heat: HF 👍8 (6 days, +2); code [2020-qqtcg/HRP](https://github.com/2020-qqtcg/HRP) ⭐1.
- Problem: after a model is trained under one harness, how much of what it learned survives a harness swap?
- Method: under KL-regularized control, the paper proves that an optimal policy's log odds recover its harness's preference over actions. Deployed return equals the harness "ceiling" minus the policy's "mismatch". Training changes only the mismatch, while swapping the harness changes both. Comparing harnesses with a fixed model therefore mixes up what the harness provides with how well the model uses it.
- Takeaway:
  - On MiniWoB++, merely reversing the order of observation fields (the optimal decision is unchanged) drops a trained model's success rate from 85.0% to 19.2%.
  - On Terminal-Bench Lite, estimating "ceiling minus mismatch" with a stronger model reproduces the accuracy ranking. Either term alone does not.

### [Rethinking Verification in Agent Harnesses](https://arxiv.org/abs/2610.34577)
- Heat: HF 👍7 (6 days, −2); no repo.
- Problem: how should the verification step in a harness be organized?
- Method: four layers across the agent lifecycle: initial instructions, mid-run reminders, completion gating, and independent review. It compares 17 designs on 7 frontier coding models, using Terminal-Bench and SWE-bench Verified plus a new VisualBench.
- Takeaway:
  - Initial instructions and mid-run reminders give small, model-dependent gains.
  - Completion gating may gain more but clearly raises cost.
  - Independent review has the best return. Terminal-Bench accuracy rises 5.9–9.5 points at 1.13–1.25× baseline cost. SWE-bench rises 3.9–6.6 points at 1.00–1.04×.

### [Skill^{infty}: Recursive Self-Improvement for Agent Skill Optimization](https://arxiv.org/abs/2610.35434)
- Heat: HF 👍8 (7 days, +5); code [taowangcheng/Skill-Infinity](https://github.com/taowangcheng/Skill-Infinity) ⭐6.
- Problem: existing skill optimizers use hand-designed pipelines, the meta-skill is locked into one pipeline, and every task is learned from scratch.
- Method: a meta-agent optimizes task skills according to a "meta-skill", and uses the same process to optimize the meta-skill itself. The meta-skill is decoupled from task skills, refined across several optimization tasks, then reused in other domains. Both layers are standard skill packages loaded through native skill discovery.
- Takeaway: on 83 SkillsBench tasks the pass rate is 60.7%, versus 56.4% for human-written skills and 54.5% for SkillEvolver.

### [R^2Orch: Recursive Self-Improvement for Agent Orchestration via Self-Play within a Skill-Internalization Loop](https://arxiv.org/abs/2610.22740)
- Heat: HF 👍49 (1 day); code [beita6969/R2Orch](https://github.com/beita6969/R2Orch) ⭐12. It was 👍85 when first seen and is now 49 (−36), so the count is volatile.
- Problem: orchestration learning relies on hand-built curricula, the advantage signal collapses when rollouts give identical outcomes, and skill evaluation is noisy.
- Method: inner-loop self-play improves the orchestrator on tasks the Proposer picks, and an outer loop improves how the inner loop improves. In "Skill Withdrawal", a skill is removed when a controlled evaluation shows the orchestrator performs the same without it. Failures are distilled into skills, skills are distilled into parameters, and the orchestrator drifts toward "zero-skill deployment".
- Takeaway: consistently beats baselines on 12 datasets (QA, math, code, interactive tasks).

### [RoboArchitect: Automating the Design of Robotic Agents with Persistent Memory](https://arxiv.org/abs/2610.42141)
- Heat: HF 👍7 (1 day, +2); code [roboarchitect-ai/RoboArchitect](https://github.com/roboarchitect-ai/RoboArchitect) ⭐3.
- Problem: frozen robot policies work far better inside a harness, but harnesses are rebuilt by hand for each robot or benchmark.
- Method: a coding model watches rollouts, diagnoses failures, and iteratively edits the harness around the frozen policy. The harness also evolves its own persistent memory, carrying learned experience (for example, effective grasp depth) into later decisions.
- Takeaway: with no weight updates, average success on unseen scenes goes from 9.7% to 43.3% (4.5×), and on unseen tasks from 12.7% to 40.2% (3.2×).

### [Matched Capabilities, Different Behaviors: A Controlled Study of MCP and CLI Interfaces for Language Agents](https://arxiv.org/abs/2610.34298)
- Heat: HF 👍5 (7 days, +5); code [ModalityDance/MICA](https://github.com/ModalityDance/MICA) ⭐0.
- Problem: when MCP and CLI expose the same semantic operations, does the agent behave the same?
- Method: MICA renders MCP and CLI from one semantic action contract and runs both through the same runtime, comparing 6 models in 3 interaction environments. It then proposes DART, which keeps validated semantic decisions and repairs only the interface-specific action implementation.
- Takeaway:
  - Matched interfaces still cause large differences in task performance and interaction cost. 94.3% of 2,004 trajectories show structural divergence.
  - DART improves the score in all 6 settings (up to +9.0) and cuts MCP token cost in 3 environments (up to 27.1k tokens per task).

## 🆕 New: published last night

- [CoworkOS: Scaling Agent Coworkers for Real-world Automation](https://arxiv.org/abs/2611.03178) (early 👍85; code [RUC-NLPIR/CoworkOS](https://github.com/RUC-NLPIR/CoworkOS) ⭐46): a general harness for long-horizon work that separates task strategy from execution management. A layered workspace and persistent semantic memory let files, key decisions and job logs be shared across agents and sessions and recovered after interruptions. With GLM-5.3 as the backbone, 5 rounds of automatic RSI (recursive self-improvement) post-training on Qwen3.6-35B-A3B lift the average over eight benchmarks from 33.19 to 42.95 (+9.76).
- [CUA-Master: Scaling Computer-use Agents through Open-World Recursive Improvements](https://arxiv.org/abs/2611.03126) (early 👍90; code [xlyu0106/CUA-Master](https://github.com/xlyu0106/CUA-Master) ⭐44): mines real workflows from tutorial videos as seed tasks and runs a two-level recursive data and model flywheel. CUA-Master-27B scores 80.2 on OSWorld Verified.
- [Do Agents Still Follow the Rules? Benchmarking Rule Compliance under Agent Context Compaction](https://arxiv.org/abs/2611.03223): ARCBench tests rule compliance after context compression on the pi agent harness. Most violations happen while the rule is still in the compacted history, not after it was dropped. Runs that keep the rule violate it more than twice as often as runs with full history. The strongest compressor-targeted attack doubles violations.
- [Agentic Context Management for Multi-Turn Human-AI Conversations](https://arxiv.org/abs/2611.00518): AC3 is a training-free method that rebuilds the task specification from user messages alone, then audits and edits the context to counter context pollution. On three of four Lost in Conversation tasks it closes 55–84% of the gap between full context and "drop assistant messages".
- [Switch-SWE: Do Coding Agents Hold Focus When Switching Between Unfinished Tasks?](https://arxiv.org/abs/2611.02017): tests whether coding agents recover after switching among several unfinished tasks in one repo. Seven agents drop 11.5 points on average. A plugin that adds task-relevant history selection and task-state summaries gains 5.5–15.5 points on OpenCode.
- [A State Change Is Local, Its Consequences Are Not (StateGraph)](https://arxiv.org/abs/2611.02912): keeps a state dependency graph for long-term memory and uses counterfactual verification to decide which derived states to invalidate when a premise changes. On its own 50-case benchmark, Impact-F1 beats a reproduction of CUPMem by 6.9 points at depth 1 and 26.0 at depth 3+.
- [Agent Memory as Rate-Limited Filtering](https://arxiv.org/abs/2611.02361): treats agent memory as recursive filtering. On an access-log decision task, open 7–32B models reading the full history reach only 48–55% at 256 events. Explicit state beats long context once the history exceeds the reader model's horizon. A filter where the model parses events and rules update the state reaches 80–89% at 256 events.
- [Learning by Doing: Autonomously Compiling and Curating Agent Skills from Verified Traces](https://arxiv.org/abs/2611.01386): Zep Agent Skills is a production service that compiles verified execution traces into versioned skills (procedural memory). Skills compiled from a teacher model's traces raise pass rates of three weaker executor models by 4.5–18.8 points.
- [When Cache Pressure Becomes a Trap: Metastability in Agent Serving](https://arxiv.org/abs/2611.02543): agent conversations resend growing contexts, so a brief traffic burst can collapse prefix reuse and leave the system degraded. On SGLang, a ten-minute burst cuts effective throughput by about 88% over the next hour. The proposed Basin reaches 1.20–1.70× Continuum on H200.
- [Parallelism-Aligned Pruning and Round-Aware Context Reuse (PARC)](https://arxiv.org/abs/2611.02601): for on-device multimodal agents, restructures the KV cache by lifecycle so past images no longer stay in the persistent cache, fitting more interaction rounds in the same budget. Decode throughput rises 23.8% on a seven-core deployment.
- [Pulse: Long-Horizon Tasks Need Streaming Personalization](https://arxiv.org/abs/2611.00988): a separate lightweight memory agent monitors continuously during execution and learns by RL when and how to step in. It scores 71.9% on π-Bench and 46.4% on MCP-Persona, the highest among compared methods.
- [MemHarmBench: Evaluating Cross-Session Prompt Injection in Memory-Persistent AI Agents](https://arxiv.org/abs/2611.01700): tests whether malicious instructions written into persistent memory shape decisions in later, normal sessions. Several agent systems finish their tasks with no visible anomaly while still making decisions that serve the attacker.

## Observations

- The past week's hot list clusters on the word "harness": verification design ([2610.34577](https://arxiv.org/abs/2610.34577)), coupling between policy and harness ([2610.37255](https://arxiv.org/abs/2610.37255)), automatic harness design with memory (RoboArchitect), and interface representation (MCP vs CLI). New papers TinyAstral and Continual Harness Evolution ([2611.03219](https://arxiv.org/abs/2611.03219)) continue the thread. The latter reports Meta-Harness falling from 94.0% on SWE-Bench to 32.0% by the fifth round of evolution.
- Memory and compression work has shifted from how much to store to whether the right things were stored: CrossProfile's failed filters, ARCBench's rules that sit in the summary but are still violated, StateGraph's dependency revision, AC3's context pollution. The findings agree: retaining information does not mean it gets used correctly.
- Skills and self-improvement run as a parallel thread: Skill^∞ and R²Orch (hot), Zep Agent Skills, CUA-Master and NorthCUA (new). Most frame it as recursive self-improvement (RSI).
- Serving research now targets agent workloads specifically: metastability, Fairway, PARC, Jet-QSparse, and the SIMPLE energy law (agentic requests use 13.0× the energy of non-agentic ones, still 4.8× after prefix caching). Most of these papers have no repo in the data, so there is no engineering-side comparison.
