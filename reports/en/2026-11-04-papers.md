## Hot list: Agent Context picks

### [CoworkOS](https://arxiv.org/abs/2611.03178)
- Heat: HF 👍96 (1 day on the list, +11); code [RUC-NLPIR/CoworkOS](https://github.com/RUC-NLPIR/CoworkOS) ★104; no X data.
- Problem: long-running office tasks need both high-quality delivery and long-term monitoring and decision-making.
- Method: a general harness that separates task policy (the model decides actions, delegation and acceptance) from execution management (the runtime keeps state and feedback). A three-layer architecture runs tasks directly or delegates them to subagents, synchronously or asynchronously. A layered workspace and persistent semantic memory let working files, important decisions and long-running job logs be shared and reused across agents and sessions, and resumed after interruptions.
- Result: competitive with frontier agent apps such as Codex and the DeepSeek harness across 12 benchmarks and 6 kinds of real applications. In one case study, GLM-5.3 drove recursive-self-improvement (RSI) post-training of Qwen3.6-35B-A3B. The average over 8 benchmarks rose from 33.19 to 42.95 (+9.76) in 5 rounds.
- Why first: the most-liked Agent Context paper today, and it has open code.

### [Switch-SWE](https://arxiv.org/abs/2611.02017)
- Heat: HF 👍6 (1 day, +6); code [Miraclecsc/Switch-SWE](https://github.com/Miraclecsc/Switch-SWE) ★26.
- Problem: when a coding agent is interrupted and moved to another unfinished task in the same repo, can it recover the original task's requirements and progress?
- Method: 200 focus tasks across 19 Python repos, rebuilt into 400 matched sessions (uninterrupted vs. interleaved with other tasks). Trajectory analysis finds two typical failures: requirements confused across tasks, and lost task state. The authors add a plug-in context-management module that selects task-relevant history and keeps a short task-state summary.
- Result: interleaving costs 7 coding agents 11.5 points on average (range 6.0–15.0). On OpenCode the module raises completion by 5.5–15.5 points.
- Why it's here: low heat, but it targets context management in long tasks directly and ships a usable module.

### [SWE-Trail](https://arxiv.org/abs/2611.02074)
- Heat: HF 👍38 (1 day, +7); no code repo.
- Problem: independently sampled trajectories grow redundant, and putting history into the agent's context as advice creates a train/test mismatch.
- Method: early trajectories decide which state deserves extra collection effort, and history always stays outside the agent's context. At that state the agent proposes candidate next actions from ordinary context, and SWE-Trail briefly executes them from the same checkpoint to choose a route.
- Result: a 124B student (Ling-3.0-flash-base) beats independent sampling by 2.33 points on SWE-bench Multilingual and 1.60 on SWE-bench Pro. Without the history, Multilingual gains only 0.11.

### [MemSteer](https://arxiv.org/abs/2610.39276)
- Heat: HF 👍8 (5 days, +8); no code repo.
- Problem: a new user's history is unlabeled, which makes it hard to tune an agent's memory design.
- Method: turns unlabeled user history into evidence-grounded QA supervision (an answer plan grounded in evidence first, then questions, then source audits and blind-answer recovery). MemSteer-Opt uses this supervision for design evaluation and failure diagnosis, and changes memory storage, retrieval and context construction without updating model parameters.
- Result: +13.4 Question Score over Base-BM25 on ATM-Bench, and +4.1 / +6.6 accuracy on RHELM without / with external data. The supervision works about as well as optimization guided by the official QA.

### [Rare, Relevant, and Still Wrong: How Memory Fails LLM Group Decisions](https://arxiv.org/abs/2610.37624)
- Heat: HF 👍8 (7 days, +4); no code repo.
- Problem: when a group discussion between LLMs is compressed into a short memory for the final decision-maker, what should be kept?
- Method: a diagnostic benchmark, CrossProfile (60 templates, 480 tasks), which crosses which agent holds the supporting, decoy and irrelevant facts while the text stays the same. It tests two heuristics: keep the rarest facts, or keep those relevant to the decision criteria.
- Result: both fail in predictable ways. Relevance-based selection lets decoys in, and a perfect relevance filter still loses to rarity-first by 23–31 points in the classic setup. Rarity-first is no better than random on average. Accuracy depends on the evidence balance in what is retained, not on the selection strategy. The decision model also over-trusts facts mentioned by several agents, and stripping attribution labels adds 13–24 points. In natural discussions, a full transcript scores below taking no notes at all.

### [GEPA-Curator](https://arxiv.org/abs/2610.37651)
- Heat: HF 👍6 (1 day, +1); no code repo.
- Problem: reflective prompt optimizers learn from failed rollouts, but failures can come from noise or harness limits, so the learning signal is unreliable.
- Method: task filtering drops noisy tasks. Successful-trajectory retrieval selectively pulls past successes for a task and gives them to the optimizer as extra context.
- Result: matches or beats two baselines on GoBrowse, ALFWorld, AppWorld and τ-bench, up to 20.7% over GEPA and 21.2% over ACE.

### [Can LLM Agents Learn by Watching Tutorial Videos? (TAL)](https://arxiv.org/abs/2611.01460)
- Heat: HF 👍5 (1 day, +3); no code repo.
- Problem: can an agent learn from tutorial videos without any parameter updates?
- Method: tutorial videos are consolidated into a persistent, structured "tutorialbook" memory. A two-stage adversarial process poses hard video-related questions and uses them to refine the memory. At inference the agent retrieves through a table-of-contents (TOC) tree, so retrieval follows the model's reasoning instead of embedding similarity.
- Result: on VidLearn (72 chess tutorial videos), up to 113% / 91% improvement over the raw MLLM on the train/test splits, rising steadily as videos are added. In real games, 69% of openings are stronger than the raw model's.

### [Rethinking Verification in Agent Harnesses](https://arxiv.org/abs/2610.34577)
- Heat: HF 👍7 (7 days, -2 since first appearance); no code repo.
- Problem: there is little guidance on how to organize verification inside a harness.
- Method: treats verification as a test-time scaling dimension across four layers: initial instructions, in-run reminders, completion gating and independent review. It compares 17 designs across 7 frontier coding models and introduces VisualBench.
- Result: independent review gives the best accuracy per cost. It adds 5.9–9.5 points on Terminal-Bench (1.13–1.25x cost) and 3.9–6.6 points on SWE-bench Verified (1.00–1.04x cost). Completion gating gains more but costs noticeably more.
- Why last: this is harness design, with a weaker link to context.

## New: announced last night
- [Route Anything](https://arxiv.org/abs/2611.05275): studies model/strategy routing over 452 candidate configurations across 25 benchmarks. Per-input oracle routing beats the best fixed candidate by 5.4 points, and routing improves efficiency 8.82x on average (initial 👍93; code [InfRec-Cardinal/route-anything](https://github.com/InfRec-Cardinal/route-anything) ★2).
- [Axion 1.0](https://arxiv.org/abs/2611.03233): a fully open agent foundation model trained in three steps (two-stage SFT, then RL), with the full data and training recipe released (👍38; code [bytedance/axion1_0](https://github.com/bytedance/axion1_0) ★19).
- [ToolSpace](https://arxiv.org/abs/2611.05036): synthesizes tool-centric long-horizon MCP environments by mining dependencies between adjacent calls from real execution traces. Qwen3.6-35B-A3B's average over seven benchmarks goes from 23.0 to 41.0 (43.2 with RL) (👍32; code [dongguanting/ToolSpace](https://github.com/dongguanting/ToolSpace) ★7).
- [ParetoSaddler](https://arxiv.org/abs/2611.02079): automatic harness optimization for quality and cost together. On GAIA2, quality goes from 56.22% to 62.89% and cost per task from \$0.78 to \$0.45 (👍16).
- [WebHarbor](https://arxiv.org/abs/2611.03634): 153 Docker-deployable replicas of real websites with 3,518 tasks, for evaluating and RL-training GUI web agents (👍19; code [aiming-lab/WebHarbor](https://github.com/aiming-lab/WebHarbor) ★44).
- [Caper ("Shall We Approve?")](https://arxiv.org/abs/2610.40753): pre-executes commands in a snapshot sandbox so an independent approver can allow or roll back based on actual effects. Harmful-outcome rate on SABER is 6.7% against at least 14.8% for baselines (👍11).
- [EvoGroup](https://arxiv.org/abs/2611.03868): a self-evolving harness for shared context in group agents, cold-started from 6 tools. Held-out pass@1 on EverMemBench rises from 71.07% to 89.58%, above Claude Code's 85.83%.
- [What Is This Memory Useful For?](https://arxiv.org/abs/2611.03930): measures the task-conditioned utility of long-term agent memory. Task-agnostic summaries and structured records help less than raw memory, and memory has no measurable effect on software-engineering and scientific-coding benchmarks.
- [EvoMemState](https://arxiv.org/abs/2611.03743): adds relational and reasoning state to personal-agent memory beyond facts. RL teaches the model to generate request-specific reasoning state, improving retrieval completeness and answer accuracy.
- [How Agent Skills Evolve](https://arxiv.org/abs/2611.04456): an empirical study of 84,200 skills and 750,898 commits on GitHub. Evolution concentrates in skills coupled to a project, redundancy is a maintenance problem, and security-related changes reduce risk only modestly.
- [GeoFaham](https://arxiv.org/abs/2611.04977): Microsoft's multi-agent system for disaster geospatial analysis. A Response Store keeps full outputs outside the LLM context and agents exchange only identifiers and summaries. Score 0.940 vs 0.879 with 7.5x fewer tokens (code [microsoft/GeoFaham](https://github.com/microsoft/GeoFaham)).
- [SKILL2STEER](https://arxiv.org/abs/2611.04497): a hypernetwork compiles a natural-language skill into a low-rank activation offset, at 2.36M parameters per skill (9.25x fewer than weight-space adapters). The compiled offsets carry a general behavioral prior rather than the skill's content: a wrong skill document works as well as the right one.

## Observations
- Memory and context research is moving from how to store and fetch toward what to store and how to measure it. [MemSteer](https://arxiv.org/abs/2610.39276) generates supervision from user history automatically. [Rare, Relevant, and Still Wrong](https://arxiv.org/abs/2610.37624) and [What Is This Memory Useful For?](https://arxiv.org/abs/2611.03930) both find that simple compression or selection heuristics are unreliable, and the latter finds memory gives no measurable benefit on coding tasks.
- Harnesses are a research subject in their own right: [CoworkOS](https://arxiv.org/abs/2611.03178) (persistent memory plus layered workspace), [Rethinking Verification](https://arxiv.org/abs/2610.34577) (verification strategy), and RoboArchitect, [ParetoSaddler](https://arxiv.org/abs/2611.02079) and [EvoGroup](https://arxiv.org/abs/2611.03868) (automatic harness evolution). "Harness" appears often in the hot list, but only CoworkOS has high heat.
- The engineering-side signal is thin. [CoworkOS](https://github.com/RUC-NLPIR/CoworkOS) ★104, [uni-robot-agent](https://github.com/Open-RUA/uni-robot-agent) ★162 and [CUA-Master](https://github.com/xlyu0106/CUA-Master) ★88 suggest that harness and CUA work with code draws more attention. Today's data has no GitHub project ranking, so there is no comparison with the engineering side.
- Most of today's hot context papers have very few likes (mostly 8 or fewer). The heat comes from a few surveys and large harness papers, so treat these conclusions cautiously.
