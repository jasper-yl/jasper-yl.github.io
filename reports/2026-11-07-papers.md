## 今日要点
- Harness 是今天最集中的话题：[DeepExperience/Harness-S](https://github.com/DeepExperience/Harness-S) 热度第一，持续进化是否遗忘、RoboArchitect、TinyAstral 也都在研究 agent 外壳（harness）的演化与迁移。
- 持续演化会遗忘，这一点有了实证：Meta-Harness 在 SWE-Bench 上从 94.0% 掉到 32.0%，相对下降 66%。
- 上下文管理开始有可量化的收益：[Miraclecsc/Switch-SWE](https://github.com/Miraclecsc/Switch-SWE) 的任务切换插件在 OpenCode 上提升 5.5–15.5 个百分点，推理历史改写可以降低 agent 总花费。
- KV cache 同时出现在两个方向：[Qile-J/SwarmEvolve](https://github.com/Qile-J/SwarmEvolve) 让 agent 之间通过 KV cache 通信，SIMPLE 定律测得缓存后的 agentic 请求能耗仍是普通请求的 4.8 倍。
- Cognitive Symbionts 以 👍40 成为上下文/记忆方向点赞最高的论文，但它是愿景论文，没有实验结果。

## 热度榜：Agent Context 精选

### [Harness-S: Learning from Sibling Harnesses for Generalizable Agent Training](https://arxiv.org/abs/2611.04277)
- 热度：HF 👍60（入榜 1 天，新增 +9）；仓库 [DeepExperience/Harness-S](https://github.com/DeepExperience/Harness-S) ★55；heat 61.1，榜首
- 问题：没有哪个 harness 通用最优，不同变体修复不同的失败，效用还会随策略学习而变。
- 方法：从同一个基础 harness 沿不同修复方向演化出固定的「兄弟 harness 池」。只有基础 harness 下所有初始尝试都失败时，才在选中的辅助 harness 下重新 rollout，并用这些轨迹替换失败组做 RL。Adaptive Harness Router 用 Harness Behavior Profiles 加多个 LLM 投票来选 Top-k，并随策略学习重新校准。
- 结论/意义：在 AppWorld、SWE-Gym、DBBench 上，回到原始基础 harness 时，训练后的策略明显优于只训策略的做法。换用 router 做 Rank-1 推理，在同样 executor rollout 数下还有额外收益。

### [From Autonomous Agents to Cognitive Symbionts: Toward AI-Augmented Human Intelligence](https://arxiv.org/abs/2611.05376)
- 热度：HF 👍40（入榜 3 天，首次出现时 0 赞，新增 +40）；无代码。这是单作者（Hao Fei）的位置/愿景论文，没有实验数据。
- 问题：人会遗忘、漏看，也缺少自己的历史作支撑，而 AI 站在情境之外帮不上忙。
- 方法：提出「认知共生体」，一个终身、嵌入式、实时、私有、主动的伴侣，跨年保存用户上下文。核心概念是「认知缺口」，即人能带入情境的内容与工作记忆所能容纳的内容之间的差距。设计空间是「感知—保存—理解—共处—为人行动/与人共思—成长」的循环，外层是个人运行时和信任机制。
- 结论/意义：把跨年的长期个人上下文当作 AI 增强人类智能的核心，同时指出新风险，如考试中的隐蔽辅助、对所有人采用它的压力，并把治理纳入范式。

### [Switch-SWE: Do Coding Agents Hold Focus When Switching Between Unfinished Tasks?](https://arxiv.org/abs/2611.02017)
- 热度：HF 👍9（入榜 4 天，首次出现时 0 赞，新增 +9）；仓库 [Miraclecsc/Switch-SWE](https://github.com/Miraclecsc/Switch-SWE) ★26
- 问题：coding agent 在同一仓库的多个未完成任务间切换后，能否恢复先前任务的需求和进度。
- 方法：基准含 200 个 focus 任务、19 个 Python 仓库、400 个配对会话。轨迹分析发现「跨任务需求混淆」和「任务状态丢失」是反复出现的失败模式。论文据此提出插件式上下文管理模块，选取与任务相关的历史，并维护简明的任务状态摘要。
- 结论/意义：7 个 coding agent 的解决率平均差距为 11.5 个百分点（6.0–15.0）。在 OpenCode 上，该模块让不同模型的任务完成率提升 5.5–15.5 个百分点。

### [Why Pay for Long Reasoning When Rewrite Do Trick? Causal Effects of Reasoning History Compaction…](https://arxiv.org/abs/2611.03852)
- 热度：HF 👍8（入榜 2 天，首次出现时 0 赞，新增 +8）；无代码；单作者 Anton Hristov
- 问题：长推理轨迹很贵，能否不重训就让开源模型的后续推理更短。
- 方法：在工具结果返回前，把先前的推理改写成紧凑的「状态记录」，再比较从原始历史和紧凑历史出发的续写。
- 结论/意义：被接受的紧凑历史通常会缩短后续推理，编码案例中的重复验证也减少。在软件 agent 部署中可以降低总花费，但任务质量和含改写的耗时取决于目标模型和压缩器。

### [GEPA-Curator: Curated Learning for Self Improving Agents](https://arxiv.org/abs/2610.37651)
- 热度：HF 👍8（入榜 4 天，新增 +3）；无代码
- 问题：失败的 rollout 未必有学习价值，可能来自 prompt 缺陷、harness 限制、随机性或噪声评审，反而误导 prompt 优化器。
- 方法：包含两个组件。任务筛选过滤掉噪声大或不可靠的任务；先前成功检索按任务选择性地取回过去的成功轨迹，作为额外上下文交给优化器。
- 结论/意义：在 GoBrowse、ALFWorld、AppWorld、τ-bench 上，用 Gemini 3.1 Pro 和 Claude Opus 5 作优化器，均值持平或更好，最高比 GEPA 高 20.7%，比 ACE 高 21.2%。

### [Can Coding Agents Sustain Continual Evolution without Forgetting?](https://arxiv.org/abs/2611.03219)
- 热度：HF 👍7（入榜 4 天，新增 +6）；仓库 [THU-Agent/continual-harness-evolution](https://github.com/THU-Agent/continual-harness-evolution) ★2
- 问题：harness 自我进化多在单任务上研究，跨多任务持续进化会不会灾难性遗忘。
- 方法：把 3 个软件工程数据集组成 6 个进化方向，用 2 种代表性 harness 进化方法做持续进化的实证研究。
- 结论/意义：后续数据集上的进化会明显损害先前数据集的表现。用 DeepSeek-V4-Flash-0731 时，Meta-Harness 在 SWE-Bench 上进化后达到 94.0%，再在 FeatureBench 上进化，到第 5 轮跌到 32.0%，相对下降 66%。

### [Can Large Language Model Agents Learn by Watching Tutorial Videos?](https://arxiv.org/abs/2611.01460)
- 热度：HF 👍5（入榜 4 天，新增 +3）；无代码
- 问题：agent 能否不更新参数，从海量教学视频中学习。
- 方法：Tutorial Agentic Learning（TAL）用两阶段对抗过程，抽取有难度、基于视频的问题并用它们精炼，把视频沉淀成持久的、结构化的「教程书」记忆。推理时通过目录（TOC）树检索，让检索与模型推理挂钩，不依赖 embedding 相似度。
- 结论/意义：在 VidLearn（72 个国际象棋教程视频、12 种开局）上优于所有基线，随视频增多单调提升，训练/测试集相对原模型最高增益 113% / 91%。实战中 69% 的对局开局局面优于原模型。

### [SwarmEvolve: Latent Agent Swarms for Evolutionary Discovery and Optimization](https://arxiv.org/abs/2611.08483)
- 热度：HF 👍6（入榜 1 天，首次出现时 0 赞，新增 +6）；仓库 [Qile-J/SwarmEvolve](https://github.com/Qile-J/SwarmEvolve) ★2；arXiv 与 HF 双来源
- 问题：LLM 引导的进化搜索很慢，每轮要生成长文本思维链，并重复多次以维持种群多样性。
- 方法：每轮由数百个低成本 agent 并行工作，在隐空间推理而不解码成文本，通过传递 KV cache 共享信息，并用隐状态向量距离做新颖性过滤。汇总 agent 接收所有成员合并后的 KV cache，在隐空间完成想法交叉。
- 结论/意义：在 21 个数学发现/科学计算问题上平均分最高。要达到其他 SOTA 框架 60 分钟才能达到的最好分数，只需中位数 3–8 分钟。部分问题上，Qwen3 8B 的结果超过 AlphaEvolve 用前沿 LLM 首次找到的解。

## 研究趋势观察
- Harness 成为主线。榜首 [DeepExperience/Harness-S](https://github.com/DeepExperience/Harness-S) 把兄弟 harness 的能力迁入单一策略，持续演化研究则给出遗忘的反面证据（94.0% → 32.0%）。机器人方向的 RoboArchitect、TinyAstral 也在榜上（RoboArchitect 👍8、★10，平均成功率从 9.7% 到 43.3%；TinyAstral 👍4、★10，4B 学生达到 62.8%）。数据里没有它们在 GitHub 工程侧的呼应，只能看到各自仓库的星数。
- 上下文管理开始可测量。[Miraclecsc/Switch-SWE](https://github.com/Miraclecsc/Switch-SWE) 把任务切换后的丢失做成基准并给出插件，推理历史改写直接量化到花费，GEPA-Curator 把过往成功轨迹作为检索上下文。三者都在回答该保留、该丢弃还是该检索什么。
- KV cache 既是通信介质，也是成本项。[Qile-J/SwarmEvolve](https://github.com/Qile-J/SwarmEvolve) 用它在 agent 间传递想法；SIMPLE 定律指出缓存只能去掉 prefill 成本，agentic 长上下文下 KV-cache 项仍然居高。
- 热度集中在少数论文上。点赞最高的是 Harness-S（60）、BestRand（47）、Cognitive Symbionts（40），其余多数在个位数到十几。Agent Context 方向点赞超过 10 的只有 Harness-S 和 Cognitive Symbionts，后者是没有实验的位置论文。
