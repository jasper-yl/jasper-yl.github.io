## 🔥 热度榜：Agent Context 精选

### [How Feedback-Free Self-Evolution Reshapes Agent Skills](https://arxiv.org/abs/2611.25534)
- 热度：HF 👍4（入榜 4 天，新增 +4）；仓库 [LitaoGuo/How-Self-Evolution-Reshapes-Skills](https://github.com/LitaoGuo/How-Self-Evolution-Reshapes-Skills) ⭐3。本批唯一有点赞的 Context 论文。
- 问题：模型在没有反馈的情况下反复改写专家写的技能文档，技能会变好还是变差。
- 方法：让模型一轮轮改写专家技能，不给任何任务、运行或评判，再用改写后的技能跑 agent。改写会把技能拉向模型自己的先验，最先丢掉的是先验之外的知识，把这部分知识放回去能找回大部分损失。据此提出 SkillDiff：原地标记这部分知识，不改技能文本。
- 结论：每个被测模型在每个基准上都变差，30 轮后 SkillsBench 平均掉 15 分；SkillDiff 平均提升 4.8 分。

### [Experience Rot: Experienced Agents Fail Where Novices Succeed](https://arxiv.org/abs/2611.20922)
- 热度：HF 👍0（入榜 7 天，无新增）；无仓库。
- 问题：agent 靠对话历史、记忆文件、检索笔记和技能积累经验，工具（MCP）被悄悄变更后会怎样。
- 方法：在 MCP 工具定义静默变化后，对比有经验的 agent 和新手 agent。有经验的 agent 照抄之前的调用，不看当前接口，还会报告成功。
- 结论：变更后有经验的 agent 在多数任务上失败，新手多数成功；每种被测记忆形式都出现这一现象，经验越多越严重。简单补救效果有限：提示「已更新」几乎没用，让它去看文档，在文档没写明答案时也无效。

### [Instant Weight-Space Consolidation for Long-Term Memory in LLMs (CLAM)](https://arxiv.org/abs/2611.20759)
- 热度：HF 👍0（入榜 7 天，无新增）；无仓库。
- 问题：文本式 agent 记忆提取容易出错并不断累积，构建成本随对话增长，模型本身也不进化。
- 方法：循环超网络把会话激活流一次前向编译成低秩 adapter，无梯度步，也无 LLM 生成调用；固定大小的门控潜状态跨会话累积，另配一个情景缓冲区补充原文细节。
- 结论：在 LoCoMo 和 LongMemEval-S、3 个 2–7B 开源模型上，领先所有 agentic 基线 1–45 点，领先梯度式参数化方法 10–45 点，构建记忆比提取式系统快 3–151 倍。两个通道互补：情景缓冲区漏掉证据时，adapter 再加 12–15 点；缓冲区即使是 oracle，仍加 4–5 点。

### [LEDGER: Auditable Agent Memory Under Change](https://arxiv.org/abs/2611.20927)
- 热度：HF 👍0（入榜 7 天，无新增）；无仓库。
- 问题：记忆系统通常只在固定历史上评测，现实里事实会变、来源可信度不同、用户还会要求遗忘。
- 方法：语言模型提出事实，由显式规则决定哪个值是当前值、信任哪个来源、删除什么，每条事实记录来源和有效期。LEDGER+EP 再加原始对话轮次检索，并在删除时清理这些轮次。
- 结论：在合成的编码 agent 工作负载上，LEDGER+EP 开发集（5 个 seed）为 94.3%，留出集（5 个 seed）为 91.1%，最强基线全量回放分别是 82.1% 和 83.3%；删除请求只描述事实时，没有已删除的值进入证据。在 LongMemEval 的 210 题子集上为 74.8%，与全量回放持平，只用 1% 的上下文。合成负载是作者自建的，LongMemEval 上最强系统之间的差异在置信区间内。

### [Stopping Is Not the Limit: Long-Horizon Vulnerability Exploitation](https://arxiv.org/abs/2611.22888)
- 热度：HF 👍0（入榜 7 天，无新增）；无仓库。
- 问题：agent 在预算没用完时就停止，继续跑会怎样。
- 方法：作者发现，同一上下文里停止响应的比例上升，以及摘要里带有「不可能」判断，都与低效继续相关。据此提出 SCoRe：连续停止时压缩上下文，并把这些判断标记为「未证实」。
- 结论：SCoRe 优于摘要式继续和其他上下文管理基线。MiMo 在 2,000 轮达到能力覆盖 67.0%，原停止策略下为 32.4%；按 ExploitBench 的 300 轮参考结果计算，GPT-5.5 为 58.6%。

### [When Agent Skills Go Stale: Runtime Behavior and Selective Maintenance](https://arxiv.org/abs/2611.22525)
- 热度：HF 👍0（入榜 7 天，无新增）；无仓库。
- 问题：环境变化后，技能状态里有些部分过期，有些仍然有用。
- 方法：选择性维护。重放成功执行中的检查，不额外调用模型，验证差异是否与技能状态冲突，然后修复并验证，局部修不好就重建，全程不告诉它环境变了什么。
- 结论：在 4 个任务设置、2 个模型上，先前有益的技能在环境变化后，可使任务表现比不用技能还低 10 个百分点以上，或使执行成本涨近 40%。相对复用过期状态，选择性维护的准确率最多提升 67pp，执行步数最多减少 37%。这篇与 Experience Rot、技能自我改写那篇讲的是同一主题的三个角度。

### [Beyond Plain MCP: Do Decision Models and Code Mode Make Tool Use Cheaper and Faster?](https://arxiv.org/abs/2611.19123)
- 热度：HF 👍0（入榜 7 天，无新增）；无仓库。
- 问题：MCP 网关管理大型工具目录时，代码模式和前置决策层（路由）哪个更好。
- 方法：预注册评测，12 个服务器、最多 1,958 个干扰工具、3 个开源 agent。发布了 harness、一个微调的 4B 工具选择模型和全部评测轨迹。
- 结论：代码模式比普通 MCP 省 70–90% token，效用也明显更高。在代码模式桩函数里声明返回结构提示，可使弱 agent 的成功率波动最多 39.5 点，影响大于加路由。「决策层 + 代码模式优于单用代码模式」的假设未被证实。

### [Where Should LLM Agents Adapt at Test Time? In Context, in Weights, or Both](https://arxiv.org/abs/2611.19700)
- 热度：HF 👍0（入榜 7 天，无新增）；无仓库。
- 问题：agent 在同一环境重复工作时，经验该留在上下文里、写进权重，还是两者兼用。
- 方法：在统一的在线协议下比较 ICL、GRPO、SDPO 及其组合，共 14 种适应机制加一个无状态基线。模型为 Qwen3.5-9B，覆盖 SWE-bench Verified、AppWorld、ScienceWorld、BIRD-Critic-SQLite 4 个环境的 109 个任务。
- 结论：ICL 的最佳策略把平均成功率从 28.8% 提到 49.4%，是最大的单独增益；在其上加 GRPO 得到最高的 51.6%，SDPO 效果不一。轨迹分析显示，ICL 让查找和尝试变少，但常跳过对当前任务的检查和验证，加 GRPO 能恢复这些行为。

## 研究趋势观察
- 经验会过期：Experience Rot、技能自我改写、技能过期这三篇点赞都很少，结论一致，即积累的记忆或技能在环境变化后，可能比没有更差。对应的修补方向有两个：选择性维护（技能过期那篇），以及标记模型自己写不出来的专家知识（SkillDiff）。
- 记忆与压缩的评估开始同时看成本和可靠性：LEDGER+EP 只用 1% 的上下文，DMC-5 利用压缩器缓存命中，CLAM 的构建提速 3–151 倍，LiveLoRA 做 KV cache 迁移。token、缓存、延迟与准确率一起报，不再只报准确率。
- Harness 是昨晚新论文里的高频词。点赞最高的两篇是 Embo-Harness（👍88）和 AutoPILOT（👍30），都在具身或游戏、实时场景。纯 Agent Context 方向的 hot 论文在 HF 上仍几乎没有点赞，热度信号主要还在具身与模型报告。
- 记忆与技能被当作需要审计的对象：HEAMS（记忆系统评估）、FORGETMENOT（商用 agent 记忆隐私）、技能供应链与检测器研究、MCP 工具提供方误绑定。本期没有联网核对 GitHub 项目侧，这条只基于论文数据，不对工程侧做呼应判断。
