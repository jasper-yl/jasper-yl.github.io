## 一、🔥 热度榜：Agent Context 精选

### [MemT-1.0: Towards Memory-Native Evolution](https://arxiv.org/abs/2610.26825)
- 热度：HF 👍134（入榜 1 天，新增 +2）；代码：[MemTensor/MemT-1.0](https://github.com/MemTensor/MemT-1.0) ⭐361
- 问题：外部记忆多为被动检索，希望把记忆变成基础模型自身的能力。
- 方法：基于 Metis，用 Gated DeltaNet-2 在每轮内做稳定的 token 级记忆更新，并引入 Mixture-of-Storage 扩展原生记忆容量。训练分持续预训练和后训练两阶段，共 34B token 数据，发布 Nano 和 Flash 两个模型。
- 结论/意义：优于参数化记忆基线，与检索增强方法相当；128K 历史下 Nano 端到端推理提速约 1.86×，持久存储相比全上下文 KV cache 减少 66×，并通过内化检索到的过程经验提升 Agent 任务成功率。

### [Cache Engineering for Agents](https://arxiv.org/abs/2610.28577)
- 热度：HF 👍130（入榜 1 天，新增 +21）；代码：[thu-nics/AKV](https://github.com/thu-nics/AKV) ⭐48
- 问题：裁剪或摘要历史会改变轨迹前缀，使后续缓存失效并触发昂贵的重新 prefill。
- 方法：提出 cache engineering，Agent 用 `drop` 把选定缓存排除出后续注意力，用 `repos` 调整保留 key 的位置编码，无需修改轨迹或重新 prefill。同时指出"相同 token 序列在不同缓存操作序列下状态不同"，因此前缀匹配不足以保证正确复用，并据此设计 AKV 服务引擎（对外无状态接口，对内管理有状态的缓存复用、驱逐与恢复）。
- 结论/意义：tool-response 滚动 drop 策略比阈值触发摘要平均分高 1.7、成本低 27.7%；AKV 最高带来 1.2× 输出吞吐和 1.5× P95 延迟加速；缓存策略的递归自我改进再降成本 7.1%。

### [OpenVLHarness: Real World Visual Agentic Tool-Use with Multimodal Memory](https://arxiv.org/abs/2610.26860)
- 热度：HF 👍113（入榜 1 天，新增 +2）；代码：[uclanlp/OpenVLHarness](https://github.com/uclanlp/OpenVLHarness) ⭐210
- 问题：视觉推理任务需要多种工具的证据，且证据要在多步推理中被保留并可解读。
- 方法：以"能力层 + 持久多模态记忆"组织 harness。能力层把异构工具输出渲染为模型可读观察；持久记忆把图像、结构化数据、网页引用保存为可寻址 artifact；再配代码接口对存储数据做跨工具计算。
- 结论/意义：22 个基准、8 个骨干上平均比无工具基线高 9.7–12.6 分；GPT-6 Luna 中等推理强度下，以不超过 37% 的 token 成本超过其他方案在最高强度下的表现 7.7–8.5 分。

### [FlowState: Execution State as Memory for Long-Horizon LLM Agents](https://arxiv.org/abs/2609.34565)
- 热度：HF 👍21（入榜 1 天，新增 +3）；暂无代码仓库
- 问题：长程任务中保留全部历史成本高，压缩又可能丢掉后来才变得重要的细节。
- 方法：把执行状态当作记忆，保存带语义类型的状态节点、节点间关系，以及指向原始工具观察的引用，将"持久保留"与"按需访问"分开。ISU 在每步根据新输入与反馈增量更新当前状态，PSA 在推理中按需逐步展开历史状态与证据。
- 结论/意义：相同 DeepSeek-V4-Flash 下，相比全上下文基线，MemoryArena 平均成功率 +4.55、τ³-Bench 平均通过率 +13.95 个百分点，总 token 消耗分别下降 43.2% 和 40.6%。

### [MemPilot: Orchestrating On-Demand Multimodal Memory Curation for LLM Agents](https://arxiv.org/abs/2610.06830)
- 热度：HF 👍36（入榜 1 天，新增 0）；代码：[ViktorAxelsen/MemPilot](https://github.com/ViktorAxelsen/MemPilot) ⭐6
- 问题：多数记忆系统与查询无关地构建记忆，预处理浪费且可能丢掉后来关键的细节。
- 方法：用 RL 训练多步 LLM 策略，在"检索与查询无关的记忆"和"把原始多模态历史交给异构 LLM / VLM 做查询相关整理"之间迭代选择，并联合控制证据量、整理指令、模型选择与视觉访问。训练上采用按目标分别估计优势再聚合，以及基于前缀的边际效用估计做信用分配。
- 结论/意义：在 5 个多模态 Agent 记忆基准上，按不同偏好扫描得到的性能–成本–延迟前沿比现有基线更宽。

### [DeLoop: Repeated Actions as Self-Supervision for Long-Horizon Agents](https://arxiv.org/abs/2610.19376)
- 热度：HF 👍22（入榜 1 天，新增 +5）；代码：[cskyl/deloop](https://github.com/cskyl/deloop) ⭐0
- 问题：Agent 会重复发出相同工具调用、得到相同观察（loop），历史被压缩后更常见。
- 方法：自监督训练，把 rollout 中的循环动作作负例，同一轨迹中之后第一个非循环动作作正例，用 DPO 学习，不需要任务奖励、标准答案或 LLM 评委。
- 结论/意义：在 CodeGym 压缩设置下，Qwen3-8B 含循环任务的比例从 57.3% 降到 6.1%，每任务步数约为原来的三分之一；Qwen3-32B 成功率从 37.7% 升到 44.8%。

### [Socratic Skill Learning: Interleaving Teaching and Practice for Transferable Agent Skills](https://arxiv.org/abs/2610.17860)
- 热度：HF 👍37（入榜 1 天，新增 +7）；代码：[NJU-LINK/Socratic-Skill-Learning](https://github.com/NJU-LINK/Socratic-Skill-Learning) ⭐2
- 问题：一次成功的任务尝试未必检验了流程及其适用条件，难以学到可迁移的 Skill。
- 方法：SSL 让专家（Educator）指导与学生（Student）实践交替进行，Student 是唯一的环境操作者和 Skill 作者，可质疑、测试、调整建议。另构建 SkillTransferBench（35 个任务族、408 个可执行用例）测试迁移；Issue-Guided SSL 跟踪跨版本未解决的问题，用来挑选和聚焦复审。
- 结论/意义：主队列上 Fixed-Window SSL 效用 0.801，高于无 Skill 的 0.723 以及适配后的 Trace2Skill（0.761）和 SKILL-KD（0.751）；Issue-Guided 版本效用 0.805，Educator token 少 61.7%。

### [Memory-Centric Continual Learning for AI Agents](https://arxiv.org/abs/2610.29357)
- 热度：HF 👍25（入榜 1 天，新增 +6）；暂无代码仓库
- 问题：外部记忆多是被动检索缓存，是否真能驱动持续学习尚无定论。
- 方法：提出 MCCL，主张以"是否改善未来行动"来评价记忆。包含三部分：按存储位置、形态、管理策略划分的三轴分类（内外两层循环）；衡量干扰下保留、变化适应和任务迁移的评测协议；覆盖非参数 / 参数记忆的记忆缩放框架。
- 结论/意义：摘要未给出实验结论，是偏框架与立场性质的工作。

## 五、研究趋势观察

- **上下文管理从"删减"转向"保持前缀与可回溯"**：Cache Engineering（不改前缀的 drop / repos）、FlowState（状态节点 + 原始观察引用）、CarryOn（折叠时只修订受影响记录）都强调压缩后仍能保持连续性或按需回溯；Skip the Compressor 则指出压缩会改动要编辑的代码文本，导致补丁更难应用。
- **记忆路线出现分歧**：MemT-1.0 把记忆内化进模型，MemPilot 做按需整理，而 Raw-RAG 表明在所评估的对话任务上简单检索即具竞争力；MCCL 则试图重新定义评价标准。这几项合起来说明"复杂记忆是否值得"目前仍是开放问题。
- **Harness 成为一等研究对象**：CoEvo-RSI、Self-HPO、Harness Scaling、Self-Evolving Agent Harness 和 HarnessPro 都在优化或演化 harness 本身；训练侧则围绕合成环境（WildAWM、CoworkEnv）和多 session RL（Mosaic）展开。
- **与工程侧的呼应**：从星数看，热度榜中 MemT-1.0（⭐361）、OpenVLHarness（⭐210）和新榜中的 OpenGCUA（⭐441）、Harness-RSI（⭐387）、Microsoft 的 TokenEconomizer（⭐211）受关注较多，覆盖记忆、harness、电脑使用和成本控制，和论文侧的热点基本一致。
