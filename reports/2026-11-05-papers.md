### [Switch-SWE: Do Coding Agents Hold Focus When Switching Between Unfinished Tasks?](https://arxiv.org/abs/2611.02017)
- 热度：HF 👍6（入榜 2 天，新增 +6）；代码 [Miraclecsc/Switch-SWE](https://github.com/Miraclecsc/Switch-SWE) ⭐26。
- 问题：coding agent 在同一仓库里被打断、做过别的未完成任务后，能否恢复原任务的需求和进度。
- 方法：基准含 200 个 focus 任务、19 个 Python 仓库、400 个配对会话（不被打断 vs 被打断）。轨迹分析发现两类反复出现的问题：跨任务需求混淆和任务状态丢失。作者提出一个即插即用的上下文管理模块，负责选取与任务相关的历史，并维护简洁的任务状态摘要。
- 结论/意义：7 个 coding agent 平均掉 11.5 个百分点（范围 6.0–15.0）；在 OpenCode 上，该模块让任务完成率提升 5.5–15.5 个百分点。

### [ParetoSaddler: Pareto-Guided Optimization of Agent Harnesses for Quality and Cost](https://arxiv.org/abs/2611.02079)
- 热度：HF 👍16（入榜 1 天，新增 +0）；无代码仓库。
- 问题：harness 优化通常只看质量；联合优化质量和成本时，中间步骤套用部署偏好会过早淘汰以后有用的候选。
- 方法：把中间候选晋升和最终部署选择分开。每轮把候选与父 harness 多次重复执行对比，用 Bayesian bootstrap Pareto 支持度判断，质量或成本任一项有可信进步就晋升，晋升的候选继续作为后续优化的父代。
- 结论/意义：ClawMark 上质量 70.86%→81.35%，成本 $1.17→$1.01/任务；GAIA2 上质量 56.22%→62.89%，成本 $0.78→$0.45/任务。

### [MemSteer: Turning User Histories into Supervision for Agent Memory Optimization](https://arxiv.org/abs/2610.39276)
- 热度：HF 👍8（入榜 6 天，新增 +8）；无代码仓库。
- 问题：新用户的历史没有标注，无法评估和改进记忆设计，手工构造 QA 和证据又太贵。
- 方法：MemSteer 先构造有证据支撑的答案计划，再生成问题，并用溯源审计和盲答恢复检查标注质量。配套的 MemSteer-Opt 用 QA 评估加证据引导的失败诊断，在不更新模型参数的前提下修改记忆存储、检索和上下文构造。
- 结论/意义：相对 Base-BM25，ATM-Bench Question Score +13.4 分，RHELM 准确率 +4.1（不用外部数据）和 +6.6（用外部数据）；自动生成的监督效果与官方 QA 引导的优化相当。

### [GEPA-Curator: Curated Learning for Self Improving Agents](https://arxiv.org/abs/2610.37651)
- 热度：HF 👍8（入榜 2 天，新增 +3）；无代码仓库。
- 问题：GEPA 这类反射式 prompt 优化器会从所有失败 rollout 中学习，但有些失败源自 harness 限制、随机性或评审噪声，反而有害。
- 方法：包含两部分。任务筛选过滤掉可能产生噪声信号的任务；成功轨迹检索按任务取出过往成功轨迹，作为额外上下文交给 prompt 优化器。
- 结论/意义：在 GoBrowse、ALFWorld、AppWorld、τ-bench 上，均值持平或超过两个基线，最高比 GEPA 高 20.7%，比 ACE 高 21.2%。

### [RoboArchitect: Automating the Design of Robotic Agents with Persistent Memory](https://arxiv.org/abs/2610.42141)
- 热度：HF 👍8（入榜 3 天，新增 +3）；代码 [roboarchitect-ai/RoboArchitect](https://github.com/roboarchitect-ai/RoboArchitect) ⭐9。
- 问题：冻结的机器人策略放进 agent harness 后表现好很多，但 harness 要为每个机器人或基准手工重做。
- 方法：编码模型观察 rollout、诊断失败并迭代修改 harness，不更新任何权重。harness 还会进化出自己的持久记忆，把学到的经验（如有效抓取深度）带入后续决策。
- 结论/意义：未见场景成功率 9.7%→43.3%（4.5x），未见任务 12.7%→40.2%（3.2x）。

### [Can Large Language Model Agents Learn by Watching Tutorial Videos?](https://arxiv.org/abs/2611.01460)
- 热度：HF 👍5（入榜 2 天，新增 +3）；无代码仓库。
- 问题：LLM agent 部署后能力冻结，如何在不更新参数的前提下从教程视频中持续学习。
- 方法：Tutorial Agentic Learning（TAL）把教程视频整合进持久的结构化「教程书」记忆，并用对抗过程生成与视频相关的难题来精炼这份记忆。推理时通过目录（TOC）树检索，由模型推理驱动检索，不靠 embedding 相似度。
- 结论/意义：在 VidLearn（72 个国际象棋教程视频）上，相对原始 MLLM 最高提升 113%（训练集）和 91%（测试集），且随视频增多单调变好；实战中 69% 的对局开局局面强于原模型。

### [Can Coding Agents Sustain Continual Evolution without Forgetting?](https://arxiv.org/abs/2611.03219)
- 热度：HF 👍6（入榜 2 天，新增 +5）；代码 [THU-Agent/continual-harness-evolution](https://github.com/THU-Agent/continual-harness-evolution) ⭐1。
- 问题：harness 自我进化能否跨多个任务持续进行而不发生灾难性遗忘。
- 方法：把 3 个软件工程数据集组成 6 个进化方向，用两种代表性的 harness 进化方法做持续进化的实证研究。
- 结论/意义：后续数据集上的进化会大幅损害先前表现。DeepSeek-V4-Flash-0731 搭配 Meta-Harness 时，SWE-Bench 进化后为 94.0%，再在 FeatureBench 上进化，第五轮掉到 32.0%（相对下降 66%）。

## 新论文：昨晚新公布

- [SpecCompact](https://arxiv.org/abs/2611.06876)：用小 drafter 并行生成摘要槽位，再由目标模型逐行验证，加速 agent 上下文压缩。在 AppWorld 和 τ³ 上比 Hermes 式摘要快 2.04–5.63x，Hermes 内用户研究的中位数快 8.68x。
- [SumOne](https://arxiv.org/abs/2611.06445)：用冻结重建器恢复被遮蔽的轨迹片段，以重建质量加长度惩罚作为 GRPO 奖励，训练任务无关的摘要器。推理成本约降 78%（DeepSearchQA）和 75%（SWE-bench Verified），绝对分数降 0.04，可跨模型和 harness 迁移。
- [Coca-Cola: Tools Need Not Speak in Text](https://arxiv.org/abs/2611.06500)：把工具输出压缩成连续潜在 token 送入 agent 的输入嵌入空间，并用 Action-Preserving Training 对齐下一步动作分布。web 搜索 agent 的 token 消耗降 70.01%–89.24%，运行时间降 24.45%–55.97%。代码 [THU-Agent/Coca-cola](https://github.com/THU-Agent/Coca-cola)。
- [Visual Token Routing](https://arxiv.org/abs/2611.06854)：轻量时空路由器决定截图中哪些区域的视觉 token 进入语言模型。在 OSWorld 等任务上与全分辨率持平，视觉 token 少 2.5–5.8x，推理成本最多降 3.3x。
- [Route to Remember: Adaptive Memory Selection for LLM Agents](https://arxiv.org/abs/2611.05636)：用在线策略自蒸馏把用户记忆写入权重，再用「验证后再生成」的路由器在权重记忆和文本记忆之间分配。HaluMem 上持平或超过文本记忆基线，每次查询读取的 token 更少。
- [Why Pay for Long Reasoning When Rewrite Do Trick?](https://arxiv.org/abs/2611.03852)：在工具结果返回前，把已有推理改写成紧凑的状态记录。多数情况下后续推理变短；软件 agent 部署中总花费可降，但任务质量取决于目标模型和压缩器。
- [FlyHash for LLM Agent Memory](https://arxiv.org/abs/2611.05791)：首次把受果蝇嗅觉回路启发的 FlyHash 用于 agent 记忆检索。同等比特下质量占优，但码更大、比较更慢，常规规模下 HNSW 仍胜过两种哈希。
- [Hybrid Computer Use](https://arxiv.org/abs/2610.41432)：把代码/命令行、无障碍（AX）和视觉 GUI 三个通道统一成一个接口，AX 工具返回紧凑观测并以 AX diff 报告效果。OSWorld 2.0 上取得对比系统中最高的 Partial 和 Binary 分（初步热度 👍6）。代码 [microsoft/Hybrid-Computer-Use](https://github.com/microsoft/Hybrid-Computer-Use)。
- [FrontierPhysics](https://arxiv.org/abs/2611.06910)：56 个由 42 位物理学家基于自己研究设计的端到端科研任务。22 个模型、26 种配置下，没有任何配置在 168 次 rollout 中通过超过 46 次（初步热度 👍32，新论文中最高）。
- [What Does Multi-Turn Reinforcement Learning Really Improve in LLM Agents?](https://arxiv.org/abs/2611.06483)：多轮 agentic RL 的优势依赖足够的轮次预算，主要体现在错误恢复和长程韧性上。作者提出训练时变化交互预算的 BudgetMix RL（初步热度 👍28）。
- [SlackBench](https://arxiv.org/abs/2611.05512)：140 个需要联合推理工作场所通信和仓库状态的查询。33 个前沿模型和 harness 中最好的约 80%，多数低于 66%。
- [Mechanical Engineering Skills](https://arxiv.org/abs/2611.05758)：含 33 个 agent skill 的开源库，按需加载、一条命令安装，覆盖 CAD、CFD、增材制造等。作者说明与其他 agent 的受控对比留待未来工作。

## 研究趋势观察

- harness 与记忆的自动优化成为主线。[ParetoSaddler](https://arxiv.org/abs/2611.02079)、[MemSteer](https://arxiv.org/abs/2610.39276)、[GEPA-Curator](https://arxiv.org/abs/2610.37651)、[RoboArchitect](https://arxiv.org/abs/2610.42141) 都在不改权重的前提下优化 harness、记忆或 prompt；[Continual Harness Evolution](https://arxiv.org/abs/2611.03219) 则指出这类进化会遗忘旧任务（94.0%→32.0%）。
- 上下文压缩有了多种形态：并行加速摘要（[SpecCompact](https://arxiv.org/abs/2611.06876)）、任务无关训练的摘要器（[SumOne](https://arxiv.org/abs/2611.06445)）、连续潜在 token（[Coca-Cola](https://arxiv.org/abs/2611.06500)）、视觉 token 稀疏化（[Visual Token Routing](https://arxiv.org/abs/2611.06854)）、权重记忆（[Route to Remember](https://arxiv.org/abs/2611.05636)）。这些论文大多刚出现，点赞接近 0，热度要几天后才能判断。
- 长程任务中的上下文丢失开始有专门基准：[Switch-SWE](https://arxiv.org/abs/2611.02017)（任务切换）、[SlackBench](https://arxiv.org/abs/2611.05512)（信息分散在通信和代码中）、[CrossSWE](https://arxiv.org/abs/2611.01484)（跨仓库一致性）。
